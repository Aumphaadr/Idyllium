Кавычки утомили

В уроке о сервере вы отдавали HTML прямо из кода: res.send("<h1>Гильдия</h1>..."). Для двух строк — нормально. Но попробуйте собрать так страницу с заголовком, тремя абзацами и списком из данных — и код превратится в клей из кавычек, плюсов и to_string. На третьей странице вы возненавидите кавычки, и будете правы: вёрстка — не дело кода. У этой боли есть классическое лекарство, и сегодня оно у вас появится: шаблоны.

Идея проста: страница живёт в отдельном HTML-файле, а в местах, где должны оказаться данные, стоят дырки с именами. Программа берёт файл, вставляет в дырки значения — и отправляет готовую страницу.

Первый шаблон

Заведите в проекте файл templates/card.html. Это обычный файл в обычной папке — никакого тайного правила «шаблоны обязаны лежать в особом месте» нет, путь вы называете сами, как в библиотеке file:

<h1>{{name}}</h1> <p>Город: {{city}} · Уровень: {{level}}</p>

Двойные фигурные скобки — те самые дырки: {{name}} значит «сюда программа подставит значение по имени name». Откуда берутся значения? Из старого знакомого — json.Object:

Сервер слушает http://127.0.0.1:8080

Откройте адрес в браузере — и увидите страницу с именем, городом и уровнем. send_template(путь, значения) делает три вещи: читает файл, подставляет значения из объекта в дырки и отправляет результат как HTML-страницу. Обработчик стал честным разделением труда: код собирает данные, шаблон отвечает за внешний вид. Захотелось перекрасить страницу или переставить абзацы — правится один HTML-файл, программа не трогается вовсе.

В Web IDE всё это работает в сервере-репетиции: шаблон — файл вашего проекта, и репетиция его читает как настоящий сервер.

Дырка с точкой: поле объекта

Значением в объекте может лежать другой объект — тогда в шаблоне работает точка, как в коде:

<h1>Карточка героя</h1> <p>{{hero.name}} из города {{hero.city}}</p>

{{hero.name}} читается дословно: «возьми hero, достань его поле name». Знакомая точка из мира объектов — только внутри HTML-файла.

Цикл в шаблоне: {% for %}

Главная сила шаблонов — списки. Витрина из базы, таблица рекордов, лента записей: в коде — json.Array, в шаблоне — цикл:

<h1>Состав гильдии</h1> <ul> {% for member in members %} <li>{{member.name}} — уровень {{member.level}}</li> {% endfor %}</ul>

Кусок шаблона между {% for member in members %} и {% endfor %} повторяется для каждого элемента списка, и внутри него member — очередной элемент. Три бойца — три <li>. Пустой список — ноль строк, и это не ошибка: страница просто выйдет без пунктов.

Заметьте разницу скобок: {{...}} — «напечатай значение сюда», {%...%} — «команда»: сама она ничего не печатает, а управляет куском шаблона и требует парного {% endfor %}. Разные роли — разные скобки, глазу легче сканировать страницу.

А где условия? В коде. Правило нашей кухни: шаблон глупый, логика в программе. «Если корзина пуста — покажи другое» решается в обработчике: два шаблона и обычный if перед send_template — это читаемее, чем ветвление внутри HTML.

Когда дырке нечего подставить

Опечатались в имени? Забыли положить значение? Сервер не упадёт и страница не исчезнет — в месте дырки появится читаемый маркер:

[[ нет значения 'ghost' ]] [[ 'title' — не объект ]] [[ 'members' — список: нужен {% for %} ]]

Вёрстка — визуальный труд: полезно видеть всю страницу с дыркой, названной по имени, а не голую ошибку вместо страницы. Взрослые шаблонизаторы, к слову, в этой ситуации часто молча печатают пустоту — и опечатка живёт в странице незамеченной неделями. Наш маркер кричит из вёрстки сразу.

А вот пропавший файл шаблона — настоящая авария обработчика: web.Response.send_template() cannot read 'templates/каточка.html': file does not exist. Сервер переживёт и её — запрос получит 500, ошибка уйдёт в консоль, остальные маршруты продолжат работать.

Данные — это текст

Важное правило подстановки: значение вставляется как текст, а не как разметка. Если в данных лежит строка <b>СРОЧНО</b>, на странице будут видны буквы <b>СРОЧНО</b> — а не жирное слово. Хотите жирным — жирным делает шаблон: <b>{{text}}</b>. Разметка живёт в шаблоне, данные — текст, и у каждого своя работа.

Это не прихоть, а взрослая гигиена. Скоро в ваши страницы начнут писать посетители — форма гостевой книги уже в конце этого урока. И первый же шутник отправит вместо текста <script>...</script> — скрипт, который выполнился бы у каждого, кто откроет страницу. У нас его ждёт участь любого текста: буквы на экране. Взрослые серверы экранируют подстановки ровно по этой причине — теперь вы знаете её изнутри.

Красивый адрес: параметр пути

Взгляните на адреса больших сайтов: карточка товара живёт не на /tovar?id=3, а на /tovar/3. Кусок пути — тоже параметр. В маршруте такой кусок объявляется в угловых скобках, а достаётся методом req.param:

Запрос /post/3 попадёт в card, и req.param("id") вернёт "3". Обратите внимание: всегда строку — числом её, как обычно, делаете вы сами через to_int, и «в адресе не число» остаётся вашей честной проверкой, а не тайной магией маршрутов.

Точный путь всегда побеждает шаблонный: если рядом зарегистрирован on_get("/post/new", ...), запрос /post/new уйдёт именно ему, а /post/7 — карточке. И нет, два шаблона одной формы (/x/<a> и /x/<b>) зарегистрировать нельзя — сервер откажет сразу, чтобы маршруты молча не спорили.

Форма: посетитель пишет вам

До сих пор посетитель только читал. HTML-форма разворачивает движение:

<form method="post" action="/add"> <input name="author" placeholder="Кто вы?"> <textarea name="text" placeholder="Что скажете?"></textarea> <button>Отправить</button> </form>

Кнопка «Отправить» делает POST-запрос на /add, а заполненные поля уезжают в теле запроса. Загляните в это тело через req.body — и увидите суп из процентов:

author=%D0%9C%D0%B8%D1%80%D0%B0&text=%D0%9F%D0%BE%D1%81%D0%BE%D1%85+%D0%BD%D0%B0%D1%88%D1%91%D0%BB%D1%81%D1%8F%21

Так браузер кодирует буквы (особенно наши, кириллические), а плюсами прячет пробелы. Разбирать это руками не нужно — поле достаётся методом req.form по имени из name="...":

req.form("author") вернёт уже раскодированное "Мира". Нет такого поля — пустая строка, как у req.query: проверка на пустоту и честный 400 — ваша работа, и вы её только что сделали.

Redirect: после письма — на главную

Обработчик формы выше отвечает страницей «Принято!». У этого пути есть скрытая беда, знакомая каждому взрослому сайту: нажмите теперь F5 — и браузер честно спросит «отправить форму ещё раз?». Согласитесь — запись уйдёт второй раз. Лекарство — классический приём PRG (POST → Redirect → GET): после успешной обработки формы не рисуйте страницу, а отправьте браузер на обычный GET-адрес:

res.redirect("/") отвечает особым кодом 303 See Other с адресом в придачу — браузер сам делает GET на главную. Теперь F5 обновляет главную страницу, а не повторяет отправку: двойных записей не бывает. Одна строка — а сайт начинает вести себя по-взрослому.

Собираем всё: гостевая книга

Все двери урока — в одном живом проекте. Шаблон templates/list.html:

<h1>{{title}}</h1> <p>Записей: {{count}}</p> {% for post in posts %}<article> <h3>{{post.author}}</h3> <p>{{post.text}}</p> </article> {% endfor %}<form method="post" action="/add"> <input name="author" placeholder="Кто вы?"> <textarea name="text" placeholder="Что скажете?"></textarea> <button>Оставить запись</button> </form>

Пройдитесь по кругу глазами посетителя: открыл страницу — увидел записи из шаблона с циклом; заполнил форму — POST ушёл на /add; сервер разобрал поля, добавил запись и отправил браузер обратно на главную; главная снова собралась из шаблона — уже с новой записью. Четыре инструмента урока работают как один механизм. Захочется, чтобы записи переживали перезапуск сервера, — вы уже знаете, куда смотреть: файлы или база данных, обе двери из прошлых разделов.
