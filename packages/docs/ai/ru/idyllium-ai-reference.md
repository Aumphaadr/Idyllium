# Справочник языка Idyllium для ИИ

Это компактный справочник по языку программирования Idyllium, предназначенный
для ИИ. Его можно целиком вставить в чат с любым ИИ-помощником, чтобы тот мог
порождать, объяснять, проверять и тестировать код на Idyllium.

*Это русская версия файла `idyllium-ai-reference.md`. Английский оригинал лежит
в каталоге уровнем выше. **Сообщения компилятора и среды выполнения оставлены
по-английски** — именно в таком виде их видит на экране ученик.*

Текущая версия языка: Idyllium 1.5.2.

Этот справочник описывает реализованное поведение. Замыслы из `BACKLOG.md`
и черновики в `spec/some_*` не являются возможностями языка, пока они
не реализованы и не описаны здесь.

Важное правило для ИИ-помощников: Idyllium — учебный язык, дружелюбный
к детям. Не выдумывайте синтаксис. Не подменяйте синтаксис Idyllium
синтаксисом C++, C#, JavaScript, Python, Java, Kotlin или псевдокодом. Если
запрошенной возможности здесь нет, так и скажите, что она пока не описана,
и предложите обсудить, а не изобретайте молча новую конструкцию.

## 1. Философия

Idyllium создан для обучения программированию детей и подростков. Язык
предпочитает предсказуемое поведение и понятные ошибки.

Основные принципы:

- `23 / 10` обязано вести себя как школьная арифметика и давать вещественный
  результат, а не целочисленное усечение.
- Текст это текст, а не байты; строки с кириллицей должны вести себя как
  строки символов.
- Виджеты — обычные объекты, а не указатели.
- Большинство неявных преобразований запрещено. Например, `label.text = 42;`
  должно быть ошибкой, а не неявным преобразованием в `"42"`.
- Ошибки времени выполнения должны быть читаемыми, копируемыми и понятными
  после машинного перевода.
- `++` и `--` в Idyllium не существуют и порождаться не должны.
- Составные присваивания (`+=`, `-=`, `*=`, `/=`) есть, но материалы курса
  сознательно предпочитают полную форму `x = x + 1`: она держит на виду обе
  роли переменной (источник справа, приёмник слева). Порождая учебный код,
  предпочитайте полную форму; `+=` оставьте для стилевого дописывания строк
  (`sign.style += "color: green;";`), где им пользуется сам курс.
- Начиная с 1.3.5 компилятор выдаёт прицельные подсказки на частые промахи
  новичка: `=` в условии, `&&`/`||`/`!` (предлагает `and`/`or`/`not`), `%`
  (предлагает `mod(a, b)`), `++`/`--` (предлагает `x = x + 1`), `elif`,
  десятичная запятая в числах, неэкранированная кавычка внутри строки,
  ключевое слово в роли имени и путаница кириллических и латинских омоглифов
  в идентификаторах. Метод или функция, названные без скобок в позиции
  оператора, — ошибка компиляции (`'info' is not called — add '()' to call it`).

## 2. Форма файла и программы

В исходном файле Idyllium обычно есть:

1. Импорты `use`.
2. Глобальные переменные, функции, классы.
3. `main()`.

Пример:

```idyllium
use console;

main() {
    console.write("Hello, World!", '\n');
}
```

Это совпадает со стартовой программой веб-IDE и с первым уроком курса
(`console.write` с явным `'\n'` преподаётся раньше `writeln`).

Модули импортируются по имени файла или библиотеки:

```idyllium
use console;
use math;
use gui;
use fonts;
```

Пользовательские модули — обычные файлы `.idyl` в том же проекте. Если есть
`helper.idyl`, его можно импортировать так:

```idyllium
use helper;
```

После этого переменные верхнего уровня, константы, функции и классы из этого
модуля доступны как `helper.имя`.

## 3. Комментарии и оформление

Однострочные комментарии:

```idyllium
// комментарий
```

Блочные комментарии:

```idyllium
/* комментарий */
```

В примерах используйте отступ в четыре пробела.

## 4. Примитивные типы

Примитивные типы:

- `int`
- `float`
- `string`
- `char`
- `bool`
- `void`

Логические литералы:

```idyllium
true
false
```

Строковые литералы пишутся в двойных кавычках:

```idyllium
string text = "Привет";
```

Символьные литералы — в одинарных:

```idyllium
char letter = 'A';
char line_break = '\n';
```

Поддерживаются экранирования `\n`, `\t`, `\r`, `\e` (ESC), `\0`, `\\`, `\"`
и `\'`. Неизвестные экранирующие последовательности — ошибки компиляции.

`null` — литерал языка, но не примитивный тип общего назначения. Принять его
или сравняться с ним могут только библиотечные контейнеры значений, явно
поддерживающие отсутствие значения. Сейчас это `json.Value` и `sqlite.Value`;
обычные переменные, массивы, объекты пользовательских классов, `json.Object`
и `json.Array` значения `null` не принимают.

## 5. Переменные и присваивание

Объявление:

```idyllium
int age = 12;
float temperature = 36.6;
string name = "Mira";
bool ok = true;
```

Присваивание:

```idyllium
age = 13;
```

Составное присваивание:

```idyllium
age += 1;          // работает, но стиль курса предпочитает: age = age + 1;
age -= 1;
temperature *= 2;
temperature /= 2;
```

Так делать нельзя:

```idyllium
age++;  // неверно: в Idyllium нет ++
age--;  // неверно: в Idyllium нет --
```

Именованные константы объявляются словом `const` перед типом:

```idyllium
use console;

const int MAX_LEVEL = 100;

main() {
    const string GAME_TITLE = "Idyllium Quest";
    console.writeln(GAME_TITLE, ": ", MAX_LEVEL);
}
```

Правила для именованных констант:

- `const` поддерживается для локальных объявлений и для объявлений верхнего
  уровня.
- Инициализатор обязателен.
- Прямое и составное присваивание такому имени — ошибки компиляции.
- Константа верхнего уровня в `config.idyl` доступна как `config.ИМЯ` после
  `use config;`.
- Для массивов и объектов `const` защищает привязку, а не весь граф объектов.
  `items[0] = value` и изменяющие методы остаются законными, а
  `items = other_items` запрещено.
- Сейчас `const` не является модификатором поля класса или параметра.
- Имена в верхнем регистре вроде `MAX_LEVEL` — соглашение, а не правило
  разборщика.

Читаемая диагностика включает:

```text
main.idyl:2:15: compile error: constant 'answer' must have an initializer
main.idyl:3:5: compile error: cannot assign to constant 'answer'
```

Объявление без инициализатора создаёт значение по умолчанию:

```idyllium
int count;        // 0
float ratio;      // 0
string name;      // ""
char letter;      // '\0'
bool ready;       // false
array<int, 3> a;  // [0, 0, 0] — N элементов по умолчанию
```

Объявление переменной классового типа (`Hero h;`) создаёт объект со значениями
полей по умолчанию. Если у класса есть конструктор, вызываемый без аргументов
(без параметров либо со всеми параметрами по умолчанию), он выполняется;
конструктор с обязательными параметрами голым объявлением НЕ вызывается —
поля просто сохраняют умолчания своих типов.

### Зарезервированные имена

Имена модулей стандартной библиотеки зарезервированы для любых объявлений —
переменных, параметров, функций и классов:

<!-- @generated:stdlib-module-names -->
```text
audio channel colors console drawable encoding file fonts gui hash http
image json math random sqlite system time turtle types url web xml
```
<!-- /@generated:stdlib-module-names -->

```idyllium
int console = 5;   // compile error: variable 'console' conflicts with
                   // a standard library module
```

Причина в неустранимой двусмысленности: `console.write(...)` разбирается как
обращение к модулю, и одно и то же слово означало бы сразу две вещи.

Имена, начинающиеся с двух подчёркиваний, принадлежат самому языку: там среда
выполнения держит метки объектов, а порождённый код — свои переменные.
Ни одно объявление такого имени не принимает: `names starting with '__' are
reserved by the language — pick another name for variable '__x'`. Это
распространяется на переменные, параметры, функции, поля, методы, события
и классы. Имена, которые всего лишь совпадают с внутренностями JavaScript
(`toString`, `valueOf`, `hasOwnProperty`), — обычные идентификаторы и работают
как члены.

Набор слов мира под капотом зарезервирован для **связываний** (переменных,
параметров, функций, классов) с ошибкой `'X' is a reserved word and cannot
be used as a name`: `await`, `case`, `debugger`, `default`, `delete`,
`enum`, `export`, `import`, `in`, `instanceof`, `new`, `super`, `switch`,
`throw`, `typeof`, `var`, `with`, `let`, `yield`, `implements`,
`interface`, `package`, `protected`, `arguments`, `eval`, `undefined`.
Полям и методам эти слова по-прежнему доступны (через объект они
безвредны). Одно исключение среди членов: `then` запрещён для методов и
событий (`the name 'then' is reserved by the language — pick another name
for method 'then'` — метод `then` делал бы объект «обещанием» для мира под
капотом и ломал вызовы). Обычное поле-значение по имени `then` или
`undefined` остаётся законным.

Имена функций зарезервированы за функциями. Объявить свою функцию или класс
с именем встроенной глобальной функции (`to_int`, `to_float`, `to_string`,
`type_name`, `max`, `min`, `sum`, `avg`; `div` и `mod` уже являются ключевыми
словами) — ошибка компиляции:

```idyllium
int function to_string(int value) { return value; }
// compile error: function 'to_string' conflicts with a built-in function
```

Переменные и параметры тоже не могут брать имена функций — ни встроенной,
ни функции, объявленной в текущем файле. Затенение отвергается прямо на
объявлении, потому что переменная по имени `sum` сделала бы невозможным
любой вызов `sum(...)` в своей области видимости:

```idyllium
int sum = 100;
// compile error: variable 'sum' conflicts with the built-in function 'sum'
```

```idyllium
void function greet() { }

main() {
    int greet = 5;
    // compile error: variable 'greet' conflicts with the function 'greet'
}
```

Поля и методы классов свободно берут такие имена (к ним всегда обращаются
через объект, так что вызовы остаются однозначными), а переменная может
совпадать по имени с функцией из другого модуля — те зовутся только как
`module.func()`:

```idyllium
class Robot {
    string function to_string() { ... }   // законно: зовётся как r.to_string()
}
```

Ещё два уголка того же правила. Имя подключённого **пользовательского
модуля** зарезервировано так же, как имя стандартной библиотеки
(`use helper;` + `int helper = 5;` → `variable 'helper' conflicts with the
module 'helper'`). А `parent` — вызов конструктора базового класса — не может
достаться файловой функции (`function 'parent' conflicts with the base class
constructor call`) и переменной внутри конструктора класса-наследника; вне
конструкторов наследников `parent` — обычный идентификатор и остаётся
популярным именем в GUI-коде.

## 6. Преобразование типов

Idyllium строг к типам.

Пользуйтесь явными функциями преобразования:

```idyllium
int a = to_int("42");
float b = to_float("3.14");
string text = to_string(123);
```

Общие правила:

- `int` можно использовать там, где ожидается числовой `float`.
- `float` нельзя присвоить в `int` без `to_int()`.
- Числа не преобразуются в строки молча.
- Строки не преобразуются в числа молча.
- `to_int(вещественное)` усекает в сторону нуля.

`type_name(value)` возвращает тип строкой, записанной так же, как типы
записывают сообщения компилятора: значения сообщают свой статический тип
(`type_name(5)` → `"int"`, `type_name(a)` → `"array<int, 3>"`), а объекты
сообщают свой НАСТОЯЩИЙ класс, даже если смотреть на них через переменную
базового типа (`Animal x = Cat(...); type_name(x)` → `"Cat"`; классы модулей
уточняются: `"zoo.Lion"`; библиотечные объекты: `"gui.Button"`,
`"json.Value"`, `"time.stamp"`). Основное применение — проверки типа внутри
контракта `equals` (§7).

Обычная арифметика `int` точна ПРИ ЛЮБОМ РАЗМЕРЕ: `+ - *`, `div`, `mod`,
сравнения, литералы любой длины, печать, круговые рейсы
`to_string`/`to_int` и ввод через `console.get_int` никогда не теряют
целочисленной точности — включая значения выше предела 2^53 в JavaScript
и за пределами 64 бит (`123456789 * 123456789 * 123456789` печатает все
25 цифр; `to_int("123456789123456789123456789")` возвращает это число точно).
Это правило языка: `int` никогда не переполняется и не врёт; заворачивание при
переполнении фиксированной ширины существует только в ячейках библиотеки
`types`. Точность честно кончается там, где начинается область вещественных:
`/` всегда возвращает `float`, и функции `math.*` работают в вещественных.

## 7. Операторы

Арифметика:

```idyllium
a + b
a - b
a * b
a / b
```

`/` — обычное деление, всегда возвращающее `float`, даже для `10 / 5`. Общее
правило: если операция теоретически могла бы дать дробь, тип её результата —
`float`; как только один из операндов `float`, результат `float` (`2.5 * 4` —
это `10` типа `float`).

Целочисленное деление и остаток — глобальные функции (оператора `%` и тернарного
`?:` в Idyllium нет):

```idyllium
int q = div(23, 10);  // 2
int r = mod(23, 10);  // 3
```

Склейка строк идёт через `+`: `string + string`, `string + char` и
`char + string` дают новую строку. `char + char` — ошибка компиляции
(преобразуйте одну сторону через `to_string()`), а повторения строки
`"ab" * 3` не существует.

Сравнения:

```idyllium
a == b
a != b
a < b
a <= b
a > b
a >= b
```

Логика:

```idyllium
if (age >= 10 and age <= 18) {
    console.writeln("школьный возраст");
}

bool only_one = left_pressed xor right_pressed;

if (not(is_ready)) {
    console.writeln("не готов");
}
```

Пользуйтесь `and`, `or`, `xor`, `not`, а не `&&`, `||`, `^`, `!`.

Сравнения порядка `<`, `<=`, `>`, `>=` принимают числовые операнды, пары
`time.stamp` (упорядочены по моменту) и объекты класса, объявившего
соответствующий контракт порядка (`less`/`greater`, см. §7). Сравнивать ими
строки или символы —
ошибка компиляции, называющая оба виноватых типа (`comparison '<' requires
numeric operands, got 'string' and 'string'`). Строки и символы поддерживают
только `==` и `!=`. Особые прицельные подсказки: `score =+ 10` → `'=+' is not
an operator — did you mean '+='?` (а `lives =- 5` остаётся законным
присваиванием числа -5); жадный `not` перед сравнением (`not coins > 100`)
добавляет `'not' takes only what stands right after it — write 'not (coins >
…)' to negate the whole comparison`.

### Правила равенства

`==`/`!=` сравнивают СОДЕРЖИМОЕ для каждого сравнимого типа: чисел, строк,
символов, логических значений, массивов (рекурсивно), `colors.Color`
(по каналам), `time.stamp` (по моменту — часовой пояс не участвует),
`json.Value` (по значению, вглубь для объектов и массивов; сравнение
циклических значений JSON — ошибка времени выполнения `cannot compare cyclic
JSON value`), `sqlite.Value` (по классу хранения SQL и значению; INTEGER
и REAL сравниваются численно; в отличие от самого SQL, два SQL NULL равны —
`x == null` и есть преподаваемая идиома).

**У объектов пользовательских классов встроенного равенства нет.** `a == b`
для объектов — ошибка компиляции, пока класс не объявит контракт равенства:

```idyllium
bool function equals(Hero other) {
    return this.name == other.name and this.level == other.level;
}
```

С контрактом `a == b` и `a != b` диспетчеризуются в него; туда же уходят
`contains`, `find`, `count` для массивов такого класса и `==` для таких
массивов (структурно, по ячейкам). Без него: `cannot compare objects of class
'Hero' with '==' — declare 'bool function equals(Hero other)' in class 'Hero'
and the comparison will use it` (поиски говорят `contains() cannot search for
'Hero' objects — …`).

Правила контракта:
- Тип параметра — сам класс; диспетчеризация СТАТИЧЕСКАЯ: контракт выбирает
  объявленный тип левого операнда. Сравнивать переменную `Cat` с переменной
  `Animal` — ошибка компиляции (`'Cat.equals' accepts a 'Cat', got 'Animal'`);
  сравнивайте оба через одно и то же классовое окошко.
- Контракты НЕ наследуются: класс обязан объявить свой `equals` (потомок может
  объявить `equals(Derived)` рядом с базовым `equals(Base)` — единственный
  случай, когда переопределение вправе изменить сигнатуру). Взгляд на два
  объекта-потомка через переменные базового типа сравнивает их БАЗОВЫМ
  контрактом («equals работает для того класса, через который смотришь»).
- `equals` должен отвечать, а не изменять — чистоту никто не проверяет,
  пишите его чистым.
- Внутри `equals` выражение `type_name(this) != type_name(other)` отличает
  тёзок из разных классов (см. `type_name` в §6).
**Контракты порядка (`less` и `greater`).** Встроенного порядка у объектов
пользовательских классов тоже нет; `<`/`>`/`<=`/`>=` для объектов — ошибки
компиляции, пока класс не объявит соответствующий контракт порядка — та же
форма, что у `equals`, и те же правила (статическая диспетчеризация по
объявленному типу левого операнда, НЕ наследуется, пишите чистым):

```idyllium
bool function less(Hero other) {
    return this.level < other.level;
}
```

С объявленным `less` сравнение `a < b` диспетчеризуется в него, а `a >= b` —
его отрицание (`not a.less(b)`); заодно для массивов такого класса открывается
`sort()` и сортирует по `less` (стабильно: элементы, которые контракт не
различает, сохраняют исходный порядок). Без него: `cannot order objects of
class 'Hero' with '<' — declare 'bool function less(Hero other)' in class
'Hero' and '<' will use it` (`sort()` говорит `sort() cannot order 'Hero'
objects — …`). Контракт `greater` работает так же и обслуживает вторую пару
знаков: `a > b` диспетчеризуется в `greater`, `a <= b` — его отрицание.
Контракты независимы: одного `less` хватает для `<`, `>=` и `sort()`; одного
`greater` — для `>` и `<=`; один из другого не выводится, и согласованность
пары в классе, объявившем оба, никто не проверяет.

Все логические операнды обязаны иметь тип `bool`; преобразования
«истиноподобное/ложноподобное» в Idyllium нет. Приоритет от высшего к низшему:
`not`, сравнения, `and`, `xor`, `or`. `and` и `or` вычисляются с сокращением.
`xor` вычисляет оба операнда слева направо ровно по одному разу и истинен,
только когда истинен ровно один операнд.

## 8. Консоль

Импорт:

```idyllium
use console;
```

Вывод:

```idyllium
console.write("Name: ", name);
console.writeln("Age: ", age);
console.clear();
console.set_precision(3);
```

`console.write(...)` печатает значения без автоматического перевода строки.
`console.writeln(...)` печатает значения, а затем перевод строки.
`console.set_precision(digits)` управляет форматированием вещественных
и принимает целое от `0` до `25`. По умолчанию вещественные печатаются
с точностью до восьми знаков после запятой, а хвостовые нули срезаются:
`10 / 3` печатает `3.33333333`, `0.1 + 0.2` печатает `0.3`, `1.5` печатает
`1.5`. Ненулевое значение, которое при текущей точности округлилось бы
до `0`, уходит в экспоненциальную форму: `3.009e-36`, но никогда не обманчивый
`0`.

Ввод:

```idyllium
int age = console.get_int();
float height = console.get_float();
string name = console.get_string();
```

Некорректный числовой ввод — ошибка времени выполнения. Пример:

```text
main.idyl:5: runtime error: cannot convert input to 'int' (expected integer, got "abc")
```

В консольном выводе можно пользоваться управляющими ANSI-последовательностями
для цвета:

```idyllium
console.writeln("\e[31m", "Красный текст");
console.writeln("\e[0m", "Обычный текст");
```

## 9. Управление ходом выполнения

`if`:

```idyllium
if (score >= 90) {
    console.writeln("отлично");
} else {
    console.writeln("попробуй ещё");
}
```

Условие каждого `if`, `while`, `do-while` и `for` обязано уже иметь тип `bool`.
Преобразований «истиноподобное/ложноподобное» в духе Python и JavaScript
в Idyllium нет:

```idyllium
// if (1) {}               // compile error: got int
// if (name) {}            // compile error: got string
// while (items.length) {} // compile error: got int

if (name != "" and items.length > 0) {
    console.writeln("данные есть");
}
```

Фигурные скобки можно опустить, когда ветка состоит ровно из одного оператора:

```idyllium
if (score >= 90)
    console.writeln("отлично");
else
    console.writeln("попробуй ещё");
```

Отступы грамматику не меняют. Без скобок ветке принадлежит только
непосредственно следующий оператор:

```idyllium
if (ready)
    console.writeln("старт");
console.writeln("всегда"); // за пределами if
```

`else` принадлежит ближайшему незавершённому `if`. Если этот `if` уже завершён
другим оператором, компилятор сообщает, что для `else` нет подходящего `if`,
и советует завернуть ветку из нескольких операторов в `{ ... }`.

Цепочки `else if` разбираются естественно (это `else`, оператором которого
служит другой `if`) и законны:

```idyllium
if (score >= 90) {
    console.writeln("отлично");
} else if (score >= 60) {
    console.writeln("хорошо");
} else {
    console.writeln("попробуй ещё");
}
```

Оператора `switch` нет, цикла `for (x in collection)` нет. Обходите коллекции
по индексу: `for (int i = 0; i < items.length; i = i + 1)`.

`while`:

```idyllium
int i = 0;
while (i < 5) {
    console.writeln(i);
    i = i + 1;
}
```

`do while`:

```idyllium
int x = 0;
do {
    x = x + 1;
} while (x < 10);
```

`for`:

```idyllium
for (int i = 0; i < 10; i = i + 1) {
    console.writeln(i);
}
```

Управление циклом:

```idyllium
break;
continue;
```

## 10. Массивы

Массивы фиксированного размера:

```idyllium
array<int, 3> numbers = [10, 20, 30];
console.writeln(numbers[0]);
```

Размер обязан быть известен до запуска программы. Пишите целый литерал,
именованную целую константу (`const`, включая константу класса) либо их
**сумму, разность или произведение**; обычные переменные отвергаются
на этапе компиляции:

```idyllium
const int SIZE = 5;
const int PAD = 2;
array<int, SIZE> cells;          // можно
array<int, SIZE * SIZE> board;   // можно — 25
array<int, SIZE + PAD> row;      // можно — 7
array<int, Board.W * Board.W> b; // можно — и константы класса тоже
// int n = 6; array<int, n> bad; // compile error: must be a 'const'
```

Деление не принимается, как и всё, что компилятор не может свернуть:

```text
compile error: array size must be known before the program runs: write a number, a constant declared with 'const', or their sum, difference or product
compile error: array size 'n' must be an integer constant declared with 'const'
compile error: array size must be non-negative, got -1
```

Динамические массивы:

```idyllium
dyn_array<string> names;
names.add("Mira");
names.add("Leo");
```

Индексы массивов начинаются с нуля. Выход за границы — читаемая ошибка времени
выполнения:

```text
main.idyl:5: runtime error: array index 5 out of bounds (size 3, valid indices 0-2)
```

Свойство массива только для чтения:

```idyllium
values.length
```

Не вызывайте его как `length()` и не присваивайте в него. Методы массива:

```idyllium
values.contains(value)
values.find(value)
values.count(value)
values.reverse()
values.sort()
```

Методы только для динамических массивов:

```idyllium
values.add(value)
values.remove_at(index)
values.resize(size)
values.insert(index, value)
values.join(other)
values.clear()
values.pop()
```

У массивов семантика значений. Присваивание, передача аргументом и возврат
из функции создают независимую копию массива. Вложенные массивы-контейнеры
копируются рекурсивно; объекты классов и библиотек, лежащие в ячейках,
сохраняют свою личность.

Сравнения массивов через `==` и `!=` структурные: рекурсивно сравниваются длины
и соответствующие ячейки. Объекты библиотек и классов внутри ячеек при этом
следуют собственной семантике равенства.

Фиксированные и динамические массивы взаимно преобразуемы, когда типы их
элементов совместимы. Тип-приёмник определяет, будет копия фиксированной
или динамической:

```idyllium
array<int, 3> fixed = [10, 20, 30];
dyn_array<int> dynamic = fixed;
```

Преобразование `dyn_array<T>` в `array<T, N>` выполняет проверку размера
во время выполнения. Несовпадение размера — читаемая ошибка времени
выполнения; массив никогда не усекается и не дополняется молча. Заведомо
несовпадающие размеры двух фиксированных массивов — ошибки компиляции.

Числовые массивы поддерживают ещё и глобальные агрегатные функции:

```idyllium
max(values)
min(values)
sum(values)
avg(values)
```

`max`, `min` и `sum` возвращают целочисленный результат для целых массивов
и вещественный для вещественных. `avg` всегда возвращает `float`. Пустые
и нечисловые массивы — ошибки времени выполнения. Это глобальные функции,
а не методы массива.

Когда строка печатается как элемент внутри массива, она показывается
в кавычках и с экранированными управляющими символами, например:

```text
["Кирка\n", "Топор\n", "Меч"]
```

Так сделано нарочно: это помогает ученику увидеть спрятанные переводы строк.

## 11. Строки и символы

Свойство строки только для чтения:

```idyllium
text.length
```

Не вызывайте его как `length()`. Методы строки:

```idyllium
text.contains("abc")
text.find("abc")
text.count("a")
text.is_int()
text.is_float()
text.to_upper()
text.to_lower()
text.substring(start, length)
text.replace(old_text, new_text)
text.split(separator)
text.trim()
```

`is_int()` и `is_float()` — стражи с точным договором: `is_int()` истинен
ровно для тех строк, которые принимает `to_int()`, а `is_float()` — ровно для
тех, которые принимает `to_float()`. Целочисленный текст является корректным
вещественным текстом, поэтому `"50".is_float()` даёт `true` (и `to_float("50")`
возвращает 50); `is_int()` таким образом является подмножеством `is_float()`.
Ни тот ни другой не принимают экспоненциальную запись («5e3»), запятые
и нечисловой текст. Оба игнорируют пробелы по краям.

Обращение к символу:

```idyllium
string word = "кот";
char first = word[0];
```

Символы строки доступны только для чтения. Не порождайте код, присваивающий
в `word[0]`. Вместо этого соберите новую строку и присвойте результат целиком.

## 12. Функции

Объявление функции:

```idyllium
int function sum(int a, int b) {
    return a + b;
}
```

Функция без результата:

```idyllium
void function say_hello(string name) {
    console.writeln("Привет, ", name);
}
```

Вызов:

```idyllium
int total = sum(10, 20);
say_hello("Mira");
```

Аргументы по умолчанию:

```idyllium
use console;

void function print_num(int num = 0) {
    console.writeln(num);
}

main() {
    print_num();
    print_num(50);
}
```

Параметры со значениями по умолчанию должны идти после обязательных:

```idyllium
int function add(int a, int b = 0) {
    return a + b;
}
```

Выражение по умолчанию может ссылаться на более ранний параметр. Аргументы
по умолчанию работают у функций, методов и конструкторов:

```idyllium
int function add_twice(int first, int second = first) {
    return first + second;
}

class Counter {
    int value;

    constructor Counter(int start = 5) {
        this.value = start;
    }

    void function add(int amount = 1) {
        this.value = this.value + amount;
    }
}
```

Именованные аргументы:

```idyllium
use console;

int function sub(int left, int right) {
    return left - right;
}

main() {
    console.writeln(sub(50, 30));                   // 20
    console.writeln(sub(left=50, right=30));        // 20
    console.writeln(sub(right=50, left=30));        // -20
}
```

Правила:

- Позиционные аргументы могут идти перед именованными.
- Позиционные аргументы после именованных запрещены.
- Передавать один и тот же параметр дважды запрещено.
- Неизвестные имена аргументов запрещены.
- Именованные аргументы работают у пользовательских функций, методов,
  конструкторов и у библиотечных вызовов с фиксированным числом аргументов.
- Именованные аргументы не поддерживаются функциями с переменным числом
  аргументов, такими как `console.write(...)`.

Рекурсия разрешена:

```idyllium
int function factorial(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * factorial(n - 1);
}
```

## 13. `main`

Педагогическая краткая форма:

```idyllium
use console;

main() {
    console.writeln("Старт");
}
```

После того как введены функции, разрешён `main` с типом:

```idyllium
use console;

int function main() {
    console.writeln("Готово");
    return 0;
}
```

`main` может возвращать любой обычный тип Idyllium. В программе может быть
только один `main`, и он не должен принимать параметров.

Возвращённое значение — это **код завершения** программы. Его печатает хост
после окончания программы, а не сама программа, поэтому он не появляется
ни в выводе консоли, ни в перенаправленных файлах, ни в блоках вывода уроков:

```text
[Программа завершилась с кодом 0]
```

- `void`-функция `main` не печатает ничего.
- Значение отображается по тем же правилам, что и в `console.write()`, поэтому
  класс с открытым `to_string()` печатается через него. Строки заключаются
  в кавычки: `[Программа завершилась с кодом "готово"]`.
- В CLI целочисленный результат становится ещё и кодом возврата процесса,
  свёрнутым в `[0, 255]`; когда свёртка меняет число, сообщение называет оба:
  `[Программа завершилась с кодом 1000 (процесс вернул 232)]`. Остальные типы
  оставляют код процесса равным 0.
- Для оконной программы сообщение появляется при закрытии последнего окна,
  а не при возврате из `main`.

```idyllium
button.on_click = void function() {
    console.writeln("нажали");

```

Либо присвоить именованную:

```idyllium
use gui;
```

## 15. Классы и ООП

Объявление класса:

```idyllium
class Hero {
    string name;
    int hp;

    constructor Hero(string ex_name, int ex_hp) {
        this.name = ex_name;
        this.hp = ex_hp;
    }

    void function hit(int damage) {
        this.hp = this.hp - damage;
        if (this.hp < 0) {
            this.hp = 0;
        }
    }

    int function get_hp() {
        return this.hp;
    }
}
```

Внутри метода экземпляра или конструктора к полям класса и к методам
экземпляра нужно обращаться через `this.`. Голое имя поля считается обычным
локальным или глобальным именем и потому является ошибкой, когда такого имени
нет:

```idyllium
this.hp = this.hp - damage;   // верно: поле класса
this.get_hp();          // верно: метод экземпляра
hp = hp - damage;             // неверно: 'hp' не локальная переменная
```

Создание объекта:

```idyllium
Hero hero("Mira", 100);
hero.hit(30);
console.writeln(hero.get_hp());
```

Педагогическая форма объявления остаётся доступной:

```idyllium
Hero hero("Mira", 100);
```

Вызов пользовательского класса создаёт и возвращает новый объект, поэтому
конструкторами можно пользоваться везде, где принимается выражение этого
класса:

```idyllium
dyn_array<Hero> heroes;
heroes.add(Hero("Kaspar", 500));

Hero raven = Hero("Raven", 600);

Hero function create_boss() {
    return Hero("Aranthir", 1000);
}

bool strong = Hero("Ornella", 750).get_hp() > 700;
```

Объявление объектной переменной без скобок НИКОГДА не вызывает конструктор
(правило заготовки). Объект создаётся со значениями полей по умолчанию (числа
нули, строки пустые). Чтобы конструктор выполнился, вызовите его явно:

```idyllium
Hero ghost;                  // конструктор НЕ вызван: поля "" и 0
Hero named = Hero("Mira");   // конструктор вызван явно
Hero short_form("Mira");     // форма объявления со скобками тоже вызывает его
```

То же правило действует для массивов объектов (`array<Hero, 3> team;` создаёт
три объекта со значениями по умолчанию) и для объектных полей внутри классов:
и то и другое — «пустые ячейки», которые программа заполняет явно. Явный вызов
без аргументов `Hero()` законен, когда у конструктора нет обязательных
параметров (или конструктора у класса нет вовсе).

Именованные аргументы и аргументы по умолчанию работают в выражениях
конструктора. Класс, импортированный из пользовательского модуля, создаётся
как `geometry.Point(10, 20)`. Каждый вызов возвращает независимый объект,
а выражение-потомок можно использовать там, где ожидается его базовый класс.
Класс без явного конструктора можно вызвать без аргументов, например `Empty()`,
но не с аргументами. Выражения конструктора законны и в инициализаторах полей
класса.

Выражения `new` не существует. Объявление деструктора — дружелюбная ошибка
компиляции (`destructors are not supported yet`). Поле, тип которого (прямо
или через цепочку) совпадает с самим классом, — ошибка компиляции
(`field 'friend' of class 'Person' creates an endless chain of default
objects — …`): построение по умолчанию уходило бы в бесконечность. Поля
`dyn_array<Person>` законны (их умолчание — пустой список), пользуйтесь ими
для деревьев и списков. Точка с запятой после тела класса (`};`) принимается
и игнорируется, так что привычки из C++ код не ломают.

### Печать объектов: контракт `to_string()`

Передача объекта класса в `console.write`/`console.writeln` — ошибка
компиляции (`cannot print object of class 'Cat' directly — declare 'string
function to_string()' in class 'Cat' and printing will use it`), пока класс
не объявит открытый метод без аргументов `string function to_string()`. Когда
метод с именем `equals`/`to_string` есть, но не той формы (приватный,
статический, не тот параметр или не тот тип результата), сообщение дописывает
точную причину, например `(class 'Cat' has 'to_string', but it returns 'int'
instead of 'string')`. Контракты не наследуются: метод должен быть объявлен
в самом классе — потомок без собственного `to_string` не печатается, даже
если он есть у базы. С методом объект печатается через него.
**Массив объектов**, чей класс элементов владеет контрактом, тоже печатается:
представления элементов собираются через `to_string()` и отображаются как
массив строк (`["Герой Мира", "Герой Кай"]`). Без контракта массив отказывается
с той же учебной подсказкой. Склейка строки с объектом по-прежнему запрещена
(как `string + int`) — пользуйтесь глобальным `to_string(obj)`, который
соблюдает контракт:

```idyllium
use console;

class Point {
    int x;
    int y;

    string function to_string() {
        return "(" + to_string(this.x) + ", " + to_string(this.y) + ")";
    }
}

main() {
    Point p;
    console.writeln(p); // (0, 0)
}
```

Массив объектов вкладывается свободно: контракт применяется на любой глубине,
поэтому `dyn_array<dyn_array<Point>>` печатается как `[["(0, 0)"]]`. Без
контракта отказ называет класс элемента (`cannot print an array of 'A'
objects directly — declare 'string function to_string()' in class 'A' and
printing will use it`).

Функции тоже не печатаются: `console.writeln(abs_value)` — промах с забытыми
скобками — это ошибка компиляции (`cannot print function 'abs_value' — add
'()' with its arguments to call it and print the result`); тот же страж
покрывает `to_string(fn)`, запись в файл и `json.Value(fn)`.

### Модификаторы доступа

`public:` и `private:` пишутся с двоеточием и действуют до следующего
модификатора или до конца класса. Члены, объявленные **до первого
модификатора, открыты**: класс, в котором модификаторов нет вовсе, открыт
целиком.

Замок стоит на КЛАССЕ, а не на объекте: метод может читать и писать приватные
члены ДРУГОГО объекта того же класса. Без этого правила нельзя было бы
написать ни `equals`, ни сравнение, ни обмен:

```idyllium
class Thermostat {
private:
    int temperature;

public:
    constructor Thermostat(int ex_temperature) {
        this.temperature = ex_temperature;
    }

    bool function warmer_than(Thermostat other) {
        return this.temperature > other.temperature;   // законно: тот же класс
    }
}
```

```idyllium
class Hero {
    private:
    int hp;

    public:
    string name;

    int function get_hp() {
        return this.hp;
    }
}
```

### Статические методы, статические поля, константы класса

```idyllium
use console;

class Cat {
    const int MAX_KITTENS = 6;      // константа класса: Cat.MAX_KITTENS
    static int population = 0;      // одно на класс, а не на объект

    static void function meow() {
        console.writeln("Мяу");
    }

    constructor Cat() {
        Cat.population = Cat.population + 1;
    }
}

main() {
    Cat.meow();
    console.writeln(Cat.population, " ", Cat.MAX_KITTENS);
    Cat.population = 3;                  // статические поля доступны для записи
    array<int, Cat.MAX_KITTENS> basket;  // целые константы класса годятся как размеры массива,
                                         // и сами по себе, и в сумме, разности, произведении
}
```

Правила: обращение ВСЕГДА идёт через имя класса (`Cat.population`; через
объект — ошибка компиляции `static field 'Cat.population' must be accessed
through class 'Cat'`; то же для статических методов). Константа класса пишется
через `const` БЕЗ `static` (`static const` → ошибка компиляции, предлагающая
простой `const`), обязана иметь инициализатор и не может быть присвоена
(`cannot assign to class constant 'Cat.MAX_KITTENS'`). Статика НЕ наследуется:
`Kitten.population` через потомка → ошибка компиляции `static field
'Cat.population' is not inherited — write 'Cat.population'` (то же и для
статических методов). `this` в статическом контексте не существует.
Параметров `const` в языке нет. Статика классов из ПОЛЬЗОВАТЕЛЬСКИХ МОДУЛЕЙ
работает по всей цепочке: `use zoo; zoo.Lion.population`, `zoo.Lion.MAX_AGE`,
`zoo.Lion.roar()` — те же правила, те же отказы.

### Наследование и полиморфизм

Наследование:

```idyllium
class Animal {
    string name;

    constructor Animal(string ex_name) {
        this.name = ex_name;
    }

    void function speak() {
        console.writeln("...");
    }
}

class Dog extends Animal {
    constructor Dog(string ex_name) {
        parent(ex_name);
    }

    void function speak() {
        console.writeln(this.name, ": гав");
    }
}
```

`parent(аргументы)` внутри конструктора потомка выполняет конструктор базового
класса. Правила:

- Вызывать `parent()` необязательно; без него унаследованные поля сохраняют
  умолчания своих типов (или инициализаторы полей базы).
- Компилятор не требует, чтобы `parent()` был первым оператором; ставить его
  первым — стилистическая рекомендация, потому что более поздний вызов
  `parent()` перезаписывает поля, присвоенные до него.

Базовый класс не обязан жить в том же файле. Работает и то и другое:

```idyllium
use zoo;   // в zoo.idyl объявлен класс Lion
use gui;

class Cub extends zoo.Lion {        // база из пользовательского модуля
    constructor Cub(string ex_name) {
        parent(ex_name);            // выполняет конструктор zoo.Lion
    }
}

class CounterButton extends gui.Button {   // база — виджет gui
    int clicks = 0;

    void function press() {
        this.clicks = this.clicks + 1;
        this.text = "Нажато: " + to_string(this.clicks);
    }
}
```

Наследование от классов модуля следует обычным правилам: `parent(...)`, поля
и методы базы наследуются, `private`-члены базы остаются приватными, статика
НЕ наследуется (`zoo.Lion.population`, но никогда `Cub.population`).

У наследования виджетов свой договор:

- Расширять можно только обычные виджеты: `gui.Button`, `gui.Label`,
  `gui.Frame`, `gui.CheckBox`, `gui.RadioButton`, `gui.LineEdit`,
  `gui.TextEdit`, `gui.ProgressBar`, `gui.Slider`, `gui.SpinBox`,
  `gui.ComboBox`, `gui.ImageBox`. `gui.Window`, `gui.Canvas`, `gui.Timer`,
  диалоги и небиблиотечные типы вне gui (`json.Value`, `time.stamp`, …) —
  ошибка компиляции.
- Потомок И ЕСТЬ виджет: у него есть все свойства и обработчики виджета плюс
  собственные поля и методы, он идёт прямо в `add_child(...)`, отрисовывается
  и зажигает события ровно как его база. `type_name()` сообщает имя класса
  потомка (`CounterButton`).
- У виджетов нет конструктора, поэтому `parent()` в потомке виджета — ошибка
  компиляции; вместо этого настраивайте свойства. Конструктор потомка
  (`constructor CounterButton(...)`) разрешён и обычно выставляет свойства
  и собирает детей.
- Поле или метод не могут переиспользовать имя члена базового виджета
  (`'text' is already a member of gui.Button — pick another name`).
- Канонический составной виджет наследуется от `gui.Frame`: дочерние виджеты
  полями, сборка в конструкторе через `this.add_child(...)`, методы,
  привязанные обработчиками (`this.slider.on_change = this.refresh;`).

Цепочки и модули следуют тому же договору: внук `gui.Button` по-прежнему
настоящая кнопка (отрисовывается, зажигает события, входит в группы
переключателей), а потомок виджета, объявленный в пользовательском модуле, —
полноценный виджет для того, кто его импортирует. Имена членов виджета
остаются занятыми по всей длине цепочки, события включительно
(`event on_click` в потомке — ошибка компиляции).

Переопределение обязано сдержать каждое обещание базового класса:

- те же типы параметров и тот же тип результата (единственное исключение —
  контракт `equals`, см. §Правила равенства);
- умолчания параметров базы: `greet(string who = "мир")` в базе
  и `greet(string who)` в потомке — ошибка компиляции, потому что тогда
  `base.greet()` попал бы в тело, которому нечего положить в `who`. Потомок
  вправе выбрать ДРУГОЕ умолчание, и оно побеждает даже через переменную
  базового типа, потому что значение подставляет тот метод, который
  действительно выполняется: при `hi(int n, int extra = 0)` в `A`
  и `hi(int n, int extra = 5)` в `B` вызов `A a = b; a.hi(2)` печатает
  `B 2 5`. C++ связывает умолчания статически и напечатал бы `B 2 0` —
  разница важна при переносе примеров;
- видимость базы: открытый метод не может стать `private` в потомке (через
  переменную базового типа он всё равно был бы вызываем);
- `private`-метод базы не может быть переопределён вовсе: у объекта одна
  ячейка на имя, поэтому тело потомка молча подменило бы механизм, который
  база вызывает у самой себя;
- имя, занятое событием (`event`) базы, не может быть переиспользовано
  методом.

Класс, импортированный из пользовательского модуля, ведёт себя в точности как
тот же класс, написанный в одном файле: перечисленные правила переопределения
действуют через границу модуля (`method 'Cub.roar' cannot be private — it
overrides a public method of class 'zoo.Lion'`), а контракты (`equals`,
`to_string`) по-прежнему не переходят к потомкам — отказ является ошибкой
компиляции по обе стороны границы модуля.

`parent()` говорит, что именно не так, вместо «функция не объявлена»:
`parent() runs the constructor of the base class and can only be called in
the constructor of class 'Dog'`; `class 'Alone' has no base class — parent()
needs 'extends'`. Приватный конструктор базы остаётся приватным и для
потомков: наследование не способ обойти `private`.

Замечание о печати: у библиотечных объектов (`gui.*`, `fonts.Font`,
`drawable.*`, потоков) текстовой формы нет, и печатать их — ошибка компиляции:
`cannot print an object of type 'gui.Button' directly — library objects have
no text form; print one of its properties instead`. Библиотечные ЗНАЧЕНИЯ
печатаются как прежде: ячейки `types.*`, `colors.Color`, `time.stamp`,
`json.Value`/`json.Object`/`json.Array`/`sqlite.Value`, а также те
библиотечные объекты, которые несут собственную текстовую форму:
`turtle.Turtle`, `gui.Canvas`, `gui.Table`, `gui.BarChart`, `gui.LineChart`,
`gui.PieChart`, `image.Vector`, `channel.Post`,
`web.Server`/`web.Request`/`web.Response` и `http.Response`. Массив объектов
с контрактом `to_string` печатается через этот контракт на любой глубине
вложенности.

### Пользовательские события

Класс может объявлять события ключевым словом `event` и зажигать их из своих
методов. Внешний код подписывается присваиванием, ровно как на обработчики
виджетов:

```idyllium
use console;

class Hero {
    int hp = 100;

    event on_death(Hero victim);

    void function hit(int damage) {
        this.hp = this.hp - damage;
        if (this.hp <= 0) {
            this.on_death(this);
        }
    }
}

void function mourn(Hero victim) {
    console.writeln("Герой погиб с hp ", victim.hp);
}

main() {
    Hero boss;
    boss.on_death = mourn;
    boss.hit(150);
}
```

Правила:

- `event имя(параметры);` объявляет член-событие; `event имя;` означает
  отсутствие параметров. У событий нет типа результата и нет умолчаний
  параметров.
- Зажигание — обычный вызов через `this.`, и оно разрешено только внутри
  объявившего класса (или его потомков). Зажигание снаружи — ошибка
  компиляции.
- Без подписчика зажигание молча ничего не делает — так же, как
  неприсвоенный `on_click` у виджета.
- Обработчик принимает либо ни одного параметра, либо полную сигнатуру
  события. Обработчиками могут быть именованные функции, встроенные функции
  и методы объектов (`hero.on_death = scoreboard.count;` сохраняет `this`
  того табло).
- Один подписчик на событие: новое присваивание заменяет прежний обработчик.
  Чтение события как значения — ошибка компиляции.
- `static event` не существует. События работают и для классов,
  импортированных из пользовательских модулей: подписывайтесь на объекты типа
  `clocks.Clock` тем же способом.

Ссылки на методы вообще сохраняют свой объект: `board.count`, использованный
как значение-обработчик, при вызове по-прежнему обновляет `board`.

Полиморфизм поддерживается для отношений классов. Функция, ожидающая базовый
класс, может получить объект потомка:

```idyllium
use console;

// Animal и Dog — классы из примера про наследование выше.
class Animal {
    string name;

    constructor Animal(string ex_name) {
        this.name = ex_name;
    }

    void function speak() {
        console.writeln("...");
    }
}

class Dog extends Animal {
    constructor Dog(string ex_name) {
        parent(ex_name);
    }

    void function speak() {
        console.writeln(this.name, ": гав");
    }
}

void function make_sound(Animal animal) {
    animal.speak();
}

main() {
    Dog dog("Rex");
    make_sound(dog);
}
```

Та же мысль движет и библиотечными API вроде
`gui.Window.add_child(gui.Widget)` и `gui.Canvas.draw(drawable.Drawable)`.

### Семантика значений и ссылок (модель памяти)

Проверенное поведение присваивания и передачи параметров — таблица
«значение/ссылка» (единственный источник истины):

| Семейство | Присваивание и передача аргументом | `==` |
|---|---|---|
| примитивы (`int`, `float`, `string`, `char`, `bool`) | копия | по содержимому |
| `array` / `dyn_array` | копия (новые ячейки; ОБЪЕКТНЫЕ ячейки по-прежнему делят объекты — «своя коробка, общие жители») | структурно по ячейкам |
| `colors.Color`, `time.stamp`, `json.Value`, `sqlite.Value` | библиотечные типы со свойствами значений | по содержимому (отметка времени — по моменту; JSON — вглубь) |
| объекты пользовательских классов | ссылка (`Hero b = a;` — тот же объект) | только через контракт `equals` (§7) |
| `json.Object`, `json.Array` и любой другой библиотечный ОБЪЕКТ (`gui.*`, `image.*`, `sqlite.Database`…) | ссылка | `json.Object`/`json.Array`, завёрнутые в `json.Value`, сравниваются по содержимому; остальные библиотечные объекты осмысленно не сравнимы |

Подробности, которые стоит цитировать:

- **Объекты классов — ссылки.** `Hero b = a;` делает `b` и `a` одним и тем же
  объектом: `b.hp = 5;` меняет и `a.hp`. Передача объекта в функцию передаёт
  тот же объект. Встроенного копирования объектов нет: напишите свой метод
  `copy()` (поверхностный или глубокий — решает автор класса).
- **Пустые поля**: ПОЛЕ классового типа, объявленное с явным инициализатором
  `= null`, может быть пустым — `class Room { Guest guest = null; }`. Это
  ЕДИНСТВЕННОЕ место, где `null` разрешён для пользовательских классов:
  локальные переменные, параметры, возвраты и ячейки массивов его никогда
  не принимают. Правила: присваивайте в такое поле объект или обратно `null`;
  проверяйте его через `room.guest == null` / `!= null` (для любого другого
  объектного выражения это ошибка компиляции); ЛЮБОЕ использование пустого
  поля — чтение через него, печать, передача куда-либо — это ошибка времени
  выполнения, называющая поле (`field 'guest' of class 'Room' is empty (null)
  — check it with '!= null' before using it`). При наличии контракта равенства
  пустое равно только пустому. `type_name(пустое поле)` → `"null"`.
  Самоссылающиеся поля становятся законными, когда допускают `null`
  (`class Person { Person friend = null; }`) — так и строятся связные списки
  и деревья; без `= null` такое поле является ошибкой компиляции (бесконечная
  цепочка объектов по умолчанию).
- **Массивы — значения.** `dyn_array<int> b = a;` создаёт копию: `b[0] = 99;`
  не меняет `a[0]`. Передача массива в функцию тоже копирует его. Копия
  МАССИВА ОБЪЕКТОВ — это новый массив, чьи ячейки указывают на ТЕ ЖЕ объекты:
  замена ячейки в копии оригиналу не видна, а изменение поля через ячейку
  видно.
- Два `dyn_array` разной длины сравниваются как `false` (длина — свойство
  времени выполнения); два фиксированных массива разного объявленного размера
  вообще не компилируются (`cannot compare 'array<int, 3>' and
  'array<int, 2>'` — размер это часть типа).
- **`colors.Color` и `time.stamp` — неизменяемые значения**: их методы `with_*`
  и `in_timezone` возвращают новые значения; оба сравниваются по содержимому
  (отметки времени по моменту, поэтому две отметки одного мгновения в разных
  часовых поясах равны — и по `<`/`>` упорядочиваются тоже по моменту).

## 16a. Библиотека `system`

Подключение:

```idyllium
use system;
```

```idyllium
system.set_recursion_depth(depth)   // void
system.recursion_depth()            // int
system.exit(code = 0)               // void, управление не возвращает
system.platform()                   // "cli" | "web" | "vscode"
system.version()                    // "1.5.5"
system.set_warnings(enabled)        // void; выключает/включает runtime-предупреждения
```

**Глубина рекурсии.** Idyllium считает глубину вызовов сам, а не полагается
на стек JavaScript, поэтому предел одинаков на любом хосте. По умолчанию
20000 вложенных вызовов; `set_recursion_depth()` принимает 10…200000
и за пределами этого диапазона поднимает ошибку времени выполнения. Превышение
предела — обычная ошибка времени выполнения с `file:line`, ловимая через
`try/catch`:

```text
main.idyl:3: runtime error: recursion depth limit of 20000 exceeded in function 'boom'
```

Верхняя граница про память, а не про стек: приостановленный кадр вызова стоит
примерно килобайт, так что 200000 кадров — это около 190 МБ.

**`system.exit(code)`** немедленно останавливает программу откуда угодно,
выполняя по дороге блоки `finally`, и выдаёт то же значение завершения, что
и `return` из `main`. Он сознательно **не** ловится через `try/catch`:
завершение программы — собственное решение программы, а не ошибка, от которой
оправляются.

**`system.platform()`** важен потому, что хосты различаются: в веб-IDE
виртуальная файловая система, `url.open()` открывает там вкладку, а звуку
нужен жест пользователя.

```idyllium
math.atan2(y, x)     // y ПЕРВЫМ; угол по всем четвертям в радианах, безопасен при x = 0.
                     // Рецепт для холста: rotation = math.to_degrees(math.atan2(ty - y, tx - x))
                     // (экранная ось Y смотрит вниз, поэтому угол по часовой стрелке — как у поворота рисуемых объектов)
math.log(value)
math.log10(value)
math.to_radians(degrees)
math.to_degrees(radians)
```

Углы у тригонометрических функций — в радианах.

Типы результата: `math.abs` сохраняет числовой тип аргумента (`int` остаётся
`int`, `float` остаётся `float`). `math.round`, `math.floor` и `math.ceil`
возвращают `int` при вызове с одним аргументом и `float`, когда передан
необязательный аргумент с числом знаков. `math.clamp` возвращает `int`, когда
все три аргумента целые, иначе `float`. Остальные математические функции
возвращают `float`.

## 18. Библиотека `random`

```idyllium
use random;

int a = random.create_int(1, 10);
float b = random.create_float(0.0, 1.0);
char symbol = random.choose_from("ABCDEF");

array<string, 3> names = ["Liam", "Mira", "Raven"];
string name = random.choose_from(names);

random.set_seed(123);
```

`create_int(min, max)` включает обе границы, поэтому `create_int(1, 10)` может
вернуть и `1`, и `10`. `create_float(min, max)` тоже включает обе границы (как
`random.uniform` в Python), хотя попасть точно в `max` исчезающе маловероятно.
Целочисленные диапазоны допускают `min == max`; вещественные требуют
`min < max`. `set_seed()` требует неотрицательного целого и делает дальнейшие
результаты воспроизводимыми (он же задаёт зерно для `random.mulberry32()` —
классического сырого генератора, который не принимает аргументов и возвращает
целое от `0` до `4294967295`). Неверные диапазоны — ошибки времени выполнения.
Не переставляйте и не подрезайте диапазоны молча. `choose_from()` принимает
непустую строку, `array<T, N>` или `dyn_array<T>`. Для строки он возвращает
`char`, для массива — `T`. Выбор из пустой коллекции — ошибка времени
выполнения.

`random.shuffle(x)` (с 1.5.5) принимает строку или любой массив и возвращает
ПЕРЕМЕШАННУЮ КОПИЮ того же типа — оригинал не меняется (массивы в Idyllium —
значения; в отличие от питоньего in-place `random.shuffle`). «Перемешать у
себя» пишется `xs = random.shuffle(xs);`. Голый вызов `random.shuffle(xs);`
строкой-соло выбрасывает копию и получает compile-предупреждение. Строка
перемешивается по видимым символам (сурогатные пары не рвутся); пустые и
одноэлементные коллекции возвращаются как есть. Порядок подчиняется
`random.set_seed()`.

## 19. Библиотека `time`

```idyllium
use time;

time.sleep(1.5);
time.stamp now = time.now();
time.stamp past = time.from_unix(0, "Asia/Yekaterinburg");
time.stamp meeting = time.create(2026, 9, 24, 18, 3);

console.writeln(now.year);
console.writeln(now.month);
console.writeln(now.day);
console.writeln(now.hour);
console.writeln(now.minute);
console.writeln(now.second);
console.writeln(now.millisecond);
console.writeln(now.week_day);
console.writeln(now.unix);
console.writeln(now.timezone);
console.writeln(now.to_string());
```

`time.now()` и `time.from_unix(seconds)` по умолчанию используют `"UTC"`. Оба
принимают необязательный часовой пояс IANA — например, `"Asia/Yekaterinburg"`,
`"Europe/Berlin"` или `"America/New_York"`; именованная форма
`timezone="..."` тоже годится. Неверные имена поясов — ошибки времени
выполнения. Хостовая реализация `Intl` применяет исторические переходы
и переходы на летнее время.

Составляющие `year`, `month`, `day`, `hour`, `minute`, `second`,
`millisecond`, `week_day`, `unix` и `timezone` — свойства только для чтения,
а не методы-геттеры. `unix` — целые секунды; `millisecond` — `0..999`.
`time.from_unix` принимает дробные секунды, и дробь становится миллисекундами
(`time.from_unix(946684800.25)` даёт `millisecond == 250`). Не порождайте
`stamp.year()` и `stamp.unix()`. `month` возвращает `1..12`, а `week_day`
следует `0..6`, где воскресенье это `0`.

`stamp.in_timezone(name)` возвращает новую отметку того же момента. Она меняет
показываемые календарные составляющие, но никогда не меняет `unix`:

```idyllium
time.stamp utc = time.from_unix(0);
time.stamp ekb = utc.in_timezone("Asia/Yekaterinburg");

console.writeln(utc); // 1970-01-01 00:00:00
console.writeln(ekb); // 1970-01-01 05:00:00
console.writeln(utc.unix == ekb.unix); // true
```

`time.create(year, month, day, hour = 0, minute = 0, second = 0,
millisecond = 0, timezone = "UTC")` собирает отметку из календарных
составляющих, истолкованных в заданном поясе IANA. Диапазоны строгие (месяц
1–12, час 0–23, …), а несуществующие даты — ошибки времени выполнения
(`time.create() date 2026-02-30 does not exist`); високосные годы
обрабатываются. Именованные аргументы читаются хорошо:
`time.create(2026, 9, 24, hour=18, minute=3)`.

`time.sleep()` принимает неотрицательное число секунд, и среда может его
прервать.

## 20. Библиотека `file`

```idyllium
use file;
```

Проверка существования:

```idyllium
if (file.exists("input.txt")) {
    console.writeln("существует");
}
```

Чтение:

```idyllium
file.istream fin = file.open("input.txt", "read");
string prefix = fin.read(5);
string line = fin.read_line();
bool more = fin.has_next_line();
string rest = fin.read_all();
fin.close();
```

`has_next_line()` сообщает, удастся ли следующий вызов `read_line()`;
канонический цикл — `while (fin.has_next_line()) { ... fin.read_line() ... }`.
`read_line()` сохраняет завершающий `\n` или `\r\n`, если он есть.
`read(count)` читает не более `count` символов Unicode с текущей позиции
потока. Количество обязано быть неотрицательным целым. `read()` без аргумента
и `read_all()` читают всё оставшееся содержимое. Все методы чтения делят одну
позицию в потоке. `read()` в конце файла возвращает пустую строку;
`read_line()` за последней строкой и любая операция с закрытым потоком —
ошибки времени выполнения.

Запись:

```idyllium
file.ostream fout = file.open("output.txt", "write");
fout.write("Score: ");
fout.write_line(42);
fout.write_line("Done");
fout.close();
```

Дописывание:

```idyllium
file.ostream fout = file.open("log.txt", "append");
fout.write_line("Новая запись");
fout.close();
```

`"append"` сохраняет существующее содержимое и пишет в конец; отсутствующий
файл создаётся пустым. `"write"` всегда начинает с пустого файла. Любой другой
режим — ошибка времени выполнения: `file.open() mode must be 'read', 'write'
or 'append', got '...'`. Учебное замечание: консольный курс первого года
намеренно не упоминает `"append"` — там школьные задания решают дописывание
чтением всего файла и его перезаписью, и это сознательное упражнение;
не предлагайте `"append"` для заданий первого года. Режим вводится в курсе
JSON третьего года и везде остальное уместен.

`write(...)` записывает ровно переданные значения. `write_line(...)`
записывает переданные значения и затем добавляет `\n`, как
`console.writeln(...)`. Открытие в режиме `"write"` создаёт или обнуляет файл.
Его родительский каталог обязан уже существовать; при необходимости
пользуйтесь `file.create_directory(..., parents=true)`.

Обычные режимы:

- `"read"`
- `"write"`

В примерах всегда закрывайте потоки.

У потоков есть свойство только для чтения типа `bool` — `is_open`:

```idyllium
file.ostream fout = file.open("output.txt", "write");
console.writeln(fout.is_open); // true
fout.close();
console.writeln(fout.is_open); // false
```

Потоки открываются через `file.open(path, mode)`. Открытого конструктора вроде
`file.ostream("output.txt")` у них нет.

Операции с файловой системой проекта:

```idyllium
file.create_directory("saves");
file.create_directory("game/saves/players", parents=true);

bool any_entry = file.exists("saves");
bool regular_file = file.is_file("saves/player.txt");
bool directory = file.is_directory("saves");
dyn_array<string> names = file.list_directory("saves");

file.copy("saves", "saves_backup");
file.rename("saves_backup", "archive");
file.remove("archive", recursive=true);
```

Правила:

- `create_directory(path)` требует, чтобы родительский каталог существовал;
- `parents=true` создаёт недостающие родительские каталоги;
- `copy()` работает и с файлами, и с деревьями каталогов;
- `rename()` заодно перемещает записи, когда у назначения другой родитель;
- `copy()` и `rename()` никогда не перезаписывают существующее назначение;
- `remove()` удаляет файлы и пустые каталоги;
- удаление непустого каталога требует явного `recursive=true`;
- изменяющие операции ограничены корнем текущего проекта.

## 21. Библиотека `encoding`

```idyllium
use encoding;

dyn_array<string> names = encoding.list_encodings();
int codepoint = encoding.char_to_codepoint('б'); // 1073
char ch = encoding.codepoint_to_char(1073); // 'б'
dyn_array<int> bytes = encoding.encode("кот", "utf-8");
string text = encoding.decode(bytes, "utf-8");
```

Канонические имена кодировок, которые возвращает
`encoding.list_encodings()`:

- `"ascii"`
- `"utf-8"`
- `"windows-1251"`
- `"koi8-r"`
- `"cp866"` (DOS-кириллица с псевдографикой)
- `"cp437"` (исходный IBM PC: латиница, псевдографика, математические знаки)
- `"windows-1252"` (западноевропейская)
- `"windows-1254"` (турецкая)

На входе принимаются также псевдонимы `"utf8"`, `"cp1251"`, `"win1251"`,
`"koi8r"`, `"ibm866"`, `"dos866"`, `"ibm437"`, `"dos437"`, `"cp1252"`,
`"win1252"`, `"cp1254"` и `"win1254"`. Кодовая позиция Unicode не зависит
от последовательности байтов кодировки: `б` — это позиция `1073`, а его
байты в UTF-8 — `[208, 177]`.

`char_to_codepoint()` принимает ровно один символ Unicode.
`codepoint_to_char()` принимает скалярные значения Unicode `0..1114111`,
исключая суррогатный диапазон `55296..57343`. Неизвестное имя кодировки, целое
за пределами байтового диапазона `0..255`, непредставимый символ или кривой
UTF-8 — ошибки времени выполнения. Все однобайтовые кодировки используют
полные таблицы на 256 байт.

У `encode()` и `decode()` есть необязательный параметр `safe` (по умолчанию
`true`). По умолчанию преобразование строгое и никогда не вставляет молча
символ-заменитель Unicode `�`. С `safe=false` ученик явно отказывается
от страховки: нераскодируемые байты становятся `�`, а непредставимые символы
кодируются в `?` (байт 63) вместо ошибки времени выполнения:

```idyllium
string mojibake = encoding.decode(bytes, "utf-8", safe=false);
```

## 21a. Библиотека `url`

```idyllium
use url;

string address = "https://www.example.org/watch?v=abc123&t=43";

url.open(address);                      // открывает системный браузер
url.scheme(address);                    // "https"
url.host(address);                      // "www.example.org"
url.path(address);                      // "/watch"
url.query(address);                     // "v=abc123&t=43"
url.fragment("https://a.io/p#top");     // "top"
url.port(address);                      // 443 (порт по умолчанию, если опущен)
url.query_value(address, "v");          // "abc123"
url.encode("идиллия");                  // процентно-кодированный текст
url.decode("%D0%B8...");                // обратно в читаемый текст
url.is_valid("просто текст");           // false
```

`url.open()` работает одинаково во всех трёх хостах: новая вкладка в веб-IDE,
системный браузер из расширения для VS Code и системный открыватель
(`xdg-open`, `open`, `start`) в CLI. Принимаются только `http` и `https`:
`file:`, `javascript:` и `data:` поднимают ошибку времени выполнения, как
и неудача запуска браузера (например, на сервере без графики). `path()`
и `fragment()` возвращают читаемый человеком текст (процентные экранирования
раскодированы); `query()` остаётся сырой, потому что это составная строка, —
для одного параметра пользуйтесь `query_value()`. Сетевых запросов в этой
библиотеке нет: она только разбирает и открывает.

## 21c. Библиотека `http` (с 1.4.0)

HTTP-клиент. Работает на любом хосте; в веб-IDE запросы удаются только
к сайтам, дружелюбным к CORS (сам сайт Idyllium отдаёт раздаточные файлы
с `Access-Control-Allow-Origin: *`, поэтому раздаточные JSON заодно служат
учебным API). Только адреса `http`/`https`.

```idyllium
use http;
use json;

main() {
    http.Response r = http.get("https://aumphaadr.github.io/Idyllium/handouts/files/guild.json");
    console.writeln(r.status);            // 200
    console.writeln(r.ok);                // true для 200-299
    console.writeln(r.header("content-type"));
    json.Array members = json.parse(r.text).to_array();

    http.Response posted = http.post("https://example.org/api", "{\"vote\": 1}");

    http.set_timeout(30);                 // секунды, 1-300, по умолчанию 10
}
```

`http.Response`: свойства только для чтения `status` (int), `ok` (bool),
`text` (string); метод `header(name)` возвращает заголовок ответа (без учёта
регистра) или пустую строку. Статус вне диапазона 2xx НЕ является ошибкой —
проверяйте `ok` или `status`. Ошибки времени выполнения читаемы и разделены
по причинам: таймаут (`timed out after N seconds`), блокировка браузером
по CORS (`was blocked by the browser … works in console runs`), сетевой отказ
(`cannot reach '…': connection refused` / `host not found`). `http.post`
отправляет тело как `text/plain; charset=utf-8`. Встроенного ограничения
частоты запросов нет (как и у стандартных клиентов Python/C#/C++), только
таймауты по умолчанию.

## 21d. Библиотека `channel` (с 1.4.1)

Почтовый канал между РАБОТАЮЩИМИ программами на одном компьютере, а не сеть.
Веб-IDE: вкладки браузера (BroadcastChannel); VS Code: работает внутри одного
окна (общий хост расширения). Запуски в консоли и CLI отказывают читаемой
ошибкой: `Post.open() is not available in the console host — run the program
in the Web IDE or VS Code, where running programs can hear each other`.

```idyllium
use channel;
use console;

void function on_letter(string text) {
    console.writeln("Получено: ", text);
}

main() {
    channel.Post office;
    office.open("room-101");        // одинаковое имя = одна комната для всех участников
    office.on_message = on_letter;  // жанр обработчика, как on_click
    office.send("Привет, соседи!");
}
```

`channel.Post`: `open(name)` (имя непустое; повторное открытие открытого
ящика — ошибка времени выполнения), `send(text)` (ящик должен быть уже
открыт), `close()` (идемпотентен), свойство только для чтения `is_open`,
свойство-обработчик `on_message`, принимающее либо ни одного параметра, либо
одну строку. Семантика: сообщение доставляется ВСЕМ остальным участникам
канала с этим именем, а отправитель собственное сообщение не получает никогда
(семантика BroadcastChannel). Сообщения не хранятся: тот, кто открыл канал
после отправки, не получает ничего. Открытый ящик держит программу живой после
`main` (жанр окна); `close()` его отпускает, а «Стоп» закрывает все ящики.
Для структурированных сообщений (игры, протоколы) отправляйте текст JSON
и разбирайте его через `json.parse` — продумайте протокол до написания кода.

## 21e. Библиотека `web` (с 1.5.0; шаблоны, параметры пути, формы и перенаправление — 1.5.1)

HTTP-сервер (жанр Flask). Работает при запуске в консоли и в VS Code
с настоящим портом. В веб-IDE та же программа поднимает **репетиционный
сервер**: Service Worker перехватывает `<сайт>/preview/<порт>/...`
и направляет запросы обработчикам ученика, поэтому консоль печатает
репетиционный адрес вместо `http://127.0.0.1:8080`, а сайт открывается
в соседней вкладке ТОГО ЖЕ браузера и только там (никто другой до него
не достучится — урок подаёт это как репетицию перед настоящим выступлением
в VS Code или в консоли). Код ученика одинаков на всех хостах. Вне страницы
веб-IDE (простые вставки `runIdylliumInBrowser`, тесты) транспорта
прослушивания нет, и `web.Server.run()` по-прежнему честно отказывается
(`web.Server.run() is not available in the Web IDE — run the program in VS
Code or the console host, where the computer can listen on a port`).

```idyllium
use web;
use json;

void function hello(web.Request req, web.Response res) {
    res.send("Привет, " + req.query("name") + "!");    // text/html
}

void function api(web.Request req, web.Response res) {
    res.send_json("{\"players\": 3}");                 // application/json
}

void function receive(web.Request req, web.Response res) {
    res.status = 201;                                  // читается при отправке ответа
    res.send("получено: " + req.body);
}

main() {
    web.Server app;
    app.on_get("/hello", hello);
    app.on_post("/mailbox", receive);
    app.on_get("/api", api);
    app.serve_directory("public");   // статические файлы, только GET, "/" -> index.html
    app.port = 8080;                 // 0-65535; 0 = попросить у ОС свободный порт
    app.run();                       // управление не возвращает; завершает «Стоп» / Ctrl+C
}
```

- `web.Server`: `on_get(path, handler)` / `on_post(path, handler)` (путь
  начинается с '/'; повторная регистрация — ошибка времени выполнения),
  `serve_directory(path)`, `run()`, свойства `port` (int; после запуска держит
  настоящий порт), `host` (по умолчанию `"127.0.0.1"` — только этот компьютер;
  `"0.0.0.0"` открывает программу всей локальной сети, только нарочно),
  свойство только для чтения `is_running`.
- **Параметры пути**: сегмент маршрута в угловых скобках — это параметр;
  `app.on_get("/post/<id>", card)` совпадает с `/post/3`, а `req.param("id")`
  возвращает `"3"`. Значения ВСЕГДА строки (преобразуйте через `to_int` сами);
  отсутствующее имя → пустая строка. Точный путь побеждает параметрический
  (`/post/new` выигрывает у `/post/<id>`). Параметр обязан занимать целый
  сегмент; два маршрута одинаковой формы конфликтуют (ошибка времени
  выполнения при регистрации).
- `web.Request`: свойства только для чтения `path` и `body`; `query(name)` —
  параметр запроса или пустая строка; `param(name)` — параметр пути или пустая
  строка; `form(name)` — поле тела HTML-формы, отправленной POST
  (application/x-www-form-urlencoded: процентное раскодирование и `+` в роли
  пробела обрабатываются), пустая строка, когда поля нет.
- `web.Response`: `send(text)` (text/html), `send_json(text)`
  (application/json), `send_template(path, values)` и `redirect(path)` —
  один ответ на запрос, вторая отправка это ошибка времени выполнения;
  свойство `status` (100–599, по умолчанию 200).
- **Шаблоны**: `res.send_template("templates/list.html", values)` читает
  HTML-файл (обычный путь проекта — никаких волшебных папок, та же файловая
  система, что у библиотеки `file`, в песочнице проекта) и отрисовывает его
  значениями из `json.Object` (необязательный второй аргумент). Язык шаблона:
  `{{key}}` и `{{key.field}}` подставляют значения, причём подставленный текст
  ВСЕГДА экранируется как HTML (данные это текст; разметка живёт в шаблоне);
  `{% for x in list %}…{% endfor %}` идёт циклом по `json.Array` (вложенность
  работает); `{% if flag %}…{% else %}…{% endif %}` ветвится по логическому
  значению json (лучше ветвиться в коде; дверь `if` существует в основном для
  переселенцев с Jinja). Промахи в шаблоне никогда не роняют сервер — вместо
  этого В СТРАНИЦУ уходит читаемая пометка: `[[ нет значения 'ghost' ]]`,
  `[[ 'title' — не объект ]]`, `[[ у 'guest' нет поля 'x' ]]`,
  `[[ 'items' — список: нужен {% for %} ]]`, `[[ 'posts' — не список ]]`,
  `[[ неизвестная команда '{% wat %}' ]]`. Отсутствующий файл шаблона — ошибка
  обработчика по канону файловой библиотеки (`web.Response.send_template()
  cannot read 'x.html': file does not exist` / `path is outside the project`).
- `redirect(path)` всегда отвечает **303 See Other** с заголовком `Location`
  (статус не выбирается). Каноническая схема PRG: после успешного обработчика
  POST-формы вызовите `res.redirect("/")`, чтобы обновление страницы
  не отправляло форму заново. Репетиция в веб-IDE переписывает `Location`
  в песочницу `/preview/<порт>/` автоматически.
- Встроенное поведение: неизвестный путь → 404; известный путь (точный или
  параметрический) при неверном методе → 405; падение обработчика → 500
  с текстом ошибки (сервер продолжает работать и пишет о падении в консоль
  программы). Запросы обрабатываются по одному в порядке поступления. Раздача
  статики никогда не выходит за пределы раздаваемого каталога (обход пути
  заблокирован). Занятый порт: `web.Server.run() port 8080 is already in use —
  choose another port or stop the other program`.
- Естественный клиент для проверки — библиотека `http` того же языка:
  `http.get("http://127.0.0.1:8080/api")`.

## 21b. Библиотека `hash`

```idyllium
use hash;

int checksum = hash.crc32("Idyllium");        // 0..4294967295
int fast = hash.fnv1a("Idyllium");
int adler = hash.adler32("Idyllium");
string digest = hash.sha256("Idyllium");      // 64 строчных шестнадцатеричных знака
dyn_array<int> raw = hash.sha256_bytes("Idyllium"); // 32 байта
```

Каждая функция принимает `string` (хешируется как её байты UTF-8) или
байтовый массив (`array<int, N>` / `dyn_array<int>`, значения `0..255`);
аргументы других типов — ошибки компиляции, а байты за пределами диапазона —
ошибки времени выполнения. Результаты одинаковы в CLI, в веб-IDE
и в расширении для VS Code: алгоритмы реализованы внутри Idyllium,
а не делегированы WebCrypto.

`crc32` — это контрольная сумма IEEE/ZIP/PNG, `adler32` — контрольная сумма
zlib, `fnv1a` — 32-битный FNV-1a, а `sha256` — SHA-256 по FIPS 180-4.
`md5` и `sha1` намеренно отсутствуют (оба сломаны), как и примитив
хеширования паролей: учебные материалы должны прямо говорить, что одного
быстрого хеша для хранения паролей недостаточно (настоящий ответ — соль плюс
медленные функции выработки ключа вроде bcrypt или Argon2).

## 23. Библиотека `types`

Библиотека `types` нарочно показывает сишные числовые пределы и переполнение.
Это исключение из обычной философии Idyllium, потому что она учит школьников
низкоуровневому поведению чисел.

Типы:

```idyllium
types.int8
types.uint8
types.int16
types.uint16
types.int32
types.uint32
types.int64
types.uint64
types.float32
types.float64
```

Точные целочисленные диапазоны:

| Тип | Минимум | Максимум |
|---|---:|---:|
| `types.int8` | -128 | 127 |
| `types.uint8` | 0 | 255 |
| `types.int16` | -32768 | 32767 |
| `types.uint16` | 0 | 65535 |
| `types.int32` | -2147483648 | 2147483647 |
| `types.uint32` | 0 | 4294967295 |
| `types.int64` | -9223372036854775808 | 9223372036854775807 |
| `types.uint64` | 0 | 18446744073709551615 |

`types.float32` использует IEEE-754 binary32; `types.float64` — binary64.

Точные пределы типов доступны как константы модуля: `types.INT8_MIN`,
`types.INT8_MIN`/`types.INT8_MAX`, `types.UINT8_MAX`,
`types.INT16_MIN`/`types.INT16_MAX`, `types.UINT16_MAX`,
`types.INT32_MIN`/`types.INT32_MAX`, `types.UINT32_MAX`,
`types.INT64_MIN`/`types.INT64_MAX`, `types.UINT64_MAX`
(18446744073709551615, сохранено точно).

Переполнение целого заворачивается без ошибок времени выполнения:

```idyllium
use types;

main() {
    types.uint8 n = 253;
    n = n + 1;  // 254
    n = n + 1;  // 255
    n = n + 1;  // 0

    types.uint8 a = -11;  // 245
    types.uint8 b = 260;  // 4
}
```

Операторы (`+`, `-`, `*`, …) над значениями `types` считают в обычных точных
числах Idyllium; усекает ПОТРЕБИТЕЛЬ — заворачивание происходит, когда
результат записывают в переменную `types`, а не внутри оператора. Методы
(`.shift_left()`, `.bit_and()`, …) считают внутри ячейки и возвращают тип
получателя:

```idyllium
types.uint8 a = 200;
types.uint8 b = 100;
console.writeln(a + b);   // 300 — ещё не записано в uint8
types.uint8 c = a + b;    // 44 — усечено записью
console.writeln(a.shift_left(1));  // 144, а не 400 — методы остаются в типе
```

`int64` и `uint64` сохраняют свои полные 64-битные диапазоны точно, включая
значения выше 2^53. На границах типа они пользуются тем же молчаливым
заворачиванием.

Присваивание вещественного в целочисленное запрещено без явного `to_int()`.
Значения из `types` принимаются обычными числовыми функциями вроде
`math.sqrt()`. Арифметическое `/` по-прежнему следует обычным правилам
Idyllium и возвращает `float`; когда нужно целочисленное деление или остаток,
пользуйтесь глобальными `div()` и `mod()`.

Вспомогательные средства:

```idyllium
value.to_bin()
value.to_hex()
value.shift_left(bits)
value.shift_right(bits)
value.bit_and(mask)
value.bit_or(mask)
value.bit_xor(mask)
value.bit_not()
types.from_bin("11111111", "uint8")
types.from_hex("FF", "uint8")
```

Оба метода сдвига работают с битовой ячейкой фиксированной ширины получателя
и доступны и у целых, и у вещественных значений `types`. Биты, уходящие
за любой край, молча отбрасываются; освободившиеся позиции всегда заполняются
нулём. Сдвиг вправо логический даже для знаковых типов и знак не сохраняет.
Величина сдвига, большая или равная ширине типа, даёт нулевую ячейку.
Отрицательное количество меняет направление: `shift_left(-N)` равносилен
`shift_right(N)`, а `shift_right(-N)` равносилен `shift_left(N)`.
Вещественные значения сдвигают своё представление IEEE-754, а затем
истолковывают получившиеся биты как тот же вещественный тип. Результат
сохраняет точный тип `types.*` получателя.

Три двухместных битовых метода требуют беззнаковой маски ровно той же битовой
ширины. Тип результата всегда тип получателя:

| Получатель | Требуемая маска |
|---|---|
| `int8`, `uint8` | `uint8` |
| `int16`, `uint16` | `uint16` |
| `int32`, `uint32`, `float32` | `uint32` |
| `int64`, `uint64`, `float64` | `uint64` |

Для вещественных получателей эти методы правят сырую ячейку IEEE-754. Поэтому
они могут дать бесконечность, NaN или на вид никак не связанное конечное
число.

Примеры с наблюдаемыми результатами:

```idyllium
types.uint8 value = 221;
value.to_bin();                       // "11011101"
value.to_hex();                       // "DD"

types.uint8 bits = types.from_bin("00101011", "uint8");
bits.shift_right(3).to_bin();         // "00000101"
bits.shift_left(3).to_bin();          // "01011000"
bits.shift_left(12).to_bin();         // "00000000"
bits.shift_right(-3).to_bin();        // "01011000"

types.uint8 flags = 173;              // 10101101
types.uint8 mask = 15;                // 00001111
flags.bit_and(mask).to_bin();         // "00001101"
flags.bit_xor(mask).to_bin();         // "10100010"
```

## 24. JSON

Импорт:

```idyllium
use json;
```

Типы:

```idyllium

```

Литерал и функции:

```idyllium
null
json.is_valid(text)

```

`null` — литерал языка, но присваивается только библиотечным типам, явно
поддерживающим отсутствующее значение. Сейчас его поддерживают `json.Value`
и `sqlite.Value`; примитивные типы, пользовательские классы, `json.Object`
и `json.Array` — нет. `json.Value()` без аргументов тоже создаёт JSON null.
Для `json.Value`, допускающего null, годятся обе проверки — `value == null`
и `value.is_null()`; в учебных материалах `is_null()` обычно яснее.

Создание JSON:

```idyllium
use console;
use json;

main() {
    json.Object root;

    root.add("name", json.Value("Mira"));
    root.add("age", json.Value(12));
    root.add("admin", json.Value(false));
    root.add("middle_name", null);

    json.Array scores;
    scores.add(json.Value(5));
    scores.add(json.Value(4));
    scores.add(json.Value(5));
    root.add("scores", json.Value(scores));

    console.writeln(root.to_pretty_json(4));
}
```

Чтение JSON из файла:

```idyllium
use console;
use file;
use json;

main() {
    file.istream fin = file.open("player.json", "read");
    string text = fin.read_all();
    fin.close();

    json.Value value = json.parse(text);
    json.Object root = value.to_object();

    string name = root.get("name").to_string();
    int level = root.get("level").to_int();

    console.writeln(name, " ", level);
}
```

Методы `json.Value`:

```idyllium

is_string()
is_int()
is_float()
is_bool()
is_object()
is_array()
to_string()
to_int()
to_int64()
to_uint64()
to_float()
to_bool()
to_object()
to_array()
set_null()
set_string(value)
set_int(value)
set_float(value)
set_bool(value)
set_object(value)
set_array(value)
to_json()
to_pretty_json()
to_pretty_json(indent)
```

Для чисел JSON `is_int()` истинен только для целого значения, а `is_float()`
истинен и для целого, и для нецелого числа, потому что оба безопасно
преобразуются через `to_float()`.

Целые лексемы JSON разбираются точно, включая значения выше предела безопасных
целых JavaScript (`2^53 - 1`). Пользуйтесь `to_int()` для обычных безопасных
целых, `to_int64()` для знакового 64-битного диапазона и `to_uint64()` для
беззнакового. Передача `types.int64` или `types.uint64` в `json.Value(...)`
и последующая сериализация записывают число JSON без кавычек и без потери
цифр.

Свойство `json.Object` только для чтения:

```idyllium

```

```idyllium

get(key)
add(key, value)
set(key, value)
remove(key)
keys()
```

`add` требует нового ключа. `set` обновляет существующий. Ключи — строки
и должны быть уникальны внутри одного объекта.

Свойство `json.Array` только для чтения:

```idyllium
array.length
```

Методы `json.Array`:

```idyllium

set(index, value)
add(value)
insert(index, value)
pop()
remove(index)
clear()
```

Не пишите комментариев внутри файлов JSON. Текст JSON использует ключи
в двойных кавычках, фигурные скобки для объектов, квадратные для массивов
и `null` для отсутствующих значений.

## 24a. Библиотека `xml` (с 1.5.4)

Чтение разметки — строгого XML и прощающего HTML — в дерево узлов:

```idyllium
use xml;

main() {
    xml.Node feed = xml.parse_xml("<feed><item><title>Новости</title><link>https://a</link></item></feed>");
    dyn_array<xml.Node> items = feed.find_all("item");
    for (int i = 0; i < items.length; i = i + 1) {
        console.writeln(items[i].first("title").text, " → ", items[i].first("link").text);
    }
}
```

- `xml.parse_xml(text)` — строгий XML. Ошибка разметки останавливает
  программу с позицией внутри разбираемого текста: `xml.parse_xml() invalid
  XML at 1:11: closing tag '</a>' does not match open tag '<b>'`; значения
  атрибутов без кавычек, незакрытые теги, повторяющиеся атрибуты, текст вне
  корня и что угодно кроме ровно одного корневого элемента — тоже ошибки.
- `xml.parse_html(text)` — прощающий HTML для страниц реального веба:
  незакрытые `<li>` и `<p>`, одиночный `<img>` без пары, атрибуты без
  кавычек, любой регистр тегов (имена приводятся к нижнему, и аргументы
  поиска приводятся так же), тела `<script>`/`<style>` сохраняются сырым
  текстом, голый `<` в тексте остаётся текстом, а страница, оборванная
  посреди тега (прерванная загрузка), всё равно разбирается.
- Оба входа пропускают комментарии, `<!doctype>` и `<?xml?>`, превращают
  CDATA в текст, раскрывают `&amp; &lt; &gt; &quot; &apos; &nbsp;` и
  числовые сущности `&#…;`. У корневого узла результата `tag == "#document"`.

`xml.Node` (всё только для чтения):

```idyllium
tag, text, children
attr(name)      // значение атрибута, "" если атрибута нет
has_attr(name)
find_all(tag)   // все потомки с этим тегом на любой глубине; пустой список — не ошибка
first(tag)      // первый такой потомок; ошибка времени выполнения, если его нет
has(tag)
```

`text` собирает текст всего поддерева с раскрытыми сущностями; куски из
одних пробелов между тегами отбрасываются. `children` держит только
узлы-элементы. `first` по отсутствующему тегу — громкая ошибка в жанре
`json.Object.get` — `xml node <item> has no <title> inside`; когда тег
необязателен, ограждайте `has()`. Сознательно за бортом: пространства имён,
XPath, CSS-селекторы, DTD и сериализация — библиотека для чтения.

```idyllium
text_color: colors.Color
background_color: colors.Color
font: fonts.Font
```

`hint` — это всплывающая подсказка: строка появляется рядом с курсором, когда
он задерживается над виджетом; пустая строка (значение по умолчанию) означает,
что подсказки нет. В отличие от `placeholder` (текста внутри пустого поля
ввода), `hint` работает у каждого виджета — пользуйтесь им для маленьких
кнопок с одной иконкой.

`visible = false` прячет виджет (он остаётся в памяти и не получает событий).
`enabled = false` оставляет виджет на экране, но выключает его: текущая тема
окна рисует его приглушённым, он игнорирует мышь и клавиатуру, а его
обработчики не срабатывают. По умолчанию оба свойства `true`. Выключение
или сокрытие контейнера (`Frame`, `TabWidget`) распространяется на всех его
детей. Ни одно из состояний не является ошибкой: «выключили и не включили
обратно» так же молчаливо, как «спрятали и не показали обратно».

Обычные свойства цвета:

```idyllium
text_color
background_color
border_color
foreground_color   // роль цвета заполнения у ProgressBar
```

`text_color`, `background_color`, `font` и `font_size` наследуются дочерними
виджетами. Явно заданное значение ребёнка перекрывает родительское.
`font_size` принадлежит виджету с текстом, а не ресурсу шрифта. Значение
по умолчанию — `13`.

### Свойство `style` (IdySS)

У каждого визуального виджета и у `gui.Window` есть свойство `style: string` —
CSS-подобная «наклейка», накладываемая поверх прямых свойств:

```idyllium
title.style = "color: white; background-color: dark-blue; border-radius: 12px;";
```

Правила наклейки:

- **Опечатки молчаливы.** Неизвестное свойство (`backround-color`) или
  недопустимое значение (`opacity: 1.5`, `color: bananas`) отбрасывается без
  всякой ошибки, как в настоящем CSS. Собственные проверки типов Idyllium
  к самому присваиванию по-прежнему применяются (`label.style = 42;` — ошибка
  компиляции).
- **Наклейка всегда побеждает** прямые свойства, пока перечисляет эту роль:
  при `style = "color: blue;"` виджет показывает синий текст, даже если был
  задан `text_color`. Присваивание `""` снимает наклейку, и прямые свойства
  снова видны. Более поздние объявления внутри одной строки побеждают более
  ранние.
- Наклейка **не наследуется** дочерними виджетами; чтение `style` возвращает
  ровно присвоенную строку.
- `style_hover`, `style_active` и `style_disabled` держат наклейки,
  действующие, пока указатель над виджетом, пока виджет нажат и пока он
  выключен (`enabled = false`). Тот же словарь, то же молчание про опечатки;
  наклейка состояния ложится поверх `style` и снимается сама, когда
  состояние заканчивается.

Поддерживаемых свойств — 44, всё остальное игнорируется. Пиксельные
значения принимаются и как `12px`, и просто как `12`.

- **Цвет и фон:** `color`, `background-color`, `background` (только
  градиенты, см. ниже).
- **Рамки:** `border-color`, `border-width` (0-20), `border-style`
  (`solid`/`dashed`/`dotted`/`none`), `border-radius` (0-100) и та же тройка
  цвет/толщина/стиль на каждую сторону — `border-top-*`, `border-bottom-*`,
  `border-left-*`, `border-right-*`.
- **Обводка** (кольцо, не сдвигающее содержимое): `outline-color`,
  `outline-width` (0-20), `outline-style`.
- **Текст:** `font-size` (6-96), `font-weight` (`normal`/`bold`),
  `font-style` (`normal`/`italic`), `font-family` (только
  `sans`/`serif`/`mono` — произвольные имена шрифтов отбрасываются),
  `text-align` (`left`/`center`/`right`), `text-decoration`
  (`none`/`underline`/`line-through`), `text-transform`
  (`none`/`uppercase`/`lowercase`/`capitalize`), `letter-spacing` (−5…20),
  `line-height` (0.8-3, без единиц).
- **Отступы:** `padding` (0-40) и `padding-top`/`-bottom`/`-left`/`-right`.
- **Тени:** `box-shadow` и `text-shadow` принимают РОВНО четыре части в этом
  порядке — `<сдвиг-x> <сдвиг-y> <размытие> <цвет>` (сдвиги −50…50, размытие
  0-50). `inset`, списки теней и `spread` не принимаются.
- **Движение:** `transition-duration` (`0`…`2s` или `0`…`2000ms`) заставляет
  `style_hover`/`style_active` проявляться плавно, а не скачком; `rotate`
  (−360…360 градусов) и `scale` (0.1-5). **`rotate` и `scale` меняют то, как
  виджет ВЫГЛЯДИТ, а не где он находится:** кликабельная область остаётся
  исходным прямоугольником, так что по повёрнутой кнопке попадают по её
  неповёрнутому контуру.
- **Поведение:** `opacity` (0.0-1.0), `cursor`
  (`default`/`pointer`/`text`/`wait`/`not-allowed`/`help`), `user-select`
  (`auto`/`none`/`text`/`all` — кнопкоподобные виджеты поставляются с `none`
  по умолчанию; задайте `user-select: text`, чтобы вернуть выделение).

`background` принимает ТОЛЬКО градиенты (сплошные цвета идут через
`background-color`): `linear-gradient([to right | 45deg,] color[, color...])`
с 2–8 остановками и `radial-gradient(color, color[, ...])`. Остановки
записываются теми же формами цвета, за которыми может следовать процентная
позиция (`yellow 20%`). Углы — `0..360deg`; направления — `to top/bottom/left/
right` и углы вроде `to top right`. `url(...)` и любые другие значения
`background` молча отбрасываются.

Значения цвета: 17 имён палитры библиотеки `colors` в kebab-case (`red`,
`dark-blue`, `light-gray`, `transparent`; `green` — это `#00FF00`),
шестнадцатеричные (`#RGB`, `#RRGGBB`, `#RRGGBBAA`) и `rgb(r, g, b)` /
`rgba(r, g, b, a)` со строгими диапазонами. Имена, существующие только в CSS,
вроде `pink` или `salmon`, НЕ поддерживаются. Нет ни `font-family`,
ни геометрии (`width`/`margin`/`position`), ни сокращённой записи
`border: 2px solid red` — пользуйтесь тремя отдельными свойствами рамки.

### Типы GUI

`gui.Window`:

```idyllium
x, y, width, height, title, theme, text_color, background_color, font, font_size
add_child(child)
show()
close()
```

`close()` убирает окно из программы. Когда закрывается последнее окно,
у программы не остаётся графики, и хост её завершает — именно так пишется
кнопка «Выход». Крестик в предпросмотре делает то же самое, но только для
своего окна: пока показано несколько окон, программа продолжает работать,
и завершается лишь с закрытием последнего.

`x` и `y` — положение окна на «рабочем столе» предпросмотра. Пока программа
их не задала, окна раскладываются автоматически — рядом, с переносом, когда
ряд кончается. Пользователь может и сам перетащить окно за шапку, как в
настоящей ОС: после перетаскивания `x`/`y` держат новое место, и программа
читает, где окно НА САМОМ ДЕЛЕ. Присваивание `x`/`y` из кода переносит окно
туда.

`theme` — строка: `"default"` (простой светлый вид), `"idyllium"`
и `"dracula"` (тёмные), `"breeze"` и `"oxygen"` (светлые, в духе KDE). Тема
охватывает всё окно — заголовок, рамки, кнопки, поля ввода, флажки, ползунки,
полоски прогресса, вкладки и модальные диалоги. Это самый нижний слой
оформления: цвет, который задал ученик (`text_color`, `background_color`,
`border_color`, `foreground_color`), и наклейки IdySS всегда её побеждают,
а нетронутые цвета следуют теме. Неизвестное имя темы — ошибка времени
выполнения с перечислением всех пяти (`Window.theme must be 'default',
'idyllium', 'dracula', 'breeze' or 'oxygen', got '...'`).

`gui.Label`:

```idyllium
x, y, width, height, visible, enabled
text, href, font_size
text_color, background_color, border_color
on_click
```

Непустой `href` превращает метку в настоящую гиперссылку (подчёркнутую,
открывающуюся в новой вкладке). Отдельного виджета LinkLabel нет.

`gui.Button`:

```idyllium
x, y, width, height, visible, enabled
text, font_size
text_color, background_color, border_color
on_click
```

`gui.Frame`:

```idyllium
x, y, width, height, visible, enabled
title, font_size
background_color, border_color, border_width
add_child(child)
```

`gui.ImageBox`:

```idyllium
x, y, width, height, visible, enabled
resize_mode
set_image(image: image.Image)
```

Режимы масштабирования — `"fit"`, `"fill"`, `"stretch"` и `"original"`; любое
другое значение это ошибка времени выполнения с перечислением всех четырёх.
Строковые перечисления у свойств виджетов СТРОГИ повсеместно (`echo_mode`,
`orientation`, `resize_mode`, `theme`) — молчаливыми по замыслу остаются
только наклейки IdySS `style`. `ImageBox` сам файлы не загружает. Загрузите
`image.Static` или `image.Animation`, а затем передайте в `set_image()`.

`gui.LineEdit`:

```idyllium
x, y, width, height, visible, enabled
text, placeholder, placeholder_color, font_size, echo_mode
text_color, background_color, border_color
on_change
```

`gui.TextEdit`:

```idyllium
x, y, width, height, visible, enabled
text, placeholder, placeholder_color, font_size
text_color, background_color, border_color
on_change
```

`gui.ProgressBar`:

```idyllium
x, y, width, height, visible, enabled
value, min, max, orientation, font_size
text_color, background_color, foreground_color, border_color
```

`background_color` виден в незаполненной части, а `foreground_color` —
в заполненной. Старый псевдоним `fill_color` удалён.

`gui.SpinBox`:

```idyllium
x, y, width, height, visible, enabled
value, min, max, step, font_size
on_change
```

`gui.FloatSpinBox`:

```idyllium
x, y, width, height, visible, enabled
value, min, max, step, font_size
on_change
```

`gui.Slider`:

```idyllium
x, y, width, height, visible, enabled
value, min, max, step, orientation
on_change
```

`orientation` — это `"horizontal"` (по умолчанию) или `"vertical"`;
вертикальный ползунок растёт снизу вверх (минимум внизу). Любое другое
значение — ошибка времени выполнения (`Slider.orientation must be
'horizontal' or 'vertical', got '...'`). У `gui.ProgressBar` то же свойство
с теми же правилами: вертикальная полоска заполняется снизу вверх.

У SpinBox, FloatSpinBox и Slider общие умолчания: `value = 0`, `min = 0`,
`max = 100`, `step = 1`. Присваивание `value` за пределами `min..max` из кода
НЕ является ошибкой и не подрезается: свойство сохраняет присвоенное число,
а элемент на экране показывает ближайшую границу (Slider) или само число
(SpinBox). Так сделано нарочно, потому что порядок настройки свойств свободен
(`value = 150`, а следом `max = 300`, — законно). Ввод ПОЛЬЗОВАТЕЛЯ, напротив,
всегда уважает границы: стрелки и колесо мыши останавливаются на краях,
а набранное в SpinBox число подрезается в `min..max` при подтверждении (потере
фокуса или Enter); пустой или нечисловой текст возвращается к последнему
подтверждённому значению, а не превращается в 0. Пока пользователь ещё
набирает, программа не получает ничего — `on_change` срабатывает с подрезанным
значением только при подтверждении (стрелки и колесо подтверждают сразу).

`placeholder_color` (значение `colors.Color`) красит подсказку-заполнитель
у `gui.LineEdit`/`gui.TextEdit`. Как и всякий цвет виджета, применяется только
явно присвоенное значение, иначе оттенок выбирает тема окна.

`on_change` у Slider срабатывает при каждом движении бегунка во время
перетаскивания, а не только когда бегунок отпустили.

`gui.CheckBox`:

```idyllium
x, y, width, height, visible, enabled
text, is_checked, font_size
on_change
```

`gui.RadioButton`:

```idyllium
x, y, width, height, visible, enabled
text, is_selected, group, font_size
on_change
```

Выбор переключателя снимает выбор с остальных кнопок той же `group`,
и `on_change` срабатывает у каждой затронутой кнопки: у только что выбранной
(с `is_selected == true`) и у каждой соседки, с которой выбор сняли
(с `is_selected == false`).

`gui.ComboBox`:

```idyllium
x, y, width, height, visible, enabled
selected_index, selected_text, font_size
add_item(text)
clear_items()
on_change
```

`selected_text` доступен только для чтения и следует за `selected_index`.
Меняйте выбранный элемент через `selected_index`; не присваивайте
в `selected_text`.

`gui.TabWidget`:

```idyllium
x, y, width, height, visible, enabled
selected_index, selected_title, tab_count, font_size
add_tab(title, content)
clear_tabs()
on_change
```

`add_tab(title, content)` принимает заголовок и один виджет в роли страницы
(обычно `gui.Frame`, наполненный детьми). `selected_title` и `tab_count`
доступны только для чтения; переключайте страницы через `selected_index`,
а `selected_title` следует за ним — он выводится из индекса, а не хранится
отдельно. `on_change` срабатывает, когда пользователь щёлкает другую вкладку.
Координаты содержимого страницы отсчитываются от страницы вкладки, а не
от окна. Виджет, переданный в `add_tab()`, НЕ должен передаваться ещё
и в `add_child()`: тогда он будет нарисован дважды.

`gui.Modal`:

```idyllium
title, message, confirm_text, cancel_text
on_confirm, on_cancel
show_alert()
show_confirm()
show_input()
get_input_value()
```

`show_alert()` показывает одну кнопку «ОК», `show_confirm()` добавляет кнопку
отмены, а `show_input()` добавляет текстовое поле, значение которого потом
читается через `get_input_value()`.

`gui.Timer`:

```idyllium
interval
running
on_tick
start()
stop()
restart()
```

`interval` задаётся в миллисекундах (`timer.interval = 1000;` — тик раз
в секунду). `running` — флаг только для чтения. `stop()` приостанавливает
таймер и сохраняет накопленный прогресс; `start()` продолжает с этого места;
`restart()` начинает заново с нуля.

### Сигнатуры обработчиков виджетов

Обработчики событий виджетов (`on_click`, `on_change`, `on_tick`,
`on_confirm`, `on_cancel`) принимают либо функцию без аргументов, либо
функцию с одним параметром — самим виджетом (отправителем). Новое состояние
читайте из свойств отправителя:

```idyllium
use console;
use gui;

void function volume_changed(gui.Slider sender) {
    console.writeln("Громкость: ", sender.value);
}

void function ticked() {
    console.writeln("тик");
}

main() {
    gui.Slider slider;
    slider.on_change = volume_changed;

    gui.Timer timer;
    timer.interval = 500;
    timer.on_tick = ticked;
    timer.start();
}
```

Обработчик не получает нового значения отдельным аргументом; формы
`(sender, value)` у виджетов не существует. Только обработчики `gui.Canvas`
получают дополнительный аргумент события или `delta_time` (см. раздел
про холст).

Пример кнопки:

```idyllium
use console;
use gui;

void function clicked(gui.Button sender) {
    sender.text = "Нажата";
    console.writeln("кнопку нажали");
}

main() {
    gui.Window win;
    win.width = 300;
    win.height = 160;

    gui.Button button;
    button.x = 40;
    button.y = 40;
    button.width = 180;
    button.height = 40;
    button.text = "Жми";
    button.on_click = clicked;

    win.add_child(button);
    win.show();
}
```

## 25a. Виджеты для показа данных (таблица и диаграммы)

Четыре виджета для показа данных (Idyllium 1.3.2+). Все следуют обычным
правилам виджетов: x/y/width/height, visible/enabled, наклейки IdySS `style`,
add_child.

```idyllium
gui.Table table;
table.set_columns("Имя", "Класс", "Уровень");   // переменное число строк
table.add_row("Мира", "маг", to_string(12));    // по одному значению на столбец
```

- `gui.Table`: `set_columns(...)` (переменное число аргументов, сбрасывает
  строки), `add_row(...)` (переменное число; количество обязано совпадать
  с числом столбцов, иначе ошибка времени выполнения),
  `set_cell(row, column, text)`, `remove_row(row)`, `clear()`; только для
  чтения `row_count`, `selected_row` (−1, когда ничего не выбрано);
  обработчик `on_select` (`void function()` или
  `void function(gui.Table sender)`) срабатывает при щелчке по строке. Ячейки
  это СТРОКИ — числа преобразуйте через `to_string()`.
- `gui.BarChart`: `add_value(label, value)`, `set_value(label, value)`,
  `clear()`; `bar_color` (один цвет на все столбики; по умолчанию акцент темы),
  `show_values` (по умолчанию true), `min_value`/`max_value` (автомасштаб, пока
  не заданы). Значения обязаны быть >= 0.
- `gui.LineChart`: `add_value(value)` добавляет точки слева направо;
  `clear()`; `line_color`, `show_dots` (по умолчанию true),
  `min_value`/`max_value` (фиксируют масштаб для приборов), `max_points`
  (кольцевой буфер для живых графиков; 0 — хранить всё). В паре с `gui.Timer`
  получаются живые панели.
- `gui.PieChart`: `add_slice(label, value)`, `set_slice(label, value)`, `clear()`;
  `show_legend`, `show_percents` (оба по умолчанию true). Проценты и цвета
  секторов вычисляются сами.

Стражи говорят буквально: `Table.add_row() expects 3 values (one per column),
got 2`; `BarChart has no bar 'Хома'`; `PieChart slice value must be >= 0,
got -3`; `LineChart.max_points must be between 0 and 100000, got -1`.

НЕ выдумывайте `load_from_result()` и `load_from_json()` — наполняйте виджеты
явным циклом по своим данным.

## 26. Холст и рисуемые объекты

```idyllium
use gui;

main() {
    gui.Window win;
    gui.Canvas canvas;

    canvas.x = 20;
    canvas.y = 20;
    canvas.width = 400;
    canvas.height = 240;

    win.add_child(canvas);
    win.show();
}
```

Обычно импортируют:

```idyllium
use colors;
use drawable;
use gui;
```

```idyllium

on_init
on_key_pressed
on_key_released
on_mouse_pressed
on_mouse_released
on_mouse_move
on_mouse_scroll
on_update
```

```idyllium
clear()

```

`draw(object)` принимает потомков `drawable.Drawable`.

События:

```idyllium
gui.KeyboardEvent.key: string

gui.MouseEvent.x: int
gui.MouseEvent.y: int
gui.MouseEvent.mouse_button: string  // "LEFT", "RIGHT", "MIDDLE"

gui.MouseScrollEvent.x: int
gui.MouseScrollEvent.y: int
gui.MouseScrollEvent.delta: int
```

Значения `KeyboardEvent.key`: одиночные символы приходят в верхнем регистре
(`"W"`, `"Д"`, `"7"`); у специальных клавиш браузерные имена вроде
`"ArrowLeft"`, `"ArrowRight"`, `"ArrowUp"`, `"ArrowDown"`, `"Enter"`,
`"Escape"` и `" "` для пробела. Сравнивайте с заглавными буквами:
`pressed_keys.contains("W")`, а не `"w"`. `MouseScrollEvent.delta` равен `1`
при прокрутке вверх и `-1` при прокрутке вниз.

### Типы рисуемых объектов

Базовый тип:

```idyllium
drawable.Drawable
contains(float x, float y) -> bool
collides_with(drawable.Drawable other) -> bool
```

`contains()` включает границу. `collides_with()` считает касание пересечением
и диспетчеризуется по настоящим типам времени выполнения.

Rectangle, Circle, Sprite и Text разделяют один API преобразований:

```idyllium
origin_x: float  // только чтение
origin_y: float  // только чтение
rotation: float
set_origin(float x, float y)
rotate(float angle)
move(float dx, float dy)
```

`x/y` — это мировая позиция локальной точки отсчёта. Точка отсчёта
по умолчанию — `(0, 0)`. Положительные углы поворачивают по часовой стрелке.
`rotate(angle)` добавляет к текущему повороту, а не заменяет его.

Позиции рисуемых объектов — вещественные значения. У Rectangle, Circle,
Sprite и Text это `x: float` и `y: float`; у Line — `x1/y1/x2/y2: float`.
Размеры, радиус, толщина рамки, толщина линии и размер шрифта остаются `int`.
Координаты виджетов GUI по-прежнему `int`, и это правило их не касается.

Для локальной точки со смещением `(radius, 0)` от точки отсчёта координаты
холста следуют тому же соглашению «по часовой стрелке, Y вниз», что
и отрисовщик:

```idyllium
float radians = math.to_radians(angle);
point.x = center_x + radius * math.cos(radians);
point.y = center_y + radius * math.sin(radians);
```

Не меняйте знак у `sin`, не сдвигайте угол и не преобразуйте результат
в `int`.

`drawable.Rectangle`:

```idyllium
x: float
y: float
width: int
height: int
fill_color: colors.Color
border_width: int
border_color: colors.Color
```

`drawable.Circle`:

```idyllium
x: float
y: float
radius: int
fill_color: colors.Color
border_width: int
border_color: colors.Color
```

Локальные границы круга — `(0, 0)..(2 * radius, 2 * radius)`, поэтому при
точке отсчёта по умолчанию его `x/y` означает левый верхний угол этого
квадрата. Чтобы `x/y` стал центром круга, вызовите `set_origin(radius,
radius)` после присваивания радиуса.

`drawable.Line`:

```idyllium
x1, y1, x2, y2: float
color: colors.Color
thickness: int
move(dx, dy)
```

### Ресурсы-картинки

Импорт:

```idyllium
use image;
```

`image.Image` — общий базовый тип, который принимают потребители GUI и холста.
Его конкретные потомки:

```idyllium
image.Static picture;
image.Animation animation;
```

`image.Bitmap` — отдельный изменяемый растровый тип. Преобразуйте его через
`to_static()`, прежде чем передавать результат в GUI или на холст.

Общие свойства только для чтения:

```idyllium
src: string
width: int
height: int
format: string
has_alpha: bool
is_loaded: bool
```

`format` определяется по содержимому файла, а не по расширению.

`image.Static`:

```idyllium
load_from_file(path)
scale(x, y) -> image.Static
rotate(angle) -> image.Static
tint(color) -> image.Static
with_opacity(opacity) -> image.Static
desaturate(amount = 1.0) -> image.Static
crop(x, y, width, height) -> image.Static
export_to_file(path)
```

Преобразования возвращают новую картинку и не изменяют исходную. Множители
масштаба могут быть положительными или отрицательными, но не нулевыми.
Отрицательный X отражает по горизонтали, отрицательный Y — по вертикали. Углы
поворота обязаны делиться на 90. Прозрачность и обесцвечивание используют
`0.0..1.0`. Прямоугольник обрезки обязан целиком помещаться в исходную
картинку.

`image.Vector` (SVG, Idyllium 1.3.3+):

```idyllium
load_from_file(path)                    // только SVG; например, файлы из turtle.save_svg()
to_static(width, height = 0) -> image.Static
src: string        // только чтение
width: int         // только чтение: собственный размер из viewBox или атрибутов width+height
height: int        // только чтение
is_loaded: bool    // только чтение
```

`to_static` растеризует вектор: опустите `height`, чтобы сохранить пропорции;
задайте оба размера — и рисунок ВПИСЫВАЕТСЯ без искажений (прозрачные поля,
как режим contain у ImageBox). Размеры — 1..4096. Результат — обычный
`image.Static`, поэтому экспорт в PNG это цепочка:
`v.to_static(512, 512).export_to_file("логотип.png")` — НЕ выдумывайте
`save_png()`. Растеризация работает на хостах веб-IDE и VS Code; в консольном
хосте `to_static` поднимает `Vector.to_static() is not available in the
console host`. Стражи: `cannot decode '...': not an SVG document (expected
<svg...>)`, `Vector.to_static() size must be between 1 and 4096, got 9000`.

`image.Animation`:

```idyllium
frame_count: int
frame_duration: float
has_uniform_frame_duration: bool
load_from_file(path)
get_frame(index) -> image.Static
get_frame_duration(index) -> float
create_from_frames(frames, frame_duration)
export_to_file(path)
```

Файлы GIF и APNG могут содержать разные задержки для разных кадров. Для
произвольных импортированных анимаций пользуйтесь
`get_frame_duration(index)`. `frame_duration` точен, когда
`has_uniform_frame_duration` истинно. У анимаций, созданных через
`create_from_frames()`, тайминг всегда равномерный, поэтому их общая
длительность — это `frame_count * frame_duration`.

`image.Bitmap` — изменяемый растр RGBA для пиксельных алгоритмов
и порождаемых картинок:

```idyllium
is_created: bool // только чтение

create(width, height, fill = colors.TRANSPARENT)
load_from_file(path)
create_from_image(source: image.Static)
get_pixel(x, y) -> colors.Color
set_pixel(x, y, color)
fill(color)
fill_rect(x, y, width, height, color)
to_static() -> image.Static
export_to_file(path)
```

Координаты начинаются с левого верхнего пикселя `(0, 0)`. Размеры обязаны быть
положительными, а все пиксельные и прямоугольные координаты — оставаться
внутри растра. `Bitmap`, загруженный или созданный из `Static`, владеет
независимой копией пикселей. `to_static()` тоже создаёт независимый
неизменяемый снимок. Передавайте в `ImageBox` или `Sprite` именно этот снимок;
изменяемый `Bitmap` сознательно не является прямым ресурсом ни для GUI, ни для
холста.

Пример, общий для GUI и холста:

```idyllium
use drawable;
use gui;
use image;

image.Static cat;
cat.load_from_file("cat.png");

gui.ImageBox preview;
preview.set_image(cat);
preview.resize_mode = "fit";

drawable.Sprite hero;
hero.set_image(cat);
```

После возврата из `load_from_file()` ресурс готов для обоих потребителей.
Никогда не порождайте вызовы `time.sleep()` и повторную отрисовку только ради
того, чтобы «дождаться» раскодирования картинки. Предпросмотр GUI
перерисовывает себя сам, когда его браузерная картинка становится доступна.

Не порождайте удалённые API `gui.Image` и `drawable.Texture`.

`drawable.Sprite`:

```idyllium
x, y
set_image(image: image.Image)
set_scale(x, y)
```

Геометрия столкновений спрайта — это преобразованный прямоугольник всей
картинки; прозрачные пиксели не исключаются. Геометрические методы сообщают
читаемую ошибку времени выполнения, пока картинка не загружена.

`fonts.Font` — канонический переиспользуемый ресурс шрифта:

```idyllium
use fonts;

src: string       // только чтение
format: string    // только чтение: "ttf", "otf", "woff" или "woff2"
is_loaded: bool   // только чтение
load_from_file(path)
```

Среда выполнения определяет формат по содержимому файла, а не по расширению.
Один и тот же загруженный объект можно присвоить и виджету GUI,
и `drawable.Text`. Ресурсы шрифтов объявляются только как `fonts.Font`.

`drawable.Text`:

```idyllium
font: fonts.Font
text: string
x, y: float
font_size: int
text_color: colors.Color
get_width() -> float
get_height() -> float
```

Отрисовка текста и геометрия столкновений поддерживают точку отсчёта
и поворот. Перед вызовом `Text.contains()` или `Text.collides_with()` свой
шрифт необязателен: без него Idyllium использует вшитый Source Code Pro.
Загруженные пользователем файлы TTF, OTF, WOFF и WOFF2 поддерживаются все.
Среда выполнения пользуется точными метриками продвижения и прямоугольником
однострочной раскладки, а не контурами отдельных глифов. Отсутствующие глифы
и многострочные строки дают читаемые ошибки времени выполнения, а не
угаданные границы.

`get_width()` и `get_height()` возвращают те же размеры однострочной
раскладки, которыми пользуются `contains()` и `collides_with()`. Они полезны
для подложек, выравнивания и отступов вокруг текста.

```idyllium
fonts.Font heading_font;
heading_font.load_from_file("Lobster-Regular.ttf");

drawable.Text heading;
heading.font = heading_font;
heading.text = "Новая игра";
heading.font_size = 48;

bool hovered = heading.contains(mouse_x, mouse_y);
bool touched = heading.collides_with(cursor_circle);
```

Пример:

```idyllium
use colors;
use drawable;
use gui;

drawable.Circle ball;

void function init(gui.Canvas canvas) {
    ball.x = 120;
    ball.y = 80;
    ball.radius = 30;
    ball.set_origin(30, 30);
    ball.fill_color = colors.RGB(255, 210, 80);

    canvas.clear();
    canvas.draw(ball);
}

main() {
    gui.Window win;
    win.width = 360;
    win.height = 240;

    gui.Canvas canvas;
    canvas.x = 20;
    canvas.y = 20;
    canvas.width = 300;
    canvas.height = 160;
    canvas.on_init = init;

    win.add_child(canvas);
    win.show();
}
```

Приём плавного движения:

```idyllium
use colors;
use drawable;
use gui;

drawable.Rectangle player;
dyn_array<string> pressed_keys;

void function init(gui.Canvas canvas) {
    player.x = 20;
    player.y = 20;
    player.width = 40;
    player.height = 40;
    player.fill_color = colors.GREEN;
}

void function on_key_pressed(gui.Canvas canvas, gui.KeyboardEvent evt) {
    if (not(pressed_keys.contains(evt.key))) {
        pressed_keys.add(evt.key);
    }
}

void function on_key_released(gui.Canvas canvas, gui.KeyboardEvent evt) {
    if (pressed_keys.contains(evt.key)) {
        pressed_keys.remove_at(pressed_keys.find(evt.key));
    }
}

void function on_update(gui.Canvas canvas, float delta_time) {
    if (pressed_keys.contains("W")) { player.y = player.y - 2; }
    if (pressed_keys.contains("S")) { player.y = player.y + 2; }
    if (pressed_keys.contains("A")) { player.x = player.x - 2; }
    if (pressed_keys.contains("D")) { player.x = player.x + 2; }

    canvas.clear();
    canvas.draw(player);
}
```

### Снимки холста

Холст умеет отдавать свою текущую картинку:

```idyllium
image.Static shot = canvas.to_static();               // весь холст
image.Static part = canvas.to_static(140, 60, 200, 150); // область x, y, ширина, высота
canvas.export_to_file("frame.png");                   // сокращение, формат по расширению
canvas.save_svg("frame.svg");                         // работает везде, включая запуск в консоли
```

Правила области: нули для ширины и высоты означают «до края»; пустая область —
ошибка времени выполнения. Снимок захватывает то, что нарисовано до этой
строки. `to_static()` и `export_to_file()` требуют растеризатора хоста
(веб-IDE); при запуске в консоли они поднимают читаемую ошибку, предлагающую
`save_svg()`. `save_svg()` сериализует список отображения и работает
на любой платформе — это правильный инструмент для долгих безголовых
симуляций, автоматически сохраняющих кадры. Ограничение: свои шрифты внутри
SVG-снимков откатываются к рубленому.

## 27. Звук

Импорт:

```idyllium
use audio;
```

`audio.Sound` предназначен для коротких звуковых эффектов. Несколько вызовов
`play()` могут накладываться.

Принимаемые форматы — WAV, MP3 и OGG, и формат определяется по **сигнатуре**
файла, а не по расширению: переименование файла не меняет того, чем он
является. Всё остальное (AAC, M4A или файл, вовсе не являющийся звуком)
отвергается при загрузке:

```text
runtime error: Sound.load_from_file() cannot decode 'fake.wav': unsupported audio format (WAV, MP3 and OGG are supported)
```

Гарантированные учебные форматы — WAV и MP3: OGG всюду проходит калитку
сигнатуры, но для воспроизведения ему по-прежнему нужен кодек от хоста.
Idyllium не перекодирует звуковые файлы. Проверка сигнатуры — это калитка,
а не полное раскодирование: усечённый файл с правильным заголовком
загружается и сообщает `duration` 0.

Свойства:

```idyllium
src: string          // только чтение
duration: float     // только чтение
volume: float       // 0.0..1.0
is_playing: bool    // только чтение
```

Методы:

```idyllium
load_from_file(path)
play()
pause()
resume()
stop()
```

`pause()`, `resume()` и `stop()` действуют на все активные копии одного
и того же `Sound`. `resume()` запускает новую копию только тогда, когда
продолжать нечего. У `Sound` намеренно нет свойства `loop`.

`audio.Music` предназначен для длинных музыкальных файлов.

Свойства:

```idyllium
src: string          // только чтение
duration: float      // только чтение
position: float
volume: float        // 0.0..1.0
loop: bool
is_playing: bool     // только чтение
on_finished
```

Методы:

```idyllium
load_from_file(path)
play()
pause()
resume()
stop()
```

`Music.position` — позиция перемотки в секундах, и она обязана оставаться
в `0.0..duration`. Присваивание в неё каждый раз выполняет перемотку, даже
если присваивается одно и то же значение. `play()` начинает с текущей позиции,
`pause()` её сохраняет, `resume()` продолжает воспроизведение, а `stop()`
сбрасывает её в `0.0`.

`on_finished` выполняется после естественного завершения, когда `loop` ложно.
Он принимает либо обработчик без аргументов, либо обработчик, получающий
текущую музыку:

```idyllium
void function next_track(audio.Music current) {
    console.writeln("Закончилось: ", current.src);
}

music.on_finished = next_track;
```

Когда `loop` истинно, воспроизведение начинается заново, и `on_finished`
на каждом круге не выдаётся. Присваивание громкости или позиции за пределами
допустимого диапазона — ошибка времени выполнения.

Пример:

```idyllium
use audio;
use gui;

audio.Sound click;

void function play_click() {
    click.play();
}

main() {
    click.load_from_file("click.wav");
    click.volume = 0.6;

    gui.Window win;
    win.width = 260;
    win.height = 140;

    gui.Button button;
    button.x = 40;
    button.y = 40;
    button.width = 160;
    button.height = 40;
    button.text = "Сыграть звук";
    button.on_click = play_click;

    win.add_child(button);
    win.show();
}
```

## 27a. Черепашья графика

Импорт:

```idyllium
use turtle;
```

`turtle.Turtle` рисует черепашью графику в духе Logo и Python. Объявление
черепахи автоматически создаёт общее окно 600×600 («Черепашье поле») — НЕ
создавайте `gui.Window` сами. Координаты математические: (0,0) — центр поля,
Y растёт ВВЕРХ, направление 0 указывает на восток, `left()` поворачивает
против часовой стрелки.

```idyllium
use turtle;

main() {
    turtle.Turtle t;
    int i = 0;
    while (i < 4) {
        t.forward(120);
        t.left(90);
        i = i + 1;
    }
}
```

Методы: `forward(px)`, `back(px)`, `left(deg)`, `right(deg)`,
`set_heading(deg)` (поворот к АБСОЛЮТНОМУ углу по кратчайшей дуге),
`goto(x, y)`, `home()`, `pen_up()`, `pen_down()`, `dot(size = 8)`,
`write(text)`, `begin_fill()`, `end_fill()`.

Свойства: `pen_color` и `fill_color` (`colors.Color`), `pen_width`
(целое 1..100, по умолчанию 2), `speed` (целое 0..10; 0 — мгновенно,
по умолчанию 6, движение анимируется), `visible` (bool). Только для чтения:
`x`, `y` (float), `heading` (float, градусы), `is_down` (bool).

Функции модуля (общее поле): `turtle.setup(width, height)`,
`turtle.title(text)`, `turtle.bg_color(color)`, `turtle.clear()`,
`turtle.save_svg(path)`.

Замечания:

- Несколько черепах делят одно поле (отлично для гонок).
- В хосте CLI поле безголовое: окно не появляется, но рисование
  и `turtle.save_svg("картинка.svg")` работают — черепашьи программы могут
  запускаться в консольном курсе.
- Стражи времени выполнения: `Turtle.speed must be between 0 and 10, got 99`;
  `end_fill() without begin_fill()`.

## 28. SQLite

Импорт:

```idyllium
use sqlite;
```

`sqlite.open(path)` открывает существующий файл SQLite или создаёт новый.
Относительные пути отсчитываются от запускаемого файла `.idyl`. Один и тот же
API работает в CLI, в расширении VSIX и в веб-IDE; веб-IDE хранит двоичный
файл `.db` в виртуальном проекте.

Внешние ключи ПРОВЕРЯЮТСЯ с момента открытия базы (Idyllium выполняет
`PRAGMA foreign_keys = ON` за вас — чистая SQLite по историческим причинам
держит проверку выключенной). Вставка строки, чей FOREIGN KEY указывает на
несуществующего родителя, падает с `FOREIGN KEY constraint failed`. Ученик
может выключить и включить проверку сам: `PRAGMA foreign_keys = OFF;` /
`= ON;` — выбор переживает записи на диск.

Полный пример:

```idyllium
use console;
use sqlite;

main() {
    sqlite.Database db = sqlite.open("players.db");
    db.execute(
        "CREATE TABLE IF NOT EXISTS players (" +
        "id INTEGER PRIMARY KEY AUTOINCREMENT, " +
        "name TEXT NOT NULL, level INTEGER NOT NULL)"
    );

    sqlite.Statement insert = db.prepare(
        "INSERT INTO players (name, level) VALUES (:name, :level)"
    );
    insert.bind("name", "Mira");
    insert.bind("level", 7);
    insert.execute();
    insert.close();

    sqlite.Result rows = db.execute(
        "SELECT name, level FROM players ORDER BY id"
    );
    while (rows.next()) {
        console.writeln(
            rows.get_string("name"), ": ", rows.get_int("level")
        );
    }

    rows.close();
    db.close();
}
```

Свойства `sqlite.Database` только для чтения:

```idyllium
path
is_open
in_transaction
```

Состояние, доступное только для чтения, остаётся синтаксисом свойств:
пользуйтесь `db.path`, `db.is_open` и `db.in_transaction`. Не выдумывайте
методов `db.get_path()` и `db.is_open()`.

Методы:

```idyllium
execute(sql)              // ровно одна инструкция SQL -> sqlite.Result
prepare(sql)              // -> sqlite.Statement
exec_script(sql)          // несколько инструкций, возвращённые строки отбрасываются
begin_transaction()
commit()
rollback()
close()
```

Не склеивайте пользовательский ввод с SQL. Пользуйтесь родными параметрами
SQLite `:name`. Метод привязки получает имя без двоеточия:

```idyllium
stmt.bind("name", value)       // обычная форма: класс хранения SQLite выводится
stmt.bind_int("name", value)
stmt.bind_int64("name", value)
stmt.bind_float("name", value)
stmt.bind_string("name", value)
stmt.bind_bool("name", value)
stmt.bind_null("name")
stmt.execute()
stmt.clear_bindings()
stmt.close()
```

Предпочитайте `bind()` для обычных `int`, `float`, `string`, `char`, `bool`,
`null`, целых из `types` и `sqlite.Value`. Типизированные методы остаются
доступными, когда важен точный класс хранения SQLite. Во время выполнения `2`
и `2.0` — одно и то же числовое значение Idyllium, поэтому пользуйтесь
`bind_float("name", 2.0)`, когда SQLite обязан сохранить это как REAL,
а не как INTEGER.

Все объявленные параметры обязаны быть привязаны до `execute()`. Привязки
сохраняются после выполнения, чтобы инструкцию можно было переиспользовать;
вызывайте `clear_bindings()`, прежде чем заполнять независимый новый набор.
Формы `?`, `@name` и `$name` намеренно не поддерживаются первым API SQLite
в Idyllium.

Метаданные `sqlite.Result` только для чтения:

```idyllium
is_open
has_rows             // истинно, только когда вернулась хотя бы одна строка
affected_rows
last_insert_id       // sqlite.Value; null, когда ничего не вставлено
```

`has_rows` истинно, когда результат держит **хотя бы одну строку**, и ложно
и для пустого `SELECT`, и для инструкций, которые строк не возвращают вовсе
(`INSERT`, `UPDATE`, `DELETE` — они отчитываются через `affected_rows`).
Поэтому это прямой ответ на вопрос «нашлось ли что-нибудь», и чтение его
ничего не тратит: строки материализуются при выполнении инструкции, так что
`next()` по-прежнему начинает с первой строки:

```idyllium
    sqlite.Result rows = db.execute("SELECT name FROM players WHERE level >= :min");
    if (rows.has_rows) {
        while (rows.next()) {
            console.writeln(rows.get_string("name"));
        }
    } else {
        console.writeln("никого нет");
    }
```

Методы строк и столбцов:

```idyllium
next()
get(column)          // sqlite.Value
is_null(column)
get_int(column)
get_int64(column)
get_float(column)
get_string(column)
get_bool(column)     // только INTEGER 0 или 1 в SQLite
column_count()
column_name(index)
close()
```

Результат начинается до своей первой строки. Вызывайте `next()` перед любым
геттером. Результаты — буферизованные снимки и могут пережить породившую их
инструкцию.

`sqlite.Value` допускает null и имеет:

```idyllium
is_null()
is_int()
is_float()
is_string()
to_int()
to_int64()
to_float()
to_string()
to_bool()
```

Значения INTEGER в SQLite читаются точно. Для значений за пределами безопасного
диапазона обычного `int` пользуйтесь `get_int64()` и `to_int64()`. У значений
BLOB пока нет отдельного типа в Idyllium. Вложенных транзакций и точек
сохранения в первом API нет.

## 28b. Предупреждения

С релиза предупреждений в Idyllium есть ТРЕТИЙ род сообщений помимо
`compile error` и `runtime error` — предупреждения. Правило, проводящее
границу (вердикт владельца): код, нарушающий конвенцию языка, — **ошибка**;
код, который всего лишь **ничего не делает**, получает **предупреждение**
и всё равно компилируется и выполняется. Предупреждения никогда не меняют
код завершения.

Метки симметричны ошибкам: `compile warning` и `runtime warning`.

Compile-предупреждения (печатаются с `file:line:column`):

```text
compile warning: this line computes a value and does not use it        // a + 1;  "text";  a == 2;
compile warning: assigning a variable to itself changes nothing        // a = a;
compile warning: this line can never run — the function returns above  // код после return (также варианты break/continue)
compile warning: variable 'x' is never used
compile warning: two float numbers are compared with '==' — they are almost never exactly equal
compile warning: comparing a bool with 'true' changes nothing          // flag == true
compile warning: this condition is always true                          // if (true); while (false) говорит "always false"
compile warning: the value returned by 'damage' is not used            // только свои функции/методы
```

Границы охвата — чтобы порождаемые примеры оставались без предупреждений:

- `while (true)` с `break` — канонический вечный цикл, предупреждения нет.
- Результат библиотечного вызова можно свободно выбрасывать
  (`db.execute("INSERT …")`) — о выброшенном результате предупреждают
  только СВОИ функции и методы классов.
- `variable is never used` срабатывает только для переменных примитивных
  типов, чей инициализатор не делает ни вызова, ни индексации:
  `file.ostream f = file.open(…)` или `int x = console.get_int();` не
  предупреждают никогда (инициализатор уже сделал настоящую работу), как и
  объекты, виджеты и массивы (их создание — уже работа).
- Когда в файле есть compile-ОШИБКИ, предупреждения подавляются целиком —
  почините первую ошибку, и предупреждения вернутся.

Runtime-предупреждения печатаются на завершении программы, без file:line:

```text
runtime warning: the program finished without showing a window
runtime warning: a widget ('gui.Button') was created but never added to a window
runtime warning: file 'notes.txt' was not closed
```

Файловое предупреждение — про гигиену: сами данные НА диске. Предупреждения
переключаются `system.set_warnings(false)` / `system.set_warnings(true)`
(по умолчанию включены); выключение гасит только runtime-предупреждения
(compile-предупреждения печатаются до запуска программы).

## 29. Ошибки

### Обработка ошибок времени выполнения через `try`

Ожидаемые ошибки времени выполнения Idyllium обрабатывает конструкцией
`try/catch/finally` уровня оператора. Фигурные скобки обязательны. Допустимые
формы — `try/catch`, `try/finally` и `try/catch/finally`:

```idyllium
try {
    int age = console.get_int();
    console.writeln("Возраст: ", age);
} catch {
    console.writeln("Введите целое число");
}
```

Привязывайте структурированную ошибку только для чтения, когда нужны
подробности:

```idyllium
try {
    float answer = 10 / 0;
} catch (error) {
    console.writeln(error.message);    // только причина
    console.writeln(error.file);       // файл относительно проекта
    console.writeln(error.line);       // строка исходника
    console.writeln(error.to_string()); // полный диагноз
} finally {
    console.writeln("Попытка завершена");
}
```

Переменная `catch` существует только внутри своего блока `catch`. Её выведенный
тип в исходнике не пишется. Сама привязка и свойства `message`, `file` и `line`
доступны только для чтения; `to_string()` возвращает нормализованную строку
вида `main.idyl:7: runtime error: division by zero`.

Ловятся только обычные ошибки времени выполнения Idyllium. В их число входит
предел глубины рекурсии (см. библиотеку `system`). Ошибка компиляции
не даёт программе запуститься, внутренние сбои JavaScript — это дефекты
реализации, `system.exit()` сознательно проходит сквозь `catch` (завершение
программы — собственное решение программы, а не ошибка), и отмена из среды
разработки тоже обязана проходить сквозь `catch`. JavaScript при раскрутке
стека во время отмены всё же заходит в `finally`, но произвольные вызовы
Idyllium после того, как хост остановил программу, не гарантированы.

`try` лексичен. Блок вокруг `win.show()` не поймает ошибку, поднятую будущим
событием GUI или холста; ставьте локальный `try` внутри этого обработчика.
Пользовательского оператора `throw` сейчас нет, как нет и типизированных или
множественных ветвей `catch`.

### Библиотечные свойства только для чтения

Библиотечные объекты могут открывать наблюдаемое состояние свойствами только
для чтения. Читайте их обычным синтаксисом свойств, но никогда в них
не присваивайте:

```idyllium
console.writeln(fout.is_open);
console.writeln(db.path);
console.writeln(picture.width, "x", picture.height);

fout.is_open = true;  // неверно: свойство только для чтения
db.path = "other.db"; // неверно: свойство только для чтения
```

API пользуется методами для действий и запросов, которым нужны аргументы,
и свойствами — для простого состояния объекта, даже когда это состояние
доступно только для чтения.

Предпочитайте примеры, дающие ясные и точные ошибки. Хороший стиль ошибок:

```text
main.idyl:5: runtime error: array index 5 out of bounds (size 3, valid indices 0-2)
main.idyl:7: runtime error: cannot convert input to 'int' (expected integer, got "abc")
main.idyl:10:13: compile error: cannot assign 'string' value to 'int' variable
```

Две формы различаются нарочно: ошибка времени выполнения несёт `file:line`,
а ошибка компиляции несёт ещё и столбец — `main.idyl:5: runtime error: …`
против `main.idyl:5:12: compile error: …`.

Порождая учебные материалы, включайте и то и другое:

- верный код;
- намеренно неверный код с ожидаемым текстом ошибки.

## 30. Так порождать нельзя

Не порождайте:

```idyllium
i++;
i--;
if (a && b) {}
if (!ok) {}
int r = n % 2;            // неверно: оператора % нет; используйте mod(n, 2)
int m = a > b ? a : b;    // неверно: тернарного оператора нет; используйте if/else
switch (x) { ... }        // неверно: switch нет; используйте if / else if
for (item in items) {}    // неверно: for-in нет; обходите по индексу
string s = "ab" * 3;      // неверно: повторения строк нет
char c = 'a' + 'b';       // неверно: char + char это ошибка
string t = "x=" + 5;      // неверно: неявного числа в строку нет; используйте to_string(5)
console.writeln(`x=${x}`); // неверно: шаблонных строк нет
int x = 23 / 10;          // неверно: / всегда возвращает float
label.text = 42;          // неверно: неявного int в string нет
button.onclick = ...;     // неверное написание; используйте on_click
int console = 5;          // неверно: имена библиотек зарезервированы за библиотекой
new Hero();               // неверно: ключевого слова new нет; используйте Hero()
Hero* hero;               // неверно: указателей нет
json.NULL                 // удалено: используйте литерал языка null
progress.fill_color = colors.RED; // удалено: используйте foreground_color
drawable.Font font;       // удалено: используйте fonts.Font
gui.Image picture;        // удалено: используйте gui.ImageBox + image.Image
drawable.Texture texture; // удалено: используйте image.Image с Sprite.set_image()
label.text_color = "#ff0000"; // неверно: используйте colors.HEX("#ff0000")
file.ostream out("x.txt");     // неверно: используйте file.open("x.txt", "write")
out.is_open = true;            // неверно: is_open только для чтения
db.get_path();                 // неверно: читайте свойство db.path
std::cout << "hi";        // неверно: это не C++
Console.WriteLine(...);   // неверно: это не C#
print("hi")               // неверно: это не Python
let x = 10;               // неверно: это не JavaScript
```

Не выдумывайте словарей и отображений, async/await, лямбд со стрелочным
синтаксисом, интерфейсов, обобщений для пользовательских классов,
`throw` и пользовательских исключений, пространств имён, импорта пакетов
и перегрузки операторов, пока текущая спецификация проекта явно их
не добавит.

## 31. Хорошее поведение ИИ в задачах на Idyllium

Когда просят породить код на Idyllium:

1. Для консольного ввода-вывода пишите `use console;`.
2. Для заданий новичкам пользуйтесь `main() { ... }`, если задание явно
   не про функции или про `main` с типом.
3. Отступ — четыре пробела.
4. Пользуйтесь явными преобразованиями `to_int`, `to_float`, `to_string`.
5. Пишите `x = x + 1` вместо `++` (стиль курса; `+= 1` тоже компилируется).
6. Для цветов GUI и холста пользуйтесь объектами `colors.Color`.
7. Для GUI и холста создавайте виджеты и объекты обычными переменными,
   настраивайте свойства, а затем вызывайте `add_child`, `draw` или
   присваивайте обработчики.
8. Для модулей обращайтесь к именам импортированного пользовательского модуля
   через `модуль.имя`.
9. Никогда не переиспользуйте имя модуля стандартной библиотеки (`console`,
   `math`, `gui`, …) для переменной, функции или класса — компилятор это
   отвергает. Имена встроенных функций (`to_string`, `sum`, …) дополнительно
   отвергаются для функций и классов; см. «Зарезервированные имена».
10. В учебных объяснениях предпочитайте маленькие шаги и внятную мотивацию.
11. Если синтаксис под вопросом, так и скажите и попросите спецификацию
    проекта, а не выдумывайте синтаксис.
12. Считайте `BACKLOG.md` и `spec/some_*` проектными обсуждениями,
    а не реализованным синтаксисом, пока пользователь явно не попросит
    обсудить эти замыслы.
