## 0. Что меняется, когда начинается год ООП

Первые два года просили ученика описывать *действия*: сделай это, потом то,
а если нажали кнопку — сделай третье. Год ООП просит описывать *вещи*,
и каждый язык этого сравнения отвечает на три вопроса о вещах по-своему:

1. **Закрыт ли набор свойств вещи?** Если опечатка может изобрести новое
   свойство, то «класс перечисляет, что есть у объекта» — определение
   из урока — в языке, в который ученик печатает, попросту ложно.
2. **Переменная, держащая вещь, — это сама вещь или записка о том, где она?**
   Все языки отвечают «записка» (кроме C++, который отвечает «и то и другое,
   смотря как написано»), и почти никто не говорит этого вслух до того дня,
   когда ученик меняет один объект, а меняются два.
3. **Когда две вещи связаны, что язык делает сам?** Наследование — место
   наибольших расхождений: что наследуется, что затеняется, что диспетчеризуется
   динамически, а что тихо не диспетчеризуется.

Этот же год — тот, в котором собственный код ученика становится тем, что кто-то
другой должен *читать*, поэтому громкость диагностики здесь важнее, чем где бы
то ни было. Тихий неверный ответ в консольном году стоил одного неверного
числа; здесь он стоит неверной картины того, что такое объект, — и эта картина
уезжает с учеником во все языки, которые он встретит потом.

## 1. Как читать разборы

Форма та же, что и во всей серии:

- **Ребёнок пишет** — правдоподобный код новичка.
- **Что делают другие языки** — по строке на язык, с классом поведения:
  - **ТИХО** — неверный или неожиданный результат без диагностики. Опасный
    класс.
  - **ГРОМКО** — отказывается или падает с сообщением.
  - **НЕВНЯТНО** — ошибка есть, но сообщение новичку не расшифровать.
  - **ОК** — ведёт себя так, как ждёт человек.
- **Ответ Idyllium** — с дословным сообщением.

Замечание о справедливости: за четырьмя языками сравнения десятилетия
промышленного применения, и большинство раскритикованных здесь поведений
сознательны. Срезка объектов в C++ — следствие семантики значений, которая
языку нужна; динамические атрибуты Python — та самая возможность, которая
делает Python Python. Вопрос здесь по-прежнему узкий: *что это делает
с тринадцатилетним, который пишет свой четвёртый класс?*

Есть и раздел — §15 — про места, где **тихим оказывается Idyllium**. Их три,
и в одном из них JavaScript справляется лучше.

## 2. Закрыт ли список свойств?

**Ребёнок пишет** имя поля с опечаткой — самый частый промах первого месяца
ООП.

```
c.age = 3;
c.aeg = 4;     // опечатка
```

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК | Поля объявлены в типе; неизвестное — ошибка компиляции. |
| C++ | **ОК, и услужливо** | Проверено: `error: 'struct Cat' has no member named 'aeg'; did you mean 'age'?` — компилятор даже подсказывает нужное имя. |
| Python | **ТИХО** | Проверено: `c.aeg = 4` создаёт **второй атрибут**; у объекта теперь три, а `c.age` по-прежнему хранит старое значение. Никакой диагностики, никогда. |
| JavaScript | **ТИХО** | Проверено: идентично — у объекта молча вырастает третье свойство. |
| **Idyllium** | **ГРОМКО** | `compile error: type 'Pet' has no field 'nmae'` |

Эта строка решает, переживёт ли данное на уроке определение встречу
с клавиатурой. «Класс перечисляет, что есть у его объектов» истинно в Pascal,
C++ и Idyllium и ложно в Python и JavaScript, где класс — это пожелание,
а любой объект в любой момент может отрастить поле.

## 3. `this`: один смысл или несколько

**Ребёнок пишет** метод, пользующийся собственными данными объекта, а потом
передаёт этот метод куда-то ещё — в событие, в обработчик, в таймер.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК | `Self` — это экземпляр, всегда. |
| C++ | ОК | `this` — это экземпляр, всегда; он указатель, что стоит стрелки вместо точки. |
| Python | ОК | `self` — это экземпляр, всегда, ценой написания его в каждой сигнатуре, включая методы, которые им не пользуются. |
| JavaScript | **ТИХО, и это флагман** | Проверено: метод, оторванный от своего объекта (`const f = btn.handler; f();`), видит `this` как `undefined` и читает из него `undefined` — ни исключения, ни сообщения. То же самое происходит с каждым обработчиком, переданным в событие, в таймер или в `map`. Лечения — `bind`, стрелочные функции, `self = this` — приходится преподавать *до* первого класса, реагирующего на клик. |
| **Idyllium** | **ОК** | `this` — это объект, на котором вызвали метод, и ничто этого не меняет |

Проверено на случае, ломающем JavaScript, — обработчик, привязанный
**внутри конструктора**:

```idyllium
        this.plus.on_click = void function() {
            this.value = this.value + 1;
            this.refresh();
        };
```

Обработчик каждого объекта трогает свои собственные поля, хотя написан один
раз. Это тот самый приём, на котором стоит весь год виджетов, — и в JavaScript
это ровно тот приём, который требует сначала прочитать лекцию про `this`.

Забыть `this` — громко, и на один промах приходится **два** сообщения:

```text
compile error: variable 'age' was not declared in this scope
compile error: 'age' was not declared in this scope
```

Одно на запись слева от `=`, одно на чтение справа.

## 4. Конструктор и объект, которого не конструировали

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | **НЕВНЯТНО** | Объявленная объектная переменная равна `nil`, пока не вызван `Create`. Пользование ею даёт `Access violation` — сообщение, которое ребёнку ничего не говорит про конструкторы. |
| C++ | ОК | Объект на стеке конструируется объявлением; неинициализированного состояния, в которое можно провалиться, нет (сырые указатели — другая история, и она вне темы). |
| Python | **почти НЕВНЯТНО** | `__init__` — имя, которое невозможно объяснить в день, когда его впервые пишут. Забытое присваивание атрибута всплывает позже как `AttributeError`. |
| JavaScript | **ОК** | `constructor` — настоящее слово, и **объект не может существовать без него**: `new` обязателен, поэтому состояния «пустой объект» не существует вовсе. Здесь лучше, чем в Idyllium. |
| **Idyllium** | ОК, с пробелом | `constructor Cat(...)`, названный как класс, с умолчаниями и именованными аргументами, — но `Cat blank;` законно и даёт пустой объект |

```idyllium
    Cat barsik = Cat("Барсик", 3);
    Cat murka = Cat("Мурка");                        // аргумент по умолчанию
    Cat hero = Cat(ex_name = "Аранфир", ex_age = 7); // по имени
    Cat blank;                                       // вызова нет — заготовка
```

Заготовка — это не падение (Pascal) и не ошибка (JavaScript): это объект
с пустыми полями, и он молчит, пока их кто-нибудь не прочитает. Курс делает
из этого целый урок — см. §15.

Ошибки в количестве аргументов громкие:
`compile error: 'Truck' expects 0 arguments, got 2`.

## 5. Объект — это ссылка

**Ребёнок пишет** `b = a` для двух объектов и ждёт двух вещей.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | (видно) | Объекты — ссылки, и ритуал с `nil` делает это очевидным рано — по неправильной причине, но очевидным. |
| C++ | **ТИХО, в обе стороны** | `Cat b = a;` **копирует** (и копия по умолчанию поверхностная — проверено: два объекта в итоге делят один указатель). `Cat& b = a;` и `Cat* b = &a;` не копируют. Один язык, две модели, и какая из них сработает, решает символ, которого ученик мог и не набрать. |
| Python | **ТИХО** | Чистая ссылочная семантика, и ни одной диагностики во всей теме. `a is b` существует, но это не тот оператор, к которому кто-то тянется. |
| JavaScript | **ТИХО** | То же самое. |
| **Idyllium** | **Тоже ТИХО — но преподано, а не обнаружено** | Одна модель без исключений; курс отдаёт ей целую книгу до массивов и композиции |

Это строка, где громким не оказывается никто, потому что и не на что быть
громким: `b = a` законно везде. Разница учебная: ловушка либо встречается
случайно (четыре языка), либо открывается сознательно, до уроков, которые
от неё зависят.

```idyllium
    Battery mine = Battery("Мой", 80);
    Battery same = mine;

    same.drain(30);        // изменение: видят оба имени
    same = Battery("Запасной", 100);   // замена: переезжает одно имя
```

В массивах следствие то же правило этажом выше, и это проверено: ячейка —
это имя, а `array<Runner,2> copy = team;` копирует **ячейки** и разделяет
**объекты**.

## 6. Печать объекта

**Ребёнок пишет** `print(cat)` в первый же день, потому что именно так
проверяют, сработало ли хоть что-нибудь.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ГРОМКО | Неявного преобразования нет; вызываешь свой `ToString`. |
| C++ | **ГРОМКО** | Проверено: `error: no match for 'operator<<' (operand types are 'std::ostream' and 'Cat')` — многословно, но отказ есть. |
| Python | **ТИХО** | Проверено: `<__main__.Cat object at 0x76b537ab8860>` — шестнадцатеричный адрес, поданный так, будто это ответ. |
| JavaScript | **ТИХО** | Проверено: `[object Object]`, и из `String(c)`, и из шаблонной строки. Самая осмеянная строка языка — и именно её выдаёт первый `console.log` объекта у новичка. |
| **Idyllium** | **ГРОМКО, с лечением в сообщении** | см. ниже |

```text
compile error: cannot print object of class 'Pet' directly — declare 'contract string function
to_string()' in class 'Pet' and printing will use it
```

Объявив контракт, получаешь работающую печать сразу везде — в том числе
внутри массивов (проверено: `["кот Барсик", "кот Барсик"]`).

## 7. Сравнение двух объектов

**Ребёнок пишет** `a == b` для двух котов с одинаковым именем.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | (редко) | Перегрузка операторов в FPC есть, но для классов используется редко; сравнение пишут руками. |
| C++ | **ГРОМКО** | Проверено: `error: no match for 'operator==' (operand types are 'Cat' and 'Cat')`. |
| Python | **ТИХО** | Проверено: без `__eq__` `a == b` даёт **`False`** для двух одинаковых котов — сравнение тождества в одежде сравнения по значению. Без всякой диагностики. |
| JavaScript | **ТИХО, и навсегда** | Проверено: и `a == b`, и `a === b` дают `false`, а **определить сравнение невозможно** — перегрузки операторов в языке нет. |
| **Idyllium** | **ГРОМКО, с лечением в сообщении** | см. ниже |

```text
compile error: cannot compare objects of class 'Battery' with '==' — declare
'contract bool function equals(Battery other)' in class 'Battery' and the comparison will use it
```

Одно объявление обслуживает сразу `==`, `!=`, `contains()` и поиск по массиву
(проверено). А контракты **не наследуются**: потомок обязан объявить свой,
потому что унаследованный `equals(Cat)` сравнивал бы котят по их кошачьей
половине и молча игнорировал всё, что потомок добавил:

```text
compile error: cannot compare objects of class 'Kitten' with '==' — declare
'contract bool function equals(Kitten other)' in class 'Kitten' and the comparison will use it
```

## 8. Наследование: что достаётся потомку и что он затеняет

**Ребёнок пишет** потомка с полем, имя которого уже занято родителем, —
обычно случайно, копируя объявление родителя.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | **ТИХО** | Поле потомка затеняет родительское; в объекте существуют оба. |
| C++ | **ТИХО** | То же: два члена с одним именем, доступные как `Base::x` и `x`. Половина программы может писать в одно, а читать другое. |
| Python | **ТИХО** | Пространство имён у экземпляра одно, поэтому присваивание потомка просто перезаписывает — родительское значение исчезает бесследно. |
| JavaScript | **ТИХО** | Как в Python. |
| **Idyllium** | **ГРОМКО** | `compile error: class 'Truck' already has member 'wheels'` |

Это одно из немногих мест, где Idyllium строже всех четырёх, и причину стоит
проговорить ученику: класс с двумя полями одного имени — это класс, в котором
вопрос «чему равно `wheels`» некорректен.

Всё остальное в наследовании ничем не примечательно и одинаково везде: поля
и методы передаются вниз, `extends` читается как «является», а до
унаследованных членов потомок дотягивается через `this`, как до своих.

Конструкторы **не** наследуются:
`compile error: 'Truck' expects 0 arguments, got 2`.

## 9. Вызов родительского конструктора

**Ребёнок пишет** конструктор потомка и забывает про родителя — или ставит
вызов не туда.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | почти ОК | `inherited Create(...)`; если забыть, родительская половина молча остаётся ненастроенной. |
| C++ | **ОК** | Базовый конструктор выполняется, **написали вы его или нет**: база с конструктором по умолчанию конструируется автоматически, а база без него — ошибка компиляции. Состояния «забыл» не существует. |
| Python | **ТИХО** | Проверено: `Child.__init__` без `super().__init__()` даёт объект с атрибутами потомка и без единого родительского; `ch.plate` поднимет `AttributeError` позже и где-то в другом месте. |
| JavaScript | **ГРОМКО** | Проверено: `ReferenceError: Must call super constructor in derived class before accessing 'this'…` — **JavaScript это ловит, а Idyllium нет.** |
| **Idyllium** | **ТИХО, сознательно** | три молчаливых исхода, см. ниже |

Проверены все три:

| что делает ученик | что происходит |
|---|---|
| `parent()` пропущен | родительская половина остаётся пустой — `: колёс 0` |
| `parent()` вызван дважды | побеждает второй вызов |
| **`parent()` вызван последним** | собственная работа потомка **молча затирается** |

Интересен третий: потомок ставит `this.wheels = 10;`, потом вызывает
`parent(plate, 6)` и заканчивает с шестью колёсами. Ничего не сказано, потому
что `parent()` заполняет те же поля и выполнился позже.

Это сознательная позиция языка — порядок операторов в конструкторе дело
автора, а не компилятора, — и курс отвечает на неё тем, что заставляет ученика
поставить все три опыта руками, а не прочитать о них. Но зона тишины здесь
настоящая, на первом из трёх случаев JavaScript справляется лучше, и §15
об этом говорит.

## 10. Переопределение: сигнатура, диспетчеризация и срезка

**Ребёнок пишет** семейство фигур, у каждой свой `area()`, кладёт их в один
массив и идёт циклом.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | почти ОК | Нужны `virtual`/`override`; компилятор предупреждает, когда `override` пропущен. |
| C++ | **ТИХО, дважды и катастрофически** | Проверено и то и другое. **(1)** Метод без `virtual` диспетчеризуется статически: `Shape* p = &rect; p->area()` возвращает **родительский** `0`, а не `12`. **(2) Срезка:** `Shape s = rect;` копирует только родительскую половину — проверено, `s.varea()` возвращает `0`, хотя поля скопировались нормально. Пол-объекта, и никакой диагностики. |
| Python | **ТИХО** | Проверено: потомок может переопределить метод с **другим числом параметров**, и класс принимается; отказ приходит при вызове как `TypeError: B.hi() missing 1 required positional argument`. |
| JavaScript | **ТИХО** | Проверено: то же переопределение, и оно даже при вызове не падает — недоданный аргумент это `undefined`, и метод выполняется. |
| **Idyllium** | **ГРОМКО про сигнатуру, ОК про диспетчеризацию, срезки нет** | см. ниже |

```text
compile error: method 'B.hi' must match inherited method signature
```

Диспетчеризация динамическая без всяких ключевых слов — ни `virtual`,
ни `override`, — и проверена на всём, что теме нужно:

```idyllium
    array<Shape, 3> shapes;
    shapes[0] = Rect(3.0, 4.0);
    shapes[1] = Circle(2.0);
    for (int i = 0; i < shapes.length; i = i + 1) { shapes[i].show(); }
```

```text
прямоугольник: 12
круг: 12.56
```

Родительский `show()` вызывает `area()` потомка (шаблонный метод), фабрика,
объявленная как `Shape function make(int)`, возвращает потомков,
`dyn_array<Shape>` работает, а `type_name()` сообщает настоящий класс.

**Срезки не существует.** Проверено: `B`, переданный в
`void function show(A x)`, печатает `B / B`; уложенный в `array<A,1>`,
он по-прежнему `B`. Объекты — ссылки, поэтому отказ в стиле C++ здесь
невозможен.

Через имя родительского типа видны только родительские члены, и это громко:
`compile error: type 'Shape' has no method 'diagonal'`.

## 11. Инкапсуляция: что на самом деле закрывает `private`

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК, со сноской | `private` настоящий, но в режиме FPC по умолчанию он виден в пределах всего **модуля**, а не только класса; то, о чём говорит урок, называется `strict private`. |
| C++ | **ОК** | `private` и `protected` настоящие и проверяются при компиляции. Лучшее из четырёх. |
| Python | **ТИХО** | Проверено: `self.__money` не спрятан, а лишь переименован — `x._Acc__money` читает его обратно, а одиночное подчёркивание чистая условность. Управления доступом в языке нет. |
| JavaScript | ОК, недавно | Проверено: `#money` действительно недоступен (даже упоминание снаружи — `SyntaxError`), тогда как `_soft` — условность, которую любой прочитает. Настоящая приватность есть, но только с ES2022. |
| **Idyllium** | **ОК, одно правило, без сносок** | см. ниже |

```text
compile error: member 'Account.money' is private and can only be used inside class 'Account'
compile error: member 'Account.secret' is private and can only be used inside class 'Account'
```

Поля и методы закрыты одним правилом и одним сообщением. А на вопрос, который
стоит задать любому языку, — **держит ли замок против потомков?** — здесь есть
проверенный ответ: да. `class Child extends Account`, чей метод читает
`this.money`, не компилируется, с тем же сообщением. `private` означает
«внутри этого класса», без исключений для родни.

Цена названа в §15: `protected` нет.

## 12. Статические члены

**Ребёнок пишет** счётчик созданных объектов.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК | `class var` и `class function`; читаемо. |
| C++ | ОК, с церемонией | `static`-членам нужно отдельное определение вне класса (до C++17), и это классический камень преткновения темы. |
| Python | **ТИХО** | Проверено: атрибут класса, прочитанный **через экземпляр**, работает и возвращает число, так что привычка складывается, — а потом `a.population = 99` создаёт атрибут *экземпляра*, затеняющий классовый. Проверено: классовый счётчик остаётся 2, тогда как `a` читает 99, а `b` читает 2. Ни слова. Объявление — `@staticmethod`, декоратор, который приходится принимать на веру. |
| JavaScript | **ТИХО** | Проверено: `static population`, прочитанный через **экземпляр**, даёт `undefined` — не ошибка, просто дыра там, где должно быть число. |
| **Idyllium** | **ГРОМКО, три разных правила** | см. ниже |

```text
compile error: static field 'Cat.population' must be accessed through class 'Cat'
compile error: 'this' cannot be used in a static method
compile error: static field 'Cat.population' is not inherited — write 'Cat.population'
```

Обратить внимание стоит на третье сообщение. В Python и JavaScript статика
**наследуется** (проверено: `Kid.population` читает родительский счётчик),
а в C++ статика потомка — буквально та же переменная: проверено,
`&Base::population == &Kid::population`, и запись через потомка меняет
родительскую. Звучит удобно ровно до момента, когда два класса делят счётчик,
которым не владеет ни один. Idyllium отказывает и тут же называет правильное
написание.

Константы класса существуют и годятся туда, где требуется константа, —
проверено, `array<int, Cat.MAX_KITTENS>` даёт длину 6.

## 13. События, которые класс объявляет сам

**Ребёнок пишет** класс, который должен сообщить внешнему миру, что
что-то произошло, — конец арки «пользователь → автор», которую весь год
виджетов и выстраивал.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК, многословно | Свойства типа `TNotifyEvent` в стиле Lazarus: процедурный тип, поле, свойство — четыре строки на событие. |
| C++ | (только фреймворк) | В чистом C++ событий нет; члены типа `std::function` собираются вручную. Сигналы и слоты Qt отличны, но требуют `Q_OBJECT`, препроцессора moc и базы `QObject`. |
| Python | **отсутствует** | Механизма событий нет, и такого слова в языке нет; приём — вручную поддерживаемый список обработчиков (`self._handlers.append(fn)`) или сторонняя библиотека. |
| JavaScript | ОК, но расколото | `EventTarget`/`CustomEvent` в браузере, `EventEmitter` в Node — два разных механизма, и код между ними не переезжает. Свои события к тому же делят одно пространство имён с событиями DOM. |
| **Idyllium** | **ОК, одно слово** | см. ниже |

```idyllium
class Door {
    event on_opened;
    event on_sound(string text);

    void function open() {
        this.is_open = true;
        this.on_opened();
        this.on_sound("скрип");
    }
}
```

Подписка — то же присваивание, которое ученик пишет весь год для `on_click`.
Слово объявления — то же, которое он весь год *читал*. А поджечь событие
снаружи не дают:

```text
compile error: event 'on_opened' can only be fired inside class 'Door' (through 'this')
```

Слушать может кто угодно; объявлять — только сам объект. Инкапсуляция событий
получается из устройства, а не из дисциплины.

## 15. Честный остаток: чего ООП в Idyllium не ловит

1. **Три опыта с `parent()` молчаливы** (§9). Пропущен, удвоен или поставлен
   последним — язык не говорит ничего, а в третьем случае *затирается
   собственная работа потомка*. Это сознательная позиция: порядок операторов
   в конструкторе принадлежит автору. Но это единственная тема года, где
   тихую неправильность оставили нарочно, и на первом из трёх случаев
   **JavaScript справляется лучше**: он не даёт трогать `this` до `super()`.
   Учебный материал обязан прогнать все три опыта руками; никогда
   не подавайте «`parent()` первым» как правило стиля, не показав, что делают
   два других порядка.
2. **Абстрактного метода нет.** Родительский метод, который *обязан* быть
   переопределён, пишется заглушкой, возвращающей затычку, а забытое
   переопределение даёт молчаливый ноль вместо отказа. В C++ есть `= 0`,
   в Python `@abstractmethod`, в Pascal `abstract`. Это самая крупная
   настоящая дыра года.
3. **Объект можно объявить без конструктора.** `Cat blank;` законно и даёт
   пустые поля; неправильность всплывает там, где эти поля читают, — возможно,
   далеко. JavaScript запрещает это прямо, требуя `new`. Курс превращает это
   в урок (та самая «заготовка» и следующая из неё строка чек-листа), а не
   делает вид, что такого не бывает.
4. **`private` есть, `protected` нет.** Замок простой и держит против
   потомков — правильное умолчание, — но идиому «открыто для родни, закрыто
   для чужих» выразить нельзя.
5. **`main()` в импортируемом файле молча пропускается**, а запуск файла-модуля
   без `main()` ничего не печатает и ни о чём не сообщает. Названо в книге
   курса про разбиение по файлам; зона тишины сохраняется.
6. **Смысловые ошибки не затронуты, как и везде.** Класс, моделирующий
   не то; `extends` там, где имелась в виду композиция (`class Engine extends
   Car` компилируется и работает); метод, который обновляет одно поле
   и забывает парное, — ни один компилятор этого не видит. Курс отвечает
   проверкой фразой «является / имеет» и детективным жанром; см.
   `idyllium-course-ai-reference.md`.

## 16. Правила для ИИ, пользующегося этим файлом

1. **Объявляйте каждое поле.** Никогда не порождайте код, рассчитывающий,
   что поле возникнет при присваивании: здесь это ошибка компиляции,
   а привычка приходит из Python и JavaScript.
2. **Всегда `this.` для собственных членов объекта** внутри методов. Неявного
   поиска нет, а диагностика за забытое `this` приходит дважды.
3. **`parent()` первым, всегда** (§9), а объясняя почему, показывайте третий
   опыт, а не утверждайте правило.
4. **Не порождайте `virtual`, `override`, `super`, `self`, `__init__`,
   `@staticmethod`, `#private` или `Q_OBJECT`.** Переопределение — это
   совпадение имени и сигнатуры; родительский конструктор — `parent(...)`;
   статика — `static`; приватность — секция `private:`.
5. **Объявляйте контракты, когда тип печатают или сравнивают** —
   `to_string()`, `equals()`, а когда объекты упорядочивают или сортируют —
   пару порядка `less()`/`greater()`, — и помните, что они **не наследуются**:
   потомку, который печатается или сравнивается, нужен свой.
6. **Обращайтесь к статике через класс**, никогда через экземпляр, и не ждите,
   что потомок её унаследует.
7. **Не имитируйте абстрактные классы комментариями.** Если родительский метод
   обязан быть переопределён, скажите это прозой и сделайте затычку явно
   неправильной (а не правдоподобным нулём) — язык этого не потребует
   (§15.2).
8. **Предпочитайте композицию и говорите почему.** Проговаривайте
   в объяснении проверку фразой: «грузовик является транспортом» работает,
   «машина является двигателем» — нет. Компилятор принимает оба варианта.
9. **Когда ученик приходит из другого языка, называйте конкретную ловушку**
   из §14, из которой выросла его привычка: «в Python твоя опечатка сделала
   второе поле, и никто ничего не сказал; здесь это ошибка компиляции» учит
   больше, чем «Idyllium строже». Пришедшим из JavaScript первыми называйте
   `this` в оторванном обработчике (§3) и `[object Object]` (§6); пришедшим
   из C++ — срезку и пропущенный `virtual` (§10).
10. **Не обещайте отловов из §15.**

## 17. Происхождение сведений

Каталог поведения языков собран из классных наблюдений на курсах Pascal, C++,
Python и JavaScript для детей 10–15 лет, накопленных до появления Idyllium
и организованных вокруг тех же пяти проектных критериев, что и вся серия.
**Три из четырёх колонок сравнения проверены прогоном** — g++ 13
(`-std=c++17`), CPython 3.12, Node 22, — и всякое значение, помеченное словом
«проверено», это снятый вывод, включая срезку и статическую диспетчеризацию
в C++, переименованную, а не спрятанную приватность и молчаливое создание
атрибутов в Python, оторванный `this`, `[object Object]` и молча принятое
переопределение в JavaScript. Колонка Pascal документарная, и прежде чем
цитировать её как факт, стоит перепроверить на сборке Free Pascal.

Колонка Idyllium — не мнение: каждое сообщение и каждое значение получены
прогоном пробной программы через текущий компилятор, включая набор проб
по полиморфизму (массивы родительского типа, шаблонный метод, фабрика),
по инкапсуляции (поля, методы, потомки), по контрактам (`to_string`, `equals`,
массивы, `contains`), по правилам статики и по механизму своих событий. Когда
язык меняется, этот файл должен перепроверяться тем же способом.
