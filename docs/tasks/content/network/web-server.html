Блок 1. Здравствуй, мир, я сервер

Практика с преподавателем

Задание 1. Первый сервер класса

У доски (VS Code или консоль — Web IDE сегодня отдыхает, и класс знает почему). Собираем первый сервер урока: маршрут /hello, run(), банер «Сервер слушает http://127.0.0.1:8080». Момент истины: рядом открывается обычный браузер, в адресную строку — адрес из консоли, на экране — ответ программы. Проговорите три вещи. Первая: программа не завершилась — run() вечный, как окно; остановка — Stop. Вторая: обработчик — это on_click, у которого событие называется «пришёл запрос». Третья: браузер — тоже клиент, как http.get из прошлых уроков, просто с красивым экраном.

Самостоятельная практика

Задание 2. Сайт-визитка

Сервер с тремя маршрутами: / — главная с HTML-заголовком и вашим именем, /hobby — страница про увлечение, /motto — девиз. На главной — HTML-ссылки на остальные страницы (<a href="/hobby">…</a>): по сайту можно ходить кликами, как по настоящему. Потому что он настоящий.

Задание 3. Обход своего сервера

Не закрывая сервер из з.2, сходите по всем трём адресам и одному несуществующему (/ghost — традиция!). Браузер покажет not found: '/ghost' — этот 404 отправила ваша программа, сама, вы её этому не учили. Проговорка в тетрадь: в прошлом уроке вы 404 читали, сегодня — отправляете. Обе стороны кода 404 — ваши.

Блок 2. Экспертиза

Задание 4. Спор за путь

Зарегистрируйте /hello дважды с разными обработчиками: web.Server.on_get() route '/hello' is already registered. Сервер отказался ещё на регистрации, не дожидаясь запросов, — почему это добрее, чем молча выбрать один из двух обработчиков? (Вспомните: молчаливый выбор — это ошибка, которую ищут неделями.)

Задание 5. Спор за порт

Запустите свой сервер. А теперь — второй раз, не останавливая первый: web.Server.run() port 8080 is already in use — choose another port or stop the other program. Порт — как парковочное место: двоим не встать. Почините двумя способами по очереди: остановив первый сервер и сменив порт второму (app.port = 8081;) — и убедитесь, что два сервера на разных портах живут одновременно.

Задание 6. Не тем глаголом

На GET-маршрут /hello отправьте POST клиентом из прошлого урока: 405 method not allowed. Помните витрину раздатки, отвечавшую 405 на ваш http.post? Теперь так же ответил ваш сервер — круг замкнулся. Заодно проверьте обратное: GET на POST-маршрут.

Задание 7. Сервер-репетиция

Откройте сервер из з.1 в Web IDE и запустите. Настоящий порт браузеру слушать запрещено (то самое правило безопасности, что и CORS, только с другой стороны — обсудите: почему хорошо, что случайная страница интернета не может поднять сервер на вашем компьютере?), поэтому консоль печатает адрес сервера-репетиции вида …/preview/8080/. Пройдите по нему и проверьте свои маршруты — ответы те же, что были в VS Code. Потом контрольный эксперимент: продиктуйте этот адрес соседу — у него НЕ откроется. Репетиция живёт внутри вашего браузера и видна только вам; нажмите Stop и убедитесь, что даже у вас страница честно скажет, что сервер остановлен. Вывод в тетрадь: код один и тот же, а вот сцена разная — репетиция в Web IDE, настоящее выступление в VS Code или консоли.

Блок 3. Запросы с вопросами

Задание 8. Приветствие по имени

Маршрут /greet с параметром: ?name=Мира → «Привет, Мира!», без параметра — вежливая подсказка «добавьте ?name=… к адресу». Проверьте прямо из адресной строки браузера — и кириллицей тоже (браузер сам закодирует адрес, сервер сам раскодирует — обратите внимание, что вам для этого не пришлось делать ничего).

Задание 9. Калькулятор в адресной строке

Маршрут /add?a=2&b=3 → «2 + 3 = 5». Параметры приходят строками — конвертация ваша (to_int, багаж). Не числа в параметрах? Статус 400 и внятное сообщение — сервер, как и консольная программа, обязан переживать кривый ввод. Расширение для беглых: /multiply, /divide (деление на ноль — 400, а не крах: вы теперь знаете, что крах обработчика превратится в 500 — но 400 с человеческим текстом лучше).

Задание 10. Таблица умножения напрокат

Маршрут /table?n=7 отдаёт HTML-страницу с таблицей умножения на 7 (цикл строит строки — багаж второй недели курса, а результат открывается браузером). Оформите заголовком и жирными произведениями. Одна функция — бесконечно много страниц: почувствуйте разницу со статикой.

Блок 4. Свой API

Практика с преподавателем

Задание 11. Гильдия онлайн

У доски. Файл guild.json из раздатки кладётся рядом с сервером, маршрут /api/guild читает его файлом и отдаёт через send_json. А затем — коронный номер: клиент из прошлого урока запускается второй программой и делает http.get("http://127.0.0.1:8080/api/guild") → разбирает JSON → печатает героев. Проговорите медленно, это кульминация раздела: та же самая клиентская программа, что ходила на сайт раздатки, теперь ходит на сервер, написанный вами; «раздатка-API» и «мой API» — одна механика. Сервер и клиент — обе роли ваши.

Самостоятельная практика

Задание 12. API с фильтром

Расширьте гильдию: /api/guild?min_level=10 отдаёт только героев с уровнем не ниже порога (фильтрация массива — багаж JSON-книг). Без параметра — всех. Проверьте и браузером (JSON виден текстом), и клиентом. Вы только что сделали то, что делают все настоящие API мира: параметры запроса управляют данными ответа.

Минутка из внешнего мира. Сервер с табличкой «не выключать»

Самый первый веб-сервер человечества стоял в 1990 году на рабочем столе Тима Бернерса-Ли в ЦЕРНе — обычный компьютер NeXT. На корпусе была приклеена рукописная табличка: «This machine is a server. DO NOT POWER IT DOWN!!» — потому что случайно выключить весь World Wide Web мог любой уборщик. Ваш сервер сегодня — прямой родственник того компьютера: та же idea, тот же протокол, тот же вечный run(). Разница лишь в том, что когда его выключаете вы — интернет переживёт.

Блок 5. Сервер принимает

Задание 13. Гостевая книга

Двухмаршрутный сервер с памятью: on_post("/sign") добавляет тело письма в динамический массив записей (статус 201), on_get("/book") отдаёт HTML-страницу со всеми записями по порядку. Подписывайтесь клиентом (http.post), читайте браузером. Обратите внимание на новость: записи живут между запросами — сервер, в отличие от ваших прежних программ, работает долго и помнит. А после Stop? Проверьте — и вспомните файлы: постоянная память — ваша забота (для беглых: сохраняйте записи в файл).

Задание 14. Счётчик посещений

Классика первых серверов: маршрут / отвечает «Вы посетитель № N» — и N растёт с каждым запросом. Обновляйте страницу и смотрите, как сервер считает. Вопрос со звёздочкой в уме: если страницу откроют двое — счётчик у них общий или у каждого свой? Проверьте вторым браузером или клиентом и объясните почему (подсказка: переменная живёт в сервере, а не в посетителе).

Задание 16 ⭐. Гильдия онлайн, полная сборка

Один сервер, всё вместе: статика (страница-витрина гильдии из папки), /api/guild с фильтром из з.12, /api/status (число героев и «аптайм» через счётчик запросов), гостевая книга для пожеланий героям. Маршруты и статика в одном сервере уживаются — проверьте порядок (кто отвечает на «/»?). Это уже архитектура настоящего сайта: витрина + API + приём данных.

Задание 17 ⭐⭐. Сервер для всего класса

Финал раздела — сценарий «сервер у одного, клиенты у всех» (по согласованию с преподавателем и только в классной сети). Один ученик добавляет своему серверу строку app.host = "0.0.0.0"; — сервер честно объявит в консоли, что теперь виден всей локальной сети, — и говорит соседям свой IP-адрес. Остальные ходят клиентами: http.get("http://АДРЕС:8080/api/guild"). Впервые в курсе две разные машины разговаривают вашим кодом. Обязательная беседа после: почему 127.0.0.1 — правильный дефолт, что именно открывает 0.0.0.0, и почему такие решения принимают явно, строкой в коде, а не случайно.
