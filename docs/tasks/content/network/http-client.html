Блок 1. Первый звонок

Практика с преподавателем

Задание 1. Программа выходит в интернет

У доски — первый запрос урока: http.get на https://aumphaadr.github.io/Idyllium/handouts/files/guild.json, печать status и ok. Момент истины дня: между запуском и цифрой «200» программа успела добежать до настоящего сервера и вернуться. Проговорите три вещи. Первая: адрес — тот самый guild.json из раздатки, который вы читали файлом в разделе JSON, — раздатка живёт на настоящем веб-сервере, и теперь она ваш личный API. Вторая: http.Response — конверт: status, ok, text, header(). Третья: один запрос — один ответ; сервер первым не звонит.

Самостоятельная практика

Задание 2. Эхо-разведка

Программа-разведчик про guild.json: напечатать статус, ok, заголовок content-type и длину текста (r.text.length). Сверьте длину с размером файла из раздатки — байт в байт. Бонус-наблюдение: напечатайте r.header("CONTENT-TYPE") большими буквами — регистр имени заголовка не важен, это в конверте так задумано.

Задание 3. Гильдия из-за океана

Полный конвейер урока: http.get → проверка ok → json.parse(r.text).to_array() → таблица «Мира (маг), уровень 12, монет: 1250» по всем пятерым. Это программа из раздела JSON, у которой заменили одну строку — чтение файла на запрос. Всё остальное — нетронутый багаж.

Задание 4. Богатейший герой сети

По той же гильдии из сети найти самого богатого героя (максимум по coins — алгоритм с самого первого курса) и напечатать «Богаче всех: Ника (3100 монет)». Данные приехали за тысячи километров, а максимум ищется той же парой строк, что и всегда, — доставка и обработка друг про друга не знают.

Блок 2. Экспертиза: дозвонился или нет

Задание 5. Сетевой призрак

Спросите у сервера ghost.json — файл, которого в раздатке никогда не было: статус 404, ok = false, программа жива. Допишите вежливую реакцию: если ok — печатаем данные, иначе — «Сервер ответил: 404, такого файла нет». Проговорка в тетрадь: 404 — это ответ. Сервер снял трубку и честно сказал «нет» — падать тут не из-за чего.

Задание 6. Опечатка в имени сайта

А теперь испортите само имя сайта: https://aumphaadr.github.iio/... (лишняя буква). Запустите: runtime error: http.get() cannot reach ... host not found — программа упала, потому что отвечать было некому: ни статуса, ни текста, ни конверта. Прочитайте сообщение до конца — причина названа прямо. Сравните с з.5 и запишите правило блока: статус — читаем, недозвон — ловим.

Задание 7. Судья происшествий

Бумажная разминка — для каждого происшествия скажите, ответ это (какой статус?) или недозвон (какая ошибка?): 1) в адресе опечатка в имени файла; 2) в адресе опечатка в имени сайта; 3) выключили вайфай и запустили программу; 4) сервер существует, но файл переехал; 5) сервер завис и молчит минуту. Подсказка к пятому: у терпения программы есть предел, и он настраивается. Ответы проверьте запусками там, где это возможно без порчи чужого имущества.

Задание 8. Страховка на недозвон

Оберните программу из з.6 в try/catch: вместо падения — человеческое «До сервера не дозвонились — проверьте адрес и интернет». Убедитесь, что на правильном адресе страховка не мешает: try просто пропускает счастливый путь сквозь себя.

Блок 3. Сеть ИЛИ файл

Практика с преподавателем

Задание 9. Выживальщик

У доски — главная программа урока для школьной жизни. Рядом с программой лежит локальная копия guild.json (раздатка). Логика: try — запрос в сеть, данные из r.text; catch — чтение той же гильдии файлом. Дальше — единый разбор JSON и таблица героев, которой всё равно, откуда пришла строка. Продемонстрируйте оба пути: с интернетом и без (выключите вайфай — на глазах у класса!). Проговорите: данные одни, разбор один, меняется только доставка — и у хорошей программы доставок две.

Самостоятельная практика

Задание 10. Табличка с источником

Доработайте выживальщика: первой строкой вывода — «Источник: сеть» или «Источник: локальная копия». Пользователь имеет право знать, свежие у него данные или запасные. Приём из взрослых программ: почта пишет «нет соединения, показаны сохранённые письма» — вы сейчас сделали ровно это.

Задание 11. Разведка соперников

В раздатке рядом с нашей гильдией живёт rival_guild.json — забрать его по сети (адрес стройте по образцу: та же папка handouts/files/). Внутри — только массив имён: соперники скрывают уровни! Напечатайте «У соперников N бойцов: ...» и сравните с нашей пятёркой: «нас больше» / «их больше» / «поровну». Два запроса в одной программе — совершенно нормальная жизнь сетевого кода.

Задание 12. Досье по кусочкам

Личные дела героев лежат отдельными файлами: hero_1.json … hero_5.json. Соберите досье циклом: пять запросов, из каждого — имя и уровень. Адрес стройте склейкой строк: "...files/hero_" + to_string(i) + ".json". И — сетевая вежливость из урока: между запросами поставьте time.sleep(0.3). К своей раздатке можно и без пауз, но привычка стучаться с передышкой должна стоять раньше, чем вы пойдёте к чужим серверам.

Минутка из внешнего мира. Комната 404

Красивая легенда гласит: в ЦЕРНе, где родился веб, стоял сервер в комнате 404, и когда файла не находилось, писали «room 404: not found». Легенда — выдумка (сотрудники ЦЕРНа сами её опровергали), а правда скучнее и умнее: коды придумали заранее, сериями. Единицы — «подожди», двухсотые — «успех», трёхсотые — «переехало», четырёхсотые — «ошибся ты», пятисотые — «сломался я». Инженеры проектировали язык для машин — а получили культурный феномен: «404» печатают на футболках и говорят про потерявшихся людей. Ваша программа сегодня научилась читать этот язык.

Блок 4. Настройки и границы

Задание 13. Предел терпения

Три опыта с http.set_timeout. Первый: поставьте 30 и убедитесь, что на живой раздатке ничего не изменилось — таймаут не замедляет быстрые ответы, он страхует от молчунов. Второй: попробуйте http.set_timeout(0) — прочитайте отказ: границы 1–300 проверяются сразу, не дожидаясь запроса. Третий — устный: почему вечное ожидание хуже ошибки? (Подсказка: что видит пользователь программы, которая «просто ждёт»?)

Задание 14. Витрина не принимает посылок

Отправьте на адрес гильдии http.post(адрес, "привет от класса") и напечатайте статус: 405 — «метод не разрешён». Витрина раздатки только выдаёт — и это снова ответ, а не крах: правило «статус читаем» покрывает и отказы. Проговорка на будущее: post заживёт по-настоящему, когда на том конце появится сервер, готовый принимать, — и в будущих разделах этим сервером станет ваша собственная программа.

Блок 5. Полигон

Задание 15. Сетевая сводка гильдии

Соберите всё в одну программу-отчёт: данные — сеть с фоллбэком на файл (з.9) и табличкой источника (з.10); отчёт — число героев, средний уровень (дробный!), богатейший герой, сумма казны. Проверьте оба пути запуска. Это готовый шаблон половины взрослых программ: «достань данные откуда получится — посчитай — отчитайся».

Задание 16 ⭐. Монитор доступности

Программа-сторож проверяет список адресов: гильдия, ghost.json, сайт с опечаткой. Для каждого — одна строка отчёта: «адрес — доступен (200)» / «отвечает, но: 404» / «недоступен: host not found». Три исхода — три ветки: ok, не-ok, catch (текст ошибки — error.message из багажа try/catch). Так работают настоящие мониторинги, которые будят админов по ночам, — у вас консольный младший брат.

Задание 17 ⭐⭐. Курьер с тремя попытками

Сеть моргает: недозвон — не приговор, а повод попробовать снова. Напишите функцию, которая пытается забрать адрес до трёх раз: недозвон — сообщение «попытка N не удалась», time.sleep(1.0), снова; успех — вернуть текст; три провала — честно сдаться с итоговым сообщением. Проверьте на живом адресе (успех с первой) и на опечатке (три попытки и капитуляция). Приём называется retry, и на нём держится надёжность всего сетевого мира: у вас в руках взрослый инструмент, соберите его аккуратно.
