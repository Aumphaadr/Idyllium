Блок 1. Первый чертёж

Практика с преподавателем

Задание 1. Приют открывается

Первый класс — у доски:

Проговорите, тыкая в строки: класс Pet описан один раз — питомцев три, и каждый хранит свои значения (Кеша не станет котом от соседства с Барсиком). Объект объявляется как обычная переменная — Pet first; читается так же, как int x;: тип, потом имя. Точка — дверь в отделение коробки: first.name — «у первого — кличка». И два оргмомента на весь раздел: имя класса — с большой буквы; точка с запятой после } класса не ставится.

Самостоятельная практика

Задание 2. Новая графа

В приют пришла проверка: в анкете не хватает окраса. Добавьте в класс Pet одно поле string color; — и почувствуйте следствие: у всех трёх питомцев немедленно появилось это отделение, заполните его каждому и допечатайте в вывод. Одна строка в чертеже — новая графа у каждого изделия; при этом заполнять графу по-прежнему нужно каждому отдельно (запомните это неудобство — к уроку о конструкторах оно созреет).

Задание 3. Книжная полка

Первый класс без подсказок, по образцу з.1: класс Book с полями «название», «автор», «страницы» — придумайте сами, какие типы. Четыре книги на полке (реальные или выдуманные), у каждой — печатная карточка вида «"Название" — Автор, N страниц». Приёмка: запуск и четыре карточки; в классе — большая буква, после класса — никакой точки с запятой.

Задание 4. Болванка с завода

Эксперимент-паспорт. Создайте Pet blank; и, ничего не заполняя, напечатайте все его поля (строки — в квадратных скобках, чтобы увидеть пустоту). Сначала предскажите: что там, мусор или ошибка? Ответ рантайма: пустые строки и ноль — свежий объект приходит с «заготовками», как болванка с завода: отделения есть, содержимого нет. Это не ошибка, но и не подарок: программа с незаполненным котом печатает « (, 0 г.)» — молча и некрасиво.

Блок 2. Чертёжная экспертиза

Блок коротких разборов: пять программ — пять способов подумать о классе неправильно. Каждая задача — на пять минут, но именно они экономят месяцы.

Задание 5. Кот целиком не лезет

Попробуйте напечатать объект одной командой: console.writeln(cat);. Компилятор: cannot print object of class 'Pet' directly. Переведите вслух: Idyllium не знает, как показать кота целиком — печатать кличку? возраст? рисовать усы? Печатайте поля по отдельности — а красивое решение этой неприятности (метод-визитка) появится через два урока, и вы его оцените.

Задание 6. Жильцы класса, жильцы main

Сортировка без компьютера. Ниже — девять строк будущей программы вперемешку; разложите их в два столбца: «живёт в теле класса» и «живёт в main»:

int age; — first.age = 4; — string name; — console.writeln(first.name); — Pet first; — string kind; — first.name = "Мурка"; — console.writeln("Приют открыт"); — first.kind = "кошка";

Правило сортировки одно: в теле класса живут только объявления полей — «из чего состоит». Все действия — создание, заполнение, печать — живут в main. Разложили — соберите программу и запустите: сортировка сдана, когда компилятор молчит.

Задание 7. Лавина

Программист перепутал столбцы из з.6 и положил печать прямо в тело класса:

Скомпилируйте и не пугайтесь: на одну строчку — лавина сообщений unexpected token ... in class body. Компилятор растерялся и ругается на каждое слово по отдельности. Приём на всю жизнь: лавину не читают целиком — читают первое сообщение и смотрят на его строку. in class body — «в теле класса» — вот и диагноз: в чертёж попала команда. Перенесите печать в main (после заполнения!) — лавина исчезнет вся разом.

Задание 8. Где живёт кличка

Три программы, отличающиеся одной строкой. Класс Pet с полем name, объект cat с кличкой «Барсик» — а печатаем тремя способами: console.writeln(name);, console.writeln(Pet.name);, console.writeln(cat.name);. Предскажите судьбу каждой, потом проверьте все три. Итог эксперимента: голое имя → 'name' was not declared in this scope — и это сообщение не врёт: в main действительно нет переменной name, поле — не переменная; через класс → instance field 'Pet.name' must be accessed through an object — у чертежа нет клички; и только через объект — «Барсик». Правило-лекарство курсивом в тетрадь: поле живёт только внутри объекта. Нет объекта — нет поля.

Задание 9. Один чертёж или десять?

Чужая программа: class hero1 { ... }, class hero2 { ... } — на каждого героя свой класс с готовыми значениями внутри. Автор уверен, что так и надо. Скомпилируйте: instance field 'hero1.name' must be accessed through an object — компилятор требует объект, а объектов в программе ноль. Почините по-настоящему: один класс Hero, четыре объекта (добавьте двух от себя). Контрольный вопрос на сдаче — тот самый: сколько классов понадобится программе с десятью героями? (Правильный ответ по-прежнему «один», и если рука дрогнула — перечитайте таблицу «чертёж/парковка» из урока.)

Блок 3. Поля в работе

Задание 10. День рождения

Три питомца с кличками и возрастами, вывод всей троицы. Затем у одного — день рождения: busya.age += 1; — и вывод троицы снова. Поле объекта — обычная переменная со всеми правами: += работает, остальные не стареют. Обе картины — «до» и «после» — входят в сдачу.

Задание 11. Распродажа

Класс Product (название, цена), четыре товара на витрине. Объявляется распродажа: всё дешевле на 20 монет. Уценка — четыре присваивания -= 20, по одному на товар, и новый прайс на печать. Сдайте — и посчитайте вместе: на уценку четырёх товаров ушло четыре строки. А тридцати? Запомните это ощущение и не чините его сейчас — в уроке о массивах объектов эти тридцать строк сожмутся в три.

Задание 12. Дуэль

Два бойца (класс Fighter: имя, сила) — законная пара, дуэль всё-таки. Программа печатает визитки и объявляет победителя сравнением полей: if (bear.power > wolf.power). Не забудьте третью ветку — ничью (проверяется на равных силах: поменяйте числа и покажите все три исхода на приёмке). Сравниваются поля — числа, как весь первый курс; сравнивать самих бойцов (bear > wolf) не пытайтесь, боец — не число.

Задание 13. Случайные новобранцы

В гарнизон прибыло пополнение: три новобранца (класс Recruit: имя, сила, удача), и все поля — случайные: имя — random.choose_from из массива строк на шесть имён (массивы строк — старый консольный друг, ему можно), сила и удача — random.create_int(1, 10). Каждый запуск — новый гарнизон. Бонус-наблюдение: имена могут повториться (два Горазда — бывает), а вот статы у тёзок всё равно свои — почему?

Задание 14. Ревизия копилок

Четыре копилки (класс Piggy: владелец, монеты — подберите суммы так, чтобы делились на четыре). Программа считает: общий капитал (сумма четырёх полей), среднее по палате — и находит богача цепочкой if с парой переменных-рекордов (richest/record — приём «поиск максимума» из консольного курса, теперь по полям объектов). Вывод: капитал, среднее, «Богаче всех Вика: 210».

Задание 15. Пара не пара [кандидат]

Носки существуют парами, но живут поодиночке. Класс Sock: цвет, размер, bool has_hole;. После стирки из машинки достали четыре носка — заполните их так: два синих 38-го (один с дыркой), красный 38-го, синий 41-го. Программа ищет пару первому носку: три проверки if с двумя условиями через and — пара это совпадение и цвета, и размера («Первый и второй — пара!» / «...не пара.»). Дырка на парность не влияет — но пусть будет в анкете: жизнь есть жизнь. Вопрос на сдаче: почему проверка одного цвета — недостаточна?

Задание 16. Перекупщик [кандидат]

Премиум-скин на пушку — цифровая вещь с биографией. Класс WeaponSkin: узор, владелец, число перепродаж, износ (float!). Скин «Драконий пламень» стартует у игрока «Стример_2013» с износом 0.05 — и дважды перепродаётся: каждый раз владелец меняется, resales += 1, вторая продажа добавляет 0.1 износа. После каждой сделки — строка-сводка («Продан! Теперь у xX_Тень_Xx (перепродаж: 1)»). Поля меняются — история накапливается: у вещи появилась судьба, хотя методов у неё ещё нет.

Задание 17. Лутбокс [кандидат]

Класс LootDrop: предмет, редкость (строка), сила. Дроп собирается случайно: предмет — choose_from из пяти, затем бросок random.create_int(1, 100) решает редкость диапазонами: до 60 — «обычный» (сила 1–10), до 90 — «редкий» (11–30), выше — «ЛЕГЕНДАРНЫЙ» (31–99). Легендарка печатается в рамке из знаков «=» (две строки до и после — if по редкости). Сделайте три дропа и запускайте, пока не выпадет легендарка, — заодно почувствуете, что такое «шанс один к десяти». Разговор после сдачи обязателен: ровно так игры и заставляют открывать «ещё один сундучок».

Минутка из внешнего мира. Слово из Норвегии

Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.

Слово «класс» пришло в программирование из науки: биологи со времён Линнея раскладывают всё живое по классам, а «классификация» — это буквально «раскладывание по полочкам». В код это слово принесли в 1967 году два норвежца — Оле-Йохан Даль и Кристен Нюгор, создатели языка Simula. Язык придумывался для симуляций: чтобы смоделировать порт, нужно много одинаково устроенных кораблей, причалов и кранов — и авторы дали программистам «чертёж», по которому штампуются объекты. Идея оказалась настолько удачной, что её унаследовали почти все большие языки — C++, Java, Python… и Idyllium. Так что, объявляя класс Pet, вы пользуетесь изобретением, которому скоро шестьдесят — а оно не постарело ни на день.

Задание 21. Хайп-машина [кандидат]

Задание 22. Ночь тамагочи [кандидат]

Задание 25 ⭐⭐. Генератор миров

Сдача: два запуска — шесть разных миров, и хотя бы один с кольцами (перезапускайте, пока вселенная не расщедрится).
