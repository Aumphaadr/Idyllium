Блок 2. Экспертиза

Задание 5. Дуэль тёзок

Испытание абзаца урока: что будет, если перепутать? string s = player.to_json(); → компилятор: ваш to_json возвращает json.Object, не строку! А json.Object o = saved.to_json(); → встроенный возвращает строку, не объект! Оба письма — про типы, оба ловятся до запуска. Правило в тетрадь: ваш to_json — до коробки, встроенный — до строки; в файл едет строка, значит цепочка: свой → встроенный (player.to_json().to_json() — легально и даже красиво, но лучше через переменную — читаемость!).

Задание 6. Сейв из прошлого

old_hero_save.json — Слава сохранился старой версией игры: ключа coins нет. Наивный from_json падает: json object has no key 'coins'. Лечение — вежливый from_json: has-сторож (№8!) — есть ключ → читаем, нет → значение по умолчанию (this.coins = 0; — новичку по старым правилам!). Прогоните на старом и новом сейвах — оба живы. Правило индустрии: загрузчик обязан переживать старые сейвы — игроки не прощают потерянного прогресса.

Задание 7. Грязный сейв

Сейв, где level — строкой «девять» (соберите такой файл руками — вы умеете!): from_json падает письмом типов. Бронирование: is_int() перед чтением (№3 з.7!) — не число → умолчание и предупреждение в консоль («сейв повреждён, уровень сброшен»). Вежливость + броня = валидирующий from_json: три уровня зрелости загрузчика (наивный → вежливый → бронированный) — запишите лесенку, она пригодится в полигоне.

Задание 8. Два пути рождения

Детектор архитектуры: у героя теперь два способа появиться — конструктор (новая игра: параметры с клавиатуры/дефолты) и пустой + from_json (загрузка: биография из файла). Постройте класс с обоими путями и программу с веткой: «сейв найден? (file.exists!) → загрузка : новая игра». Вопрос детектора: почему бы не сделать конструктор, читающий файл? (Можно — но конструктор, лезущий в файловую систему, — тугой узел: рождение и загрузка — разные заботы; урок недаром разделил.) Ветка «продолжить/новая игра» — теперь и в ваших программах, как во всех играх мира.

Задание 12. Версия сейва

Три ветки судьбы файла — миграции №5 и валидация №8 поселились внутри класса, где им и место.

Минутка из внешнего мира. Слово, которое вы уже умеете

Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.

То, что вы делаете двумя методами, взрослый мир зовёт сериализацией (превратить живой объект в последовательность байтов или текст) и десериализацией (оживить обратно). Слово громкое, а суть — ваши to_json и from_json. На сериализации стоит больше, чем кажется: облачные сейвы (герой засыпает на вашем телефоне, а просыпается на компьютере — между устройствами летит его JSON), автосохранения каждые полминуты, синхронизация настроек браузера, даже «отправить персонажа другу» — всё это чьи-то to_json и from_json, гоняющие объекты через файлы и сети. И индустриальная боль тоже ваша, из з.6: миллионы игроков хранят сейвы старых версий, и каждый патч обязан их пережить — поэтому в каждом серьёзном from_json мира сидят has-сторожа и версии. Вы сегодня написали не учебный приём — вы написали ремесло.

Это настоящая игра с настоящей памятью — покажите её дома: пусть кто-то из родителей пройдёт пару ходов, а вы объясните, где он спит в файле.
