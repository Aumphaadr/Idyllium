## 0. Что меняется, когда начинается год JSON

До этого момента всякое значение, с которым имел дело ученик, **рождалось
внутри программы**: переменная объявлялась с типом, у массива была длина,
класс перечислял свои поля. Компилятор видел всё.

JSON это ломает. Текст приходит из файла, который ученик правил руками,
от одноклассника, из ответа сервера — и его форма *неизвестна в момент
компиляции*. Впервые ученик пишет код, правильность которого зависит от
данных, которых ещё нет.

Именно эта перемена делает тему опасной. Каждая конструкция здесь обязана
отвечать на один и тот же вопрос: **что происходит, когда данные не такие,
как предполагал код?** Возможных ответов ровно три, и приемлемы только два:

1. **Сказать об этом в момент несовпадения**, назвав ключ или индекс
   и ожидавшийся тип.
2. **Отказаться до начала работы** — проверка годности, которую ученик
   запускает нарочно.
3. Вернуть что-нибудь правдоподобное и промолчать.

Третьему ответу и посвящён этот документ. Он же в двух из трёх экосистем
сравнения — *поведение по умолчанию*.

Вторая перемена важна для русскоязычного класса: **файл сейва читает ребёнок.**
Не сервер, не библиотека, а двенадцатилетний, который открывает его
в текстовом редакторе, чтобы посмотреть, сделала ли программа то, что он имел
в виду. Формат, который пишет `{"\u0438\u043c\u044f": "\u0410\u043d\u044f"}`
там, где ребёнок написал `имя`, свою работу провалил, как бы он ни соответствовал
стандарту.

## 1. Как читать разборы

Форма та же, что в частях 1–4:

- **Ребёнок пишет** — правдоподобный код новичка.
- **Что делает остальной инструментарий** — по строке на экосистему,
  с классом поведения:
  - **ТИХО** — неверный или неожиданный результат без диагностики. Опасный
    класс.
  - **ГРОМКО** — отказывается или падает с сообщением.
  - **НЕВНЯТНО** — ошибка есть, но сообщение новичку не расшифровать.
  - **ОК** — ведёт себя так, как ждёт человек.
- **Ответ Idyllium** — с дословным сообщением.

Замечание о справедливости: nlohmann/json, `json` и `JSON` отлично делают то,
для чего созданы, — перевозят данные между программами, написанными
профессионалами. Почти каждое раскритикованное ниже поведение в этом контексте
осознанный и защитимый выбор. Здесь вопрос уже: *что это делает
с двенадцатилетним, у которого в файле сейва одна неверная строка?*

## 2. Разбор текста, который не является корректным JSON

**Ребёнок пишет** файл сейва руками и оставляет висящую запятую, или
комментарий, или забывает запятую между двумя строками.

```json
{
  "name": "Аня",
  "age": 12
  "city": "Тюмень"
}
```

| Экосистема | Поведение | Подробности |
|---|---|---|
| C++ (nlohmann) | ГРОМКО | Бросает `json::parse_error`, в тексте которого названы строка, столбец и то, чего ждал разборщик. Сообщение хорошее — но это *исключение*, а значит, чтобы его увидеть, ученик уже должен знать `try`/`catch`; непойманное доходит до консоли как `terminate called after throwing an instance of …`. |
| Python | ГРОМКО | `json.JSONDecodeError: Expecting ',' delimiter: line 4 column 3 (char 30)` — точно и с позицией. |
| JavaScript | ГРОМКО | Современный V8: `SyntaxError: Expected ',' or '}' after property value in JSON at position 13 (line 3 column 3)`. Тоже хорошо. Старые движки сообщали только позицию в байтах. |
| **Idyllium** | **ГРОМКО** | `runtime error: json.parse() invalid JSON: expected ',' or '}' after object value at line 4, column 3` |

Это единственная тема, где все четверо в одном классе, и об этом стоит сказать
прямо: разборщики JSON как семейство ведут себя на кривом вводе хорошо.
Расхождения начинаются *после* того, как текст разобрался.

Две особенности Idyllium, которые стоит преподать:

```idyllium
json.is_valid(text)     // true/false — спросить до разбора, исключения не нужны
json.parse(text)        // разбирает или останавливает программу сообщением выше
```

`is_valid` существует, чтобы программа первого года с JSON могла проверить
файл, который правил ребёнок, не встречаясь сперва с исключениями. Строгость
соответствует настоящему стандарту JSON, проверено пробами:

```idyllium
json.is_valid("{\"a\":1}")     // true
json.is_valid("{\"a\":1,}")    // false — висящая запятая
json.is_valid("{'a':1}")       // false — одинарные кавычки
json.is_valid("{\"a\": +5}")   // false — ведущий плюс
json.is_valid("{\"a\": 01}")   // false — ведущий ноль
json.is_valid("{\"a\": .5}")   // false — голая дробная часть
json.is_valid("{\"a\": NaN}")  // false — NaN это не JSON
json.is_valid("{\"a\":1} tail")// false — мусор в хвосте
json.is_valid("")              // false
json.is_valid("  {\"a\":1}  ") // true — пробелы вокруг допустимы
```

Обратите внимание на две последние строки в сравнении с Python: `json.loads`
`NaN` и `Infinity` на входе *принимает*, потому что и сам их выдаёт (§6).
Idyllium отказывает в обе стороны, поэтому файл, написанный программой
на Idyllium, всегда читается любым другим инструментом JSON в мире.

## 3. Отсутствующий ключ — флагманское расхождение

**Ребёнок пишет** чтение файла сейва, а файл на одну версию старше: в нём есть
`name`, но ещё нет `level`.

```idyllium
    int level = root.get("level").to_int();
```

| Экосистема | Поведение | Подробности |
|---|---|---|
| C++ (nlohmann) | **ТИХО** | `j["level"]` на неконстантном объекте **молча вставляет null-член** и возвращает его — чтение *меняет документ*, а `get<int>()` на свежем null потом бросает где-то в другом месте. Безопасная форма `j.at("level")` бросает `json::out_of_range` с именем ключа, но первым во всех руководствах показывают `operator[]`. |
| Python | ГРОМКО | `d["level"]` поднимает `KeyError: 'level'`. Но `d.get("level")` возвращает `None` без всякой диагностики, а `.get` широко преподают как «безопасную» форму, после чего `None` едет дальше, пока не встретит оператор, который его отвергнет. |
| JavaScript | **ТИХО** | `obj.level` — это `undefined`. Не сообщается ничего. Программа продолжает; ошибка всплывает позже и в другом месте: `TypeError: Cannot read properties of undefined (reading 'name')` — с указанием на невиновный код далеко от пропавшего ключа. |
| **Idyllium** | **ГРОМКО** | `runtime error: json object has no key 'level'` — в той строке, которая его и спросила. |

Именно из-за этого пункта тема JSON вообще попала в этот документ. В JS отчёт
приходит по неверному адресу; в C++ чтение молча *меняет документ, который вы
читали*; в Python громкая форма есть, но «безопасная» альтернатива тихо
неправа. У Idyllium одно поведение, и сообщение называет ключ.

Задуманный способ обращения с действительно необязательным полем — сначала
спросить, той же формой, которую ученик уже знает по массивам:

```idyllium
    int level = 1;
    if (root.has("level")) {
        level = root.get("level").to_int();
    }
```

`has()` — это вопрос с ответом «да/нет», а не поиск, возвращающий загадочное
отсутствующее значение. Ни `undefined`, ни `None` в языке нет, и протечь
в арифметику позже нечему.

## 4. Неверный тип

**Ребёнок пишет** `to_int()` для поля, которое в файле записано строкой, —
`"age": "12"` вместо `"age": 12`, ровно то, что происходит, когда данные пришли
из формы или из выгрузки таблицы.

| Экосистема | Поведение | Подробности |
|---|---|---|
| C++ (nlohmann) | ГРОМКО / **ТИХО** | `get<int>()` на строке бросает `json::type_error` с указанием и требуемого, и настоящего типа. Но `get<int>()` на числе `3.5` **молча отбрасывает дробь и даёт 3** — числовые преобразования внутри `get` разрешены. |
| Python | **ТИХО** | Значения приходят родными типами Python, поэтому `d["age"]` — это строка `"12"`. `int("12")` тихо срабатывает: строка и число становятся взаимозаменяемыми — ровно та путаница, которую консольный год месяцами разбирал. `int(3.5)` тихо даёт `3`. Отказ всплывает, только если строка не числовая, и тогда — `ValueError` где-то далеко. |
| JavaScript | **ТИХО** | `obj.age + 1` на `"12"` даёт `"121"`. Самая цитируемая бородавка JS, до которой здесь доводят совершенно обычные данные. Побитовая идиома `3.5 \| 0` тихо даёт `3`. |
| **Idyllium** | **ГРОМКО** | `runtime error: json value is string, expected int` — а для дробного числа `runtime error: json value is number, expected int` |

Оба сообщения называют **что там лежит** и **что спросили**. Ни одно
не преобразует. Обратите особое внимание на второе: `to_int()` от `3.5`
отвергается, а не усекается, — то же правило, которое язык применяет везде:
`int r = 37 / 10;` это ошибка компиляции, а `div(37, 10)` — именованная
операция, означающая «остаток выбрасываем нарочно».

Предикаты типа делают проверку явной, когда данные и правда неопределённы:

```idyllium
    json.Value v = root.get("age");
    if (v.is_int()) { ... } else if (v.is_string()) { ... }
```

Проверенная пробами семантика, которую стоит знать точно: в JSON числовой тип
один, поэтому `is_int()` отвечает на вопрос *«это число целое?»* — истина
для `5` и для `5.0`, ложь для `3.5`, — а `is_float()` отвечает
на вопрос *«это вообще число?»*, истина для всех трёх. `is_string()`,
`is_bool()`, `is_null()`, `is_object()` и `is_array()` точны.

## 5. Числа: что переживает круговой рейс

**Ребёнок пишет** программу, хранящую идентификатор — длинное число
из настоящей системы, номер телефона, код счёта.

```json
{"id": 12345678901234567890}
```

| Экосистема | Поведение | Подробности |
|---|---|---|
| C++ (nlohmann) | ОК / ТИХО | Целые лексемы хранятся как `int64`/`uint64` и переживают рейс точно внутри этого диапазона. За его пределами значение молча становится `double` и теряет цифры. |
| Python | ОК | Целые произвольной точности; `12345678901234567890` возвращается точно (проверено). |
| JavaScript | **ТИХО** | Все числа — IEEE-двойные. Проверено: `12345678901234567890` становится `12345678901234567000`, а `9007199254740993` становится `9007199254740992`. Никакого предупреждения. Половина цифр идентификатора может измениться между чтением файла и записью его обратно. |
| **Idyllium** | **ОК** | Целые лексемы разбираются точно и сериализуются точно, без верхнего предела. |

Проверено от начала до конца:

```idyllium
    json.Object o;
    o.add("id", json.Value(123456789012345678901234567890));
    console.writeln(o.to_json());
    // {"id":123456789012345678901234567890}
    console.writeln(json.parse(o.to_json()).to_object().get("id").to_int());
    // 123456789012345678901234567890
```

Это не возможность JSON — это следствие того, что `int` в языке точен при
любом размере. `to_int64()` и `to_uint64()` есть для программ, которым нужно
уживаться с системами фиксированной ширины и нужен контроль диапазона.

Обратная опасность — **утечка нечисловых значений в файл JSON** — закрыта
в корне:

| Экосистема | `NaN` / `Infinity` на выходе | Следствие |
|---|---|---|
| C++ (nlohmann) | пишется как `null` | число молча превращается в отсутствие |
| Python | пишется как `NaN` / `Infinity` (проверено: `{"x": NaN, "y": Infinity}`) | **порождает текст, который не является JSON**; любой строгий разборщик такой файл отвергнет |
| JavaScript | пишется как `null` (проверено) | то же молчаливое отсутствие, что и в C++ |
| **Idyllium** | возникнуть не может | `1.0 / 0.0` — это `runtime error: division by zero`; значение просто не существует, чтобы его записать |

## 6. Создать ключ и обновить ключ

Пункт, у которого нет аналога в трёх остальных экосистемах.

**Ребёнок пишет** сборщик файла сейва и, правя позже, добавляет один и тот же
ключ дважды — или хочет обновить значение, но опечатывается в ключе.

| Экосистема | Поведение | Подробности |
|---|---|---|
| C++ (nlohmann) | ТИХО | `j["hp"] = 100;` создаёт или перезаписывает; обе операции — одни и те же значки. Опечатка в ключе молча создаёт второй член, а исходный сохраняет старое значение. |
| Python | ТИХО | `d["hp"] = 100` — ровно та же ситуация. `d["hpp"] = 100` добавляет второй ключ, без диагностики. |
| JavaScript | ТИХО | `obj.hp = 100` — то же самое, плюс вариант с опечаткой `obj.hpp = 100`, который тоже молча срабатывает. |
| **Idyllium** | **ГРОМКО в обе стороны** | `add` требует, чтобы ключ был **новым**; `set` требует, чтобы он **существовал** |

```idyllium
    json.Object hero;
    hero.add("hp", json.Value(1000));
    hero.add("hp", json.Value(500));
    // runtime error: json object already has key 'hp'

    hero.set("hpp", json.Value(500));
    // runtime error: json object has no key 'hpp'

    hero.remove("nope");
    // runtime error: json object has no key 'nope'
```

Устройство прямо продолжает первое большое различение консольного года:
`int a = 20;` объявляет, `a = 60;` присваивает, а перепутать их — ошибка,
а не молча заведённая вторая переменная. Объект JSON — та же идея этажом
выше: **создание ключа и изменение ключа это разные действия, и код говорит,
какое вы имели в виду.** Ключ с опечаткой не может тихо стать новым полем,
а это самый частый способ, которым файл сейва обрастает мусором.

## 7. Повторяющиеся ключи во входящем тексте

**Ребёнок получает** файл, где ключ встречается дважды, — обычно потому, что
правил его руками и скопировал строку.

```json
{"a": 1, "a": 2}
```

| Экосистема | Поведение |
|---|---|
| C++ (nlohmann) | ТИХО — побеждает последний |
| Python | ТИХО — побеждает последний (проверено: `{'a': 2}`) |
| JavaScript | ТИХО — побеждает последний (проверено: `{"a":2}`) |
| **Idyllium** | **ТИХО — побеждает последний** (проверено: `{"a":2}`, `length` равна 1) |

Сообщается честно: на *входе* Idyllium ведёт себя ровно как остальные,
и продублированный ключ в правленном руками файле исчезает без единого слова.
Почему этот случай не закрыли и что с ним делает курс — см. §14.

Асимметрия при этом сознательная, и её стоит проговорить ученику: **язык
не даст вашей программе создать дубликат ключа (§6), но не может отменить тот,
что пришёл в тексте.** Чтение снисходительно, потому что стандарт считает
такой текст корректным; запись строга, потому что там у вас ещё есть выбор.

## 8. Массивы и индексы

**Ребёнок пишет** цикл по списку очков и заходит на одну позицию за конец.

| Экосистема | Поведение | Подробности |
|---|---|---|
| C++ (nlohmann) | **ТИХО / неопределённое поведение** | `j[5]` на массиве из трёх **расширяет массив до шести** значениями null и возвращает новый элемент. `j.at(5)` бросает `json::out_of_range` с индексом. Тот же раскол `operator[]` против `at()`, что и у объектов, и более опасный член снова короче. |
| Python | ГРОМКО | `IndexError: list index out of range`. |
| JavaScript | **ТИХО** | `arr[5]` — это `undefined`; ошибка приходит позже, в другом месте и другими словами. |
| **Idyllium** | **ГРОМКО** | `runtime error: json array index 5 out of bounds (size 3, valid indices 0-2)` |

Сообщение называет и размер, и допустимый диапазон, совпадая с собственным
сообщением языка про массивы из консольного года, — ученик читает фразу,
которую уже встречал.

Методы `json.Array`, все проверены пробами: `at`, `set`, `add`, `insert`,
`pop`, `remove`, `clear` плюс свойство `length` только для чтения. У `set`
и `insert` та же проверка диапазона, что и у `at`.

## 9. Сборка JSON: что можно завернуть

**Ребёнок пишет** процедуру сохранения и отдаёт сериализатору весь игровой
объект целиком.

| Экосистема | Поведение | Подробности |
|---|---|---|
| C++ (nlohmann) | ГРОМКО | Свой тип без крючка `to_json` не компилируется — шаблонная ошибка обычно в десятки строк, с типами, о которых ученик никогда не слышал. Громко, но по форме НЕВНЯТНО. |
| Python | ГРОМКО | `TypeError: Object of type Player is not JSON serializable` (проверено) — ясно. Обычный обходной приём из интернета — `json.dumps(obj.__dict__)`, который **молча выгружает все атрибуты**, включая задуманные внутренними (проверено: `_secret` вылез наружу). |
| JavaScript | **ТИХО** | `JSON.stringify(player)` срабатывает и выгружает все собственные перечислимые свойства — проверено: `{"name":"Мира","level":7,"_secret":"токен"}`. Методы исчезают. `JSON.parse` возвращает **простой объект, а не экземпляр**: проверено, `back instanceof Player` даёт `false`, а `back.greet()` поднимает `TypeError: back.greet is not a function`. И ни на одном шаге этого пути не сказано ни слова. |
| **Idyllium** | **ГРОМКО, на этапе компиляции** | `compile error: json.Value() cannot wrap an object of class 'Hero' — build a json.Object from its fields instead` |

Сообщение Idyllium отказывает *до запуска программы* и, необычно для отказа,
говорит, что делать вместо. Курс преподаёт явную пару:

```idyllium
class Player {
public:
    string name;
    int level;

    json.Object function to_json() {
        json.Object obj;
        obj.add("name", json.Value(this.name));
        obj.add("level", json.Value(this.level));
        return obj;
    }

    void function from_json(json.Object obj) {
        this.name = obj.get("name").to_string();
        this.level = obj.get("level").to_int();
    }
}
```

Две строки на поле, написанные руками, — и в этом весь смысл. Ученик видит,
что формат файла это **решение**, а не автоматическая тень класса:
переименуйте поле — и прошлонедельные сейвы всё равно загрузятся, потому что
соответствие видно и его можно править. Путь JS учит противоположному, и учит
невидимо: класс исчезает в дороге, а объект, который приезжает обратно, только
*похож* на тот, что уезжал.

## 10. Сериализация: что пропадает на выходе

**Ребёнок пишет** объект со значением, которому в JSON нет соответствия.

| Случай | C++ (nlohmann) | Python | JavaScript | Idyllium |
|---|---|---|---|---|
| `undefined` или отсутствующее значение в объекте | неприменимо | неприменимо | **молча выброшено** (проверено: `{a:1, b:undefined}` → `{"a":1}`) | такого значения не существует |
| `undefined` или функция внутри массива | неприменимо | неприменимо | **молча становится `null`** (проверено: `[undefined, fn]` → `[null,null]`) | такого значения не существует |
| функция или метод | ошибка компиляции | `TypeError` | **молча выброшено** | такого значения не существует |
| `NaN` / `Infinity` | `null` | `NaN` / `Infinity` — некорректный JSON | `null` | возникнуть не может (§5) |
| нестроковый ключ | неприменимо (ключи строки) | **молча приводится к строке**; проверено: `{1: "a", "1": "b"}` → `{"1": "a", "1": "b"}` — **дубликат ключа в выводе** | неприменимо (ключи строки) | ключи строки по типу |
| значение даты и времени | вручную | `TypeError` | **молча становится строкой** (проверено: `"1970-01-01T00:00:00.000Z"`) и остаётся строкой после `JSON.parse` | вручную, по замыслу |
| не-ASCII текст | как написано | **по умолчанию экранируется** (проверено: `{"имя": "Аня"}` → `{"\u0438\u043c\u044f": "\u0410\u043d\u044f"}`) | как написано | как написано (проверено: `{"name":"Аранфир"}`) |

Последняя строка мала инженерно и велика для класса. Файл сейва, который
ребёнок не может прочитать, — чёрный ящик; файл, который он открывает, находит
в нём своё имя, правит и перезагружает, — *учебный инструмент*. Idyllium
пишет текст UTF-8 текстом, и в `to_json()`, и в `to_pretty_json()`.

Экранирование символов, которым оно действительно нужно, точное и переживает
круговой рейс (проверено): `"он сказал \"привет\""`, `"C:\\путь\\файл"`,
`"две\nстроки"`, `"а\tб"` возвращаются побайтово теми же,
а `\u041f\u0440\u0438\u0432\u0435\u0442` во входящем файле раскодируется
в `Привет`.

## 11. Два документа, которые выглядят одинаково

**Ребёнок пишет** проверку: изменился ли файл сейва с прошлого раза?

| Экосистема | Поведение | Подробности |
|---|---|---|
| C++ (nlohmann) | ОК | `operator==` сравнивает по содержимому; порядок ключей не важен. |
| Python | ОК | `dict == dict` сравнивает по содержимому (проверено: `{"x":1,"y":2} == {"y":2,"x":1}` даёт `True`). |
| JavaScript | **ТИХО** | `JSON.parse(a) === JSON.parse(b)` **всегда `false`** — сравнение ссылок (проверено). Обычный обходной приём `JSON.stringify(a) === JSON.stringify(b)` тоже даёт `false`, если ключи идут в другом порядке (проверено). Оба ответа выглядят сравнением данных и им не являются. |
| **Idyllium** | **ОК** | `==` для `json.Value` сравнивает по содержимому; порядок ключей не важен (проверено: два документа с одинаковыми парами в разном порядке равны) |

`value == null` и `value.is_null()` оба годятся как проверка; учебные
материалы предпочитают `is_null()`, потому что он читается вопросом.

## 12. Контейнеры — ссылки, и это единообразно

Проверенное пробами поведение, названное потому, что это единственное место,
где ученик может удивиться *без* диагностики:

```idyllium
    json.Array arr;
    arr.add(json.Value(1));

    json.Object o;
    o.add("list", json.Value(arr));

    arr.add(json.Value(2));              // меняем arr ПОСЛЕ вложения
    console.writeln(o.to_json());        // {"list":[1,2]}  — документ тоже изменился

    json.Value got = o.get("list");
    json.Array inner = got.to_array();
    inner.add(json.Value(3));
    console.writeln(o.to_json());        // {"list":[1,2,3]} — вытаскивание не копирует
```

`json.Object` и `json.Array` — ссылочные типы, как любой другой библиотечный
объект языка и как собственные объекты классов ученика. Заворачивание
не копирует, извлечение не копирует, второе имя — это второе имя.

Python и JavaScript ведут себя здесь идентично (`dict`/`list` и объекты
с массивами — ссылки). Особняком стоит nlohmann/json: `json` — это **тип-значение**,
поэтому `auto inner = j["list"];` берёт копию, и правки в неё до документа
не доходят: зеркальный сюрприз, столь же молчаливый, — и потому код на C++
пишет `auto&`, а новички забывают амперсанд.

Ответ Idyllium не «ссылки лучше», а «**одно правило везде**»: ученик выучил
его для объектов классов в году ООП, и оно не изменилось, когда тип пришёл
из библиотеки.

## 13. Файл сейва от начала до конца

Вся тема существует ради одной формы программы, и стоит показать, чего эта
форма стоит в каждой экосистеме. Idyllium, проверено:

```idyllium
use console;
use file;
use json;

main() {
    json.Object save;
    save.add("player", json.Value("Аня"));
    save.add("level", json.Value(7));

    file.ostream fout = file.open("save.json", "write");
    fout.write(save.to_pretty_json());
    fout.close();

    file.istream fin = file.open("save.json", "read");
    string text = fin.read_all();
    fin.close();

    json.Object back = json.parse(text).to_object();
    console.writeln(back.get("player").to_string(), " уровень ", back.get("level").to_int());
}
```

Файл на диске, проверено:

```json
{
  "player": "Аня",
  "level": 7
}
```

Ничего JSON-специфически церемониального в этой программе нет: `file.open`
с произносимым режимом, `read_all`, `to_pretty_json` с отступом 2
по умолчанию (`to_pretty_json(4)` и `to_pretty_json(0)` тоже проверены;
`0` даёт компактную форму). Ни блока `with`, ни флагов потока,
ни `ensure_ascii=False`, ни `std::setw`, ни `fs.readFileSync(path, 'utf8')`,
где забытый второй аргумент молча даёт `Buffer`.

Что та же программа требует в других местах и что ученик обязан выучить
*сначала*, чтобы её написать:

| Экосистема | Церемония до того, как первое сохранение заработает |
|---|---|
| C++ (nlohmann) | заголовочная зависимость, которую надо поставить, `std::ofstream`, `<<` со `std::setw(2)`, исключения на пути чтения |
| Python | `with open(..., encoding="utf-8") as f`, `json.dump(..., ensure_ascii=False, indent=2)` — два именованных аргумента, которых ученик не угадает и о которых ему не расскажут, пока его файл не станет нечитаемым |
| JavaScript | `fs.writeFileSync(path, JSON.stringify(obj, null, 2))` — средний аргумент `null` (замена) необъясним в первый день; пути чтения нужен аргумент `'utf8'`, иначе вернутся байты |

## 14. Сводка: инвентарь тихих ошибок темы JSON

Обозначения: **да** — в этой экосистеме отказ тихий; `—` — отвергает или ведёт
себя как ожидается; примечание в скобках — жалуется, но с оговоркой.

| № | Тихий отказ | nlohmann/json | `json` в Python | `JSON` в JS | Idyllium |
|---|---|---|---|---|---|
| 1 | Кривой текст всё равно разбирается | — | — | — | — |
| 2 | Отсутствующий ключ возвращает правдоподобное значение | **да** (`operator[]`, и он *вставляет*) | (`.get` даёт `None`) | **да** (`undefined`) | — `json object has no key 'x'` |
| 3 | Ошибка об отсутствующем ключе всплывает далеко от причины | **да** | (через `None`) | **да** | — |
| 4 | Строка прочитана как число | — | **да** (`int("12")`) | **да** (`"12" + 1`) | — `json value is string, expected int` |
| 5 | Дробное число молча усечено до целого | **да** (`get<int>()`) | **да** (`int(3.5)`) | **да** (побитовое «или ноль») | — `json value is number, expected int` |
| 6 | Большое целое теряет цифры | **да** (за пределами 64 бит) | — | **да** (за пределами 2^53) | — точно при любом размере |
| 7 | `NaN`/`Infinity` записаны в файл | (как `null`) | **да** (выдан некорректный JSON) | (как `null`) | — возникнуть не может |
| 8 | Опечатка в ключе создаёт второй ключ | **да** | **да** | **да** | — раскол `add`/`set` |
| 9 | Добавление существующего ключа молча перезаписывает | **да** | **да** | **да** | — `json object already has key 'x'` |
| 10 | Дубликат ключа во входящем тексте | **да** | **да** | **да** | **да** — см. §15 |
| 11 | Индекс массива за концом | **да** (`operator[]` расширяет) | — | **да** (`undefined`) | — называет размер и диапазон |
| 12 | Объект класса сериализован целиком, вместе с внутренним состоянием | — (ошибка компиляции) | (через `__dict__`) | **да** | — ошибка компиляции с указанием лечения |
| 13 | Класс потерян на обратном пути, методов нет | неприменимо | неприменимо | **да** (простой объект) | — соответствие пишется руками |
| 14 | Значения молча выброшены или превращены в `null` на выходе | — | — | **да** (`undefined`, функции) | — таких значений нет |
| 15 | Нестроковый ключ молча приведён к строке и может столкнуться | неприменимо | **да** (в выводе дубликат ключа) | неприменимо | — ключи строки |
| 16 | Файл сейва нечитаем для своего автора (экранированный не-ASCII) | — | **да** (`ensure_ascii` по умолчанию) | — | — |
| 17 | Два одинаковых документа оказываются неравными | — | — | **да** (ссылки; и порядок ключей) | — сравнение по содержимому |
| 18 | Вложенный контейнер скопирован там, где ждали ссылку, или наоборот | **да** (семантика значений, забытый `&`) | — | — | — одно правило, как у объектов классов |

Закономерность темы: отказы скапливаются там, где инструмент **подменяет
ответ значением** (`undefined`, `None`, вставленный null), где он
**преобразует, не спросив** (строка↔число, дробное→целое, большое целое→двойное)
и где он **решает за вас, что должно быть в файле** (выброшенные ключи,
экранированные буквы, `NaN`, записанный как `null`). Ответ Idyllium одинаков
во всех случаях: вопрос получает ответ или ошибку, но не подмену; никакого
преобразования, пока его не назвали; и записано то, что собрали.

## 15. Честный остаток: чего JSON в Idyllium по-прежнему не ловит

1. **Дубликаты ключей во входящем тексте молча схлопываются** (§7). Проверено:
   `{"a": 1, "a": 2}` разбирается в объект с одним ключом и `a = 2`, ровно
   как у трёх остальных. Стандарт JSON это допускает, а отказ сделал бы
   Idyllium неспособным читать файлы, которые производят другие инструменты.
   Курс разбирает это прямо в уроке про ошибки, а не делает вид, что такого
   не бывает, и ставит рядом громкий отказ `add`, чтобы ученик увидел обе
   стороны.
2. **Схема не проверяется.** Ничто не удостоверяет, что в файле сейва есть
   ключи, которых ждёт ваша программа, до момента чтения каждого ключа. Файл
   без трёх полей сообщит о первом и остановится. Ответ, которому учат, —
   приём `has()` плюс значение по умолчанию (§3), и применять его —
   обязанность ученика.
3. **`is_int()` не отличает `5` от `5.0`.** В JSON один числовой тип, так что
   это свойство формата, а не библиотеки, — но ученик, сравнивающий «как было
   записано в файле» с «что говорит предикат», обнаружит расхождение,
   и материал должен предупредить об этом до того, как он споткнётся.
4. **Числа в экспоненциальной форме разбираются и записываются обратно
   обычными.** Проверено: `1e3` читается как `1000`. Правильно, стандартно
   и удивительно для ребёнка, который писал файл руками и ждёт его назад
   дословно.
5. **Порядок ключей сохраняется, но ничего не гарантирует.** Проверено:
   порядок `keys()` и вывода `to_json()` совпадает с порядком вставки.
   Не преподавайте это как правило, которое соблюдут другие инструменты, —
   многие сортируют ключи, а сравнение по содержимому (§11) порядок
   сознательно игнорирует.
6. **Глубина документа не ограничена.** Проверено до 200 уровней вложенности
   без единой жалобы. Патологический файл мог бы исчерпать стек; в классе
   такого не появится, и защиты не предусмотрено.
7. **Смысловые ошибки не затронуты, как и везде.** Файл сейва с `"hp": -5`,
   номер уровня, не совпадающий с картой, поле, написанное верно,
   но означающее другое, — этого не видит ни один разборщик. Тот же остаток
   назван в каждой части серии, и курс отвечает на него детективным жанром,
   а не инструментарием.

## 16. Правила для ИИ, пользующегося этим файлом

1. **Никогда не порождайте `.get(key)` для необязательного поля.**
   Пользуйтесь `has(key)` со значением по умолчанию или дайте громкой ошибке
   прозвучать. Не заворачивайте чтение JSON в оборонительный код, прячущий
   сообщение от ученика.
2. **Пользуйтесь `add` для новых ключей и `set` для существующих
   сознательно.** Если порождённый код дважды вызывает `add` на одном ключе,
   это ошибка, а не стилистический выбор, — среда выполнения об этом скажет.
3. **Не тащите идиомы трёх остальных.** Никакого создания при чтении в стиле
   `operator[]`, никаких умолчаний `None`/`undefined`, никакого
   `JSON.stringify(obj)` для экземпляра класса, никакой рефлексии по полям.
   Объекты преобразуются написанными руками методами `to_json()` /
   `from_json()` (§9).
4. **Заворачивайте значения явно**: `json.Value(x)` для скаляров,
   `json.Value(arr)` и `json.Value(obj)` для контейнеров. `json.Value()` без
   аргумента — это JSON null, а `null` присваивается в `json.Value`.
5. **Пишите файлы через `to_pretty_json()`**, когда их откроет человек, —
   а в этом курсе почти всегда. `to_json()` оставьте для сетевых посылок
   и текста от машины к машине.
6. **Цитируйте сообщения дословно**, объясняя ошибку ученику, и называйте
   *конкретную* ловушку из §14, из которой выросла его привычка: «в JavaScript
   отсутствующий ключ дал тебе `undefined`, и ошибка появилась тремя функциями
   позже; здесь останавливается та самая строка, которая ключ и спросила»
   учит больше, чем «Idyllium строже».
7. **Не обещайте отловов из §15.** Дубликаты ключей во входящем файле,
   отсутствие схемы и смысловая чепуха — забота ученика, и материалы должны
   говорить это прямо.
8. **Эта тема стоит после года ООП.** Примеры должны выглядеть как классовый
   код, который ученик пишет параллельно, — `Player` с
   `to_json()`/`from_json()`, а не куча разрозненных переменных `json.Object`
   в `main()`.

## 17. Происхождение сведений

Каталог поведения экосистем собран из классных наблюдений на курсах C++,
Python и JavaScript для детей 10–15 лет и организован вокруг тех же пяти
проектных критериев, что части 1–4. В отличие от предыдущих частей, колонки
Python и JavaScript здесь дополнительно **проверены прогоном** (CPython 3
и Node/V8), а не взяты из документации: всякое значение, помеченное словом
«проверено», — снятый вывод. Колонка nlohmann/json документарная, и прежде
чем цитировать её как факт, стоит перепроверить на сборке.

Колонка Idyllium — не мнение: каждое сообщение, каждое значение и каждый
круговой рейс получены прогоном пробной программы через текущий компилятор
и среду выполнения, включая рейс целого произвольной точности, таблицу
экранирования, последовательность со ссылочной семантикой, таблицу годности
и сохранение файла с перезагрузкой. Когда язык меняется, этот файл должен
перепроверяться тем же способом.
