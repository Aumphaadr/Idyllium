# AI-справка Idyllium: embed-юниты

Этот файл учит универсального AI-ассистента **составлять embed-юниты
Idyllium** — маленькие самопроверяющиеся упражнения по программированию,
которые встраиваются в любую веб-страницу. Вставьте файл в чат, опишите
упражнение — и ассистент выдаст готовый файл `.idyunit` или готовый HTML, без
захода в конструктор юнитов https://aumphaadr.github.io/Idyllium/authors/.

Текущая версия: Idyllium 1.6.2, `format` файла юнита — 1.

Соседние файлы (в той же папке): `idyllium-ai-reference.md` — ЯЗЫК (он нужен,
чтобы верно написать заготовку и решение автора);
`idyllium-site-ai-reference.md` — сайт. Здесь они не повторяются.

Правила для ассистента:

- Не выдумывайте поля конфигурации, функции формул и библиотеки. Всё, что
  существует, перечислено здесь; неизвестное поле юнит молча пропустит — и
  упражнение молча станет слабее.
- Запустить Idyllium вы не можете. Скажите это прямо и ВСЕГДА отправляйте
  пользователя открыть результат в конструкторе (`/authors/` → «Открыть
  файл…»): самопроверка там прогоняет решение автора по тестам и называет
  ошибки словами. Юнит, не прошедший самопроверку, — черновик.
- Idyllium — не C++, не Python и не JavaScript. Самые частые ошибки генерации:
  `%` (пишите `mod(a, b)`), `/` для целых (он всегда даёт `float`; пишите
  `div(a, b)`), `x++` и `x += 1` в учебном коде (пишите `x = x + 1`),
  `&&`/`||`/`!` (пишите `and`/`or`/`not`), `int main()` (пишите `main()`),
  `console.read_line` (такого нет: `console.get_string()`,
  `console.get_int()`, `console.get_float()`), забытый `use console;`.

## 1. Что такое юнит

Юнит — это кадр, в котором есть: необязательное условие задачи, редактор кода
с заготовкой, консоль и кнопки «Запустить», «Проверить», «Форматировать»,
«В Web IDE» (продолжить в большой среде), «Сбросить».

- **«Запустить»** — обычный живой запуск с вводом самого ученика. Вердикта не
  даёт (только мягкую подсказку «этот запуск сходится с условием»).
- **«Проверить»** прогоняет программу ученика на НАБОРЕ тестов автора
  и к каждому прогону применяет правила автора. Вердикт: решено / не решено,
  с первым провалившимся вводом и причиной словами.
- Юниты — **только консоль**. Доступные библиотеки: `console`, `math`,
  `random`, `time`, `types`, `encoding`, `hash`, `system`. Никаких `gui`,
  файлов, сети, `json`, `sqlite`: любой другой `use` внутри юнита — ошибка
  компиляции.
- Пределы: 10 секунд на тест (`time.sleep` спит по-настоящему), 65536 символов
  вывода на тест, не больше 200 записей в тестах.
- Ни сервера, ни аккаунтов, ни статистики. Тесты лежат в исходнике страницы
  и не секретны: юнит — тренажёр, а не экзамен.

## 2. Три способа отдать юнит

1. **Файл `.idyunit` — ЛУЧШИЙ путь для ассистента.** Это JSON конфигурации из
   раздела 3, сохранённый как `имя.idyunit`. Пользователь открывает его
   в конструкторе, видит живой предпросмотр и самопроверку, чинит найденное
   и там же копирует итоговый HTML. Решение автора кладите в `solution` (оно
   остаётся в файле; когда оно попадает на страницу — см. раздел 3).
2. **Полная HTML-форма** — скрипт-загрузчик и элемент `<idyllium-unit>`. Это
   обычный текст, ассистент может написать его напрямую:

   ```html
   <script src="https://aumphaadr.github.io/Idyllium/embed/idyllium-unit.js" async></script>

   <idyllium-unit id="loop-10-15">
   <script type="text/idyllium">
   use console;

   main() {
       for (int i = ; i < ; i = i + 1) {
           console.writeln(i);
       }
   }
   </script>
   <script type="application/json">
   {
     "format": 1,
     "title": "Числа от 10 до 15",
     "statement": "Допишите цикл так, чтобы программа вывела числа от 10 до 15, каждое с новой строки.",
     "inputs": "none",
     "check": { "kind": "expect", "output": "10\n11\n12\n13\n14\n15\n" },
     "code": { "require": ["for"], "maxCalls": { "writeln": 1 } }
   }
   </script>
   </idyllium-unit>
   ```

   Заготовка кладётся в `<script type="text/idyllium">` как есть — `<` и `&`
   экранировать не нужно; только последовательность `</script` пишется как
   `<\/script`. Второй `<script type="text/idyllium" data-role="solution">`
   несёт эталонное решение (нужно только при `check.kind = "reference"`).
   Скрипт-загрузчик подключается один раз на страницу, сколько бы юнитов ни шло
   следом. Пропущенные поля JSON получают значения по умолчанию.
3. **Форма «только iframe»** — для платформ, вырезающих `<script>`: весь юнит
   упакован в адрес после `#unit=` как base64url от JSON. **Не составляйте её
   вручную** — надёжно закодировать её ассистент не может; конструктор делает
   это одной кнопкой.

## 3. Конфигурация (формат 1)

```json
{
  "format": 1,
  "id": "circle-area",
  "title": "Площадь круга",
  "statement": "Текст условия над редактором; пусто — условие пишет сама страница-хозяин.",
  "lang": "ru",
  "starter": "use console;\n\nmain() {\n    \n}\n",
  "solution": "…полная программа автора…",
  "libs": ["console", "math"],
  "inputs": "some",
  "tests": [
    { "in": "2" },
    { "in": ["3", "4"] },
    { "random": 1, "range": [-50, 50], "times": 4 },
    { "random": 1, "range": [-5, 5], "times": 4, "kind": "float", "digits": 1 }
  ],
  "check": { "kind": "formula", "tolerance": 0.001, "rules": [ { "when": "", "expr": "…" } ] },
  "code": { "require": ["if"], "forbid": ["while"], "maxCalls": { "writeln": 1 } },
  "editor": { "rows": 16, "consoleRows": 6, "fontSize": 16, "theme": "auto",
              "mode": "monaco", "autocomplete": true, "format": true, "openInIde": true },
  "feedback": { "reveal": false, "softRunHint": true, "shareCode": false, "branding": true },
  "hooks": { "solved": "", "failed": "", "check": "" }
}
```

По полям:

| Поле | Значения и умолчание | Смысл |
|---|---|---|
| `format` | `1` | Номер схемы файла. Всегда пишите `1`. |
| `id` | латиница, цифры, дефис; по умолчанию — транслит `title` | id элемента и ключ сохранённого черновика ученика. Уникален на странице. |
| `title` | строка | Название юнита (заголовок кадра, конструктор). |
| `statement` | строка, по умолчанию `""` | Условие задачи. Простой текст. |
| `lang` | `"ru"` (по умолчанию) или `"en"` | Язык кнопок и вердиктов юнита. |
| `starter` | код; `"minimal"` (по умолчанию: `use console;` + пустой `main`), `"empty"` | Что ученик видит сначала. Заготовка вправе нарочно не компилироваться («допишите условие») — самопроверка покажет безобидное предупреждение. Она НЕ должна уже проходить проверку. |
| `solution` | код | Решение автора. Нужно самопроверке конструктора; в режиме `reference` оно ЕЩЁ И уезжает на страницу (видно в её исходнике). В остальных режимах файл `.idyunit` оно не покидает. |
| `libs` | подмножество восьми библиотек; по умолчанию — все восемь | Сужение, например `["console"]`, чтобы запретить `math`. `console` есть всегда. |
| `inputs` | `"some"` (по умолчанию) / `"none"` | `"none"`: по условию ввода нет; программа, пытающаяся читать, проваливает тест. |
| `tests` | массив, см. раздел 4 | Вводы проверочных прогонов. |
| `check` | см. раздел 5 | Как судится прогон. `{"kind": "none"}` (по умолчанию) — песочница без вердикта. |
| `code` | см. раздел 6 | Требования к тексту программы. |
| `editor.rows` | 4–40, по умолчанию 16 | Высота редактора в строках. |
| `editor.consoleRows` | 3–20, по умолчанию 6 | Высота консоли в строках. |
| `editor.fontSize` | 10–28, по умолчанию 16 | |
| `editor.theme` | `"auto"` (по умолчанию), `"light"`, `"dark"` | `auto` следует системной теме посетителя. |
| `editor.mode` | `"monaco"` (по умолчанию) / `"light"` | `light` — простой лёгкий редактор вместо Monaco. |
| `editor.autocomplete` | по умолчанию `true` | `false` — никаких подсказок вообще (ученик набирает каждое имя сам). |
| `editor.format` | по умолчанию `true` | `false` убирает кнопку «Форматировать». |
| `editor.openInIde` | по умолчанию `true` | Кнопка «В Web IDE»: открывает код ученика в большой Web IDE в новой вкладке (отдельным гостевым проектом, ссылкой `#p1=`). `false` — если ученик не должен уходить со страницы урока. |
| `feedback.reveal` | по умолчанию `false` | Показывать ожидаемый ответ проваленного теста (режимы `expect` и `reference`). |
| `feedback.softRunHint` | по умолчанию `true` | Мягкая подсказка после обычного запуска. |
| `feedback.shareCode` | по умолчанию `false` | Отдавать текст программы ученика функциям страницы-хозяина. |
| `feedback.branding` | по умолчанию `true` | Маленькая ссылка «Idyllium» в углу. |
| `hooks.*` | имена функций, по умолчанию `""` | См. раздел 8. |

## 4. Тесты

Один тест = один прогон программы с заготовленным вводом.

- `{ "in": "3 4" }` — строка делится по пробелам: две строки ввода, `3` и `4`.
  Каждый вызов `console.get_*` забирает одну.
- `{ "in": ["Анна Мария", "12"] }` — массив даёт строки как есть; нужен, когда
  в строке есть пробелы (для `console.get_string()`).
- `{ "random": N, "range": [низ, верх], "times": T }` — `T` прогонов, в каждом
  `N` случайных ЦЕЛЫХ (`N` 1–20, `T` 1–50). С `"kind": "float", "digits": D`
  (`D` 1–6) числа дробные, `D` знаков после точки. Случайные тесты создаются
  заново при каждой проверке, поэтому работают только с правилами, которые
  ВЫЧИСЛЯЮТ ответ (`formula`, `reference`), и никогда — с `expect`.
- Программа, читающая больше, чем даёт тест, проваливает его («ввод
  кончился»); чтение `2.5` через `get_int` — тоже провал, словами.
- При `"inputs": "none"` оставьте `tests` пустым — прогон ровно один.

Как выбирать тесты — здесь ассистенты ошибаются чаще всего:

- **По тесту на каждую ветку плюс каждая граница.** Для `if (R >= 0)`:
  положительное, ноль, отрицательное — И значения вплотную к границе.
- **Если ввод может быть дробным, нужны дробные тесты.** Иначе неверное
  `R > -1` проходит все целые тесты вместо требуемого `R >= 0` (они различаются
  только на вводах вроде `-0.5`) — как и ученик, прочитавший число через
  `get_int`. Правило для границы `c` на дробном вводе: тесты `c`, `c - 0.5`,
  `c + 0.5`, `c - 1`, `c + 1`.
- **Никогда не полагайтесь на один «везучий» ввод.** В задаче про
  прямоугольник ввод `1 1` принимает `w * 4` за периметр и `w * w` за площадь.
  Берите неравные значения и добавляйте случайные тесты.
- Добавляйте 3–5 случайных тестов, когда ответ считается формулой или эталоном.
- Самопроверка конструктора проверяет и сами тесты: слегка портит решение
  автора (`>=` → `>`, `0` → `-1`, `>= 0` → `> -1`) и сообщает о каждом мутанте,
  которого тесты не отличают от оригинала, — вместе с вводом, который отличает.
  Скажите пользователю нажать там «+ тест».

## 5. Виды проверки

### 5.1. `formula` — правила над значениями прогона

```json
"check": { "kind": "formula", "tolerance": 0.001, "rules": [
  { "when": "{in1} >= 0", "expr": "{outs} == 1 and {out1} == 3.14 * {in1} * {in1}" },
  { "when": "{in1} < 0",  "expr": "{line1} == \"Ошибка\"" }
] }
```

Правило применяется, когда его `when` пусто или истинно; каждое применимое
правило обязано дать `true`. Прогон, к которому НЕ применилось ни одно правило,
не засчитывается; если так вышло со всеми прогонами, проверка сообщит «ничего не
проверено» — поэтому условия `when` должны покрывать все тесты.

Значения в фигурных скобках:

| Слот | Смысл |
|---|---|
| `{in1}`, `{in2}`, … | Строки ввода, которые программа действительно ПРОЧЛА, по порядку. Похожее на число — число. |
| `{out1}`, `{out2}`, … | Ответ, разбитый по пробельным символам. Похожее на число — число, остальное — строки. |
| `{line1}`, `{line2}`, … | Целые строки ответа (всегда строки, хвостовые пробелы срезаны). |
| `{ins}`, `{outs}`, `{lines}` | КОЛИЧЕСТВА перечисленного. |
| `{output}` | Весь ответ одной строкой. |

**Приглашения в ответ не входят**: текст, висящий на текущей строке в момент,
когда программа читает ввод («Введите радиус: »), частью ответа не считается.
Так что заготовка вправе приглашать ко вводу. Но приглашение, напечатанное
через `writeln` (с концом строки), в ответ ВХОДИТ — в заготовках и решениях его
избегайте.

Язык формул — подмножество выражений Idyllium:

- `and`, `or`, `not`, `xor`; `==`, `!=`, `<`, `<=`, `>`, `>=`; `+ - * /`
  (`/` — дробное деление; `+` склеивает, если хоть одна сторона — строка);
  скобки; числа, `"строки"` (или `'строки'`), `true`, `false`.
- Функции — полный список: `abs(x)`, `round(x)`, `round(x, digits)`,
  `floor(x)`, `ceil(x)`, `sqrt(x)`, `pow(x, y)`, `min(a, b)`, `max(a, b)`,
  `mod(a, b)`, `div(a, b)` (округление вниз, остаток со знаком делителя — то же
  правило, что в языке с 1.6.1), `to_int(x)`, `to_float(x)`, `to_string(x)`,
  `length(s)`, `contains(s, part)`, `lower(s)`, `upper(s)`.
- Числа сравниваются с допуском `tolerance` (по умолчанию `0.000001`): `==`
  значит «отличается не больше чем на допуск»; `<=` и `>=` расширены на него.
  Для денег и площадей берите `0.001`–`0.01`; для целых ответов — `0`.
- Нет переменных, `if`, циклов, `%`, `&&`, `||`, `!` (каждое из них даёт ошибку
  словами с позицией).
- Всегда закрепляйте объём вывода (`{outs} == 2` или `{lines} == 2`) — иначе
  пройдёт программа, печатающая лишний мусор. Обращение к отсутствующему слоту
  (`{out2}`, когда выведено одно значение) проваливает тест с ясной причиной.

### 5.2. `expect` — точный вывод

```json
"inputs": "none",
"check": { "kind": "expect", "output": "10\n11\n12\n13\n14\n15\n" }
```

Сравнение построчное; хвостовые пробелы строки и пустые строки в конце не
учитываются, всё остальное — точно. Для задач БЕЗ ввода (или с одним
фиксированным вводом) и полностью определённым выводом. Ставьте вместе
с правилами `code`, иначе шесть `writeln` подряд пройдут задачу «напишите цикл».

### 5.3. `reference` — сравнение с решением автора

```json
"check": { "kind": "reference", "tolerance": 0 }
```

На каждом тесте запускается и `solution` автора; ответы сравниваются значение
за значением (деление по пробельным символам, числа — с `tolerance`). Самый
простой выбор, когда ответ трудно выразить формулой (сумма цифр, циклы, обработка
строк). Работает со случайными тестами. Цена: решение уезжает в исходник
страницы, и каждый тест запускает две программы.

### 5.4. `none`

Без вердикта: песочница для опытов («запусти и поменяй число»).

## 6. Требования к коду

```json
"code": { "require": ["for"], "forbid": ["while", "math"], "maxCalls": { "writeln": 1 } }
```

Проверяются по ТОКЕНАМ программы до тестов — слово внутри строки или
комментария не считается. `require` — слово должно встретиться; `forbid` — не
должно; `maxCalls` — не больше N вхождений `имя(` (для метода пишите последнее
имя: `writeln`, а не `console.writeln`). Нарушение останавливает проверку
с причиной словами. Пользуйтесь скупо: требуйте конструкцию, которой посвящён
урок.

## 7. Детерминизм

- `random` в проверяемой программе: условие обязано сказать «сначала вызовите
  `random.set_seed(42)`», иначе ответы разные при каждом запуске. Лучше — не
  использовать `random` в проверяемых юнитах.
- `time.now()` точным сравнением не проверить.
- `time.sleep()` спит по-настоящему; сумма пауз должна быть заметно меньше
  10 секунд на тест.

## 8. Страница-хозяин: функции, события, методы

Есть только у полной HTML-формы.

- Атрибуты `<idyllium-unit>`: `on-solved="showBunny"`, `on-failed="…"`,
  `on-check="lms.report"` — ИМЕНА глобальных функций страницы (можно путь через
  точку), а не код. То же самое — `hooks` в JSON. Функция получает один объект:

  ```js
  {
    unit: "circle-area",        // id
    verdict: "solved",          // или "failed"
    passed: 10, total: 10,
    attempt: 3,                 // нажатий «Проверить» с загрузки страницы
    firstFailure: null,         // или { input, answer, reason } — reason текстом
    code: "…"                   // только при feedback.shareCode = true
  }
  ```

- DOM-события на элементе (всплывают): `idyllium-ready`, `idyllium-run`
  (`detail`: `{ unit, output, error }`), `idyllium-check`, `idyllium-solved`,
  `idyllium-failed` (`detail` — объект выше).
- Методы элемента: `getCode()` (возвращает Promise), `setCode(text)`,
  `reset()`, `run()`, `check()`, `setTheme('light' | 'dark' | 'auto')`.
- Быстрые правки атрибутами, не трогая JSON: `rows`, `console-rows`,
  `font-size`, `theme`, `editor="light"`, `autocomplete="off"`, `format="off"`,
  `open-in-ide="off"`,
  `lang`, `accent="#0a7"` (акцентный цвет кнопок юнита).
- Из кода: `IdylliumUnit.create(container, config)`.
- Черновик ученика хранится в `localStorage` страницы-хозяина — по пути
  страницы и `id` юнита; «Сбросить» возвращает заготовку.

## 9. Три проверенных примера

Все три прошли самопроверку конструктора на Idyllium 1.6.1. Сохраните любой как
`имя.idyunit` и откройте на `/authors/`.

### 9.1. Ветвление, дробный ввод — `formula`

```json
{
  "format": 1,
  "id": "circle-area",
  "title": "Площадь круга",
  "lang": "ru",
  "statement": "Программа читает радиус круга R (может быть дробным). Если R не отрицателен, выведите площадь круга, считая π = 3.14. Иначе выведите слово «Ошибка».",
  "starter": "use console;\n\nmain() {\n    console.write(\"Введите радиус: \");\n    float R = console.get_float();\n    \n}\n",
  "solution": "use console;\n\nmain() {\n    console.write(\"Введите радиус: \");\n    float R = console.get_float();\n    if (R >= 0) {\n        console.writeln(3.14 * R * R);\n    }\n    else {\n        console.writeln(\"Ошибка\");\n    }\n}\n",
  "inputs": "some",
  "tests": [
    { "in": "2" }, { "in": "0" }, { "in": "0.5" },
    { "in": "-0.5" }, { "in": "-1" }, { "in": "-3" },
    { "random": 1, "range": [-20, 20], "times": 4, "kind": "float", "digits": 1 }
  ],
  "check": { "kind": "formula", "tolerance": 0.001, "rules": [
    { "when": "{in1} >= 0", "expr": "{outs} == 1 and {out1} == 3.14 * {in1} * {in1}" },
    { "when": "{in1} < 0", "expr": "{line1} == \"Ошибка\"" }
  ] },
  "code": { "require": ["if"], "forbid": [], "maxCalls": {} }
}
```

Ответы решения: `2` → `12.56`, `0` → `0`, `0.5` → `0.785`, `-0.5` → `Ошибка`.
Именно тесты `-0.5` и `-1` ловят `R > -1`.

### 9.2. Без ввода, точный вывод, правила к коду — `expect`

```json
{
  "format": 1,
  "id": "loop-10-15",
  "title": "Числа от 10 до 15",
  "lang": "ru",
  "statement": "Допишите цикл так, чтобы программа вывела числа от 10 до 15, каждое с новой строки.",
  "starter": "use console;\n\nmain() {\n    for (int i = ; i < ; i = i + 1) {\n        console.writeln(i);\n    }\n}\n",
  "solution": "use console;\n\nmain() {\n    for (int i = 10; i < 16; i = i + 1) {\n        console.writeln(i);\n    }\n}\n",
  "inputs": "none",
  "tests": [],
  "check": { "kind": "expect", "output": "10\n11\n12\n13\n14\n15\n" },
  "code": { "require": ["for"], "forbid": [], "maxCalls": { "writeln": 1 } }
}
```

Заготовка нарочно не компилируется; самопроверка отвечает предупреждением
«Заготовка не компилируется. Если так задумано… — всё в порядке». `maxCalls`
не даёт пройти шести `writeln` подряд.

### 9.3. Ответ трудно записать формулой — `reference`

```json
{
  "format": 1,
  "id": "digit-sum",
  "title": "Сумма цифр",
  "lang": "ru",
  "statement": "Программа читает целое неотрицательное число и выводит сумму его цифр.",
  "starter": "minimal",
  "solution": "use console;\n\nmain() {\n    int n = console.get_int();\n    int total = 0;\n    while (n > 0) {\n        total = total + mod(n, 10);\n        n = div(n, 10);\n    }\n    console.writeln(total);\n}\n",
  "inputs": "some",
  "tests": [
    { "in": "0" }, { "in": "7" }, { "in": "10" }, { "in": "999" }, { "in": "1000000" },
    { "random": 1, "range": [0, 1000000], "times": 5 }
  ],
  "check": { "kind": "reference", "tolerance": 0 },
  "code": { "require": ["while"], "forbid": [], "maxCalls": {} }
}
```

Ответы решения: `0` → `0`, `7` → `7`, `10` → `1`, `999` → `27`.

## 10. Чек-лист перед выдачей юнита пользователю

1. Решение — полная программа Idyllium (`use console;`, `main()`), использует
   только восемь библиотек юнита и не печатает ничего, кроме ответа
   (приглашения — только через `console.write`, без конца строки).
2. Заготовка ещё не решает задачу.
3. Тесты: каждая ветка, каждая граница и её соседи, дробные значения при вводе
   `float`, никаких «везучих» равных значений, несколько случайных тестов для
   `formula`/`reference`; со способом `expect` случайных тестов нет.
4. `formula`: условия `when` покрывают все тесты; объём вывода закреплён;
   `tolerance` подходит числам.
5. JSON корректен: код — строка JSON с `\n` и `\"`; без комментариев и висячих
   запятых.
6. Скажите пользователю: «Откройте файл на
   https://aumphaadr.github.io/Idyllium/authors/ («Открыть файл…»), посмотрите
   самопроверку и скопируйте HTML оттуда».
