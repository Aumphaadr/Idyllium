## 0. Аксиома: враг — молчание

Единственный организующий принцип этого документа:

> **Ошибка, которая объявляет о себе, — это урок. Ошибка, которая промолчала, —
> это ущерб.** Новичок не может отличить «моя программа верна» от «моя
> программа неверна так, как этот язык решил не упоминать». Каждая тихая
> неправильность выращивает картину мира, которая *работает*, — и переучиваться
> потом придётся куда дороже.

Поэтому у языка, нацеленного на новичков, ровно два допустимых поведения
на всё, что ребёнок способен правдоподобно написать:

1. **Сделать то, чего ждёт человек.** `23 / 10` — это `2.3`; `"белый"` — пять
   символов; `true` печатается как `true`.
2. **Громко отказать понятными словами, указав строку.** Никакого молчаливого
   отбрасывания, никаких молчаливых преобразований, никакого `undefined`,
   никакого «значения из чужой памяти», никакого `0` вместо ввода, который
   пользователь не набирал.

Третье поведение — *сделать что-то неожиданное и промолчать* — и есть то, что
этот документ каталогизирует у других языков.

### Пять проектных критериев, стоящих за языком

Они старше Idyllium: их выжали из многолетнего преподавания Pascal, C++
и Python детям 10–15 лет, и язык строился так, чтобы им удовлетворять.

1. **Единая логика на всём протяжении.** Конструкция, выученная в первый месяц,
   сохраняет смысл в девятый; от ученика не требуется помнить десятки
   контекстных исключений.
2. **Никакой двусмысленности.** Ни одного оператора, чей смысл зависит
   от типов вокруг.
3. **Высокая ассоциативность.** Ключевые слова ложатся на обычные, угадываемые
   английские слова (`function`, `while`, `read`, `write`), а не «`Rewrite`
   означает открыть на запись».
4. **Никаких чёрных ящиков.** Ни одной конструкции, которая «просто работает»
   и объяснима только после нескольких лет опыта (`while (getline(fin, S))`,
   `for line in f`).
5. **Понятия видны в коде.** Если ученик обязан на экзамене дать определение
   переменной, типа, массива, функции — код на экране должен *показывать*
   определяемое, а не прятать его за выводом типов.

## 1. Как читать разборы

У каждой темы ниже одна и та же форма:

- **Ребёнок пишет** — правдоподобный код новичка, запускающий беду.
- **Что делают другие языки** — таблица, по строке на язык. Класс поведения
  помечен так:
  - **ТИХО** — неверный или неожиданный результат без диагностики. Опасный
    класс.
  - **ГРОМКО** — отказывается или падает с сообщением. Приемлемо, даже если
    само сообщение плохое.
  - **НЕВНЯТНО** — ошибка есть, но сообщение новичку не расшифровать
    (`invalid syntax`, `Runtime error 106`, `segmentation fault`).
  - **ОК** — ведёт себя так, как ждёт человек; чинить нечего.
- **Ответ Idyllium** — с дословным сообщением компилятора или среды выполнения.

Замечание о справедливости: этот документ — про *обучение новичков*. Некоторые
перечисленные здесь как беды поведения в своих языках — осознанные, защитимые
инженерные решения: целочисленное деление в C быстро и предсказуемо,
приведения типов в JavaScript держат веб-страницу живой. Критика здесь строго
одна: «что это делает с двенадцатилетним, который строит свою первую картину
мира».

## 2. Шаблон программы — первый экран

**Ребёнок пишет** свою самую первую программу и вынужден скопировать некоторое
количество церемонии перед единственной строчкой, которая действительно
что-то делает.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК | `program name;` + `begin`/`end.` — три структурные строки, все произносимые. Странность: программа заканчивается точкой, а не точкой с запятой; блоки — через `end;`. |
| C++ | НЕВНЯТНО | Четыре строки церемонии (`#include <iostream>`, `using namespace std;`, `int main()`, скобки) перед первым осмысленным оператором. `cout`, `endl`, `include`, `namespace` — неугадываемые слова; `int` перед `main` в первый день необъясним. |
| Python | ОК | Пустой файл и `print('Hello')`. Лучший из возможных первых экранов. |
| JavaScript | ТИХО | `console.log('Hello')` печатает в консоль, которую ученик сперва должен *найти* (DevTools); пока не нашёл — вывод уходит в никуда без единого признака. `alert`/`prompt` — второй, модальный мир вывода. Точки с запятой необязательны (ASI), так что язык сам не знает, строгий он или нет. |

**Ответ Idyllium:**

```idyllium
use console;

main() {
    console.writeln("Привет!");
}
```

- `use console;` — *осмысленная* строка, а не церемония: «эта программа
  пользуется консолью». То же слово ученик потом напишет для `file`, `random`,
  `gui`.
- В `main()` нет ни `int`, ни `void`, ни `return 0`. На первом экране нет
  ничего, что нельзя объяснить в первый же день.
- Канал вывода один, и это тот самый, на который ученик смотрит: никакого
  второго модального мира, никакой консоли, спрятанной за сочетанием клавиш
  браузера.

## 3. Переменные — объявление против присваивания

**Ребёнок пишет:**

```
A = 20      // это создание переменной или изменение?
A = 60
```

Экзаменационный вопрос «что такое переменная?» требует, чтобы две операции
*выглядели* по-разному. Там, где они не различаются, ученики годами отвечают
«буква, которая равна числу».

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК / ТИХО | `var A: integer;` против `A := 20;` — видимая разница, тип на виду. Но идентификаторы **нечувствительны к регистру**: `A` и `a` — молча одна и та же переменная. |
| C++ | ОК | `int A;` против `A = 20;`. Регистр учитывается. Тип виден. |
| Python | ТИХО | Объявления не существует; `A = 20` и `A = 60` — одни и те же значки для двух разных понятий, а тип нигде не написан. **Опечатка создаёт совершенно новую переменную** без единой диагностики: `summa = 0`, затем `sumaa = 5` — две переменные, ошибки нет. |
| JavaScript | ТИХО | `let A = 20;` против `A = 60;` — различие есть и видно (лучше, чем у Python). Но без `'use strict'` **пропущенный `let` молча создаёт глобальную переменную**, а опечатка молча создаёт ещё одну. Три ключевых слова объявления (`var`, `let`, `const`) с разной областью видимости встречаются вперемешку в любом коде из интернета. |

**Ответ Idyllium** — объявление и присваивание различаются на вид, тип пишется
всегда, и ни опечатка, ни промах регистра не проходят:

```idyllium
int a = 20;   // объявление: тип — часть строки
a = 60;       // присваивание: типа нет, с объявлением не спутать
int a = 30;   // compile error: 'a' is already declared in this scope
b = 20;       // compile error: variable 'b' was not declared in this scope
Summa = 30;   // compile error: variable 'Summa' was not declared in this scope
```

И диагностика, которой нет ни у одного другого языка в этом сравнении, —
**ловушка омоглифов**, когда кириллическая буква стоит внутри латинского
имени (или наоборот) и на экране получаются два попиксельно одинаковых имени:

```text
compile error: variable 'сat' was not declared in this scope — but 'cat' is:
the two names mix Russian and English letters that look alike
```

В Python или JavaScript та же опечатка вообще не ошибка: она молча создаёт
вторую переменную, выглядящую в точности как первая.

## 4. Арифметика и преобразование типов

Тема с наибольшей плотностью тихого вреда во всех языках, кроме Pascal.

### 4.1. Оператор деления

**Ребёнок пишет** `9 / 2` и ждёт `4.5`, потому что пять лет школьной
математики говорят именно это.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК | `/` — всегда вещественное деление. Целочисленное деление — отдельный именованный оператор `div`, остаток — `mod`. Присваивание `A / B` в `integer` — ошибка компиляции. |
| C++ | **ТИХО** | `/` означает две разные вещи в зависимости от типов операндов: `9 / 2` — это `4`, `9.0 / 2` — это `4.5`. Флагманская двусмысленность языка для новичка: тот же оператор, тот же на вид код, два поведения. Чтобы вернуть ожидаемое, нужен каст: `float(A) / B`. |
| Python | ОК / мелочь | `/` всегда вещественное, `//` — целочисленное. Логика верна, а вот *написание* неудачно: `//` — это маркер комментария в каждом языке C-семейства, куда ученик пойдёт дальше. |
| JavaScript | ТИХО | Все числа вещественные, поэтому `9 / 2` — это `4.5`, верно по случайности. Целочисленного деления не существует, его собирают как `Math.floor(a / b)`. |

**Ответ Idyllium** — у `/` ровно один смысл, а целочисленные операции —
именованные функции:

```idyllium
float d = 37 / 10;          // 3.7
int    r = 37 / 10;         // compile error: cannot assign 'float' value to 'int' variable
console.writeln(div(37, 10));   // 3
console.writeln(mod(37, 10));   // 7
console.writeln(9 / 2);         // 4.5
```

`div`/`mod` согласованы на отрицательных и следуют правилу Python (с 1.6.1):
`div` округляет вниз, остаток берёт знак делителя — `div(-7, 3)` — это `-3`,
`mod(-7, 3)` — это `2`, и `-3 * 3 + 2 = -7` сходится. C++, Java и JavaScript
округляют к нулю (`-7 % 3` — это `-1`), и это тихо ломает `n % 2 == 1` для
отрицательных нечётных и индексы «по кругу».

### 4.2. Оператор остатка и знак процента

**Ребёнок пишет** `int F = 50 % 14;` и читает это как «50 процентов
от 14» — задокументированное, повторяющееся классное прочтение, потому что
у `%` есть сильное школьное значение.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК | `mod` — слово, ложной ассоциации нет. |
| C++ | мелочь | `%` — тянет за собой проценты и отказывается работать с дробными: `7.5 % 2` не компилируется, остаток вещественных требует `fmod` из другого заголовка. Одна идея, два написания. |
| Python | мелочь | `%` — та же ассоциация, и тот же символ вдобавок служит старым оператором форматирования строк (`"%d items" % n`), так что один значок несёт два несвязанных смысла. |
| JavaScript | мелочь | `%` — та же ассоциация; в отличие от C++ работает с дробными. |

**Ответ Idyllium** — единственное написание `mod(a, b)`, а знак процента
перехватывается прицельной подсказкой, а не ошибкой разбора:

```text
compile error: '%' is not an Idyllium operator — remainder is the function mod(a, b)
```

### 4.3. Дробное в целое

**Ребёнок пишет** `int A = 7.9;`.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ГРОМКО | Ошибка компиляции. |
| C++ | **ТИХО** | Присваивает `7`. Дробная часть исчезает без единого слова. В сочетании с §4.1 именно так арифметика новичка тихо становится целочисленной во всей программе. |
| Python | ТИХО | Переменная просто меняет тип. Ничего не нарушено, потому что ничего и не обещалось, — ровно поэтому по такому коду нельзя преподать понятие «тип». |
| JavaScript | ТИХО | Целого типа, который можно было бы нарушить, попросту нет. |

**Ответ Idyllium:**

```text
compile error: cannot assign 'float' value to 'int' variable
```

Расширяющее направление разрешено (`float c = a;`, где `a` — `int`), как
в математике: любое целое — вещественное число, но не наоборот.

### 4.4. Деление на ноль, корни из отрицательных и семейство NaN

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ГРОМКО/НЕВНЯТНО | Ошибка времени выполнения (целочисленное деление) либо исключение сопроцессора. |
| C++ | **ТИХО/ПАДЕНИЕ** | Целочисленное деление на ноль — неопределённое поведение: обычно падение без внятного объяснения; вещественное деление даёт `inf`. |
| Python | ГРОМКО | `ZeroDivisionError` — ясно, хотя и завёрнуто в трассировку. |
| JavaScript | **ТИХО** | `5 / 0` — это `Infinity`, `0 / 0` — `NaN`, `Math.sqrt(-4)` — `NaN`. Дальше `NaN` расползается по всем последующим вычислениям и печатается там, где ждали число, — а `NaN === NaN` **ложно**, так что даже проверка, которую придумал бы ученик, не работает. |

**Ответ Idyllium** — в консольном году нет ни `NaN`, ни `Infinity` вовсе;
каждый такой случай — ошибка времени выполнения, называющая проступок:

```text
runtime error: division by zero
runtime error: math.sqrt() expects a non-negative number, got -4
```

### 4.5. Переполнение целого

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ТИХО | Типы фиксированной ширины заворачиваются по кругу (проверка диапазона во многих настройках выключена). |
| C++ | **ТИХО** | Переполнение знакового — неопределённое поведение; на практике значение заворачивается, и программа продолжает с бессмысленным числом. |
| Python | ОК | Целые произвольной точности. |
| JavaScript | ТИХО | За пределами 2^53 целые молча теряют точность: `9007199254740993` печатается как `9007199254740992`. |

**Ответ Idyllium** — `int` произвольной точности, проверено:

```idyllium
int a = 4611686018427387904;
console.writeln(a * a);   // 21267647932558653966460912964485513216
```

### 4.6. Показ вещественных чисел

Все языки этого сравнения хранят вещественные в двоичном виде, поэтому
`0.1 + 0.2` нигде не равно ровно `0.3`. Различается то, что *видит ребёнок*.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | НЕВНЯТНО | `writeln` вещественного по умолчанию печатает научную нотацию (` 3.00000000000000E-001`), пока ученик не выучит аргументы форматирования. |
| C++ | ОК | Точность `cout` по умолчанию (6 значащих цифр) печатает `0.3`. |
| Python | **ТИХО** | `print(0.1 + 0.2)` печатает `0.30000000000000004` — формально честно, педагогически граната на третьем уроке. |
| JavaScript | **ТИХО** | То же самое: `0.30000000000000004`. |

**Ответ Idyllium** — показ по умолчанию человеческий, а честность сохранена
там, где она нужна:

```idyllium
console.writeln(0.1 + 0.2);            // 0.3
console.writeln((0.1 + 0.2) == 0.3);   // false
console.writeln((0.1 + 0.2) - 0.3);    // 5.551115123125783e-17
console.writeln(1.0 / 3.0);            // 0.33333333
```

Вещественные печатаются с точностью до восьми знаков после запятой, хвостовые
нули срезаются. Ненулевое значение, слишком мелкое для текущей точности,
уходит в экспоненциальную форму, а не печатается обманчивым `0`.
`console.set_precision(digits)` открывает ручку, когда уроку это нужно. Урок
про двоичное представление, таким образом, доступен по требованию (`==`,
вычитание), а не подстерегает ученика на третьем занятии.

## 5. Ввод с консоли

**Ребёнок пишет** строку ввода сразу после строки вывода и ждёт симметрии
с тем, что уже знает.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК / НЕВНЯТНО | `readln(A)` идеально зеркалит `writeln(A)`, и разбор определяется типом `A`. Плохой ввод обрывает программу с `Runtime error 106` — громко, но число ребёнку ничего не говорит. |
| C++ | **ТИХО** | `cin >> A` красиво зеркалит `cout << A` — ровно до момента, когда пользователь набрал буквы. Тогда `A` становится `0`, поток переходит в сбойное состояние, **все последующие чтения пропускаются**, и программа доходит до конца, печатая чепуху. Это самая вредная тихая ошибка консольного года: программа не падает, она врёт. |
| Python | ГРОМКО / неуклюже | `A = int(input('...'))` — функция внутри функции, скобки в два уровня, и всё это в день, когда ученик ещё не встречал функций. `input()` всегда возвращает строку, так что преобразование обязательно. На плохом вводе — `ValueError` с трассировкой: громко, но трассировка — это пять строк шума вокруг одного полезного слова. |
| JavaScript | **ТИХО** | `prompt()` всегда возвращает строку; `Number(prompt())` на мусоре даёт `NaN`. Нажатие *Отмена* возвращает `null`, а `Number(null)` — это **`0`**: программа продолжает с числом, которого пользователь не набирал. |

**Ответ Idyllium** — именованная функция на каждый тип, симметрия с выводом,
никакой вложенности и громкий отказ на плохом вводе:

```idyllium
console.write("Введите число: ");
int a = console.get_int();
string name = console.get_string();
float h = console.get_float();
```

```text
runtime error: cannot convert input to 'int' (expected integer, got "сорок два")
runtime error: cannot convert input to 'int' (expected integer, got "")
compile error: 'get_int' expects 0 arguments, got 1
compile error: cannot assign 'int' value to 'string' variable
```

Сообщение цитирует *то, что пользователь на самом деле набрал*, — включая
пустую строку: случай, когда ученик дважды нажал Enter и иначе не понял бы,
что произошло.

## 6. Условия и блоки кода

### 6.1. Где блок начинается и где кончается

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК / ловушка | `begin`/`end` читаются. Но правила точки с запятой ходят у ученика под ногами: после `end` однобранчевого `if` точка с запятой нужна; перед `else` — запрещена; финальный `end` программы берёт точку. Профессионалу объяснимо («`if` — это оператор, а не конструкция»), новичку — непреподаваемо, и он заключает, что язык произволен. |
| C++ | ОК | Фигурные скобки ограничивают блоки; наличие или отсутствие `;` чисто разделяет *операторы* и *конструкции*. Эталонное решение. |
| Python | **ТИХО** | Блок — это отступ. Смешение табов и пробелов даёт либо `TabError`, либо — что хуже, исторически и в редакторах, преобразующих при сохранении, — код, работающий **с другой структурой блоков, чем видит ученик**. Забытое двоеточие сообщает `invalid syntax` без намёка, в конце какой строки его не хватает. |
| JavaScript | ОК | Фигурные скобки, как в C++. |

### 6.2. Залётная точка с запятой

**Ребёнок пишет** `if (A > 10);`, потому что «каждая строка кончается точкой
с запятой».

| Язык | Поведение |
|---|---|
| Pascal | ТИХО — `if (A > 10) then ;` — законный пустой оператор; блок ниже выполняется всегда. |
| C++ | **ТИХО** — классика. `if` управляет пустым оператором, скобки ниже становятся безусловным блоком, программа тихо неверна. |
| Python | неприменимо — двоеточие не даёт получиться такой форме. |
| JavaScript | **ТИХО** — как в C++. |

**Ответ Idyllium** — пустой оператор не может стоять после условия:

```text
compile error: expected expression, got ';'
```

### 6.3. Присваивание внутри условия

**Ребёнок пишет** `if (a = 5)` — самая предсказуемая ошибка новичка в любом
языке C-семейства, потому что школьная математика пять лет учила читать `=`
как «равно».

| Язык | Поведение |
|---|---|
| Pascal | ГРОМКО — `:=` и `=` разные символы; ошибку невозможно совершить. |
| C++ | **ТИХО** — присваивает 5, потом проверяет `5` на истинность. Компилируется. Большинство компиляторов предупредят, только если предупреждения включены и кто-то их читает. |
| Python | ГРОМКО — синтаксическая ошибка (а морж `:=` включается сознательно). |
| JavaScript | **ТИХО** — как в C++. |

**Ответ Idyllium** — прицельная ошибка компиляции с готовым лечением
в сообщении:

```text
compile error: assignment '=' is not allowed in a condition — did you mean '==' ?
```

### 6.4. Истинность — числа и строки в роли условия

**Ребёнок пишет** `if (a)` в смысле «если a существует / задано».

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ГРОМКО | Несовпадение типов. |
| C++ | **ТИХО** | Любое ненулевое число истинно, включая `-1`; любой ненулевой указатель истинен. |
| Python | ТИХО | Пустая строка, пустой список, `0` и `None` ложны; правило преподаваемо, но список членов длинный. |
| JavaScript | **ТИХО** | Самый длинный такой список среди языков: `''`, `0`, `NaN`, `null`, `undefined` ложны; `'0'`, `'false'`, `[]` истинны. |

**Ответ Idyllium** — условия принимают только `bool` и говорят, что получили:

```text
compile error: if condition must be 'bool', got 'int'
compile error: if condition must be 'bool', got 'string'
compile error: while condition must be 'bool', got 'int'
```

Это закрывает всё семейство случайностей «сработало, потому что число было
не ноль», включая `while (items.length)`, которым пользуются взрослые кодовые
базы и который ни один новичок не защитит на экзамене.

### 6.5. `else if`, написанный по-питоновски

Пришедшие из Python пишут `elif`. Idyllium отвечает подсказкой, а не ошибкой
разбора:

```text
compile error: 'elif' is not an Idyllium keyword — write 'else if'
```

## 7. Составные условия

### 7.1. «если A и B больше нуля»

**Ребёнок пишет** `if (A and B > 0)` — буквальную запись правильной русской
фразы, в которой одно сравнение законно обслуживает два подлежащих.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ГРОМКО | У `and` приоритет выше сравнения, поэтому `A and B > 0` не компилируется или даёт ошибку типов — промах всплывает. |
| C++ | **ТИХО** | `A && B > 0` вычисляет `B > 0`, потом проверяет `A` на ненулевость. Компилируется, работает и на большинстве тестовых данных *случайно печатает верный ответ* — худший из возможных исходов, потому что ученик уносит заблуждение дальше. |
| Python | ТИХО | Та же форма: `A and B > 0` законно и означает не то, что задумано. |
| JavaScript | **ТИХО** | То же самое. |

**Ответ Idyllium** — логические операторы принимают только `bool`:

```text
compile error: operator 'and' requires bool operands
```

### 7.2. `not` без скобок

**Ребёнок пишет** `if (not A > 35)`.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | **ТИХО** | `not` связывает крепче сравнения, поэтому сначала вычисляется `not A` — на целом операнде это побитовое дополнение, — и сравнение проверяет число, которого никто не задумывал. Компилируется, работает, неверно. |
| C++ | **ТИХО** | Идентично: `!A < 0` становится `(!A) < 0`, то есть `false < 0`, то есть `0 < 0`. Чтобы объяснить эту цепочку новичку, нужны четыре понятия, которых у него ещё нет. |
| Python | ОК | У `not` приоритет ниже сравнения; `not A > 35` означает задуманное. |
| JavaScript | **ТИХО** | Как в C++. |

**Ответ Idyllium:**

```text
compile error: operator 'not' requires 'bool', got 'int'
```

### 7.3. Цепочка сравнений

**Ребёнок пишет** `if (0 < a < 100)` — снова верную математику.

| Язык | Поведение |
|---|---|
| Pascal | ГРОМКО — ошибка типов. |
| C++ | **ТИХО** — `(0 < a)` даёт bool, который затем сравнивается со 100; условие истинно для *любого* `a`. |
| Python | ОК — цепочка сравнений здесь настоящая возможность и означает математическое. |
| JavaScript | **ТИХО** — как в C++. |

**Ответ Idyllium:**

```text
compile error: comparison '<' requires numeric operands, got 'bool' and 'int'
```

### 7.4. Сценарий «любознательный ученик»

Почему эти три пункта важнее, чем следует из их частоты: в C++ и JavaScript
каждый из них **компилируется, работает и часто печатает ожидаемое
на демонстрационных данных**. Ученик, который попробовал убрать скобки,
увидел, что «всё равно работает», и усвоил привычку, встретит ошибку через
несколько месяцев в коде, который важен, — и уже не вспомнит день, когда
привычка сложилась. В Idyllium каждый из трёх отвергается ещё до запуска.

## 8. Циклы

### 8.1. `while`

Здесь все четыре языка согласны, и Idyllium с ними: `while` + условие + блок.
Единственное отличие — §6.4: Idyllium требует, чтобы условие было `bool`,
поэтому `while (n)` и `while (items.length)` не компилируются.

### 8.2. `for`

**Ребёнку нужно** «повторить это 20 раз», и он встречает ключевое слово,
которое переводится как «для».

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК / ограниченно | `for i := 0 to 19 do` — счётчик объявлен самим учеником, а граница включительная, как в речи. Но шаг зафиксирован на ±1 (`to`/`downto`); любой другой требует собранного вручную `while`. |
| C++ | ОК | Трёхчастный заголовок многословен, но это *конструктор*: старт, условие, шаг — всё из уже выученного. Ловушка: `i++` — новый оператор с двумя формами и значением. |
| Python | **ТИХО/НЕВНЯТНО** | `for i in range(20)`: (а) `i` не выглядит переменной — её нигде не объявляли, и ученики регулярно заводят рядом второй счётчик; (б) `range` принимает один, два или три аргумента с разными смыслами; (в) верхняя граница **исключается** — сразу после урока, где `randint(0, 10)` её **включал**. |
| JavaScript | ОК / ловушка | Заголовок в стиле C; историческая ловушка захвата `var` в замыканиях до сих пор встречается в скопированном коде. |

**Ответ Idyllium** — конструктор в стиле C, счётчик объявлен явно и ограничен
областью видимости, а ловушка `++` перехвачена:

```idyllium
for (int i = 0; i < 20; i = i + 1) {
    console.writeln(i);
}
console.writeln(i);   // compile error: 'i' was not declared in this scope
```

```text
compile error: '++' is not an Idyllium operator — write 'i = i + 1'
```

Составные присваивания (`+=`, `-=`) в языке есть, но материалы курса
сознательно пользуются полной формой `x = x + 1`, которая держит на виду обе
роли переменной: источник справа, приёмник слева.

## 9. Случайные числа

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ТИХО | `random(30)` возвращает 0..29 — верхняя граница *исключена*, тогда как речь говорит «до 30». Хуже того: без `Randomize` **каждый запуск даёт одну и ту же последовательность**, без предупреждения. Игра ученика в кости детерминирована, и он не видит почему. |
| C++ | НЕВНЯТНО | `rand() % 50` требует рассуждения про периодичность остатка в тот самый день, когда вводится случайность; `srand(time(0))` требует сидов, эпох и постороннего заголовка. Без него — та же последовательность каждый запуск, тихо. Плюс: тему *можно* преподать во всю глубину, и для сильных групп это настоящая учебная ценность. |
| Python | ОК | `random.randint(24, 52)` — обе границы включены, сид ставится сам. Яснее всех четырёх. Минус: псевдослучайность нигде не всплывает, и ученики верят, что компьютер «просто знает» случайные числа. |
| JavaScript | НЕВНЯТНО | `Math.floor(Math.random() * 50)` — два вложенных вызова и арифметическое преобразование на каждое случайное число. Управления сидом нет вовсе, поэтому урок о псевдослучайности не просто пропущен — он невозможен. |

**Ответ Idyllium** — включающие границы, автоматический сид, управление сидом
доступно, когда уроку нужно, а неверный диапазон отвергается громко:

```idyllium
use random;

int a = random.create_int(24, 52);     // обе границы включены
float b = random.create_float(1.0, 4.0);
random.set_seed(42);                    // воспроизводимые прогоны, когда учим ГПСЧ
```

```text
runtime error: random.create_int() min must be less than or equal to max (got min 100, max 1)
```

`create_int` называет собственное действие («создать целое»), и оба аргумента
означают ровно то, о чём догадается ребёнок. Урок про псевдослучайность
*доступен* (`set_seed`), а не *обязателен* (C++) и не *невозможен*
(JavaScript).

## 10. Массивы фиксированного размера

Массивы — место, где частота ошибок новичка подскакивает, потому что выигрыш
появляется, только когда сложится несколько инструментов сразу. Поэтому то,
что делает язык *в момент промаха*, здесь важнее, чем где бы то ни было.

### 10.1. Чтение и запись за границей массива

**Ребёнок пишет** `A[10]` для массива из четырёх ячеек.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | **ТИХО** | С выключенной проверкой диапазона (обычная настройка по умолчанию) программа читает или пишет ту память, которая там оказалась. Привычка доверять индексам складывается без всякого сопротивления. |
| C++ | **ТИХО** | Неопределённое поведение: читает мусор, портит соседние данные. Программа может упасть через несколько минут в постороннем коде. Худший для отладки отказ всего консольного года. |
| Python | ГРОМКО | `IndexError: list index out of range` — единственное место, где Python строже двух других старых языков. |
| JavaScript | **ТИХО в обе стороны** | Чтение `A[10]` возвращает `undefined`; **запись** `A[10] = 99` расширяет массив дырами. Здесь нет даже единственной победы Python. |

**Ответ Idyllium** — громко и на чтении, и на записи, а сообщение называет
допустимый диапазон, превращая ошибку в микроурок:

```text
runtime error: array index 10 out of bounds (size 4, valid indices 0-3)
```

### 10.2. Операция над всем массивом по случайности

**Ребёнок пишет** `B = 240;`, или `cout << B;`, или `if (A > B)`.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ГРОМКО | Любая операция над массивом целиком — ошибка; пользоваться можно только ячейками. Педагогически чисто. |
| C++ | **ТИХО** | `cout << B` печатает **адрес** массива; `A > B` сравнивает **адреса**. И то и другое компилируется, и то и другое что-то печатает, и то и другое для ученика бессмысленно. |
| Python | **ТИХО** | `F = 240` молча уничтожает список и привязывает имя к числу; `A > G` сравнивает списки поэлементно (защитимо, но непреподаваемо на этом этапе); `print(A)` печатает весь список, приучая к тому, что «команды работают со списком целиком», — ровно до первой команды, которая так не умеет. |
| JavaScript | ТИХО | Похоже, плюс `A.length = 2` **обрезает массив** присваиванием в свойство. |

**Ответ Idyllium:**

```text
compile error: cannot assign 'int' value to 'array<int, 4>' variable
compile error: property 'length' is read-only
compile error: array element type 'string' does not match 'int'
```

Размер — часть типа (`array<int, 4>`), поэтому фиксированный массив не может
молча стать чем-то другим. Единственное сознательное исключение:
`console.writeln(a)` печатает весь массив (`[1, 2, 3, 4]`), потому что отладочная
печать дороже догмы. Тексты курса проговаривают это прямо — **печать
единственная операция, принимающая массив целиком**, — именно чтобы
питоновское обобщение («раз print умеет, то и всё остальное умеет») никогда
не сложилось.

### 10.3. Нумерация с нуля или с единицы

Pascal разрешает `array [1..50]`, что избавляет новичка от перевода в нулевую
нумерацию, но сажает привычку, за которую его накажет любой другой язык;
а его же динамические массивы начинаются с 0, противореча статическим.
В Idyllium нумерация с нуля везде, без исключений, которые надо помнить,
и сообщение о выходе за границу называет допустимый диапазон при каждом
промахе.

## 11. Динамические массивы

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | НЕУКЛЮЖЕ | `setLength(K, length(K) + 1)`, чтобы добавить одну ячейку; никакого API «через точку»; и переход от статических массивов с единицы к динамическим с нуля падает на тот же урок. |
| C++ | ОК | `vector<int> K; K.push_back(x);` — разумно, но три семейства скобок в одной теме: угловые для типа, круглые для метода, квадратные для ячейки. |
| Python | ОК | `K.append(x)` — образцовая реализация. Единственный её изъян — тот же, что в §10: отдельного понятия «статический массив» не существует, поэтому «у массива фиксированный размер» никогда не выучивается. |
| JavaScript | ТИХО | `push` хорош, но действует §10.1: дыры и `undefined` находятся в одной опечатке. |

**Ответ Idyllium** — отдельный тип держит границу «статический / динамический»
на виду, с коротким глаголом и теми же скобочными привычками, что
у фиксированных массивов:

```idyllium
dyn_array<int> k;
k.add(24);
k.add(73);
console.writeln(k.length, " ", k[0]);   // 2 24
console.writeln(k);                      // [24, 73]
console.writeln(k[5]);
```

```text
runtime error: array index 5 out of bounds (size 2, valid indices 0-1)
compile error: type 'dyn_array<int>' has no method 'size'
```

`length` — свойство у массивов обоих видов (не `len(x)`, не `.size()`,
не `.Length`), так что одна привычка покрывает строки, массивы и динамические
массивы.

## 12. Символы и строки

### 12.1. Нелатинский текст — катастрофа «шесть букв стали двенадцатью»

**Ребёнок пишет** `S = 'белый'` и спрашивает длину.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | **ТИХО** | `length('белый')` — это **10**: строка это массив байтов, а каждая кириллическая буква занимает в UTF-8 два байта. `Q[1]` печатает половину буквы — символ-заменитель. Любое строковое упражнение, написанное по-русски, ломается, а лечение требует преподавать кодировки в день, когда вводятся строки. |
| C++ | **ТИХО** | Идентично: `Q.size()` — 10, `Q[0]` — половина буквы. |
| Python | ОК | `len('белый')` — 5, `B[0]` — `'б'`. Текст есть текст. |
| JavaScript | ОК (почти) | Кодовые единицы UTF-16: верно для кириллицы, по-прежнему неверно для эмодзи и редких письменностей. |

**Ответ Idyllium** — сверено с компилятором:

```idyllium
console.writeln("белый".length);   // 5
console.writeln("белый"[0]);       // б
console.writeln("ёжик".length);    // 4
```

### 12.2. Арифметика над символами и строками

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК | `char` — самостоятельный тип; `'a' + 1` — ошибка; `ord()`/`chr()` преобразуют явно. |
| C++ | **ТИХО, эффектно** | `char` — маленькое целое: `'A' + 'j'` — это `171`; `char B = B + 3` сдвигает букву. И жемчужина короны: `string B = "capability" + 3;` компилируется и даёт **`"ability"`** — арифметика указателей по строковому литералу. Ни одному ученику из сотни нельзя объяснить почему, а те, кто это откроет, теряют доверие к языку. |
| Python | ГРОМКО | `'text' + 3` немедленно поднимает `TypeError`. Зато `'ab' * 3` — законное повторение строки: приятный фокус, тихо приучающий к тому, что `*` работает с текстом. |
| JavaScript | **ТИХО, катастрофически** | `'5' + 1` — это `'51'`, а `'5' - 1` — это `4`. Один и тот же операнд, четыре оператора, две философии. Для ученика, чей ввод приходит строкой из `prompt()`, это событие каждого дня. |

**Ответ Idyllium** — склейка только для строк; всё остальное отвергается:

```text
compile error: operator '+' cannot be applied to 'string' and 'int'
compile error: operator '*' cannot be applied to 'string' and 'int'
compile error: operator '+' cannot be applied to 'char' and 'int'
compile error: operator '+' cannot be applied to 'char' and 'char'
```

`string + char` **разрешено** (`"кот" + 'a'` даёт `"кота"`), что совпадает
со здравой половиной паскалевского правила. Числа присоединяются к тексту
именованным преобразованием `to_string(x)` либо просто передаются
в `console.writeln(...)` дополнительными аргументами — эту форму материалы
курса показывают первой.

### 12.3. Сравнение и изменение строк

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal / C++ | ТИХО | `R < S` сравнивает побайтово, что выглядит как алфавитный порядок ровно до первой кириллической строки или заглавной буквы. |
| Python | ТИХО | Тот же порядок по кодовым позициям, та же иллюзия. |
| JavaScript | **ТИХО** | `'5' == 5` — **истина**; `S[0] = 'w'` **молча не делает ничего** (строки неизменяемы, а присваивание вне строгого режима не ошибка). |

**Ответ Idyllium** — для строк определено только равенство, а изменение
отвергается, а не игнорируется:

```text
compile error: comparison '<' requires numeric operands, got 'string' and 'string'
compile error: cannot compare 'string' and 'int'
compile error: cannot compare 'string' and 'char'
compile error: string characters are read-only
```

Алфавитный порядок — это *задача* (напишите то сравнение, которое вы и имели
в виду), а не скрытая побайтовая случайность.

## 13. Логический тип

**Ребёнок пишет** `N = 24 + F;`, где `F` — флаг, или `if (F == 1)`.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК | Логическое есть логическое. Любая смесь с арифметикой или сравнением — ошибка компиляции. Эталонное поведение. |
| C++ | **ТИХО** | `bool` — переодетое целое: `F = 24` сохраняет `true`; `F = "island"` сохраняет `true`; `24 + F` — это `25`; `F - 1` — это `false`; а по умолчанию `cout << F` печатает **`1`**, а не `true`, так что первое, что ученик видит в логическом типе, — число. |
| Python | ТИХО | `True` *и есть* `1`: `24 + True` — это `25`, `True == 1` истинно. |
| JavaScript | **ТИХО** | Всё вышеперечисленное плюс таблица приведений со строками вроде «`[] == false` истинно». |

**Ответ Idyllium** — строгость Pascal плюс честная печать:

```text
compile error: operator '+' cannot be applied to 'int' and 'bool'
compile error: comparison '<' requires numeric operands, got 'bool' and 'int'
```

```idyllium
bool f = true;
console.writeln(f);              // true
console.writeln(to_string(f));   // true
```

## 14. Функции

### 14.1. Объявление

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК / ловушка | Чистое разделение `procedure` и `function`. Две ловушки: результат отдаётся **присваиванием в собственное имя функции** (`stepen := R;`), что приучает к мысли «функция — это разновидность переменной» — заблуждение, дословно слышанное на экзаменах; и тип результата стоит *после* списка параметров, так что список из двух `integer`, за которым идёт `: integer`, читается двусмысленно. К тому же вызов без аргументов можно писать без `()`, стирая зрительную границу между тем, что *хранит*, и тем, что *действует*. |
| C++ | ОК | Тип результата перед именем, `return` для результата, скобки обязательны всегда. Эталонное поведение. `void` явно называет случай «результата нет». |
| Python | ТИХО | `def` — сокращение, которого ученик больше нигде не встретит. Тип результата не пишется, так что «процедуру» от «функции» отличает только наличие `return`, — а забыв его, получаешь `None`, который расползается дальше. `global` по запросу заново открывает побочные эффекты. |
| JavaScript | **ТИХО, основательно** | Ключевое слово `function` — лучшее из четырёх. Всё вокруг него не охраняется: недоданные аргументы становятся `undefined` (и арифметика над ними даёт `NaN` пятью строками позже), лишние аргументы игнорируются, отсутствующий `return` даёт `undefined`, а стрелочные функции добавляют третий синтаксис для того же понятия в каждом примере из интернета. |

**Ответ Idyllium** — полное слово `function`, тип результата спереди, и любое
несовпадение количества и типов отвергается:

```idyllium
int function stepen(int num, int s) {
    int r = 1;
    for (int i = 0; i < s; i = i + 1) { r = r * num; }
    return r;
}
```

```text
compile error: function with return type 'int' must return a value
compile error: 'stepen' expects 2 arguments, got 1
compile error: 'stepen' expects 2 arguments, got 3
compile error: cannot return 'string' value from 'int' function
compile error: cannot assign 'void' value to 'int' variable
```

`void` — настоящий тип, как в C++, поэтому «ничего не возвращает» видно
в сигнатуре, а не выводится из отсутствия `return`.

### 14.2. Чистота и глобальные переменные

C++ даёт новичку случайную дисциплину: поскольку `main` сам по себе функция,
ничто из написанного первокурсником не глобально, и результат обязан ехать
через `return`. Pascal и Python оба предлагают лёгкий побег (`global` или
просто переменные верхнего уровня), а JavaScript раздаёт глобальные бесплатно
за одну опечатку. Idyllium оставляет переменные верхнего уровня доступными —
курс пользуется ими скупо в первый год и бросает на третьем, где состояние
забирают классы, — но компилятор по-прежнему отказывается выдумывать
переменную, которую не объявляли, поэтому javascript-овский отказ «опечатка
стала глобальной» здесь невозможен.

## 15. Текстовые файлы

Последняя тема консольного года и та, где «забыл закрыть» традиционно
наказывается пустым файлом без всяких объяснений.

| Язык | Поведение | Подробности |
|---|---|---|
| Pascal | ОК / провал в именах | `writeln(F, ...)` и `readln(F, ...)` идеально продолжают консольные привычки — лучшая параллель из четырёх. `eof(F)` читается по-английски. Открытие отсутствующего файла падает громко, что педагогически честно. Но три команды открытия — заклинания с *отрицательной* ассоциативностью: `Rewrite` открывает **на запись** (и стирает файл — ученики читают это как «редактировать существующий»), `Reset` открывает **на чтение** (в переводе — «сброс»), и только `Append` честен. |
| C++ | ОК / ТИХО | `fout`/`fin` в точности наследуют `cout`/`cin` — язык наконец собирает урожай со своего мучительного первого урока. А дальше: `while (getline(fin, S))` — откровенный чёрный ящик (функция в роли условия); `>>` и `getline` читают по-разному и взаимодействуют через оставшийся в буфере перевод строки, что лечится необъяснимым `fin.ignore()`; и **открытие отсутствующего файла происходит молча** — поток в сбое, цикл чтения не выполняется ни разу, программа заканчивается без вывода и без подсказок. |
| Python | ОК / смерть от тысячи порезов | `open(path, mode)` — лучшее название операции открытия из четырёх. А дальше: запись идёт через `write`, а не `print`, ломая консольную параллель; `write` не добавляет перевод строки; `write` принимает **только строки**, так что числам нужен `str()`; каждая прочитанная строка приходит с хвостовым `'\n'`, из-за чего сравнения молча не срабатывают, пока не применили `.strip()`; методов чтения три, они различаются двумя буквами (`read`, `readline`, `readlines`) и делают совершенно разное; а идиоматичное `with open(...) as f:` — это три незнакомых слова в день, когда вводятся файлы. |
| JavaScript | ОТСУТСТВУЕТ | У браузерного JavaScript нет файловой системы. Тема заменяется на `localStorage` (хранилище «ключ — строка», стираемое вместе с данными браузера), поэтому весь понятийный мост от консоли к файлу попросту не существует. |

**Ответ Idyllium:**

```idyllium
use file;

file.ostream fout = file.open("data.txt", "write");
fout.write_line("Первая строка");
fout.write_line(25);          // числа можно, ровно как в console.writeln
fout.close();

file.istream fin = file.open("data.txt", "read");
while (fin.has_next_line()) {
    string s = fin.read_line();
    console.writeln(s.trim());
}
fin.close();
```

- **Одна команда открытия с режимом**, как в Python, — но режимы записаны
  целыми словами, а не буквами, которые надо помнить:

  ```text
  runtime error: file.open() mode must be 'read', 'write' or 'append', got 'r'
  ```

- **Отсутствующий файл — громко**, предложением, а не номером ошибки:

  ```text
  runtime error: file.open() cannot open 'нет-такого.txt' for reading: file does not exist
  ```

- **`write_line` зеркалит `console.writeln`** — та же форма, та же
  снисходительность к типам аргументов (`25`, `3.5`, `true` записываются
  корректно), и перевод строки она добавляет сама. Питоновская матрёшка
  со `str()` и ловушка отсутствующего перевода строки закрыты обе.
- **`has_next_line()` читается вопросом**, заменяя и `eof` (сокращение),
  и `while (getline(...))` (чёрный ящик).
- **Забытый `close()` не уничтожает работу.** Проверено: программа,
  записавшая 500 строк и завершившаяся без закрытия, оставляет на диске все
  500 строк. Классическая травма файловой темы — «программа выглядит
  правильно, а файл пустой» — здесь невозможна. Закрытию по-прежнему учат,
  потому что открытый поток — настоящее понятие, но забыть о нём больше
  не значит молча потерять данные.

**Задокументированное поведение (вердикт владельца):** `read_line()`
возвращает строку *вместе* с её завершителем — сознательно, по симметрии
с `write_line()`, который завершитель добавляет: что один записал, то другой
прочитал целиком. Последняя строка файла без завершающего перевода строки
приходит без него. Чистка строки — работа читающего, и `.trim()` здесь
канонический инструмент; учебный код вызывает `.trim()` после `read_line()`
как норму, а не как обходной приём.

## 16. Диагностика, которой нет больше нигде

Помимо отказа от плохого кода компилятор Idyllium перехватывает конкретные
*известные намерения новичка* и отвечает на них словами. Это не общие ошибки
типов; каждая добавлена потому, что промах наблюдался снова и снова:

| Ученик пишет | Компилятор отвечает |
|---|---|
| `if (a = 5)` | `assignment '=' is not allowed in a condition — did you mean '==' ?` |
| `i++` | `'++' is not an Idyllium operator — write 'i = i + 1'` |
| `50 % 14` | `'%' is not an Idyllium operator — remainder is the function mod(a, b)` |
| `elif (...)` | `'elif' is not an Idyllium keyword — write 'else if'` |
| `сat = 6;` (кириллическая `с`, объявлена латинская `cat`) | `variable 'сat' was not declared in this scope — but 'cat' is: the two names mix Russian and English letters that look alike` |
| `a[10]` для массива из четырёх ячеек | `array index 10 out of bounds (size 4, valid indices 0-3)` |
| `console.get_int("Введите:")` | `'get_int' expects 0 arguments, got 1` |
| `use consol;` | `module 'consol' was not found` |
| `a.size()` для массива | `type 'array<int, 3>' has no method 'size'` |

Чтение сообщений компилятора — явно преподаваемый навык курса; сообщения
написаны так, чтобы пережить машинный перевод, и ученик, не читающий
по-английски, всё равно может по ним действовать.

Идиомы, принесённые из других языков (`print(...)`, `input()`, `len(s)`,
`str(42)`), пока дают общее `function 'print' was not declared in this scope`.
Это громко и правильно, но ещё не прицельная подсказка, — стоит знать, помогая
ученику, который переводит питоновские привычки.

## 18. Честный остаток: что Idyllium по-прежнему не ловит

Документ, перечисляющий одни победы, бесполезен для написания настоящих
учебных материалов. Остаются вот эти вещи:

1. **Висящие выражения.** `a + 1;` и `a == 6;` компилируются и молча
   выполняются. Вычисленное значение испаряется. Это заблуждение
   «испаряющееся значение» в чистом виде, и компилятор сейчас его
   не помечает. (Канал предупреждений в инструментарии есть, но к этому
   случаю не подключён.)
2. **Цепочка равенств.** `a == b == false` проходит проверку типов, потому
   что `bool == bool` законно; `0 < a < 100` ловится только потому, что второе
   сравнение смешивает `bool` с числом.
3. **Затенение во вложенных блоках.** Объявить `int a` внутри `if`, когда `a`
   есть снаружи, разрешено и молча создаёт вторую переменную — то же
   поведение, что у C++ и у `let` в JavaScript.
4. **`if` из одного оператора без скобок.** `if (a > 10) console.writeln("x");`
   законно, поэтому классическая ошибка «дописал вторую строку, и она
   перестала быть внутри `if`» остаётся возможной. Материалы курса всегда
   ставят скобки.
5. **Печать массива целиком** (§10.2) разрешена сознательно.
6. **`read_line()` сохраняет перевод строки** (§15) — живой дефект,
   пользуйтесь `.trim()`.
7. **Печать значения функции — **починено**: `console.writeln(answer)`
   с голым именем функции теперь отвергается на этапе компиляции
   (`cannot print function 'answer' — add '()' with its arguments to call it and print the result`).
   Учебные примеры могут спокойно показывать этот промах: компилятор называет
   функцию и диктует лечение.

Граница — в этом весь смысл: **язык может поймать синтаксис заблуждения,
но не само заблуждение.**

## 19. Правила для ИИ, пользующегося этим файлом

1. **Не тащите чужие идиомы.** Если вопрос ученика сформулирован
   по-питоновски или по-джаваскриптовому, отвечайте на Idyllium:
   `console.writeln`, а не `print`; `console.get_int()`, а не `int(input())`;
   `k.length`, а не `len(k)`; `x = x + 1`, а не `x++`.
2. **Когда ученик переходит с другого языка, называйте конкретную ловушку**
   из таблиц выше, а не говорите «Idyllium строже». Привычка пришла
   из конкретного поведения, и лечит её конкретный контраст.
3. **Никогда не подавайте ошибку компилятора как провал.** Каждое
   процитированное здесь сообщение — урок, который выдаёт язык; объясните,
   что именно он поймал. В этом курсе «скомпилировалось, но напечатало
   странное» — исход *хуже*, чем «отказалось компилироваться».
4. **Не выдумывайте строгости, которой нет**, и не обещайте отловов из §18.
   Если ученик спрашивает, скажет ли Idyllium что-нибудь про `a + 1;`,
   сегодняшний ответ — нет.
5. **Держите список остатка в голове, когда пишете примеры**: скобки всегда,
   `.trim()` после `read_line()`, никогда голое имя функции в выводе.
6. **Не воспроизводите сравнения из этого файла как критику других языков
   в материалах для учеников.** Адресат контраста — взрослые, проектирующие
   учебные программы; ребёнку полезна только одна рамка: что делает Idyllium
   и чем это ему помогает.
