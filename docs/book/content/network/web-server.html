Другая сторона трубки

В уроке о сети ваша программа задавала вопросы: http.get — и чей-то сервер отвечал. Сегодня вы пересаживаетесь на другую сторону трубки: ваша программа сама станет сервером — будет слушать, принимать запросы и отвечать. Роль вам знакома: эхо-бот из урока про канал всегда отвечал и никогда не спрашивал. Теперь то же самое — по-настоящему, по HTTP, так, что ответ откроется в обычном браузере.

Первый сервер

Сервер слушает http://127.0.0.1:8080

Запустите — и обратите внимание: программа не завершилась. app.run() — вечный цикл в жанре программ с окном: сервер обслуживает запросы, пока его не остановят кнопкой Stop (или Ctrl+C в консоли). Пока он работает, откройте в браузере адрес из консоли — http://127.0.0.1:8080/hello — и увидите свой ответ настоящей веб-страницей. Ваша программа только что обслужила настоящий браузер.

Разберём состав. web.Server — сам сервер. on_get(путь, обработчик) — регистрация маршрута: «на такой путь отвечает такая функция». Обработчик — функция с двумя параметрами: web.Request (что спросили) и web.Response (чем ответить); жанр тот же, что у on_click, только событие называется «пришёл запрос».

Где это работает: в консольном запуске и VS Code — полноценно (VS Code особенно удобен: сервер в редакторе, браузер рядом). Web IDE сам живёт внутри браузера, а браузеру запрещено слушать порты — поэтому там программа поднимает сервер-репетицию: консоль печатает особый адрес вида …/preview/8080/, и по нему ваш сайт открывается в соседней вкладке. Код ровно тот же, ответы ровно те же — но видит этот сайт только ваш браузер: это репетиция перед настоящим выступлением. Настоящий сервер, к которому сможет прийти сосед по классу, программа поднимет в VS Code или консоли.

Маршруты и 404

Маршрутов может быть сколько угодно — по функции на путь. Путь сравнивается точно: /hello и /hello/ — разные адреса. А что, если спросят путь, которого нет? Сервер сам ответит 404 — и вы теперь знаете эту механику с обеих сторон: в уроке о сети ваша программа читала 404 от чужого сервера, сегодня ваш сервер 404 отправляет. Адрес умеет нести параметры — вы видели их в строке браузера тысячу раз: ?name=Мира&level=12. На сервере они достаются методом req.query:

http://127.0.0.1:8080/greet?name=Мира ответит «Привет, Мира!», а без параметра query вернёт пустую строку — и воспитанный сервер подскажет, чего ему не хватило.

Положите в папку public файл index.html (и хоть целый сайт: страницы, стили, картинки) — адрес http://127.0.0.1:8080/ отдаст index.html, остальные файлы доступны по своим именам. Сервер не падает

Что будет, если обработчик сломается — например, поделит на ноль? Упасть целиком сервер не имеет права: один неудачный запрос — не повод бросить остальных посетителей. Поэтому авария обработчика превращается в ответ 500 тому, кто спросил, и строку с текстом ошибки в консоли сервера — чините по ней; остальные запросы обслуживаются дальше. Самому посетителю текст ошибки не показывают: в нём имена файлов, строк и таблиц вашей программы, а это не для чужих глаз. Пока посетитель — вы сами, можно включить app.debug = true; — тогда текст ошибки придёт и в ответ; перед показом другим выключите. Пятисотые коды из урока о сети — «у меня самого всё сломалось» — рождаются ровно так.

Кому виден ваш сервер

По умолчанию сервер слушает адрес 127.0.0.1 — это «только мой компьютер»: ни сосед по парте, ни кто-либо из сети ваш сервер не увидит. Так же по умолчанию ведут себя взрослые фреймворки, и это правильный дефолт: учебный сервер не должен случайно оказаться доступным всем.

Открыть сервер классу — явное решение программиста: app.host = "0.0.0.0";. Честное слово, которое надо понимать, произнося эту строку: она делает вашу программу доступной всей локальной сети — любому устройству вашего вайфая. Сервер даже напишет об этом в консоли. Сценарий «сервер у одного — клиенты у всех» мы разыграем отдельно, когда дойдём до классных проектов.

И последняя житейская мелочь: порт может оказаться занят — например, вторым запуском вашего же сервера. Ошибка читаемая: port 8080 is already in use — choose another port or stop the other program. Порт меняется свойством: app.port = 8081;.
