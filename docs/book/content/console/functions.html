Функции — уже знакомые нам инструменты

Ранее мы уже многократно использовали функции:

Во всех случаях функция превращает входные данные в выходные.

Вход и выход — основа функции

  • Входные данные (аргументы) — то, что мы передаём функции при вызове;
  • Выходные данные (результат) — то, что функция возвращает после выполнения.

По сути, функция — это механизм для превращения одних данных в другие.

Синтаксис объявления функции

Функция — это блок кода, который один раз описывается, а затем может многократно использоваться.

Функция как сущность

У функции есть:

  • тип — что она возвращает (int, float, и т.д.);
  • название — по которому к ней обращаются;
  • набор действий — что она делает, когда её вызывают.

Это похоже на переменную (у неё тоже есть тип, имя и содержимое), но вместо данных — действия.

Пример: создание собственной функции abs_value()

Воссоздадим поведение math.abs(), но своими руками. Назовём функцию abs_value — от английского absolute value, «модуль числа»:

23 40

Мы сами решили, что делает эта функция, и теперь можем использовать её где угодно.

Функция с массивами: mul_all()

Создадим функцию, которой ещё не было — она вычисляет произведение всех чисел в динамическом массиве:

720 24024

Обратите внимание: в теле main() переменная some_arr не объявлена. Она существует только внутри функции и заменяется на реальный аргумент при вызове.

Это ключевой принцип: описание функции использует временные имена, а вызов — реальные данные, подходящие по типу.

void-функции: когда не нужно возвращать значение

Слово void переводится как «пустота». Функция типа void ничего не возвращает, а значит, не требует оператора return.

Такие функции полезны, когда нужно выполнить действие (например, вывести данные), но не получить результат.

У аргументов есть имена

Функция может принимать несколько аргументов. При обычном вызове они попадают в параметры слева направо. Но иногда полезно прямо написать, какое значение предназначено какому параметру.

15 15

Во втором вызове аргументы переданы в обратном порядке, но их имена не дают функции перепутать ширину с высотой. Именованные аргументы особенно удобны, когда у функции много похожих параметров.

Можно сначала передать позиционные аргументы, а затем именованные. После первого именованного аргумента возвращаться к позиционным уже нельзя. Один параметр нельзя передать дважды, а имя должно совпадать с объявлением функции.

Значение по умолчанию

Иногда один из аргументов почти всегда одинаковый. Тогда в объявлении функции можно задать ему значение по умолчанию. При вызове такой аргумент разрешается не указывать.

Привет, Мира! Доброе утро, Лиам! С возвращением, Саша!

В первом вызове greeting не указан, поэтому функция берёт строку "Привет". Во втором и третьем вызовах стандартное приветствие заменено другим.

Сначала в объявлении идут обязательные параметры, а после них — параметры со значениями по умолчанию. Иначе короткий вызов был бы неоднозначным.

main.idyl:3:56: compile error: parameter 'name' without default value cannot follow a parameter with default value

main тоже является функцией

С первого урока мы писали main() { ... }, хотя ещё не знали функций. Это специальное педагогическое сокращение для void function main(). Теперь при желании можно записать полную форму.

main тоже умеет возвращать значение

У main не должно быть аргументов, а во всей программе может существовать только одна такая функция. Idyllium разрешает ей любой обычный возвращаемый тип, но тогда подходящий return становится обязательным.

А что происходит с возвращённым значением? Его показывает среда запуска — серой строкой после того, как программа закончила работу:

[Программа завершилась с кодом 0]

Это код завершения — короткий отчёт программы о том, чем всё кончилось. Договорённость всего мира программ такая: ноль значит «всё прошло хорошо», любое другое число — «что-то пошло не так», а какое именно число за что отвечает, решает автор программы. В терминале этот код видит не только человек: по нему другие программы понимают, стоит ли продолжать работу.

Обратите внимание: серая строка — это не вывод вашей программы, а сообщение среды. В файл она не попадёт и в console её нет. А у void-овой main её не будет вовсе: раз функция ничего не возвращает, то и сообщать нечего.

Короткая запись main() { ... } никуда не исчезает. Для большинства учебных программ она остаётся самой простой и удобной.

Выйти досрочно: system.exit()

Иногда продолжать работу бессмысленно: файл не найден, данные испорчены, пользователь передумал. Возвращаться из глубины вложенных функций через цепочку проверок утомительно — проще сказать «всё, заканчиваем».

Возраст принят: 12 Возраст не бывает отрицательным.

system.exit(1) останавливает программу немедленно, где бы её ни застали, — и передаёт наружу тот же код завершения, что и return из main. Последняя строка main так и не выполнилась.

Одна тонкость: system.exit() нельзя перехватить через try/catch. Это не ошибка, которую можно исправить и пойти дальше, а решение самой программы закончить работу — отменять его никто не вправе.

Пользуйтесь этим инструментом бережно. Программа, выходящая из середины произвольной функции, читается тяжелее той, где всё сводится к main. Хороший повод для system.exit() — именно аварийный: дальше работать нельзя.
