Методы догоняют функции

В ваших классах методы пока скромные: без параметров и без результата — напечатал визитку, изменил своё поле, и всё. А функции давно умеют больше: принимают аргументы, возвращают ответ. Пора уравнять в правах — метод тоже может принять параметр и вернуть значение:

true

Присмотритесь к паре слов внутри метода: this — «я, кого позвали», это вы знаете с прошлого урока. А other — обычный параметр, в котором приехал второй герой. Один метод — два объекта: свой доступен через this, чужой — через параметр. Именно эта пара открывает сегодняшнюю тему.

Проблема: равны ли двое?

Попробуем спросить у языка, равны ли два героя, привычным знаком:

main.idyl:17:21: compile error: cannot compare objects of class 'Hero' with '==' — declare 'contract bool function equals(Hero other)' in class 'Hero' and the comparison will use it

Компилятор отказывается — и не из вредности. Числа и строки язык сравнивает сам, потому что там равенство очевидно. А что значит «равны» для двух героев? Совпали имена? Имена и уровни? Или это вообще должен быть один и тот же герой? У равенства объектов нет единственно правильного ответа — ответ знает только автор класса. Поэтому язык не гадает, а прямо в ошибке называет условия договора.

Контракт equals

Договор такой: объявите в классе публичный метод ровно такой формы — contract bool function equals(СвойКласс other) — и знак == начнёт работать, вызывая ваш метод. Новое слово здесь одно — contract в самом начале:

true false true

Такой метод-договор называется контрактом: вы обещаете языку метод условленной формы — язык за это подключает к нему свой знак. Заметьте, что решаете именно вы: напишете в equals сравнение только имён — тёзки станут «равны»; сравните все поля — равенство станет строже. Знак один, а смысл ему назначает автор класса.

Слово contract — пометка и для языка, и для читателя: «этот метод зовут не только по имени — его вызывает знак». Пометка обязательна: имена контрактов в классах заняты, и метод equals без неё компилятор не примет — подскажет, как записать договор. Зато и ошибиться молча не выйдет: лишний параметр или не тот тип результата в помеченном методе — и ошибка прозвучит прямо у объявления, а не когда-нибудь потом, на знаке ==.

!= отдельного контракта не требует: это «не equals», язык выводит его сам. И одно правило хорошего тона, которое стоит записать: equals отвечает на вопрос и ничего не меняет. Метод сравнения, который двигает поля, — источник самых загадочных ошибок.

Контракт оживляет поиск

Вместе со знаком == договор подключает и поиск в массивах — contains, find и count начинают искать «по смыслу», через ваш equals:

true 1

Обратите внимание: wanted — не тот объект, что лежит в массиве, а собранный заново образец с теми же полями. Без контракта такой поиск был бы невозможен (компилятор отказал бы с той же подсказкой про equals) — а с контрактом «найди героя по описанию» пишется одной строкой. Сравнение двух массивов героев знаком == тоже оживает: массивы равны, когда попарно равны их жители — по вашему же контракту. А вот sort() контракт равенства не открывает: равенство вы объявили, но «кто меньше» — отдельный вопрос, и у него свой договор — прямо в следующем разделе.

И ещё одна дверь, которую открывает строковый контракт из конца урока: массив объектов с контрактом печати выводится целиком — console.writeln(guild) покажет представления всех жителей списком, как массив строк.

Контракт порядка: less

Вернёмся к самому первому методу урока — stronger_than. Он честно отвечает, кто сильнее, но зовётся длинно: mira.stronger_than(kai). А числа тот же вопрос решают одним знаком. Попробуем и с героями:

main.idyl:17:21: compile error: cannot order objects of class 'Hero' with '<' — declare 'contract bool function less(Hero other)' in class 'Hero' and '<' will use it

Знакомая картина: у порядка объектов, как и у равенства, нет единственно правильного ответа. Кто «меньше» — герой с меньшим уровнем? Тот, чьё имя раньше по алфавиту? Решает автор класса, и договор тот же: метод условленной формы — contract bool function less(СвойКласс other), «я меньше, чем other?»:

true false

Один контракт подключил сразу два знака: < вызывает ваш less, а >= достаётся бесплатно — «не меньше» есть отрицание «меньше», ровно как != был отрицанием equals.

Но главный подарок контракта — не знаки. Помните, что sort() отказывался сортировать объекты? Ему как раз не хватало ответа на вопрос «кто меньше» — и теперь этот ответ есть:

Кай — уровень 9 Мира — уровень 12 Тася — уровень 15

Гильдия выстроилась по уровню — по вашему less, одной строкой. Сортируйте героев по уровню, книги по году, рекорды по очкам — что значит «меньше», каждый класс объявляет сам, а sort() послушно этому следует. Полезная мелочь: если ваш less кого-то не различает (у двух героев одинаковый уровень), сортировка оставит их в исходном порядке — никто не «перепрыгнет» соседа без причины. И правило хорошего тона у порядка то же, что у равенства: less отвечает на вопрос и ничего не меняет.

Контракт greater

У знака > — свой отдельный контракт: contract bool function greater(СвойКласс other), «я больше, чем other?». Работает точь-в-точь как less: > вызывает ваш greater, а <= достаётся отрицанием:

true false

Контракты порядка независимы: less обслуживает <, >= и sort(), greater — знаки > и <=; один из другого язык не выводит. Объявили оба — следите сами, чтобы они не спорили друг с другом: язык поверит каждому на слово.

Строковый контракт: to_string

Остался ещё один договор — у печати. Помните запрет cannot print object of class 'Hero' directly и метод-визитку info()? У печати есть свой контракт: назовите визитку to_string, пометьте её тем же словом contract, пусть она возвращает строку — и writeln научится печатать объект сам:

Мира (уровень 12)

Разница с info() принципиальная: визитка печатала сама, а контракт возвращает строку — и ею распоряжается тот, кто печатает. Внутри метода можно спокойно звать глобальную to_string(число) — это разные вещи: глобальная превращает значение в строку, а ваш метод-контракт описывает, как выглядит объект.

Один соблазн контракт не открывает: "строка" + объект по-прежнему запрещён — ровно так же, как запрещена склейка строки с числом. Лечение то же самое: глобальная to_string(объект) — при контракте она использует ваш метод, и "Встречайте: " + to_string(mira) собирается честно.

  • Контракт — договор с языком: метод условленной формы подключает встроенный знак или механизм.
  • Контракт помечается словом contract. Имена контрактов в классах заняты: метод equals, less, greater или to_string без пометки компилятор не примет, а ошибку формы назовёт прямо у объявления.
  • Что значит «равны» и «меньше» — решает автор класса: по уровню, по имени, по всем полям — выбор за вами.
  • Контракты отвечают, но не меняют; отрицания достаются бесплатно: != — от equals, >= — от less, <= — от greater.
  • sort() сортирует объекты по контракту less; равных он оставляет в исходном порядке.
  • Склейка "строка" + объект запрещена, как и с числом: собирайте через to_string(объект).
  • О судьбе контрактов при наследовании — в уроке про наследование.
