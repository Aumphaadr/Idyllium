Напоминание: переменные и функции

Переменные предназначены для хранения данных. Функции предназначены для выполнения действий.

У каждого из этих инструментов есть фундаментальное ограничение:

  • Переменные могут хранить данные, но не могут ничего с ними делать.
  • Функции могут обрабатывать данные, но не могут их хранить.

Переменные и функции взаимно дополняют друг друга — каждый делает то, чего не умеет другой.

Объекты объединяют данные и действия

Ключевая фишка объектов в ООП — они умеют и хранить данные, и выполнять действия. Объекты объединяют в себе способности переменных и функций.

Как это происходит? Очень просто: внутри класса можно объявить как переменные, так и функции.

Мяу! Мяу!

Класс Cat определяет набор переменных (name, color, age) и функцию (meow()). Объект my_cat пользуется этими переменными и функцией.

Терминология: свойства и методы

В контексте ООП используются специальные термины:

  • Свойство (поле) — это переменная, объявленная в теле класса.
  • Метод — это функция, объявленная в теле класса.

То есть, у класса Cat есть свойства name, color, age и метод meow().

Правило перевода простое — что было снаружи, то есть и внутри класса, только под новым именем:

Вне классаВнутри классаЗадача
переменнаясвойство (поле)хранить данные
функцияметодвыполнять действия

Пример: класс Brick

Рассмотрим класс Brick (кирпич) со свойствами и методом:

Бам! На голову упал красный кирпич! Бам! На голову упал белый кирпич!

В этом примере:

  • Свойства: color, mass, material
  • Метод: fall_on_head()
  • Создано два объекта (b1 и b2) с разными характеристиками
  • Один и тот же метод у каждого кирпича напечатал свой цвет

Внутри метода встретилось новое слово — this. Так метод обращается к свойствам того объекта, у которого его вызвали: у b1 это красный цвет, у b2 — белый. Подробно про this — в следующем уроке.

И спокойствие: при написании этого урока ни одна голова не пострадала — наши кирпичи падают исключительно в консоли. Но на настоящей стройке всё-таки носите каску.

Важное замечание

Свойства и методы объявляются в теле класса, а используются объектами этого класса.

Попытка вызвать метод через сам класс (а не через объект) приведёт к ошибке компиляции:

main.idyl:8:5: compile error: instance method 'Cat.meow' must be called on an object

Компилятор так и объясняет: метод Cat.meow нужно вызывать у объекта (on an object). То же самое со свойствами — если заменить эту строку на string n = Cat.name;, компилятор ответит:

main.idyl:8:16: compile error: instance field 'Cat.name' must be accessed through an object

Класс — это только чертёж. Чертёж кота не мяукает и не имеет имени. Чтобы что-то сделать, создайте по чертежу объект — и обращайтесь к нему.
