Блок 1. Метод без объекта

Практика с преподавателем

Задание 1. Мяу без кота

Собираем у доски обе половины урока. Сначала боль: обычный meow() печатает фиксированное «Мяу», полей не трогает — а объект заводить приходится. Потом лекарство:

Проговорите три вещи. Первая: Cat.meow() — вызов у класса, и это законно ровно потому, что метод помечен static (помните отказ «чертёж не мяукает» из третьей книги? Для статиков чертёж — как раз тот, кто мяукает). Вторая: MathUtils — класс, у которого вообще не планируются объекты: он существует как фамилия для инструментов. Третья: критерий на всю жизнь — нужен ли методу this? Нужен — обычный. Не нужен — кандидат в статики.

Самостоятельная практика

Задание 2. Текстовая мастерская

Свой утилитный класс по образцу: TextUtils со статиками shout(string s) (возвращает строку с «!!!»), whisper(string s) (в скобочках: «(тишина)») и underline(string s) (строка + перевод строки из дефисов — длину дефисной линии выберите на вкус). Прогоните пару фраз через все три. Ни одного объекта в программе — только фамилия и таланты.

Задание 3. Кому нужен this

Задача-детектор. Класс Cat с двумя методами: static species_info() — «Кошки — древние спутники человека» (факт о виде, никакой личности) и обычный introduce() — «Я — Барсик» (this.name). Позовите каждый со своей стороны: факт — у класса, знакомство — у объекта. Сформулируйте, почему методы разложены именно так, — и попробуйте мысленно поменять их местами: у introduce() без this не будет имени, а species_info() объект таскает без нужды. Критерий урока работает в обе стороны.

Задание 4. Поля так не умеют

Эксперимент-граница. Раз методы бывают статическими — может, и поля? Попробуйте: static int count; в теле класса. Компилятор отвечает редким по честности сообщением: static fields are not supported yet — «пока не поддерживаются». Вывод для практики: общий счётчик экземпляров на статике не построить — если нужен счёт рождений, держите обычную переменную в main (как весь курс и делали). Заодно оцените слово yet в сообщении: язык честно признаётся, что дверь не заколочена, а просто ещё не построена.

Блок 2. Экспертиза сторон

Задание 5. this без хозяина

Классическая поломка урока — воспроизведите: в статический метод впишите console.writeln(this.name);. Гроздь из двух сообщений: настоящее — 'this' cannot be used in a static method, и эхо — type '<error>' has no member 'name'. Правило первой строки, канонизированное самим уроком: чините первое — второе исчезнет само. И проговорите смысл: у статика нет хозяина, поэтому «я» ему произносить не с чего.

Задание 6. Не с той стороны

Зеркальная пара — обе поломки в одном сеансе. Первая: MathUtils m; int y = m.square(5); — статик через объект → static method 'MathUtils.square' must be called on class 'MathUtils'. Вторая: обычный meow() (без static) через класс → старый знакомый instance method 'Cat.meow' must be called on an object. Сведите в тетради таблицу сторон: статики зовутся у класса, обычные — у объекта, и компилятор в обоих отказах называет правильную сторону по имени. Заблудиться теперь можно только назло.

Задание 7. Утилита зовёт утилиту

Статики дружат между собой — по полному имени. Дострой MathUtils: static int function fourth_power(int x) — четвёртая степень через двойной вызов собственного квадрата: return MathUtils.square(MathUtils.square(x));. Проверка: 3 → 81. Внутри статика соседний статик зовётся так же, как снаружи, — с фамилией; никакого this и не понадобилось.

Блок 3. Знаменитые утилиты

ParrotConverter со статиками to_parrots(float meters) (попугай — 0.26 м: делим), to_monkeys(float meters) (мартышка — 1.9 м) и to_elephants(float meters) (слонёнок — 4.9 м). Измерьте удава длиной 9.88 метра во всех трёх единицах — и проверьте главное число мировой мультипликации: попугаев должно выйти ровно 38. Финальная строка обязательна: «А в попугаях он гораздо длиннее!» (Мартышек выйдет 5.2, слонёнков — дробное: у float нет пиетета к слонёнкам.)

Задание 10. Кузница никнеймов

Скуйте себе личный и два легендарных. Каждый ученик уносит с урока никнейм — сгенерированный статикой судьбы (эталон выдал «БешеныйХомяк_666»; завидуйте).

Задание 11. Кошачий переводчик

CatTranslator.translate(string meow) — принимает любое кошачье высказывание и возвращает случайный перевод из массива («Покорми меня», «Открой дверь. Нет, закрой. Нет, открой», «Я видел птицу, это меняет всё», «Просто хотел напомнить о себе»). Три перевода одного и того же «мяу» — три разных смысла. Научная честность: точность перевода не гарантируется, но и опровергнуть его кот не сможет.

Задание 12. Паспортный стол

Утилита-валидатор — родня сеттеров-привратников из книги инкапсуляции, но без объекта: NickRules.valid(string nick) возвращает bool — короче трёх символов или длиннее шестнадцати не пропускаем. Массив кандидатов («Ян», «Стример_2013», «Оченьдлинноеимякотороеникуданевлезет») — цикл с вердиктами «принят/отклонён». Проговорите родство и разницу: сеттер охраняет своё поле, статик-валидатор — общий закон, ничей и для всех.

Задание 13. Судья по камню и ножницам

RpsJudge.decide(string a, string b) — возвращает вердикт: «Ничья», «Первый победил», «Второй победил» (цепочка if с and — три победных случая первого, остальное додумает return). В main — три раунда со случайными ходами из массива. Судья не играет, ставок не делает, объектов не имеет — идеальная беспристрастность статики.

Минутка из внешнего мира. Фамилия для инструментов

Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.

В большой программе живут тысячи функций, и держать их россыпью — как высыпать все инструменты города в одну кучу посреди площади. Программисты придумали давать инструментам фамилии: в любом взрослом языке вы встретите Math.sqrt, Files.read, Color.parse — класс-фамилия говорит, откуда инструмент родом, ещё до чтения документации. Присмотритесь: это тот же трюк, что у модулей из книги №5 («болит прямоугольник — открывай rect.idyl»), только этажом ниже — внутри одного файла. Порядок в большом хозяйстве держится на одном приёме, применённом дважды: у всего должен быть адрес.

Задание 18 ⭐⭐. Монетный двор

Финал: фабрики на конвейере. Класс Coin (металл, номинал, конструктор) с тремя фабриками: gold() (100), silver() (10) и random_find() — случайная находка с шансом золота 1 к 10 (и заметьте: фабрика внутри зовёт другие фабрики — return Coin.gold();). Кошелёк-dyn_array: по монете каждого сорта руками и пять случайных находок циклом; опись с номиналами и итоговая сумма. Два запуска — два разных урожая. Всё, чему учила книга, в одном дворе: фабрики с говорящими именами, статик зовёт статик, случайность под контролем — и ни одной «голой» цифры номинала в main.
