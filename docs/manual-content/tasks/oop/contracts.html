Блок 1. Договор подписан

Практика с преподавателем

Задание 1. Первый метод с ответом

У доски — программа из урока: Hero с методом stronger_than(Hero other), двое героев, вопрос «кто сильнее». Проговорите три вещи. Первая: это первый метод с параметром и результатом — методы догнали функции, весь багаж функций (аргументы, return) теперь работает и здесь. Вторая: внутри метода живут ДВА объекта — свой через this, чужой через параметр other; выражение this.level > other.level читается как «мой уровень против его». Третья: mira.stronger_than(kai) и kai.stronger_than(mira) — разные вопросы; проверьте оба и объясните почему.

Задание 2. Подписываем equals

Там же, у доски: попытка a == b без контракта — читаем отказ компилятора ВСЛУХ и до конца: он сам диктует, что объявить. Объявляем bool function equals(Hero other) по имени и уровню — знак оживает. Момент истины: смысл знака == назначили вы, строкой своего метода. Проверьте и != — он достался бесплатно.

Самостоятельная практика

Задание 3. Тёзки

Класс Pet (кличка, возраст) с equals только по кличке. Два Барсика разных возрастов — «равны»! Ужесточите договор до кличка+возраст — «неравны». Вывод в тетрадь: строгость равенства — решение автора класса, и оба варианта законны, если выбраны осознанно.

Задание 4. Сам с собой

Допишите к з.3 проверку barsik == barsik. Работает — а почему? Проследите глазами: в equals и this, и other — один объект, поля сравниваются сами с собой. Заодно проверьте пару «двойник против второго имени»: Pet copy_name = barsik; — тут даже сравнивать нечего, имена ведут к одному коту (багаж «кот один — имён два»).

Блок 2. Экспертиза

Задание 5. Чужой класс не пришьёшь

Заведите рядом class Robot с теми же полями и попробуйте pet == robot: cannot compare 'Pet' and 'Robot'. Кот и робот не сравниваются, даже если поля совпали, — у каждого класса свой договор и своя мерка. Прочитайте сообщение и объясните, почему это добрее молчаливого «false».

Задание 6. Кривой договор

Испортите форму контракта тремя способами по очереди: (1) верните int вместо bool; (2) примите string other вместо своего класса; (3) сделайте метод приватным. После каждой порчи попробуйте a == b — компилятор всякий раз отвечает подсказкой «declare 'bool function equals(...)'», потому что метод НЕ ТОЙ формы договором не считается. Форма контракта — не придирка, а подпись под договором.

Задание 7. Сравнение, которое кусается

Вредительский эксперимент (на копии программы!): внутри equals допишите other.age = other.age + 1;. Программа компилируется, сравнение «работает» — а возраст второго кота растёт от каждой проверки. Прочувствуйте, почему правило урока — equals отвечает, но не меняет — записано кровью: сравнение зовётся невидимо (из ==, из contains), и побочный эффект в нём срабатывает там, где его никто не ждёт.

Блок 3. Поиск по договору

Практика с преподавателем

Задание 8. Розыск по приметам

У доски — сцена из урока: гильдия в dyn_array<Hero>, образец wanted собран заново с теми же полями, contains и find находят. Проговорите: образец — ДРУГОЙ объект, поиск идёт по смыслу, через ваш equals; уберите контракт — и компилятор откажет в самом contains (проверьте и прочитайте отказ). Это типовое взрослое задание «найди запись по описанию» — теперь оно ваше.

Самостоятельная практика

Задание 9. Перекличка без дублей

Отряд набирают по одному: перед add проверяйте squad.contains(новичок) — дубль по договору в отряд не проходит («такой боец уже есть»). Наберите пятерых с одной попыткой дубля. Бонус-вопрос: а два РАЗНЫХ объекта с одинаковыми полями — дубль или нет? Ответ уже записан в вашем equals.

Задание 10. Инвентарь и счётчик

Рюкзак dyn_array<Item> (название, вес). Соберите добычу с повторами и отчитайтесь через count: «Зелий: 3». Затем сравните два рюкзака целиком знаком == — массивы объектов равны, когда попарно равны их жители, и жителей меряет ваш же контракт. Поменяйте порядок в одном рюкзаке — равенство сломалось; обсудите, почему порядок входит в равенство массивов.

Задание 11. Порядка нет

Попробуйте guild.sort(): sort() cannot order 'Hero' objects — objects have no built-in ordering. Равенство вы объявили — а «кто больше» не объявлял никто, и язык не гадает (по уровню? по имени? по алфавиту?). Отсортируйте честно: методом stronger_than из з.1 и знакомым обменом соседей — заодно почувствуете, ЧЕГО именно не хватает объектам для сортировки.

Блок 4. Контракт печати

Задание 12. Визитка становится контрактом

Возьмите любой класс с info() из прошлой книги и переименуйте визитку в to_string, заменив печать на return строки. Теперь console.writeln(объект) работает сам. Проговорите разницу: визитка печатала, контракт — отдаёт строку, и распоряжается ею печатающий (можно склеить с чем угодно, записать в файл, положить в переменную). Внутри метода глобальная to_string(число) для полей — это ДРУГАЯ to_string, они не путаются.

Задание 13. Табель о двух контрактах

Класс Student (имя, средний балл — дробный!): контракт to_string печатает «Мира — 4.5», контракт equals сравнивает по имени. Ведомость dyn_array<Student>, печать всех через writeln в цикле, поиск ученика по образцу, вежливое «такого нет» при промахе. Два договора в одном классе — обычная норма взрослых классов.

Блок 5. Полигон

Задание 14 ⭐. Колода без близнецов

Карточная игра честности: класс Card (масть, достоинство), equals по обоим полям, to_string вида «дама пик». Соберите колоду из 8 карт СО СЛУЧАЙНЫМИ полями (random — багаж) так, чтобы близнецов не было: карта-кандидат с deck.contains отправляется на пересдачу. Напечатайте колоду контрактом печати и завершите контрольной строкой: «повторов: 0» (проверьте через count по каждой карте). Все три механики урока — в одной программе.

Задание 15 ⭐⭐. Сравнить сохранения

Игра хранит два снимка отряда — «до похода» и «после»: два dyn_array<Hero>. Напишите отчёт об изменениях: кто ушёл (есть в старом, нет в новом — contains), кто пришёл, кто изменился (имя то же — уровень другой: тут понадобится ДВА взгляда, и это главная головоломка задачи — equals по всем полям находит «того же героя с тем же уровнем», а «того же, но подросшего» ищите циклом по имени). Финальная строка — «изменений: N». Задача — репетиция взрослой синхронизации данных, и она честно показывает границу контракта: один equals не может значить «тот же человек» и «полностью совпал» одновременно — выбирать вам.

Дополнение: детектив

Задание 16 ⭐. Зеркальная ловушка

Программа-улика: внутри equals кто-то написал return this == other; — «равны, когда равны», звучит же логично? Запустите сравнение и прочитайте приговор: recursion depth limit of 20000 exceeded in function 'Hero.equals'. Проведите следствие по шагам: знак == для объектов зовёт контракт equals… который выполняет ==… который зовёт контракт. Программа крутится в зеркале, пока язык не останавливает её честной ошибкой с именем виновника. Вывод в тетрадь двойной: термин не определяют через него самого — а язык, который вместо зависания называет имя зациклившегося метода, экономит вам час жизни.
