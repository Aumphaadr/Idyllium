Блок 1. Данные под охрану

Практика с преподавателем

Задание 1. Незащищённое здоровье

Собираем у доски драму урока в двух актах. Акт первый — беда: класс Hero с публичным hp, кто-то дописал hero1.hp = hero1.hp + 75; — и у героя 115 здоровья из 100 возможных. Акт второй — охрана:

Прогоните сценарий урока: лечение с перебором (40 + 75 → честные 100), удары с перебором (→ честный 0). Проговорите три вещи. Первая: private: и public: — заголовки секций, как рубрики в списке: всё ниже относится к заголовку до следующего заголовка. Вторая: изнутри класса — из конструктора и методов — приватное поле доступно свободно; закрыта только дверь снаружи. Третья: перехилить теперь невозможно в принципе — все пути к hp ведут через сторожей.

Самостоятельная практика

Задание 2. Заноза выходит

Помните батарейку из книги this — «здоровье −241%»? Обещание исполняется. Класс PhoneBattery: процент — приватный, снаружи только drain(int) и charge(int) со сторожами (ниже нуля — «экран погас. Темнота», выше ста — «заряжен под завязку») и геттер get_percent(). Разрядите в минус и зарядите в плюс — сторожа держат 0 и 100. Заноза, жившая три книги, извлечена — и проговорите, почему лечение стало возможно только сейчас: раньше охрана жила в наших привычках, теперь — в типе.

Задание 3. Дверь заперта

Попробуйте взломать героя из з.1 снаружи: warrior.hp = 999;. Компилятор: member 'Hero.hp' is private and can only be used inside class 'Hero' — полное имя виновника и правило одним предложением. Прочитайте вслух и оцените: это не runtime-сторож, который ловит на месте преступления, — это компилятор, который не даёт программе с взломом даже собраться. Читер не будет наказан — читер не запустится.

Задание 4. Правила секций

Эксперимент-паспорт на синтаксис. Соберите класс-солянку: поле до первого заголовка, потом private: с полем, потом public: с полем — и проверьте из main, кто доступен. Итоги в тетрадь: поле до первого заголовка — публичное (нет рубрики — нет запрета); секции можно чередовать сколько угодно; каждая действует до следующей. Совет стиля из урока: обычно пишут одну private:-рубрику и одну public: — солянка законна, но читается хуже.

Блок 2. Геттеры и сеттеры

Практика с преподавателем

Задание 5. Пара на все времена

Канонический дуэт — у доски. Класс Pupil: возраст приватный; int function get_age() — читает; void function set_age(int value) — пишет, но со сторожем: отрицательный возраст и возраст за 150 отклоняются с репликой («Столько не живут»), поле не меняется. Прогоните: честная установка, попытка «−5», попытка «200». Проговорите имена: get_ и set_ — не закон языка, а всемирное соглашение программистов: увидел get_x/set_x — понял, что поле под охраной.

Самостоятельная практика

Задание 6. Read-only своими руками

Мост к прожитому. Весь второй курс вас окружали свойства «только для чтения»: selected_title, running, duration — читать можно, писать нельзя. Теперь вы знаете их секрет: геттер без сеттера. Класс Stopwatch: приватное поле «тики», публичный метод tick() (единственный способ наращивать) и get_ticks() — а сеттера нет вовсе. Снаружи счётчик читается, но не подделывается. Сдача с проговоркой: «read-only — это не магия языка, это дизайн класса: чтение дали, запись не дали».

Задание 7. Сеттер с ответом

Сеттер может отчитываться об успехе: bool function set_nickname(string value) — пустая строка и строка длиннее двадцати отклоняются (return false;), годная — принимается (return true;). В main — три попытки с if по ответу: «принято»/«отклонено». Метод-привратник теперь не просто молча охраняет — он ведёт диалог с вызывающим: договор «я попробую, а ты проверь ответ» — основа всех форм регистрации.

Задание 8. Кухня и зал

Пробой подтверждено: методы тоже бывают приватными. Класс Robot: публичный ритуал morning_routine() («просыпается... готов к работе!»), внутри которого зовётся приватный internal_diagnostics() («[внутренняя диагностика: топливо N]»). Изнутри — работает; попытка позвать диагностику из main — знакомое семейство: member 'Robot.internal_diagnostics' is private.... Метафора в тетрадь: публичные методы — зал (меню для посетителей), приватные — кухня (посетителям вход воспрещён, но именно там готовится еда).

Блок 3. Классы-сейфы

Задание 9. Джинн

Флагман книги. Класс Genie: счётчик желаний — приватный, рождается тройкой в конструкторе. Публичный интерфейс: grant_wish(string wish) — сторож проверяет остаток («Исполнено: гору мороженого! (осталось желаний: 2)» — или «Лампа закрыта. Приходите в следующей жизни»); отдельный метод wish_for_more_wishes() — вечный отказ («Так нельзя, и вы это знаете»); геттер остатка. Сценарий: три желания, наглая попытка четвёртого, попытка пожелать больше желаний. Соль задачи проговорите после сдачи: четвёртое желание невозможно физически — не потому что джинн вредный, а потому что к счётчику нет других дверей. Сказка стала инженерией.

Задание 10. Лужа

Инкапсуляция как саспенс. Класс Puddle: ширина публичная (её видно!), глубина приватная и случайная (1–30, решается в конструкторе — даже программист не знает!). Единственный способ узнать правду — step_in(): по глубине три исхода — «Плюх! По подошву», «ПЛЮХ! По щиколотку. Носок промок», «БУЛТЫХ!!! По колено. Там вообще дно есть?!». Три лужи разной ширины, три шага. Мораль после запусков (сделайте несколько — random бывает жесток): ширина ничего не обещает — самая безобидная лужа з.10 нашего эталона оказалась по колено. Приватное поле, о котором узнаёшь только опытным путём, — самая честная модель луж в мировой литературе.

Задание 11. Киндер

Одноразовое раскрытие. Класс KinderEgg: игрушка — приватная строка, случайно выбранная конструктором из четырёх; публичный bool unwrapped; и метод unwrap() — первый вызов раскрывает («Шурх-шурх... внутри — бегемотик!») и поднимает флаг, повторный — «Уже развёрнуто. Чуда дважды не бывает». Три яйца, три разворачивания, одна попытка повторного. Снаружи все яйца одинаковы — в этом и был замысел производителя; ваш private честно его воспроизводит.

Задание 12. Банкомат

Сейф в железе. Класс ATM: наличность приватная; withdraw(int) — сторож наличия («Недостаточно средств в банкомате»), refill(int) — инкассация, report_for_bank() — геттер для своих. Сценарий дня: выдача, отказ, инкассация, выдача, отчёт. Обсуждение на сдаче: почему у банкомата нет метода «показать всем, сколько внутри»? (Геттер — тоже решение дизайнера: отчёт для банка есть, табло для прохожих — намеренно нет. Приватность — это не только «нельзя менять», это ещё и «не всякому знать».)

Минутка из внешнего мира. Капот и панель приборов

Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.

Сядьте в любой автомобиль: руль, педали, пара рычагов — вот и весь интерфейс. А под капотом — сотни деталей, к которым водителя не подпускают: капот закрыт не от жадности, а от беды — крутанёшь не то, и привет. Инженеры прячут сложное ровно по вашему сегодняшнему правилу: публичное — то, чем пользуются; приватное — то, что сломают. И заметьте: хорошей машиной можно прекрасно управлять, не зная, что под капотом, — как вашим джинном можно пользоваться, не видя счётчика. Это и называется скрытием реализации, и на нём стоит вся современная техника: от машин до программ, в которых вы сейчас прячете первые поля.

Задание 13. Наследство под замком

Эксперимент-граница (пробой подтверждено — результат многих удивляет). Родитель Animal с приватной энергией; потомок Dog extends Animal пытается в своём методе написать this.energy = this.energy - 10;. Компилятор: member 'Animal.energy' is private and can only be used inside class 'Animal' — даже потомку нельзя! Приватное наследуется (энергия у пса есть), но видно только методам самого Animal. Почините по-взрослому: дайте родителю публичный метод spend_energy(int) со сторожем — и пусть потомок зовёт его. Правило в тетрадь: потомки ходят к приватному родителя через его публичные двери, как все. (В больших языках есть промежуточный уровень для «своих» — в Idyllium честная двухуровневая система.)

Задание 16. Сервер с анти-читом

Сборка книги в геймерской подаче. Класс Hero для «сервера»: приватные hp и mana; публичный интерфейс — take_hit(int), heal(int) (зажимы 0–100), cast_spell() (стоит 30 маны; не хватает — «Недостаточно маны», каст не происходит), meditate() (+20 маны, потолок 100), bool function is_alive(), геттеры. Инкапсуляция — не школьная условность, а индустрия.

Задание 17 ⭐. Арбуз и наука о стуке

Приватность с косвенным датчиком. Класс Watermelon: спелость — приватный bool, решается конструктором с шансом 7 из 10; публичный knock() возвращает строку «звонкий»/«глухой» — и датчик коррелирует с истиной, но врёт с шансом 2 из 10 (спелый обычно звонкий — но не всегда!); cut_open() — момент истины. Серия из трёх арбузов циклом: стук — предсказание покупателя — разрез. Приёмка двумя запусками и разговором: приватное поле нельзя прочитать — но можно оценивать по косвенным признакам, и признаки иногда врут. Это уже не программирование — это эпистемология в арбузе. Бонус для смелых (пробой подтверждено): метод same_ripeness(Watermelon other) имеет право сравнить приватную спелость двух арбузов — изнутри класса приватность общая на всех собратьев.

Задание 18 ⭐⭐. Казна клана

Финал — бухгалтерия под охраной. Класс ClanVault: баланс приватный; публичные — имя клана, счётчик операций, deposit(int), bool function withdraw(int) (овердрафт отклоняется с репликой «ОТКАЗ: в казне лишь 250, а просят 500» и return false — отказ операцией не считается), audit() — геттер для казначея. Сценарий недели: вклады и снятия вперемешку, одна наглая попытка овердрафта. Приёмка — бухгалтерская сверка: посчитайте на бумаге сумму принятых операций и сравните с audit(); в эталоне 300 + 150 − 200 + 50 = 300 — сходится до монетки, и обратите внимание на счётчик: операций 4, а вызовов было 5 (отказ не в счёт — и это дизайнерское решение, которое вы обязаны отстоять на сдаче).
