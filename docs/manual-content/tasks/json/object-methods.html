Блок 1. Инвентаризация

Практика с преподавателем

Задание 1. Перепись и снос

Собираем у доски программы урока — три новинки за заход:

Вывод: ["name", "level", "money"] и Всего ключей: 3 — keys() выдаёт перечень (обычный dyn_array строк, печатается целиком!), а length у объекта считает ключи. Затем — вежливое чтение: if (player.has("level")) { ... } else { «У игрока пока нет уровня» } — программа решает сама, а не падает. И снос: player.remove("temporary_bonus") — ключа больше нет, length похудел. Проговорите: add — новосёл, set — ремонт (№2 помнит), remove — снос, has — разведка, keys — перепись: жилищное хозяйство объекта в сборе.

Самостоятельная практика

Задание 2. Опись артефакта

Задание 3. Прозвище по желанию

Задание 4. Снос времянки

Соберите объект с ключом-времянкой (по образцу урока: temporary_bonus), напечатайте length, снесите remove-ом, напечатайте снова: 2 → 1. Ключи приходят и уходят — length всегда честен.

Блок 2. Экспертиза

Задание 5. Снести несуществующее

remove("level") на объекте без level → json object has no key 'level' — то же письмо, что у set (№2 з.6!): изменять и удалять можно только существующее. Тройка add/set/remove с has-разведкой перед каждым спорным случаем — полная дисциплина ключей; таблицу «кто на чём падает» — в тетрадь (add — на занятом, set и remove — на пустом).

Задание 6. Снимок, а не трансляция

Жемчужина книги — экспериментом: возьмите keys() в переменную-снимок, снесите ключ, напечатайте старый снимок — в нём снесённый ключ ещё числится! — и свежий keys() — там правда. Вывод двойной: снимок не следит за объектом (перепись — на момент переписи); и потому удаление ключей в цикле по снимку — безопасно (снимок неподвижен — цели не съезжают!). Помните СПАМ-тройку №7, где цели уезжали из-под цикла? У объектов эта ловушка не работает — и понять, почему тут можно, а там нельзя, — значит понять обе книги.

Задание 7. Две длины

Детектор смыслов: у массива length — элементы, у объекта — ключи. Серия предсказаний: что станет с length объекта после set существующего? (Ничего — ремонт не строит комнат!) После add? После remove? А у массива после set(1, ...)? Таблица двух length — в тетрадь: слово одно, счётчики разные, и путать их — классика собеседований.

Задание 8. Принтер всего на свете

Соберите универсальный принтер объектов: цикл по keys() + get + полная is_*-лесенка (№3 з.18 — но там ключи были известны заранее, теперь их выдаёт сам объект!): строка — «строка "..."», число, дробь, булево, null, вложенный объект — «объект (N ключей)», массив — «массив (N элементов)». Прогоните на любых двух файлах раздатки — принтер всеяден. Вы написали инструмент, которому не нужна документация к данным, — им и будете вскрывать незнакомые файлы до конца курса.

Самостоятельная практика

Задание 10. Переводчик

translations.json: спрашивать английские слова в цикле (пустой ввод — конец), по каждому — has → перевод или «нет в словаре» (и посчитать успехи/промахи). Словарь работает как настоящий: bug переводится двусмысленно — прочтите вслух.

Задание 11. Рюкзак-счётчик

Главный словарный узор — upsert-счётчик: подбирать предметы (ввод в цикле), и на каждый: has(предмет) → set(+1) : add(1) (узор «добавь или обнови» из №2 з.7 — в главной роли!). Финал — опись: «зелье ×3, носок ×1» (обход keys). Инвентарь из №4 хранил дубли списком — словарь хранит счётчиком: две модели одного рюкзака, у каждой свои плюсы (порядок против компактности — обсудите!).

Задание 12. Чистка ветеранов

old_save.json — сейв Кая тащит ключи-ветераны: old_score, temp_flag, legacy_bonus. Программа-чистильщик: список ветеранов — массив строк; по каждому — has → remove (вежливость з.5!); отчёт «снесено: N»; запись файла. (Чистить «всё, что начинается с old_» не выйдет — starts_with у строк нет, проверено; список имён — честный путь.) Миграция-чистка — родня великой миграции №5: данные стареют, программы их омолаживают.

Минутка из внешнего мира. Словари держат интернет

Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.

Структура «ключ → значение» — возможно, самая эксплуатируемая идея в истории программирования. Телефонная книга (имя → номер), DNS (адрес сайта → адрес сервера: каждый ваш заход в интернет начинается со «посмотреть в словаре»!), кэши («запрос → готовый ответ»), базы данных Redis и DynamoDB, где хранятся сессии половины крупных сайтов, — всё это словари, раздутые до планетарного масштаба. Даже переменные вашей программы — словарь «имя → значение» внутри рантайма Idyllium. Почему идея так живуча? Потому что вопрос «дай по имени» — самый частый вопрос к данным вообще, а словарь отвечает на него мгновенно, хоть в нём три ключа, хоть три миллиарда. Ваш прайс из з.9 — младший брат систем, которые прямо сейчас отвечают миллионам людей.

Блок 5. Полигон

Задание 17. Лавка на словаре

Полный сервис на prices.json — меню в цикле: 1 — прайс (обход); 2 — купить (has → цена → бюджет-проверка → чек); 3 — режим хозяина: добавить товар (has → «уже есть» : add!), изменить цену (has → set : «такого нет»), снять с продажи (has → remove); 0 — выход с записью файла. Сдача сценарием: купить → подорожало → снят с продажи → перезапуск → прайс помнит всё. CRUD по ключам — близнец гильдии 2.0 (№6 з.17), но там записи искались циклом по таблице, тут — ключом мгновенно: почувствуйте разницу архитектур (и вспомните минутку).

Задание 19 ⭐⭐. Частотный анализатор

Полный пайплайн текст → словарь → аналитика → файл: прочитать story.txt (read_all().trim() — сага о хомяке в одну строку), разбить на слова split(" ") (№1-навык вернулся!); словарь частот upsert-ом (з.11); отчёт: всего слов / разных; топ-3 — три прохода: обход keys с поиском максимума → печать → remove найденного из словаря (снос рекордсмена открывает серебро — и это законно: удаление по снимку безопасно, з.6 гарантирует!); остаток словаря — в word_stats.json.
