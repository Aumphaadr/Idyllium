Блок 2. Экспертиза

Задание 5. Не тот ярлык

Попросите имя числом: root.get("name").to_int() на player.json → runtime error: json value is string, expected int. Письмо образцовое: что лежит (string), чего ждали (int). Диагноз в тетрадь: сначала посмотри в файл, потом пиши распаковку — типы назначаете вы, и рантайм сверяет ваше слово с данными. Почините и попробуйте обратное враньё (age как to_string) — симметричная ошибка.

Задание 6. Пустая ячейка

Ключ middle_name из player.json — пора: to_string() → json value is null, expected string. null — не пустая строка, не ноль, не false: ячейка подписана, но пуста. Таблица четырёх «ничего» в тетрадь (детектор!): null (ячейка есть, значения нет) / "" (строка есть, но пустая) / 0 (число, равное нулю) / нет ключа (и ячейки нет — своя ошибка, get так и скажет). Четыре разных пустоты — четыре разных поведения; проверка на null — is_null() (полный набор is_* — в подарок, уроки показывают не все).

Задание 7. Детектив типов

Серия mystery_1/2/3.json: в каждом — ключ mystery, но тип неизвестен заранее. Функция-инспектор: is_int → «целое число 42», is_string → «строка "сорок два"», is_bool → «булево true» (лесенка else if — и ветка «что-то иное» на всякий случай!). Прогнать по всем трём файлам одной функцией. Правило грязного мира: не уверен в типе — спроси, потом распаковывай; программа, которая спрашивает, не падает.

Задание 8. Число-гигант

big_id.json: player_id = 9007199254740993. Прочитайте его to_int() — и убедитесь: печатается весь, до последней цифры. Обычный int в Idyllium точен на любом размере — гигантские идентификаторы серверов ему не страшны. А теперь второй опыт: тот же файл через use types; + types.uint64 id = ...to_uint64(); — тоже весь, но это уже 64-битная ячейка с честными границами: скормите ей json.parse("-1").to_uint64() — и получите runtime error: json integer -1 is outside the types.uint64 range. Правило на полях: числа в Idyllium не переполняются — переполняются ЯЧЕЙКИ из types, и границы охраняют именно их.

Минутка из внешнего мира. Открой сейв блокнотом

Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.

Многие настоящие игры хранят сохранения и настройки в JSON или его родственниках — и их можно открыть обычным блокнотом. Настройки почти любой браузерной игры, конфиги Minecraft-серверов, моды Factorio, файлы The Sims — загляните в папку любимой игры и поищите файлы .json: внутри вы теперь всё поймёте — ключи, значения, вложенные коробки. Игроки-энтузиасты строят на этом целые ремёсла: редакторы сейвов, генераторы персонажей, анализаторы статистики. Два честных правила этого мира: свои файлы — твоя территория (сломаешь — сам и починишь, копию сделай!), а вот чужие сейвы и онлайн-игры — нет: там правка данных называется читерством и карается баном. Инструмент из з.12 — ровно того же рода, что взрослые редакторы сейвов; пользуйтесь мудро.
