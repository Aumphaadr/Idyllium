Задание 1. Условие в запросе

Собираем у доски полный пример урока — с параметрами, как учит №4:

Проговорите три вещи. Первая: WHERE — это if, живущий в базе: те же сравнения (>=, >, =, <), только применяются они к каждой строке до отправки. Вторая: AND требует обоих условий разом (логика из консольного курса — только пишется словом). Третья: ORDER BY ... DESC + LIMIT 3 — готовая тройка лидеров, и лидеров выбирает база. Заодно повторите вслух главное правило №4: числа и слова в условии — параметрами, никогда склейкой.

Блок 2. Экспертиза

Задание 5. Пустой невод

Условие, под которое никто не подходит: WHERE level >= 50. Ошибки нет — while просто не выполнится ни разу, программа напечатает пустоту (или ваш вежливый текст «никого не нашлось» — добавьте!). Родня тихого нуля из №2 (там affected_rows = 0, тут — ноль строк): пустой результат — не ошибка, а ответ. Дисциплина: у каждой выборки должна быть ветка «а если пусто».

Задание 6. Гонка двух армий

Сравнение подходов на одной задаче — «герои уровня 10+»: армия базы (WHERE) против армии программы (SELECT всех + if в цикле). Оба варианта дают одно; сравните по трём меркам: длина кода (WHERE короче), число строк, пришедших в программу (5 против 10 — а на миллионе строк?), и кто делает работу. Вывод книги: фильтруй у источника. Программе-грузчику платят меньше, чем программе-заказчику.

Задание 7. Порядок слов

Синтаксическая дисциплина SQL: попробуйте написать SELECT ... LIMIT 3 ORDER BY level DESC (переставив хвост) → near "ORDER": syntax error. У SQL строгий порядок частей: SELECT → FROM → WHERE → ORDER BY → LIMIT. Запишите цепочку в тетрадь как считалку: «что берём → откуда → каких → как разложить → сколько». Почерк ошибок SQLite знаком с первой книги: near "..." — вот тут.

Задание 8. Три сравнения строк

Тонкость, о которую спотыкаются все: WHERE name = 'мира' (маленькая буква) → ноль строк, а = 'Мира' → одна. Сравнение строк чувствительно к регистру; вспомните Ё-сюрприз №3 — та же природа: база сравнивает коды символов, а не «смысл слова». Испытайте и лишний пробел 'Мира ' — тоже ноль. Диагноз в тетрадь: выборка пуста, хотя «точно есть» → регистр, пробелы, опечатка; профессионалы лечат это LIKE (з.13) или нормализацией данных при вставке.

Задание 9. Тройка лидеров

У доски — ORDER BY + LIMIT как единый инструмент: SELECT name, level FROM players ORDER BY level DESC LIMIT 3 → Ника (21), Агата (18), Лея (15). Затем — тонкость мастера: LIMIT без ORDER BY бессмыслен (какие три? база не обещает порядок — №3 з.4 предупреждала!). И «сортировка второго уровня»: ORDER BY level DESC, name — при равных уровнях старший тот, кто раньше по алфавиту (нужны данные с ничьёй — сделайте свою таблицу с двумя одинаковыми уровнями и покажите).

Задание 10. Спички по карману

Живой ввод (№4!) в фильтр: спросить бюджет игрока → SELECT title, price FROM items WHERE price <= :budget ORDER BY price DESC LIMIT 5 — «что можно купить на 400 монет». Задание 11. ИЛИ, а не только И

Специя сверх урока (с напоминанием — уроки показывают AND): OR — «либо-либо»: герои уровня 18+ ИЛИ с золотом 900+ → Лея, Ника, Агата (Лея прошла по золоту, Агата — по уровню!). Логика знакома с консольного курса, слово новое. Проговорка: AND сужает, OR расширяет; в одном условии их смешивают со скобками — и скобки в SQL значат ровно то же, что в математике.

Задание 12. Кроме

Ещё специя: NOT — «все, кроме»: WHERE NOT level > 10 → Кай, Борис, Тимур, Рита (четверо «до десятого»). Сравните с level <= 10 — тот же ответ двумя способами (проверьте!). Правило вкуса: пишите то, что читается вслух понятнее; NOT хорош там, где условие сложное и его целиком проще отрицать.

Минутка из внешнего мира. Почему поиск отвечает мгновенно

Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.

Ваш WHERE честно проходит все десять строк. А как база находит одного человека среди ста миллионов за доли секунды? Она не перебирает — она пользуется индексом, и устроен он как алфавитный указатель в конце учебника: отсортированный список значений с адресами строк. Искать в отсортированном можно «делением пополам» — открыл посередине, понял, в какой половине искать, повторил: сто миллионов записей отсекаются за 27 шагов. Цена — место на диске и лишняя работа при вставке (указатель надо обновлять), поэтому индексы строят не на всё подряд, а на колонки, по которым ищут чаще всего. В SQLite индекс создаётся одной командой CREATE INDEX, и на больших таблицах разница видна невооружённым глазом — секунды превращаются в миллисекунды. Ваш ORDER BY name на индексированной колонке база даже сортировать не станет: указатель уже отсортирован.

Блок 4. Сцены с управлением

Задание 13. Поиск по кусочку

Долгожданная специя — LIKE: WHERE class LIKE '%рь%' находит «рыцаря» (единственного в гильдии — Кая!). Знак % означает «сколько угодно любых символов», и потому '%рь%' — «где-то внутри есть рь». Постройте поисковую строку по вводу: спросить кусочек имени → bind шаблона "%" + кусочек + "%" (шаблон собирается в переменной и уходит параметром — склейки в SQL по-прежнему нет!). Терминал из №4 з.14 обрёл человеческий поиск: теперь «Ник» найдёт Нику.

Задание 15. Список допустимых

Специя IN: WHERE class IN ('маг', 'жрица') — «класс из списка» (Мира и Агата). Сравните с длинным class = 'маг' OR class = 'жрица' — то же самое, но IN читается лучше и растёт легче (добавить третий класс — одно слово). Плюс BETWEEN: WHERE level BETWEEN 9 AND 15 — диапазон включительно (пятеро: Мира, Кай, Лея, Слава, Олег). Проверьте границы: 9 и 15 входят. Две специи, экономящие по строке каждый раз.

Задание 16. Богатство на уровень

Выражения в условии: WHERE gold / level > 50 — «кто накопил больше пятидесяти монет на уровень» (Лея и Ника — эффективные!). База считает и сравнивает — целочисленное деление помним из №2. Второй заход: тот же расчёт как вычисляемая колонка (gold / level AS per_level, №3-навык) + сортировка по ней — теперь виден весь рейтинг эффективности, а не только прошедшие порог. Одна формула, два применения: отбор и показ.

Задание 18 ⭐. Конструктор условий

Динамический фильтр — по-взрослому: программа спрашивает, какие условия применить (минимальный уровень? класс? бюджет? — на каждое «да/нет»), и собирает текст WHERE из кусочков (" AND level >= :min_level" и т. п.), а значения привязывает bind-ами только для выбранных условий. Тонкость мастера: начинать с WHERE 1=1 — тогда каждое добавленное условие просто дописывается через AND, и не нужно ловить «первое условие без AND» (взрослый приём, живущий в тысячах программ!). Проговорка по следам №4 з.7: куски команды собираются из своих строк, данные — всегда через bind. Приёмка: три разных набора фильтров дают три разные выборки, и ни один ввод пользователя не попадает в текст SQL.

Задание 19 ⭐⭐. Постраничный просмотр

Пагинация — та самая, что живёт в каждом списке интернета: LIMIT :size OFFSET :skip — где size — размер страницы, skip — сколько пропустить (страница × размер). Программа: показать страницу героев по 4, «дальше? (Enter)» — следующая, и так пока страницы не кончатся (пустая страница = конец — з.5 привит!). Эталон на guild.db: страница 1 — Ника, Агата, Лея, Олег; страница 2 — Мира, Слава, Кай, Тимур; страница 3 — Рита, Борис. Тонкость: пагинация без ORDER BY — лотерея (порядок не обещан, строки могут повториться или пропасть между страницами!) — сортировка обязательна. Кто добавит «страница N из M» — упрётся в необходимость знать общее число строк... и это последний крючок к десятой книге, где COUNT наконец придёт.
