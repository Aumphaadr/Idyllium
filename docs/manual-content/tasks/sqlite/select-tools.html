Практика с преподавателем

Задание 1. Одна строка вместо десяти

Собираем у доски примеры урока. Сначала осмотр — SELECT *:

SELECT * FROM players;

Затем — сводка:

На guild.db: 10 героев, уровни от 3 до 21, средний 11.5. Проговорите три вещи. Первая: агрегат сворачивает много строк в одну — поэтому next() зовётся один раз, а не в цикле (запрос вернул именно одну строку!). Вторая: AVG даёт дробь — читаем get_float (get_int здесь — типичная ошибка новичка). Третья: AS обязателен по-хорошему — иначе колонка будет называться «COUNT(*)», и обращаться к ней неудобно.

Блок 2. Экспертиза

Задание 5. Ноль или неизвестность

Жемчужина книги. Спросите сводку по выборке, где никого нет: WHERE level > 100. Результат: COUNT = 0, а MIN, MAX и AVG — NULL (проверьте через is_null — №6-навык!). Логика железная: строк ноль — это честный ответ «сколько»; но «какой самый маленький уровень среди никого» — вопрос без ответа, и база честно говорит «неизвестно», а не «ноль». Диагноз в тетрадь: у пустой выборки COUNT есть, а средних и краёв нет — и программа, которая читает AVG без страховки, упадёт (is null, expected float). Всякий отчёт по фильтру обязан начинаться с проверки: а нашлось ли хоть что-то?

Задание 6. Две звёздочки, два счёта

Тонкость, которую путают даже взрослые: COUNT(*) считает строки, COUNT(колонка) — строки, где эта колонка не NULL. Соберите таблицу из трёх строк, где в колонке b два NULL: COUNT(*) = 3, COUNT(b) = 1 (проверено!). И следствие: AVG и SUM тоже игнорируют пустоты — среднее по b вышло 10, а не 3.33 (десять поделили на один, а не на три!). Мораль: среднее по колонке с пропусками — среднее по заполненным; если пустоту надо считать нулём — скажите это явно (AVG(COALESCE(b, 0)) — №6 в помощь). Эта разница ежедневно портит чужие отчёты — вы теперь знаете, где искать.

Задание 7. Звёздочка для осмотра

SELECT * — удобно, но урок предупреждает: в готовой программе лучше перечислять колонки. Проверьте почему: напишите чтение с SELECT * и get_string("name") — работает; теперь представьте, что в таблицу добавили колонку (или сделайте это через ALTER TABLE из №9 з.18!) — программа тащит лишние данные, а если колонку переименуют, чтение упадёт неожиданно. Правило: звёздочка — для глаз человека, список колонок — для программы.

Задание 8. Среднее в целых

Проверьте, что будет, если прочитать AVG(level) через get_int: sqlite column 'average_level' is real, expected int (или похожее — прочитайте письмо дословно и запишите). Семейство писем типов из №3 пополняется. И вопрос вдогонку: а COUNT(*) — целое или дробное? (Целое — считаются штуки!) SUM(gold) по целым? (Тоже целое.) Тип агрегата — от природы вопроса: «сколько штук» — целое, «в среднем» — дробное.

Блок 3. Аналитик

Практика с преподавателем

Задание 9. Разложить по полочкам

У доски — GROUP BY: товары по редкости с количеством и средней ценой:

SELECT rarity, COUNT(*) AS n, AVG(price) AS avg_price
FROM items
GROUP BY rarity
ORDER BY avg_price DESC;

Эталон: легендарный — 3 шт, средняя 959; эпический — 3, 649.67; редкий — 6, 202.5; обычный — 8, 44.5. Проговорите механику: GROUP BY сначала собирает строки в группы по одинаковому значению, потом считает функции для каждой группы отдельно — и строк в результате столько, сколько групп (не одна! — цикл while вернулся). И тонкость: в SELECT рядом с агрегатами ставят ту самую колонку, по которой группируем — иначе непонятно, к какой группе относится число.

Задание 12. Средний чек

Синтез: по items — средняя цена в каждой редкости (з.9), а по purchases — сколько покупок совершил каждый игрок (GROUP BY player_id). Второе даёт номера вместо имён — и это опять тоска по JOIN: «игрок 3 купил 4 раза» просится стать «Лея купила 4 раза». Финальная книга раздела расставит имена по местам; пока — числа с их немой красноречивостью.

Минутка из внешнего мира. Кто на самом деле считает

Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.

Одна и та же задача — «средний чек по категориям» — решается двумя способами: вытащить миллион строк в программу и посчитать циклом или отправить базе десять слов SQL. Разница не только в скорости: данные надо везти. В настоящих системах база живёт на отдельном сервере, и миллион строк поедет по сети — секунды, мегабайты, деньги за трафик; агрегат же вернёт одну строчку. Поэтому в мире данных есть золотое правило: вычисляй там, где данные. На нём стоят и хранилища данных, и «умные» отчёты в аналитических системах, и целые профессии — инженер данных получает зарплату во многом за умение написать один правильный GROUP BY вместо трёх циклов. Ваш счётчик в цикле, проводивший вас через семь книг, был честным работягой — но он всегда таскал коробки; SQL умеет попросить, чтобы посчитали на складе.

Задание 14. Кто чем богат

Обратный скаффолд: «По guild.db собрать таблицу: класс, число героев, суммарное золото класса (SUM), средний уровень, минимальный и максимальный уровень — одним GROUP BY-запросом; вывести отсортированной по суммарному золоту убыванием; в конце — строка "ИТОГО" с общими цифрами (второй запрос без группировки!)». Соберите. Отчёт с итоговой строкой — классика бухгалтерии, и делается она именно так: детализация + сводка.

Задание 15. Только большие группы

Специя сверх урока — HAVING: фильтр по группам (не по строкам!). GROUP BY rarity HAVING COUNT(*) >= 4 — только редкости, где товаров четыре и больше (эталон: обычный 8, редкий 6). Тонкость, ради которой стоит вводить: WHERE отбирает строки до группировки, HAVING — группы после. Проверьте на паре: «дешёвые товары по редкостям» (WHERE price < 200 + GROUP BY) против «редкости, где средняя цена ниже 200» (GROUP BY + HAVING AVG(price) < 200). Разные вопросы — разные места фильтра.

Задание 16. Своя статистика

По своей базе (школа из №9!): средний балл по каждому предмету (GROUP BY subject_id), число оценок у каждого ученика, лучший и худший балл в журнале. И проверка на з.5: если у предмета нет ни одной оценки — попадёт ли он в отчёт? (Нет! GROUP BY идёт по существующим строкам оценок — предмета без оценок в результате не будет. Это тоже урок: агрегаты видят только то, что есть; «отсутствующие группы» появятся только с LEFT JOIN — финал книги.)

Блок 5. Полигон

Задание 17. Панель гильдии

Полная аналитическая панель (эталон прогнан!): шапка с рамкой; сводка — герои, средний уровень, казна, богатейший; классы — GROUP BY со средним уровнем, топ-4 по среднему; ассортимент — по редкости с MIN..MAX цен; торговля — покупки по дням; и страховка з.5: перед каждым блоком проверять, есть ли данные (COUNT = 0 → «данных нет» вместо падения на NULL). Сдача: панель целиком + устный экзамен по каждому числу («откуда 5075?»). Кто украсит панель выравниванием колонок — получит отчёт, который не стыдно показать заказчику.

Блок 6. Со звёздочкой

Комбинацию инструментов не подсказываем — в этом и звёздочка.

Задание 18 ⭐. Гистограмма уровней

Аналитика с картинкой: разложить героев по «корзинам» уровней — 1–5, 6–10, 11–15, 16–20, 21+ — и нарисовать гистограмму из звёздочек («11–15: ***»). Как разложить? Два пути: пять отдельных COUNT-запросов с разными WHERE (просто и наглядно) или один запрос с вычисляемой колонкой-корзиной и GROUP BY по ней ((level - 1) / 5 AS bucket — целочисленное деление из №2 делит на пятёрки!). Сделайте оба и сравните — второй короче, первый понятнее. Гистограмма — первый инструмент любого аналитика: среднее лжёт, распределение — нет (средний уровень 11.5, а героев ровно этого уровня в гильдии... проверьте!).

Задание 19 ⭐⭐. Отчёт с итогами и долями

Финал аналитики раздела: по каждому классу — число героев, суммарное золото, доля в общей казне в процентах (второй запрос даёт общую сумму, проценты считает программа: часть * 100 / целое — целочисленно или через float?), и визуальная полоска длиной в проценты (звёздочки — з.18-навык). Плюс строка ИТОГО. Плюс — обязательно! — обработка пустых случаев (з.5). Кто добавит сортировку по доле и подпись «топ-3 класса держат N% казны» — тот сделал отчёт уровня настоящей аналитики: не просто числа, а вывод. Покажите панель родителям: «вот столько золота у магов, вот их доля» — и объясните, что всё это посчитала база, а программа только нарисовала. Умение превращать таблицу в вывод — то, за что аналитикам платят.
