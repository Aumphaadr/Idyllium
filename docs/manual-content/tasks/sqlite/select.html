Задание 1. Глазок рассекречен

Собираем у доски программы урока — и группа узнаёт «глазок» №2 в лицо:

Проговорите модель курсора — она главная в книге: Result — не массив, а указатель перед первой строкой; next() — шаг вперёд с ответом «удалось ли»; чтение (get_string, get_int — каждому типу свой метод!) — только стоя на строке. Блок 2. Экспертиза

Задание 5. Чтение до шага

Уберите next: свежий Result и сразу get_string → sqlite result has no current row; call next() first — письмо само прописывает лечение (традиция раздела!). Курсор стоит ПЕРЕД первой строкой — «нулевой строки» не существует. Диагноз: сначала шаг, потом взгляд.

Задание 6. За краем

Мирная граница: после отработавшего while вызовите next ещё раз — false, не ошибка (курсор спокойно стоит за краем и говорит «дальше пусто»). А теперь второй while тем же Result — ноль строк: курсор не перематывается. Свежие данные — свежий execute (прогоните: второй execute — и снова всё читается). Result — прочитанная книга: перечитать — взять с полки новый экземпляр.

Задание 7. Не тот читатель

get_int("name") → sqlite column 'name' is text, expected int. Семейство писем типов — теперь в мире SQL (JSON-№3 передаёт привет: там «json value is string, expected int» — почерк общий: что лежит, чего ждали). Симметрично испытайте get_string на level. Диагноз старый: смотри в схему, потом объявляй тип.

Задание 8. Колонка-невидимка

Запросите SELECT name FROM players, а прочитайте get_int("level") → sqlite result has no column 'level' — хотя в таблице level есть! У результата — только заказанные колонки: SELECT — это меню заказа, Result — поднос: чего не заказывал, того на подносе нет. Диагноз: ошибка «no column» при «точно есть в таблице» → перечитай свой SELECT.

Минутка из внешнего мира. Язык старше интернета

Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.

SQL родился в 1974 году — раньше интернета, персональных компьютеров и мобильных телефонов. Дональд Чемберлин и Рэймонд Бойс из IBM придумали язык SEQUEL («продолжение», иронично!), чтобы с базами могли говорить не только программисты: запрос должен читаться почти как английское предложение — SELECT name FROM players WHERE level > 5 и правда читается. Полвека спустя SQL — возможно, самый живучий язык программирования вообще: сменились поколения машин, языков и мод, а на SQL до сих пор говорят банки, больницы, игры и соцсети — и ваш guild.db. Мораль у долгожителя одна: удачно придуманная простая вещь переживает всё сложное. Кстати, «SQL» читают и «эс-кью-эл», и «сиквел» — оба варианта легальны, споры о произношении идут те же полвека.

Блок 4. Сцены с управлением

Задание 13. Два зала библиотеки

Два SELECT подряд в одной программе (guild.db): сначала герои, потом товары — два независимых Result (каждый со своим курсором, каждый закрыт после себя!). Отчёт с заголовками разделов. Простая, но важная механика: сколько запросов — столько курсоров, и они не мешают друг другу.

Задание 14. Сырые связи

Обратный скаффолд: «Прочитать purchases из guild.db: SELECT player_id, item_id, day FROM purchases ORDER BY day — печать как есть: "День 1: игрок 3 купил товар 7"». Соберите — и вглядитесь в вывод: одни числа. Кто такой «игрок 3»? Что за «товар 7»? База знает — но связывать таблицы мы ещё не умеем. Это самый честный крючок раздела: имена вместо чисел приедут в финальном уроке о JOIN — а тоска по ним начинается сегодня.

Задание 15. Сюрприз буквы Ё

Экспертиза-жемчужина: своя таблица с именами Агата, Борис, Яна, Ёлка и ёж → ORDER BY name → предскажите порядок письменно → запустите. Сюрприз: Ёлка — первая (до Агаты!), ёж — последний (после Яны!). Разгадка: база сортирует по кодам символов, а в таблице кодов заглавная Ё живёт до А, строчная ё — после я (наследие устройства кодировок!). Взрослые базы лечат это настройками сортировки (collation) — нам довольно знать: алфавит машины — не алфавит букваря, и Ё — вечный пограничник. (Кто вспомнил кракозябры broken_letter — тот видит систему: кодировки — подводная часть всех текстов.)

Задание 16. Скидка на лету

Вычисляемые колонки в полную силу (guild.db, только чтение!): SELECT title, price, price * 80 / 100 AS sale_price FROM items ORDER BY price DESC — прайс с колонкой «по скидке» («Скипетр короля мемов: 1200 → 960»). Главная проговорка — контраст с №2: там скидка меняла данные (UPDATE), тут — считается при чтении, и завтра лавка торгует по старым ценам. Хранить или вычислять — выбор архитектора (заноза №1-заметки вернулась с примером!); витрина «сегодня скидка» — точно вычислять.

Задание 19 ⭐⭐. Курсор в руках

Сделайте курсор осязаемым — интерактивная читалка гильдии: программа показывает героев по одному: после каждой строки — «Enter — дальше, стоп — хватит» (console.read_line — пауза-листалка; ввод НЕ попадает в SQL — закон №2 чтим!); next() зовётся ровно тогда, когда читатель попросил; конец таблицы — «герои кончились, прочитано N». Плюс режим «сначала» — свежий execute (з.6: курсор не перематывается — а читалка умеет, потому что берёт новый!). Каждое нажатие Enter — это ваш палец на next(): курсор перестал быть абстракцией. Кто добавит счётчик «осталось примерно...» — стоп, откуда взять «сколько всего» без второго прохода или агрегатов? Честный тупик — и десятая книга уже машет из-за горизонта.
