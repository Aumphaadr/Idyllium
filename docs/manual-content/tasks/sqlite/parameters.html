Блок 1. Параметры

Практика с преподавателем

Задание 1. Апостроф и лекарство

Собираем у доски обе половины урока. Сначала — беда:

Запустите: sqlite execution failed: near "Neil": syntax error. Разберите вслух, что увидел SQL: VALUES ('O'Neil') — строка закрылась после O, а Neil') осталось непонятным обломком. Затем — лекарство:

В базе — O'Neil целым. Проговорите три вещи. Первая: prepare готовит форму с пустыми местами :name, execute выполняет её. Вторая: в SQL — с двоеточием, в bind — без (частая опечатка!). Третья, главная: значения едут отдельным каналом, а не внутри текста команды — потому апостроф остаётся буквой, а не синтаксисом. И закрывать теперь надо двоих: Result и Statement.

Самостоятельная практика

Задание 2. Первый живой ввод

Историческая задача: программа спрашивает имя и уровень героя (console.read_line + to_int — багаж!) и вставляет через prepare/bind в свою базу. Проверьте глазком (SELECT из №3 — теперь он ваш по праву). Введите имя с апострофом — О'Коннор, Д'Артаньян — работает! Первый пользовательский ввод, дошедший до базы: два курса ждали этой минуты.

Задание 3. Три места

Запрос с тремя параметрами (:name, :class, :level): три bind, один execute, прибор. Проговорка: порядок bind неважен (привязка по имени, не по позиции!) — переставьте их и убедитесь. Имена делают форму читаемой: :level в bind виден лучше, чем «третий вопросительный знак» (в других языках параметры бывают безымянными — цените).

Задание 4. Поиск по имени

bind работает и в SELECT: SELECT name, class, level FROM players WHERE name = :name — спросить имя у пользователя, найти героя, напечатать досье (if (rows.next()) — нашёлся, else — «в реестре не значится»). Апострофные фамилии ищутся так же безупречно, как вставляются.

Блок 2. Экспертиза

Задание 5. Что увидел SQL

Разбор письма з.1 по буквам: напечатайте склеенную строку console.writeln до execute — увидите глазами то, что видел SQL: INSERT ... VALUES ('O'Neil'). Обведите в тетради, где строка открылась и где закрылась, и что осталось за бортом. Правило-диагноз: ошибка near "..." при работе с чужим текстом → ищи склейку; лечится не заплаткой, а переходом на параметры.

Задание 6. Двоеточие туда и обратно

Две опечатки, два разных письма. Первая: bind(":name", ...) — с двоеточием — → sqlite statement has no parameter '::name' (двоеточие удвоилось — Statement такого места не знает). Вторая: лишний bind несуществующего места (bind("ghost", 42)) → sqlite statement has no parameter ':ghost'. Оба письма — об одном: Statement знает свои места наперечёт; форма подготовлена, чужие имена в неё не лезут. И заметьте разницу с забытым bind — та ошибка ждёт вас в седьмой книге (unbound parameter).

Задание 7. Параметр — не имя

Важнейшая граница (уроки её не проговаривают — исследуем сами!): попробуйте подставить параметром имя колонки: SELECT :col FROM players + bind("col", "name"). Ошибки нет — и это ловушка: результат вернёт строку «name» (буквально слово!), а не значения колонки. Диагноз в тетрадь: параметры — только для значений; имена таблиц и колонок частью данных быть не могут (они — часть команды, и потому в динамических запросах их собирают строкой... с проверкой по белому списку — но это разговор для взрослых). Проверьте и с именем таблицы — та же история.

Задание 8. Один-равно-один

Драма книги — воспроизводим безопасно, в учебной базе. Программа «повышает героя по уровню»: "UPDATE players SET level = 99 WHERE level = " + ответ_пользователя — и пользователь вводит 1 OR 1=1. Прибор: задето 2 строки (все!), глазок: у всех героев 99. Условие превратилось в «где уровень 1 ИЛИ где правда» — а правда всюду. Никакой ошибки: команда синтаксически безупречна — просто это уже не ваша команда, часть её написал пользователь. Имя беды — SQL-инъекция, и она вот такая простая. Перепишите на bind и повторите ввод: в базе будет искаться герой с уровнем «1 OR 1=1» — не найдётся, задето 0, и это правильный ответ. Правило на всю жизнь: чужой текст никогда не становится частью команды.

Блок 3. Приёмная

Практика с преподавателем

Задание 9. Анкета героя

У доски — полный приём с диалогом: спросить имя, класс, уровень → одним подготовленным INSERT-ом записать → отчитаться прибором → показать реестр глазком. Апостроф в имени приветствуется (проверьте при всех!). Проговорите архитектуру приёмной: форма готовится один раз (prepare до диалога), данные приходят потом (bind после ввода) — как бланк на столе и посетитель с ответами.

Самостоятельная практика

Задание 10. Правка по запросу

Диалог: «кого повышаем?» → bind в UPDATE heroes SET level = level + 1 WHERE name = :name → прибор: 1 (нашёлся) или 0 (тихий ноль №2 — вежливо сообщить «такого нет»!). Ввод правит данные — и приборы по-прежнему на страже.

Задание 11. Отчисление по правилам

DELETE с параметром: «кого отчисляем?» + подтверждение («точно? да/нет» — ввод дважды, вторая проверка своя, не SQL-ная). Прибор скажет, состоялось ли. Опасная команда с чужим именем — и всё безопасно: параметр не даст вводу стать командой (попробуйте ввести Мира' OR '1'='1 — увидите тихий ноль вместо катастрофы!).

Задание 12. Типизированные варианты

Урок упомянул bind_string/bind_int/bind_bool — испытайте: та же анкета, но с явными типами. Проговорка урока дословно: «это не разные способы выполнить запрос — они только точнее описывают тип». Когда полезно? Когда значение приходит из строки и вы хотите заявить намерение (bind_int("level", to_int(ответ)) читается строже). Дело вкуса и дисциплины — но знать надо.

Минутка из внешнего мира. Малыш Таблички-Сбрось

Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.

В 2007 году вышел комикс xkcd, ставший вечным: мама называет сына Robert'); DROP TABLE Students;-- — и школьная база теряет всех учеников, потому что имя ребёнка приклеили в SQL-команду. Шутка стала настолько знаменитой, что мальчика прозвали Little Bobby Tables — «малыш Таблички-Сбрось», а в интернете живут списки «имён-инъекций»: люди по фамилии Null, O'Hara и один настоящий британец, официально сменивший имя на кусок SQL. Отрасль борется с инъекциями полвека, и они до сих пор в первой тройке уязвимостей мира — потому что каждый год кто-то заново решает, что «здесь-то можно и склеить». Ваша сегодняшняя привычка — bind вместо плюса — та самая, что отличает тех, у кого база цела, от тех, кто попал в новости.

Блок 4. Сцены с управлением

Задание 13. Ворота гильдии

Приём в гильдию с проверками: спросить имя → поиск дубля (bind-SELECT з.4: уже есть? — «такой герой в реестре») → если свободно, спросить класс и уровень → INSERT с параметрами → показать реестр. Проверка перед вставкой — узор из JSON-книг (has перед add!) в новом мире. Апострофы, пробелы, странные буквы — реестр принимает всех.

Задание 14. Поисковая строка

Обратный скаффолд: «Читалка guild.db (только чтение!): спрашивать имя героя в цикле (пустой ввод — выход); по каждому — bind-SELECT по имени; нашёлся — досье (класс, уровень, золото), нет — "не значится". Вести счёт удачных и неудачных запросов, в конце — сводка». Соберите. Первая программа курса, где чужая база отвечает на вопросы пользователя — маленький справочный терминал.

Задание 15. Калькулятор цены

bind с числами и вычислением: спросить у пользователя «сколько монет у вас?» → SELECT title, price FROM items WHERE price = :budget (точное совпадение — фильтры «меньше-равно» будут в №5!) — «за ровно столько можно купить: ...» или «ничего ровно за столько». Слегка обидное ограничение — и честный крючок: со следующей книги придут <=, диапазоны и сортировка по подходящим, и калькулятор станет умным.

Задание 16. Форма и посетители

Проговорка архитектуры на примере: один prepare — три execute (по образцу урока): подготовить INSERT, затем три раза подряд bind всех параметров и execute (три героя из массивов). Работает! И честное предупреждение: полный ритуал безопасного цикла (с clear_bindings) — тема седьмой книги; сегодня мы привязываем все параметры каждый виток, и потому всё в порядке. Заметьте главное: текст команды готовился один раз — база разобрала SQL единожды, а исполнила трижды.

Сервис приёма с меню: 1 — принять героя (анкета з.9 + проверка дубля з.13); 2 — найти по имени (з.4); 3 — повысить уровень (з.10); 4 — отчислить с подтверждением (з.11); 5 — показать реестр; 0 — выход. Сдача сценарием + устный вопрос: где в вашей программе значения становятся частью команды? (Правильный ответ: нигде.)

Задание 18 ⭐. Демонстрация для родителей

Двухрежимная программа-урок (учебная база!): режим «дырявый» — склейка ("... WHERE name = '" + ввод + "'") и режим «крепкий» — bind; одна и та же операция, переключатель в начале. Прогнать в обоих режимах на трёх вводах: обычное имя (работает везде), имя с апострофом (дырявый — падает!), строка-инъекция ' OR '1'='1 (дырявый — выдаёт всех героев или задевает все строки; крепкий — вежливый ноль). Отчёт-табличка «ввод × режим × результат» — и покажите её дома: за две минуты объясните родителям, почему в новостях воруют базы. Демонстрировать уязвимость на своей учебной базе — законно и полезно; на чужих системах — преступление (разговор об этике обязателен).

Задание 19 ⭐⭐. Анкета-конструктор

Инженерная звезда: программа собирает INSERT под структуру ввода — спрашивает, сколько полей заполнит пользователь (1–3 из name/class/level), и строит текст запроса под выбранные колонки... но значения — всегда через bind! Тонкость мастера: имена колонок собираются строкой (з.7 доказала: параметром их не подставить) — и потому берутся только из белого списка программы (массив разрешённых имён, ввод сверяется с ним — чужое имя колонки не пройдёт!), а значения не склеиваются никогда. Так устроены настоящие конструкторы запросов: динамическая часть — из своего списка, данные — параметрами. Кто пройдёт приёмку тремя тестами (обычный ввод; апостроф в значении; попытка ввести «name); DROP TABLE heroes;--» и в поле, и в имени колонки) — тот написал безопасный генератор SQL, а это уже уровень стажёра в настоящей команде.
