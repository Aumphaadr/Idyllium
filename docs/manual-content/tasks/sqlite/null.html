Блок 2. Экспертиза

Задание 5. Равно ничему

Жемчужина книги — и главная классика SQL. Спросите базу: WHERE nickname = NULL → 0 строк (хотя NULL-ы есть!). Логично? Тогда спросите обратное: WHERE nickname != NULL → тоже 0 строк! Оба ответа пусты, и это не поломка, а философия: NULL — неизвестность, а неизвестное нельзя сравнить ни на равенство, ни на неравенство (сравните два запечатанных конверта: равны ли их содержимого? неизвестно — а «неизвестно» это не «да» и не «нет»). Поэтому у SQL есть отдельные слова: IS NULL и IS NOT NULL — они спрашивают не о значении, а о самом факте пустоты. Прогоните оба — получите 2 и 1. Запишите жирно: с NULL сравниваются словом IS, а не знаком =.

Задание 6. Обязательное поле держит удар

Попробуйте нарушить NOT NULL: bind("name", null) → sqlite execution failed: NOT NULL constraint failed: players.name. База назвала и правило, и колонку — как с UNIQUE в будущей книге ключей. Ограничение — это не совет, а охрана: схема сторожит данные даже от программиста.

Задание 7. Заражение

Коварнее равенства: колонка bonus у Кая — NULL; посчитайте level + bonus AS total. У Миры (12 + 5) — 17, у Бориса — 5, а у Кая — NULL, а не 9! Неизвестное слагаемое делает неизвестной всю сумму (и это честно: если не знаешь бонус, не знаешь и итог). Проверьте — и запомните: NULL заражает арифметику; любая формула по необязательной колонке обязана быть готова к пустому результату (is_null("total") — проверка после вычисления!). Лечение — з.13.

Задание 8. Пустые впереди

Сортировка с пропусками: ORDER BY nickname (по возрастанию) → сначала все NULL, потом значения. Проверьте на своей таблице. Логика простая: «пусто» база кладёт в начало (как «меньше всех»), и в DESC они окажутся в хвосте. Практический вывод: в списке, отсортированном по необязательной колонке, сверху окажутся те, у кого её нет — почти всегда не то, что вы хотели показать (з.14 покажет, как чинить).

Задание 9. Универсальное значение

У доски — sqlite.Value из урока: sqlite.Value nickname = rows.get("nickname"); — и два равноправных способа спросить: nickname == null и nickname.is_null(); дальше — to_string(), to_int() и родня. Проговорите родство: это близнец json.Value из прошлого раздела (там был is_null и to_string — здесь то же самое, и по той же причине: значение, чей тип и наличие заранее неизвестны). Когда типизированный читатель, когда Value? Знаете тип и уверены в наличии — читатель (короче); не уверены — Value (безопаснее).

Минутка из внешнего мира. Миллиард долларов на пустом месте

Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.

В 1965 году британский учёный Тони Хоар придумал для языка Algol «нулевую ссылку» — способ сказать «здесь ничего нет». Спустя сорок лет он назвал это своей ошибкой на миллиард долларов: null расползся по десяткам языков и стал причиной бесчисленных падений программ — «обращение к тому, чего нет» до сих пор в списке самых частых аварий в мире. Языки борются кто как: одни требуют явно объявлять, что значение «может отсутствовать», другие вводят особые типы-обёртки, третьи (как Idyllium) разрешают null только там, где отсутствие осмысленно — вы это уже видели: json.Value и sqlite.Value его принимают, а int и string — нет. И заметьте: SQL с его NULL старше признания Хоара, но повёл себя мудрее многих — он хотя бы честно требует спрашивать IS NULL вместо =, не давая притвориться, что неизвестное — это обычное значение.

Задание 17. Личное дело

Полный сервис карточек с необязательными полями: 1 — завести дело (имя обязательно, три необязательных поля — пустой ввод превращается в null); 2 — показать дело по имени (все поля с прочерками через COALESCE, плюс «неизвестно: N полей»); 3 — дозаполнить поле (выбор поля из белого списка — №4 з.19! — и UPDATE с bind); 4 — стереть поле (bind null — з.11!); 5 — список неполных дел (WHERE nickname IS NULL OR email IS NULL OR note IS NULL — OR из №5 в новой роли!); 0 — выход. Сдача сценарием: завести дело с двумя пропусками → найти его в списке неполных → дозаполнить одно → снова список (дело всё ещё неполное!) → дозаполнить последнее → список пуст. CRUD, где пустота — полноправное состояние.

Задание 19 ⭐⭐. Аудит анкет с картой

Полный инструмент качества данных: таблица profiles (name NOT NULL + три необязательных), заполненная разнобоем; программа: аудит по колонкам (цикл по списку необязательных, для каждой — счёт пропусков функцией count_nulls(db, колонка) — имя колонки собирается в SQL из белого списка!) с отчётом «nickname: пропусков 3 из 4»; общий счёт дыр; карта анкет — таблица с прочерками через COALESCE (эталон: у Бориса и Ники — сплошные прочерки); и вердикт качества: «полных анкет: N, дырявых: M, хуже всех заполнена колонка X». Кто добавит рекомендацию («колонка birth_year пуста у четверти — стоит сделать обязательной?») — тот уже разговаривает как аналитик данных. Это настоящая профессиональная задача: качество данных измеряют именно так — не «есть ли база», а «сколько в ней дыр и где».
