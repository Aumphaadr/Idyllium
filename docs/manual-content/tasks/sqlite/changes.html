Блок 2. Экспертиза

Задание 5. Команда без прицела

Главная тихая всего раздела — воспроизводим намеренно в учебной базе. Таблица с тремя героями разных уровней; «хотели повысить Кая», но написали UPDATE players SET level = 10 — без WHERE. Прибор: задето 3. Глазок: все — десятого уровня, индивидуальность стёрта. Никакой ошибки, никакого предупреждения — команда успешна. Диагноз-ритуал в тетрадь: сначала напиши WHERE, потом SET (буквально порядок набора: прицел раньше выстрела); и всегда смотри на прибор — «задето 3» при задумке «задеть 1» кричит громче любой ошибки.

Задание 6. Тихий ноль

Опечатка в значении: WHERE name = 'кай' (маленькая буква!) → задето 0, программа молчит, глазок показывает нетронутого Кая. Ни падения, ни намёка — только прибор выдаёт промах. Правило: affected_rows = 0 при задумке «точно есть» — это сигнал, не пустяк: опечатка в значении, лишний пробел, не тот регистр. База ищет ровно то, что написано, — она буквальна и в поиске.

Задание 7. DELETE без тормозов

В учебной базе (и только в ней!): DELETE FROM players без WHERE — прибор: задето всё, глазок: пустота. Одна строка — и таблицы как не было (сама таблица цела — вымерли жители). Прочувствуйте вес: в лавке из полигона это был бы весь каталог, в настоящем магазине — все заказы. Минутка расскажет, как это выглядит во взрослом мире; ваш ритуал прежний: WHERE пишется до глагола.

Задание 8. Причуда двойных кавычек

Мировая знаменитость среди ловушек SQLite. Шаг первый: VALUES ("Мира") — двойные кавычки вместо одинарных — работает! (SQLite прощает: не нашёл такого имени колонки — принял как текст.) Расслабились? Шаг второй: таблица с колонками name и nickname (nickname пуст); команда UPDATE t SET name = "nickname" — хотели записать ТЕКСТ «nickname», а двойные кавычки совпали с именем колонки — и SQL скопировал в name содержимое пустой колонки: NULL вместо слова, тихо (прибор: задето 1 — «успех»!). Итог в тетрадь жирно: двойные кавычки в SQL — для имён; для текста — только одинарные. Прощающий фолбэк шага один — не доброта, а мина: работает, пока не совпадёт.

Задание 12. Детектор второго запуска

Хитрая связка памяти базы и тихого нуля: программа без DROP-пролога, таблица создаётся IF-безопасно... нельзя — IF NOT EXISTS не изучен! Честная версия: два файла-программы над одной базой: setup.idyl (DROP-пролог + CREATE + заселение: герой Слава 9 уровня) и promote.idyl (только UPDATE ... SET level = 10 WHERE level = 9). Запустите setup, затем promote — задето 1; promote снова — задето 0: Слава уже десятый, WHERE по старому значению никого не находит! Прибор различил первый и повторный запуск — тихий ноль из ловушки стал детектором. (Идемпотентность — слово из одиннадцатой книги, а чутьё — уже ваше.)

Минутка из внешнего мира. Понедельник, продакшен, забытый WHERE

Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.

В фольклоре программистов есть жанр страшилок, и половина их начинается одинаково: «запустил UPDATE на рабочей базе и забыл WHERE». Компании теряли за секунды миллионы строк: цены всех товаров становились одинаковыми, все пользователи получали одно имя, а однажды известный сервис случайно «удалил» базу целиком — администратор перепутал окна терминалов. Отрасль выработала обереги, и все они вам знакомы или скоро будут: бэкапы (копия базы перед опасным делом — ваш ритуал копии guild.db!), транзакции (отмена, если пошло не так, — восьмая книга), проверка affected_rows (задето миллион при задумке «один» — тревога!), и золотое правило админов: перед UPDATE/DELETE запустить SELECT с тем же WHERE — «посмотри в прицел до выстрела» (сможете со следующей книги). А пока запомните сам жанр: без WHERE — это не ошибка новичков, это ошибка ВСЕХ, потому и оберегов столько.

Задание 17. Хозяйство лавки

Задание 18 ⭐. Сценарий дня гильдии

Драматургия хардкодом: программа-сценарий проживает день: утро — найм двух новичков (INSERT); день — служба: повышение отличившегося, штраф проштрафившемуся (точечные UPDATE), премия всем выжившим (+15 монет по площади!); вечер — отчисление героя нулевого уровня (DELETE по условию); каждый акт — протокол з.16 (слова → команда → прибор → глазок). Задание 19 ⭐⭐. День сурка

Исследование памяти базы — через кино. Сценарий з.18 с DROP-прологом — запускается сколько угодно раз, и каждый раз день проживается заново, одинаково до последней монеты (прогоните трижды — выводы идентичны: чистый лист делает программу повторяемой!). А теперь эксперимент: закомментируйте пролог и запустите ещё раз. Что сломается? (Прогнозы письменно — потом запуск!) Ответ: CREATE упадёт о существующую таблицу (память №1 з.5!)... а если и CREATE закомментировать? Новички наймутся второй раз (дубли!), премия выдастся повторно, отчисленный не найдётся (тихий ноль!). Полугодовалый день сурка — данные наслаиваются, программа «работает», мир — портится. Верните пролог и запишите вывод звезды: программа над базой обязана решить, что она делает с прошлым: стирает (пролог) или уживается (одиннадцатая книга научит) — а «не думать о прошлом» — это самый тихий способ испортить всё.
