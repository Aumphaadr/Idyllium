Проговорите четыре вещи. Первая: точка с запятой завершает каждую команду, и в одном файле их сколько угодно. Блок 2. Экспертиза

Задание 5. Одна команда — не две

execute("INSERT ...; INSERT ...") → execute() expects exactly one SQL statement, got more than 1. Строгий разделитель труда: execute — ровно одна команда, exec_script — много. Диагноз: увидел эту ошибку — либо убери лишнюю точку с запятой, либо возьми exec_script.

Задание 6. Ремонт скрипта

Жанр «ремонт данных» из JSON-раздела возвращается в новом обличье — ремонт скрипта. В раздатке setup_broken.sql спрятана ровно одна ошибка. Запустите: sqlite script execution failed: near "12": syntax error. Найдите место по подсказке (что стоит перед 12? чего не хватает между 'попугай' и 12?), почините файл, запустите снова, покажите питомцев. Письмо SQLite указало на слово, а не на строку — учитесь читать такие письма: near "X" значит «споткнулся, дойдя до X», то есть беда чуть левее.

Задание 7. Молчаливый SELECT

Положите в скрипт SELECT * FROM achievements; и выполните: ничего не напечатается — exec_script ничего не возвращает, найденные строки отбрасываются. Урок предупреждал; проверьте лично. Правило: скрипт строит и наполняет, читает — программа (отдельный execute с Result — так и разделяются роли).

Задание 8. Половина скрипта — эксперимент с сюрпризом

Проверка обещания урока. Урок пишет: «exec_script не создаёт транзакцию автоматически» — значит, при ошибке в середине первые команды должны остаться выполненными? Проверим: скрипт создаёт таблицу, вставляет две строки, потом обращается к несуществующей таблице (сбой!), потом ещё вставка. Запустите — увидите script execution failed: no such table: ghosts. А теперь загляните в базу: таблицы нет вовсе — откатилось всё, включая создание и две вставки (проверено!). Вывод двойной, и оба важны. Первый: в текущей версии Idyllium скрипт применяется целиком или никак — приятная новость. Второй, инженерный: документация обещает иначе, а полагаться на неописанное поведение опасно (завтра версия изменится — и половина скрипта останется). Поэтому правило книги: если скрипт обязан примениться целиком — оберните его в begin_transaction() / commit() явно (№8 у вас в руках!) — так вы получите гарантию, записанную в коде, а не надежду на реализацию.

Минутка из внешнего мира. Схема в системе контроля версий

Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.

Почему взрослые команды так любят SQL-файлы? Потому что файл можно положить в систему контроля версий рядом с кодом — и тогда история схемы становится видна: кто добавил колонку, когда, и что он написал в комментарии. Из этой привычки выросла целая дисциплина — миграции: набор пронумерованных скриптов (001_create_players.sql, 002_add_email.sql, ...), которые применяются по порядку и превращают пустую базу в актуальную. Каждый разработчик у себя на компьютере прогоняет ту же цепочку и получает ту же базу, что на сервере, — конец эпохи «а у меня работает». Специальные инструменты (Flyway, Liquibase, Alembic) даже ведут в базе служебную таблицу «какие миграции уже применены», чтобы не применять дважды. Ваши два скрипта из з.11 — первый шаг ровно в эту сторону, а таблицу-журнал применённых миграций вы сможете сделать сами уже после урока о ключах.

Задание 19 ⭐⭐. Журнал применённых миграций

Финальная звезда раздела о скриптах — инструмент, который не применяет дважды. Заведите служебную таблицу applied_migrations (filename TEXT, applied_day INTEGER) (создаётся отдельным скриптом, если её нет — читается через sqlite_master!); мигратор: по каждому файлу из списка — проверить, есть ли он уже в журнале (bind-SELECT — №4!), если да — «пропущено: 002_seed.sql (уже применялось)», если нет — выполнить в транзакции и записать в журнал внутри той же транзакции (гениальная тонкость: применение и отметка о нём атомарны — либо оба, либо ни одного!). Прогоните трижды: первый раз применяются все, второй и третий — «пропущено» по всем. Затем добавьте четвёртый файл — применится только он. Вы написали Flyway для бедных: именно так устроены настоящие инструменты миграций, и «атомарность применения вместе с отметкой» — их главный секрет, который вы вывели сами.
