Как читать ошибки

Этот урок — справочник самых частых ошибок при работе с классами и объектами. Все сообщения в нём настоящие: можете скопировать любой пример, запустить его и получить точно такой же текст.

Формат сообщений вы уже знаете по разделу «Консоль», напомним его на живом примере:

main.idyl:2:5: error: unknown class 'Cat'

Через двоеточия перечислены: файл, номер строки, номер символа в строке — а дальше описание того, что пошло не так. Компилятор показывает место ошибки с точностью до буквы.

💡 Совет: если сообщений несколько — исправляйте первое. Одна опечатка часто порождает целую гроздь сообщений-«эха», и после исправления первого остальные исчезают сами. Дальше в уроке вы увидите такой пример.

Лишняя точка с запятой после класса

В Idyllium после закрывающей фигурной скобки класса точка с запятой не нужна. Привычка ставить её приходит из других языков — например, в C++ без неё класс не скомпилируется.

Одну случайную точку с запятой сразу после класса компилятор молча прощает — эта программа скомпилируется. Но не стоит полагаться на его доброту: в любом другом месте между классами и функциями «висячая» точка с запятой — уже ошибка. Например, после main():

main.idyl:7:2: error: unexpected token 'Semicolon' at top level

Исправление: уберите лишний символ. Точка с запятой нужна после команд внутри функций, а после } классов, функций и main() — нет.

this в статическом методе

Статический метод принадлежит классу, а не объекту, поэтому this и нестатические свойства ему недоступны.

main.idyl:7:25: error: 'this' cannot be used in a static method main.idyl:7:25: error: type '<error>' has no member 'name'

Вот и обещанная «гроздь»: сообщения два, но настоящая ошибка — первая. Раз this недоступен, компилятор уже не знает, у чего мы просим name, — отсюда вторая строка. Исправьте первую — исчезнут обе.

Исправление: либо сделайте метод нестатическим, либо передавайте нужные данные как параметры.

Обращение к приватному свойству извне

Свойства, объявленные как private, доступны только внутри методов класса. Из main() или других классов к ним обратиться нельзя.

main.idyl:8:5: error: member 'BankAccount.balance' is private and can only be used inside class 'BankAccount'

Исправление: создайте публичные методы для работы с приватным свойством — например, get_balance() для чтения и deposit() с проверкой суммы для пополнения.

Печать объекта целиком

Объект — это не текст, и Idyllium не берётся угадывать, как показать его на экране. Попытка отправить объект в console.writeln() — ошибка компиляции.

main.idyl:11:21: error: cannot print object of class 'Cat' directly

Исправление: печатайте свойства по отдельности — console.writeln(cat.name); — или напишите в классе метод info(), который сам выводит всё, что нужно.

parent() и ответственность

Эта запись — особенная: сообщения об ошибке здесь не будет. Если в конструкторе потомка забыть вызвать parent(), программа скомпилируется и запустится:

Имя: Здоровье: 0 Возраст: 3

Конструктор Animal так и не выполнился, поэтому поля родителя остались со значениями по умолчанию: пустая строка вместо имени и 0 вместо здоровья. Добавьте parent(); первой строкой конструктора Cat — и вывод станет ожидаемым: Имя: Зверь, Здоровье: 100, Возраст: 3.

💡 Территория человека. Idyllium сознательно не заставляет вызывать parent(): его можно забыть, вызвать не первым или даже дважды — компилятор промолчит. Компилятор ловит «тихие сюрпризы» машины, а логика программы — ответственность программиста. Поэтому заведите привычку: открыли конструктор потомка — первой строкой напишите parent(). Привычка надёжнее памяти.

Класс не найден (забыли подключить файл)

Если класс объявлен в другом файле, его нужно подключить через use.

main.idyl:2:5: error: unknown class 'Cat'

Исправление: подключите файл и обращайтесь к классу по полному имени — с префиксом имени файла. Одного use недостаточно: без префикса компилятор выдаст ту же ошибку. Пусть рядом с программой лежит файл с классом:

Циклическая зависимость файлов

Нельзя, чтобы файл a.idyl подключал b.idyl, а b.idyl — обратно a.idyl. Такой круг компилятор разорвёт с ошибкой.

a.idyl:2:1: error: module import cycle detected: b -> a -> b

Компилятор прямо рисует круг: b подключает a, тот — снова b, и так до бесконечности. Исправление: пересмотрите структуру проекта. Уберите один из use или вынесите общую часть в третий файл, который подключат оба.

Вызов метода «не с той стороны»

Статические методы вызываются через класс, обычные — через объект. Перепутать стороны легко, но компилятор в обоих случаях подскажет, как надо.

Статический метод через объект:

main.idyl:9:13: error: static method 'MathUtils.square' must be called on class 'MathUtils'

И зеркальная ситуация — обычный метод через класс:

main.idyl:10:5: error: instance method 'Cat.meow' must be called on an object

Исправление: статические методы вызывайте через класс — MathUtils.square(5), обычные — через объект: some_cat.meow().

Итог

  • После } класса точка с запятой не нужна; в других местах верхнего уровня она вызовет ошибку.
  • Статические методы не видят this и нестатические члены; вызывайте их через класс, а обычные методы — через объект.
  • Приватные свойства доступны только внутри класса — снаружи работайте через публичные методы.
  • Объект нельзя напечатать целиком — выводите свойства по отдельности или заведите метод info().
  • Забытый parent() — не ошибка компиляции, а вопрос стиля: привычка вызывать parent() первой строкой конструктора потомка убережёт от пустых полей родителя.
  • Классы из других файлов подключайте через use и называйте по полному имени: файл.Класс.
  • Не допускайте циклов между файлами.
  • Если сообщений несколько — исправляйте первое: остальные часто лишь «эхо».
