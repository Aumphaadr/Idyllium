Проблема: метод, которому не нужен объект

До сих пор все методы, которые мы писали, вызывались у конкретного объекта. Но что, если метод не использует никакие свойства объекта? Например, метод meow() у кота — он просто выводит «Мяу», не обращаясь к this.name или другим свойствам.

Мяу

Программа работает, но создавать объект только для того, чтобы вызвать метод, который не использует свойства объекта — нелогично и накладно.

Решение: статический метод

Статический метод — это метод, который принадлежит не конкретному объекту, а самому классу. Для его вызова не нужно создавать объект — достаточно обратиться к классу.

Синтаксис: ключевое слово static перед объявлением метода.

Мяу

Метод вызван напрямую у класса Cat, без создания объекта.

Ограничение статических методов

Статический метод не имеет доступа к this. Он не связан ни с каким конкретным объектом, поэтому не может обращаться к нестатическим свойствам и методам класса.

В примере ниже мы заодно задали полю значение прямо в классе: string name = "Барсик";. Так можно — это значение получит каждый новый объект класса.

main.idyl:7:25: compile error: 'this' cannot be used in a static method

Сообщение одно и называет причину точно: this в статическом методе недоступен. Общее правило от этого не отменяется: когда сообщений несколько — читайте и исправляйте первое, остальные обычно исчезают вместе с ним.

Статические методы могут работать только с:

  • своими локальными переменными
  • другими статическими методами
  • параметрами, переданными в метод

Практическое применение: вспомогательные функции

Статические методы идеально подходят для функций, которые логически относятся к классу, но не требуют объекта. Например, математические утилиты, конвертеры, фабричные методы.

Квадрат 5: 25 Куб 5: 125 5 чётное? false

Все эти методы не требуют создания объекта MathUtils — они вызываются напрямую у класса.

Сравнение: статический vs обычный метод

Характеристика Обычный метод Статический метод
Вызов объект.метод() Класс.метод()
Доступ к this есть нет
Доступ к нестатическим свойствам есть (через this) нет
Нужен ли объект? да нет

Когда использовать статические методы?

  • Метод не использует свойства объекта (не нужен this).
  • Метод выполняет вспомогательную функцию, логически связанную с классом.
  • Метод является «фабричным» — создаёт объекты определённым образом.
  • Метод не должен зависеть от состояния конкретного объекта.

Если метод обращается к свойствам объекта — он не должен быть статическим.

Статическое поле — общая тетрадь класса

Статическими бывают не только методы. Обычное поле — у каждого объекта своё: сто котов — сто имён. А статическое поле — одно на весь класс, как общая тетрадь на классной доске: кто бы ни подошёл, тетрадь одна. Классика — счётчик созданных объектов:

Котов: 0 Котов: 2

Каждый конструктор дописывает в общую тетрадь — и класс сам знает, сколько котов создано, без всяких глобальных переменных. Обращение — всегда через имя класса: Cat.population. Попытка спросить через объект (first.population) — честная ошибка: static field 'Cat.population' must be accessed through class 'Cat' — тетрадь общая, и язык не даёт притвориться, будто она принадлежит одному коту.

Константа класса

Если значение принадлежит классу и никогда не меняется — это константа класса: знакомое слово const, только в теле класса. Слова static рядом не нужно — константа и так одна на класс, по-другому не бывает:

Не больше 6 котят Корзинка на 6

Константа обязана получить значение прямо при объявлении, присвоить ей новое нельзя (cannot assign to class constant 'Cat.MAX_KITTENS'), а целочисленная константа класса годится размером массива — как и обычные константы. Вы уже встречали этот жанр у библиотек: types.INT8_MAX — ровно такая же константа, только чужого класса. Теперь такие есть и у ваших.

Осталась одна честность напоследок: статические члены не наследуются. У наследника Kitten спросить Kitten.population нельзя — компилятор подскажет: static field 'Cat.population' is not inherited — write 'Cat.population'. Общая тетрадь принадлежит тому классу, который её завёл.

Итог

  • Статический метод принадлежит классу, а не объекту.
  • Вызывается через имя класса: ИмяКласса.метод().
  • Не имеет доступа к this и нестатическим членам класса.
  • Идеален для вспомогательных и утилитарных функций.
  • Статическое поле — одно на класс: общая тетрадь (Cat.population), доступ только через имя класса.
  • Константа класса — const в теле класса: значение обязательно, присваивание запрещено, целочисленная годится размером массива.
  • Статические члены не наследуются — тетрадь принадлежит своему классу.
