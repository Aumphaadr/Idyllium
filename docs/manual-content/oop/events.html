Кнопка, которую вы соберёте сами

Вспомните раздел «Виджеты»: вы писали button.on_click = обработчик; — и кнопка сама решала, когда позвать ваш код. Вы подписывались на событие, а запускал его кто-то другой. Всё это время механизм событий был привилегией библиотечных классов. Пора сравняться с кнопкой: сегодня ваши собственные классы научатся объявлять события и звонить в них.

Слово event

Событие объявляется внутри класса словом event: имя и список параметров, как у функции, — но без тела и без возвращаемого типа. Запускает событие сам класс — обычным вызовом через this.:

Скрип-скрип!

Знакомо, правда? Снаружи — то же присваивание, что у on_click. Внутри — класс звонит в звонок this.on_opened(), когда посчитает нужным. Дверь открылась один раз — и скрипнула один раз.

Звонок в пустом зале

А что, если на событие никто не подписался? Ничего. Запуск события без подписчика — тишина, программа спокойно идёт дальше. Класс не обязан знать, слушают ли его, — ровно так живут и кнопки:

Дверь открыта

События с данными

Параметры события — это посылка подписчику. Классический сюжет: герой сообщает миру о своей гибели и передаёт себя — пусть слушатели сами решают, что важно:

Бой продолжается... Дракон пал в бою

Обработчик может принять либо все параметры события, либо ни одного — если посылка не нужна, её можно не забирать: boss.on_death = void function() { ... }; тоже законно.

Обработчик со своей памятью

Обработчиком может быть и метод другого объекта. Это открывает красивый приём: слушатель со своим состоянием. Табло считает погибших — а герои даже не знают о его существовании:

Счёт потерь: 1 Счёт потерь: 2

Оба героя подписаны на один и тот же метод одного табло — и this.deaths внутри count честно указывает на табло, а не на героя. Метод помнит свой объект, куда бы его ни передали.

Правила подписки

  • У события один слот: новая подписка молча заменяет старую — как у on_click.
  • Снять подписчика отдельной командой нельзя (у кнопок её тоже нет); практический приём — подписать пустую инлайн-функцию.
  • Наклейка… то есть подписка не наследуется объектами: каждый объект подписывают отдельно.
  • События наследуются классами: наследник получает события базового класса и может запускать их из своих методов.
Гав-гав!

Чего события не позволяют

Запустить чужое событие снаружи класса нельзя — звонок принадлежит классу, снаружи на него только подписываются. Компилятор на страже:

main.idyl:7:5: error: event 'on_opened' can only be fired inside class 'Door' (through 'this')

И прочитать событие как значение тоже не выйдет — оно не переменная:

main.idyl:9:21: error: event 'on_opened' cannot be read as a value; assign a handler or fire it inside class 'Door'

Что запомнить

  • event объявляет событие — звонок, в который класс звонит сам, когда происходит важное.
  • Запуск — только изнутри класса через this.; снаружи — только подписка присваиванием.
  • Без подписчика событие молчит, и это нормально: класс не знает, кто его слушает.
  • Обработчик — функция без параметров, функция с полной сигнатурой события или метод объекта-слушателя.
  • Именно так устроены все кнопки, слайдеры и таймеры, которыми вы пользовались. Теперь этот механизм — ваш.
