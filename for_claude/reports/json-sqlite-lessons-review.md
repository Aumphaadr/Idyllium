# Ревью разделов «JSON» (10), «SQLite» (14) и «Примеры задач» (1)

Дата: 2026-07-24. Критерии Т/АТ; 4 ревьюера; **полные run-прогоны со сверкой выводов дословно** (JSON: 30/30 программ; SQLite: ~40 прогонов включая повторные запуски и построение состояния БД). Правки не вносились.

## 1. JSON — самый крепкий раздел учебника

| № | Урок | Вердикт | Суть |
| --- | --- | --- | --- |
| 1 | intro | **хороший** | мотивация через сохранения игры, эскалация «два файла → шкаф»; третий пример — «слепой» (нет ни входных файлов, ни output-блока) |
| 2 | first-object | **хороший** | лучший в первой пятёрке: правила JSON-текста до кода, ошибка дублирования ключа с ТОЧНЫМ текстом, файл побайтово совпал; магическая «4» в to_pretty_json(4) не объяснена |
| 3 | reading | скорее хороший | цепочка read_all→parse→to_object→get; null-семантика безупречна и подтверждена компилятором; секция про uint64/18446744073709551615 — скачок сложности не по возрасту |
| 4 | arrays | **хороший** | образцовое самоограничение («однотипные значения, чтобы не путаться»); pretty-вывод совпал посимвольно; из методов только add/at/length без анонса остальных |
| 5 | nested-objects | смешанный | тема раскрыта, но урок недоделан: главный пример печатает pretty-JSON БЕЗ output-блока, самый тонкий в пятёрке, ни одной ошибки |
| 6 | object-arrays | скорее хороший | образцовый цикл чтения массива объектов; у первого примера нет output-блока, а вводный JSON-сниппет показывает ТРЁХ игроков при коде с двумя (Noah исчезает); подзаголовок обещает файл — file.* в уроке нет |
| 7 | array-methods | **хороший** | опорный список методов (Т7!), мотивация fail-fast («лучше, чем искать проблему полчаса»); clear() объявлен, но не показан |
| 8 | object-methods | скорее хороший | пример с has() — «решение, а не синтаксис»; НО set() объявлен и ни разу не показан, его падение на отсутствующем ключе не демонстрируется нигде (единственная дыра покрытия API) |
| 9 | oop | скорее хороший | сильнейшая идея — «JSON как мост между объектом и сохранением»; подтверждённая ловушка: два разных `to_json()` в соседних строках (метод класса → Object, встроенный → string) без единого слова пояснения |
| 10 | errors | **хороший** | лучший errors-урок ВСЕГО учебника: все 4 цитируемых текста совпадают дословно, включая номера строк; не показан текст ошибки parse на невалидном JSON (`json.parse() invalid JSON: expected a string key at line 1, column 19` — получен пробником) |

**JSON: хороших — 5, скорее хороших — 4, смешанных — 1.** Техническое качество: 30/30 программ работают, каждый output/error-блок совпал дословно (кириллица, отступы pretty, номера строк). Сюжет (Liam/Mira, инвентарь) сквозной.

Ключевые находки: **`json.Value(container)` упаковывает ССЫЛКУ, не копию** (проверено пробниками: правка исходного объекта видна внутри упакованного) — нигде не проговорено, для урока 6 это мина («оптимизация» в цикл с одной переменной даст массив клонов); `json.Object.set`/`remove` по отсутствующему ключу падают той же `json object has no key` — не показано; Т7 системно слаб в первой пятёрке (~20 методов россыпью).

## 2. SQLite — точная фактология, недостроенный хвост

| № | Урок | Вердикт | Суть |
| --- | --- | --- | --- |
| 1 | intro | **хороший** | мотивация через контраст с JSON; повторный запуск честно предупреждён; текст ошибки не показан |
| 2 | changes | скорее хороший | «SQL послушен буквально» — лучшая находка; DELETE удаляет несуществующую 'Nika' (реально «Удалено строк: 0» — урок молчит) |
| 3 | select | скорее хороший | курсор «до первой строки» объяснён образцово; НО фрагмент читает несуществующую колонку id (падение проверено), продолжение секции использует закрытый rows |
| 4 | parameters | **хороший** | O'Neil — образцовая мотивация; полная дисциплина закрытия; текст ошибки от склейки не показан (`near "Neil": syntax error` — получен) |
| 5 | filters | **хороший** | «база фильтрует до попадания в программу», мостик WHERE↔if; LIMIT без подтверждённого вывода |
| 6 | null | смешанный | концептуальное ядро лучшее в разделе («пустая строка — известное значение из нуля символов»); НО ни одной полной программы и ни одного output-блока |
| 7 | reuse | смешанный | clear_bindings мотивирован ошибкой с ТОЧНЫМ текстом (совпал!); но тоже ни полной программы, ни вывода; Result в цикле не закрываются |
| 8 | transactions | скорее хороший | перевод монет, таблица трёх состояний, авто-rollback при close — вся механика подтверждена прогонами; ни программ, ни выводов |
| 9 | scripts | скорее хороший | все три тонкости exec_script подтверждены; единственное настоящее нарушение Т4: setup.sql использует DROP TABLE IF EXISTS (№11) и AUTOINCREMENT (№12) до их объяснения; префикс `sqlite script execution failed:` нигде не упомянут |
| 10 | select-tools | **хороший** | лучший баланс SQL/Idyllium; взвешенный совет про SELECT *; нюанс: таблица GROUP BY показывает 4.0/9.0, а get_float печатает 4/9 |
| 11 | defaults | скорее хороший | закрывает долг «повторного запуска» с урока 1; НО собственный пример плодит дубликаты Mira при каждом запуске — реран-безопасность не доведена до INSERT |
| 12 | keys | скорее хороший | эталонные определения PRIMARY KEY; last_insert_id с проверкой null; фрагмент «из воздуха» (statement из №7 без напоминания) |
| 13 | joins | **хороший** | образцовая подача сложнейшей темы (Nika с NULL как контраст JOIN/LEFT JOIN); НО FOREIGN KEY реально НЕ проверяется базой (guild_id=999 вставляется молча — проверено), а после «база не станет молча портить правило» из №12 ожидание защиты неизбежно |
| 14 | errors | скорее хороший | три репро — все тексты дословны; «забыли next()»/«закрытый объект» — комментарии вместо реальных текстов (а они поучительны: `no current row; call next() first`); как финал ВСЕЙ учебной линии — обрыв: ни итога, ни «что дальше» |

**SQLite: хороших — 5, скорее хороших — 7, смешанных — 2.** Фактология точна: все показанные выводы и тексты ошибок совпадают дословно; собран полный каталог реальных sqlite-ошибок (14 текстов, включая транзакционные, UNIQUE, NOT NULL — готовы к вставке в уроки).

Системное: **вторая половина раздела (уроки 6–8, 11–13) не содержит ни полных программ, ни output-блоков** — резкий контраст с первой; **«закрывайте всё» против практики** — Result от INSERT/UPDATE не закрывается во всех уроках; повторный запуск полных программ №2–5 падает, предупреждение было один раз в №1.

## 4. Сквозное по трём разделам + приоритеты

1. **Учебная линия не имеет финала**: sqlite/errors — последний содержательный урок книги, обрывается техническим абзацем. Нужен финал-капстоун (итог линии, прощание с героями, «что дальше»); sqlite-ошибки не связаны с try/catch из консоли, хотя ловятся (проверено: e.message содержит текст без префикса).
2. **Т7 — общий провал**: опорные таблицы методов отсутствуют почти везде (исключения: json/array-methods, sqlite-таблицы данных).
3. **Т9 зрелее, чем в других разделах** (json/errors — эталон; sqlite тексты точны там, где показаны), но в SQLite реальные тексты появляются слишком поздно — каталог из 14 собранных текстов готов к использованию.
4. Приоритеты правок: (а) достроить хвост SQLite (полные программы + выводы в null/reuse/transactions/defaults/keys/joins); (б) починить падающие фрагменты select; (в) реран INSERT в defaults; (г) оговорка про FOREIGN KEY; (д) слепые примеры JSON (intro ex3, nested ex1, object-arrays ex1 + исчезающий Noah); (е) врезка «Value(container) — ссылка»; (ж) показать set(); (з) написать финал учебника и урок-пример «Калькулятор».

## 5. Для команды компиляции

1. **FOREIGN KEY не enforced**: SQLite по умолчанию не проверяет внешние ключи (`PRAGMA foreign_keys` выключен) — вставка guild_id=999 проходит молча. Вопрос дизайна: включать ли `PRAGMA foreign_keys=ON` в рантайме Idyllium? Для детского языка «честная ошибка» кажется соответствующей философии.
2. Мелочь: два префикса ошибок — `sqlite execution failed:` (execute) и `sqlite script execution failed:` (exec_script) — консистентно, но нигде не документировано.
3. Остальные тексты ошибок sqlite/json — читаемые и точные, замечаний нет.
