Инфраструктура: 11 уроков мигрированы в `docs/manual-content/oop/` (2 уже были), `LESSON_REPLACEMENTS` дополнен; сайт пересобран; финальная валидация штатным чекером команды `check-lesson-outputs` — **ноль расхождений** (остаются только «к сведению» о многофайловых примерах, которые чекер не умеет собирать — см. §4).

## Главное содержательное достижение: ссылочная семантика объектов

- **this (№4)**: новая врезка «Объект — это ссылка» (`Cat b = a; b.age = 5;` → `5 / 5`, прогнано) — закладка для всего раздела.
- **arrays (№6)**: фактически неверный вывод исправлен ЧЕСТНО — секция-ловушка показывает реальные «Бобик 5 / Бобик 5» при переиспользовании одной tmp (add хранит ссылку), затем правильный паттерн: **`Dog tmp;` внутри тела цикла создаёт новый объект на каждой итерации** (подтверждено экспериментом: «Шарик 3 / Бобик 5 / Рекс 2»). Обе программы получили недостающий `use console;`.
- **composition (№8)**: «матрёшка» оставлена только для чтения цепочек; новая секция «Ловушка: один цвет на двоих» (после `red.r = 1` меняются обе фигуры — прогнано) + правильный паттерн «каждому свой `Color(255, 0, 0)`»; урок впервые получил output-блоки (0 → 4).

## Философия parent() (по решению команды)

- **inheritance (№9)**: «parent() всегда первым» переформулирован в правило стиля; новая секция «Что будет, если забыть parent()?» с фактическим прогоном (поля родителя остаются дефолтными); проверены все три свободы: забыт / не первым / дважды (конструктор родителя честно отрабатывает два раза).
- **errors (№13)**: восстановленная запись «parent() и ответственность» — tip-box «Территория человека»: компилятор молчит про parent-вариации, показано фактическое поведение и совет-привычка. «Итог» переписан.

## §3. Открытие по ходу редактуры: парсер прощает `;` после класса

Моё ревью (до слияния) фиксировало: `;` после `}` класса — ошибка `unexpected token 'Semicolon' at top level`. **На актуальном компиляторе это изменилось**: парсер сознательно прощает одну `;` сразу после класса (комментарий в `src/core/parser.ts`: «безвредная привычка из C++»), а ошибка возникает только от «висячей» `;` в других местах верхнего уровня. Урок errors написан по фактическому поведению: «после класса не нужна — компилятор простит; в остальных местах — ошибка» (репро с `;` после `main()` прогнан). Фраза в classes («точка с запятой не ставится») — стилистическая, согласована.

## §4. Замечание команде про check-lesson-outputs

Отличный инструмент (мы им финально валидировались). Одно ограничение: блоки прогоняются в изоляции, поэтому **многофайловые примеры** (уроки modules console/oop/canvas: `use rect;`, `use draw;`, `use scene;`, `use cat;`, циклический импорт `use b;`) падают на `module ... was not found` и попадают в «к сведению», хотя в контексте урока (с соседним файлом) корректны и их error-блоки правдивы. Идея: научить чекер собирать соседние `*.idyl`-блоки того же урока (по комментарию `// имя.idyl` в первой строке — конвенция уже используется в уроках) — тогда «к сведению» очистится, а многофайловые error-блоки начнут проверяться по-настоящему.
