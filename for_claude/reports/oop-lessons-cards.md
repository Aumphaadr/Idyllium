# Приложение: полные карточки ревью 13 уроков «ООП»

Детальные карточки к [oop-lessons-review.md](oop-lessons-review.md). CLI-проверка = прогон `run` со сверкой выводов дословно (для фрагментов — `check` в обёртке).

### 1. intro — «Введение в ООП» — смешанный
**Сильное:** Т1 — образцовый мостик: повторение переменных/функций → «gui.Button — готовый сложный тип» → «а что, если свой?». Т2 — «Класс описывает, какие данные будет хранить объект и какие действия он сможет выполнять». Т5 — обе полные программы сверены дословно. Т6 — snake_case, русский метаязык.
**Слабое:** выдуманный «warning» `main.idyl:6: warning: ⚠️ …торговля людьми — уголовно наказуемое преступление` — компилятор такого не выдаёт, шутка неуместна (продажа Анны за 19.99). Output-блок у некомпилирующегося кода с Cat («предположим» есть, но конвенция нарушена; вывод ещё и противоречит уроку 3). Т10 — список «C++, Java, C#, Python и JavaScript»; «парадигма» без пояснения. Т4 — `array<Cat, 10>` (тема №6). Т7 — таблиц нет.
**CLI:** 5 проверок (3 run + 2 check); расхождений в выводах нет; Cat-пример ожидаемо не компилируется (`error: unknown class 'Cat'`).

### 2. classes — «Создание класса» — хороший
**Сильное:** Т3 — минимальная форма: класс только с полями, объекты `Car car1;` + поштучное присваивание. Т2 — «Класс — самодельный тип данных. Объект — переменная самодельного типа» + параллель `int points; / Car ferrari;`. Т5/Т12 — вывод сверен дословно. Аналогия «коробка с отделениями». Т4 — чисто.
**Слабое:** Т8 — три безликие машины. Т7 — таблицы «класс vs объект» нет. АТ6-мягко — англ. значения "red"/"black"/"white". Т9 — ошибок нет (терпимо для второго урока).
**CLI:** 4 проверки — всё ок, вывод дословно. Класс без `;` после `}` — правильно (с `;` не компилируется).

### 3. fields-methods — «Свойства и методы» — скорее хороший
**Сильное:** Т1 — лучшая мотивация раздела: «переменные хранят, но не действуют; функции действуют, но не хранят; объекты умеют и то и другое». Т2 — «Свойство — переменная в теле класса. Метод — функция в теле класса». Т5/Т12 — обе программы сверены дословно. Т8 — кирпич на голову: живо. Т9-замысел — секция про обращение через класс.
**Слабое:** Т9-исполнение — текст выдуман: в уроке `main.idyl:8: error: 'meow' is not a static member of 'Cat'`, реально `main.idyl:7:5: error: instance method 'Cat.meow' must be called on an object` (+ для поля `instance field 'Cat.name' must be accessed through an object`); слово «static» в выдуманном тексте — забег в №12. «Силикатный» как цвет. Т7 — таблицы нет.
**CLI:** 3 run — выводы дословно; репро падает с другим текстом.
**Особое:** второй шуточный warning (про кирпичи) — тоже выдумка, но безобидная по тону.

### 4. this — «Идентификатор this» — смешанный
**Сильное:** Т1 — «какой именно кот мяукнул?» → this; проблема→решение дважды. Т2 — «this — как если бы методу невидимо передавался параметр „тот объект, от которого меня вызвали“». Т5/Т12 — три программы сверены дословно. Т4 — чисто. Итог-список.
**Слабое:** КРИТИЧНО: секция «Проблема: вывод объекта на консоль» заявляет ошибку компиляции `cannot print object of class 'Cat' directly` — реально программа компилируется и печатает `[object Object]` (см. баги компилятора). Текст «метод info(), который возвращает строковое представление» — а `info()` объявлен void и печатает. «3 лет» — грамматика. Правило «к полям строго через this» не сформулировано, ошибка «поле без this» не показана. Т7 — таблицы нет.
**CLI:** 4 run; три — дословно; печать объекта — расхождение с заявленным.

### 5. modules — «Разбиение проекта по файлам» — скорее хороший
**Сильное:** Т1 — «файл раздувается до сотен строк». Т5/Т12 — многофайловый rect.idyl+main.idyl сверен дословно (600 / 780). Т8 — парк грузовиков, «доставить из Тюмени в Тюмень» → quest.idyl. Т7 — «Правила хорошего тона». Квалифицированное `rect.Rect r1;` — верно (неквалифицированное не компилируется). «main должен читаться как инструкция».
**Слабое:** camelCase (`getArea`, `scaleX`, `scaleY`) против snake_case курса. Т9 — ловушка `Rect r;` без префикса не показана; правило «только имяфайла.Класс» есть лишь в комментарии. Заголовок «класс Rectangle» при классе `Rect`. `r1.width = 20` — int-литерал во float-поле без оговорки. Нет различения `use console` (библиотека) и `use rect` (файл).
**CLI:** многофайловый run — дословно; контрольный неквалифицированный — `error: unknown class 'Rect'`.

### 6. arrays — «Массивы объектов» — смешанный
**Сильное:** Т1–Т3 — мостик «ячейка массива = переменная → ячейка = объект», повтор пройденного, «7 строк → цикл». Итог-список.
**Слабое:** КРИТИЧНО: секция «Динамический массив объектов» переиспользует `tmp` — но `add` хранит ссылку: заявленный вывод «Шарик 3 / Бобик 5» неверен, реально «Бобик 5 / Бобик 5» (подтверждено: dogs[0], dogs[1] и tmp — один объект). Единственное расхождение вывода в разделе — и оно концептуальное. Правильный паттерн `dogs.add(Dog(...))` недоступен до №7 — аргумент за перестановку секции. Обе «полные» программы секций 3 и 6 не компилируются — нет `use console;`. Корявый комментарий «добавляем во временную переменную в массив». Т7 — нет; Т8 — минимален.
**CLI:** 6 примеров + 2 исправленных варианта; ex1–ex2 дословно; ex3/ex6 — ошибка импорта.

### 7. constructor — «Конструктор» — скорее хороший (свежий replacement)
**Сильное:** Т1 — «пачка присваиваний» на трёх героях. Т3 — минимальная форма → дефолтные значения → конструктор-выражение по шагам. Всё компилируется, `Kaspar: 500` дословно; дефолт (`100 900`), именованные `Hero(ex_hp=1000, ex_name=…)`, `Hero(...)` в add/return/немедленный доступ — работают. «new нет» — сказано. Деструкторы больше не упоминаются — старая проблема решена. Инициализатор `Health health = Health(100);` — «изменение здоровья одного не меняет другого» подтверждено прогоном (5 100).
**Слабое:** висячий «Empty()» в итоге — класс-пример в уроке не определён. Блок «Значение по умолчанию» — голый constructor рядом с main вне класса (как фрагмент не собирается). Сбитый отступ `bool very_strong`. Т7 — таблицы нет.
**CLI:** 6 блоков — всё сверено.

### 8. composition — «Композиция» — смешанный
**Сильное:** Т1 — дублирование colorR/G/B → DRY. Понятное определение; бытовые has-a; противопоставление has-a/is-a как мостик. Весь код компилируется; `int r, g, b;` работает.
**Слабое:** ни одного output-блока на весь урок — ребёнок не видит результата. camelCase не исправлен (`colorR`, `redValue`). Метафора «матрёшки» умалчивает ссылочность: `rect.color = red` разделяет объект — после `red.r = 1` меняются обе фигуры (проверено), а предыдущий урок обещал независимость Health. Т7 — нет; сюжет — сухие фигуры.
**CLI:** 3 примера ок; дополнительный прогон ссылочности подтвердил разделение.

### 9. inheritance — «Наследование» — хороший
**Сильное:** Т1 — «антипример → решение». Т8 — автопарк, КАМАЗ. Все 4 примера компилируются, оба вывода дословно (включая печать `20.0` → «20 тонн»). `parent()` мотивирован. snake_case + `ex_` последовательны. Итог-список.
**Слабое:** «parent() всегда должен быть первым» подано как правило языка — компилятор не проверяет (работает и второй строкой); честнее — правило стиля. Пункт итога «Потомок может переопределять методы» — тема следующего урока (лёгкая утечка). Фрагменты без `use console;` (допустимо). Т7 — нет.
**CLI:** 4 примера + проба порядка parent() — расхождений нет.

### 10. polymorphism — «Полиморфизм» — хороший (свежий replacement)
**Сильное:** Т1 — «одна функция вместо десятка draw_*». Т2 — «тип родителя, внутри — потомок». Оба примера минимальны, компилируются, выводы дословно. «new не используется» проговорено. Отсылка к пройденному `gui.Window.add_child()`. Полиморфизм работает во всех формах (переприсваивание, параметр, конструктор-в-выражении — проверено).
**Слабое:** упоминание `canvas.draw()` — Canvas не пройден (только упоминание, без кода). «drawable-объекты» — англицизм. Т7 — нет; сюжет абстрактный.
**CLI:** 2 программы + 2 фрагмента — всё сверено.

### 11. encapsulation — «Инкапсуляция» — скорее хороший
**Сильное:** арка «антипример → принцип → защищённая версия». Оба примера сверены дословно (включая порядок строк). Т8 — Hero/hp. Секции `private:`/`public:` соответствуют реальному синтаксису.
**Слабое:** текст ошибки выдуман: в уроке `main.idyl: error: 'hp' is private in this context` (даже без номера строки), реально `main.idyl:22:5: error: member 'Hero.hp' is private and can only be used inside class 'Hero'`. «Синтаксис — как в C++» (Т10). Правило «все свойства private» противоречит собственному примеру с публичным name. Пустой `<!-- Hero -->`.
**CLI:** выводы сверены; репро — реальный текст выше.

### 12. static — «Статические методы» — скорее хороший
**Сильное:** Т1 — «объект не нужен». Ключевые примеры сверены дословно (включая `false`). Т7 — опорная таблица «статический vs обычный» — единственная в разделе. Правило вызова через класс. snake_case.
**Слабое:** сниппеты секций 1 и 3 без `use console;` — секция 1 подана как рабочая программа, а падает; в секции 3 первая реальная ошибка — про импорт, а не про this. Текст ошибки this-в-static почти точен: реально `'this' cannot be used in a static method` (в уроке без «a») + каскадная вторая ошибка, о которой урок молчит. Инициализатор поля `= "Барсик"` ранее в курсе не вводился. Эмодзи ✅/❌ в таблице.
**CLI:** выводы сверены; ошибки импорта зафиксированы.

### 13. errors — «Типичные ошибки» — плохой
**Сильное:** темы каталога адекватны (static/private/use/циклы); формат «код → ошибка → исправление» правильный; репро (кроме секции 1) воспроизводят ошибки.
**Слабое:** все 6 цитируемых текстов не совпадают с компилятором (0/6). Секция 1 учит противоположному реальности: `;` после класса не нужна, а «исправление» урока (добавить её) ломает код (`unexpected token 'Semicolon' at top level`) — активно вредная секция. Структура битая: секции 1–2–3–6–7–8–9 (4–5 вырезаны), «Итог» ссылается на удалённую секцию про parent(). `'Cat' was not declared in this scope` — GCC-калька; реально `error: unknown class 'Cat'`.
**CLI:** 6 репро прогнаны; совпадений 0.
