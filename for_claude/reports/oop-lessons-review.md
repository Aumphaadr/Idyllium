# Ревью 13 уроков раздела «ООП» по критериям конспектов

Дата: 2026-07-24. Оценены все уроки `docs/book/content/oop/` по критериям Т/АТ ([conspect-criteria.md](conspect-criteria.md)). Три ревьюера (5+4+4); **все примеры прогнаны через компилятор** (~60 прогонов `run`/`check` + ~15 контрольных проб), output-блоки сверены дословно. Правки не вносились. Ветка — моя рабочая копия; исправления, которые команда компиляции делает параллельно (Timer, RadioButton, stdin, file-пути, рекурсия), здесь не видны.

## 1. Сводная таблица

| № | Урок | Вердикт | Суть |
| --- | --- | --- | --- |
| 1 | intro | смешанный | образцовый мостик от виджетов («gui.Button — готовый тип; а свой?»); НО выдуманный «warning» про торговлю людьми (неуместная шутка), output-блок у некомпилирующегося кода, список чужих языков |
| 2 | classes | **хороший** | минимальная форма (класс = поля), «самодельный тип данных», вывод сверен дословно; суховат, без сюжета |
| 3 | fields-methods | скорее хороший | лучшая мотивация раздела («переменные хранят, но не действуют; функции действуют, но не хранят»); текст ошибки выдуман (реально `instance method 'Cat.meow' must be called on an object`) |
| 4 | this | смешанный | отличное объяснение механики this; КРИТИЧНО: заявленная «ошибка печати объекта» не существует — реально печатается `[object Object]` (см. §3-баги); void-`info()` при тексте «возвращает строку» |
| 5 | modules | скорее хороший | живой сюжет парка грузовиков, многофайловый пример сверен; camelCase (`getArea`, `scaleX`) против конвенции курса; правило «только имяфайла.Класс» не сформулировано явно |
| 6 | arrays | смешанный | хороший мостик «ячейка = объект»; КРИТИЧНО: output-блок секции про dyn_array неверен — урок обещает «Шарик 3 / Бобик 5», реально «Бобик 5 / Бобик 5» (add хранит ссылку, переиспользование tmp даёт два указателя на один объект); 2 «полные» программы без `use console;` |
| 7 | constructor | скорее хороший | свежий replacement удался: деструкторы убраны, дефолты/именованные/конструктор-выражение — всё сверено и работает; остался висячий «Empty()» в итоге (класс-пример не определён в уроке) |
| 8 | composition | смешанный | понятная мотивация через DRY; НО ни одного output-блока на весь урок; camelCase не исправлен (`colorR`, `redValue`); метафора «матрёшки» умалчивает, что `rect.color = red` разделяет ссылку (проверено: изменение red меняет цвет у обеих фигур) |
| 9 | inheritance | **хороший** | «антипример → решение», КАМАЗ, оба вывода дословно (включая печать `20.0` как «20»); «parent() всегда первым» подано как правило языка, а компилятор не проверяет |
| 10 | polymorphism | **хороший** | свежий replacement: всё компилируется, полиморфизм работает во всех формах; лёгкое упоминание canvas.draw (будущий раздел) |
| 11 | encapsulation | скорее хороший | арка «антипример → принцип → защита», выводы сверены; текст ошибки выдуман (реально `member 'Hero.hp' is private and can only be used inside class 'Hero'`); «синтаксис — как в C++» |
| 12 | static | скорее хороший | есть опорная таблица (единственная в разделе!); два сниппета без `use console;` — падают не на той ошибке; текст ошибки this-в-static почти точен (без артикля «a») |
| 13 | errors | **плохой** | 0 из 6 цитируемых текстов совпадают с компилятором; секция про `;` после класса **активно вредна** — её «исправление» ломает работающий код; секции 4–5 вырезаны, «Итог» ссылается на удалённую; GCC-калька `'was not declared in this scope'` |

**Распределение: хороших — 3, скорее хороших — 5, смешанных — 4, скорее плохих — 0, плохих — 1.**

## 2. Сквозные паттерны

### Хорошее

1. **Код и выводы почти образцовы**: из ~30 полных программ раздела не компилируются только 4 (у всех причина одна — забытый `use console;`), все остальные output-блоки совпадают с реальным выводом дословно, включая тонкости печати float.
2. Прогрессия тем выдержана: конструкторы не появляются до №7, наследование до №9; свежие replacement-уроки (constructor, polymorphism) заметно сильнее соседей — переработка работает.
3. Мотивации в среднем лучше, чем в других разделах (intro, fields-methods, this, modules, inheritance — все из потребности).

### Системные проблемы

1. **Ссылочная семантика объектов нигде не проговорена и дважды предана**: arrays учит переиспользовать `tmp` при `add()` (фактически неверный output-блок — единственное расхождение вывода в разделе, и оно концептуальное), composition называет вложенный объект «матрёшкой», хотя `rect.color = red` разделяет один объект между фигурами. Нужна явная врезка «объект — это ссылка» (и перестройка секции dyn_array: правильный паттерн `dogs.add(Dog(...))` доступен только после урока о конструкторе).
2. **Все цитируемые тексты ошибок раздела выдуманы или устарели** — 8 из 8 не совпадают с компилятором (реальные тексты собраны в §4). Особый случай — oop/errors.html: ноль совпадений плюс фактологически инвертированная секция про `;`.
3. **Шуточные «warning'и компилятора»** (intro: «торговля людьми — уголовно наказуемое преступление»; fields-methods: про кирпичи) — компилятор warnings не выдаёт вообще; формат имитирует реальные диагностики. Шутку про торговлю людьми рекомендую убрать безусловно; про кирпичи — мила, но жанр «выдуманный вывод компилятора» стоит запретить как класс.
4. Т7 провален: одна опорная таблица на 13 уроков (static).
5. Гигиена: camelCase в modules и composition; `use console;` забыт в 4 «полных» программах (arrays ×2, static ×2); англ. значения в русских уроках; «силикатный» как цвет.

## 3. Приоритеты будущих правок

1. arrays — переписать секцию dyn_array (фактическая ошибка вывода + ложная модель семантики).
2. errors — полная переработка по образцу консольного errors: все репро прогнать, секцию про `;` инвертировать (реально `;` запрещена), восстановить структуру.
3. this — секцию «печать объекта» привести к реальному поведению (или дождаться фикса компилятора — см. §4-баг) и починить «возвращает строку» у void-info().
4. Врезка о ссылочной семантике (например, в this или arrays) + починка «матрёшки» в composition.
5. Убрать выдуманные warnings (или заменить честным приёмом без имитации компилятора); вычистить чужие языки (intro, encapsulation).
6. Тексты ошибок по всем урокам; `use console;`; camelCase; таблицы.

## 4. Ответы компилятора на старые открытые вопросы (проверено прогонами)

| Вопрос | Ответ компилятора |
| --- | --- |
| `;` после `}` класса | НЕ нужна и запрещена: `error: unexpected token 'Semicolon' at top level` |
| Класс из модуля без префикса | не работает: `error: unknown class 'Cat'`; только `cat.Cat c;` |
| Класс без конструктора | `Empty e;` и `Empty()` — ок (поля дефолтные); с аргументами `error: 'Empty' expects 0 arguments, got 1` |
| Печать объекта | **НЕ ошибка** — печатает `[object Object]` (см. баги ниже) |
| Поле без this в методе | `error: 'name' was not declared in this scope` |
| Метод через класс | `error: instance method 'Cat.meow' must be called on an object`; поле — `instance field 'Cat.name' must be accessed through an object` |
| static через объект | `error: static method 'MathUtils.square' must be called on class 'MathUtils'` |
| this в static | `error: 'this' cannot be used in a static method` (+ каскадная `type '<error>' has no member…`) |
| private извне | `error: member 'Hero.hp' is private and can only be used inside class 'Hero'` |
| Циклический импорт | `error: module import cycle detected: b -> a -> b` |
| `dyn_array.add(obj)` | хранит ССЫЛКУ (не копию): переиспользование tmp даёт массив одинаковых объектов |
| Инициализатор поля `Health health = Health(100);` | работает, выполняется на каждый объект (объекты независимы) |
| `parent()` не первой строкой | компилируется и работает — «всегда первым» компилятор не требует |
| Деструкторы | спец-сообщения нет: `destructor`/`~Hero()` дают каскад сырых парсер-ошибок |

### Находки для команды компиляции (Idyllium-баги/вопросы)

1. **Печать объекта класса**: `console.writeln(cat)` компилируется и выводит `[object Object]` — утечка JS-представления. Контракт (ai-reference, уроки) обещает ошибку `cannot print object of class 'Cat' directly`. Либо регресс, либо недоделанная проверка.
2. **Регресс диагностики деструкторов**: инвентаризация 2026-06 (`docs/migration/outdated-syntax-report.md`) фиксировала понятное `error: destructors are not supported yet`; сейчас `destructor Hero() {}` даёт каскад сырых парсер-ошибок (`expected ';' after field declaration`, `unexpected token 'LeftParen' in class body`…).
3. **Вопрос дизайна**: должен ли `parent()` быть первым оператором конструктора потомка? Уроки подают это как правило языка, компилятор не проверяет. Либо добавить проверку, либо переформулировать уроки в «правило стиля».
4. Мелкое: каскадные `type '<error>' has no member…` после первичной ошибки шумят в детских диагностиках (пример: this-в-static даёт 2 ошибки вместо 1).
