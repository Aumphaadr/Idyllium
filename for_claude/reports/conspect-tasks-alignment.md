## 1. Содержание конспекта (для справки)

Последовательность изложения:

1. **Связка с пройденным**: «ранее изучили ввод-вывод и переменные» → мотивационный пример-программа: подсчёт стоимости покупки йогуртов (`total = price * amount`).
2. **Мотивирующий вопрос**: «что делать, если при разных данных нужны разные ответы?» → термин «условный оператор».
3. **Определение** (рамка): выполняет блок действий, если условие истинно.
4. **Синтаксис** `if (условие) { действия }` + пример: `if (number > 50) { cout << number; }` + дословный перевод («если number больше 50, то вывести…»).
5. «Действиями могут быть любые изученные команды» (вывод, создание переменных, ввод, любые другие).
6. **Определение условия** (рамка): выражение, истинное либо ложное. Простейший вид — сравнение.
7. **6 операторов сравнения** с русскими именами: `>` больше, `<` меньше, `==` равно, `<=` **не больше**, `>=` **не меньше**, `!=` не равно. Слева/справа — числа, переменные (`N > 10`, `A < B`, `P == 42`) и арифметические выражения (`A*4 <= 20`, `P >= A-B`, `N%7 != K+3`).
8. **Обработка ложного условия**: `else` («иначе»), полный пример про покупку йогурта: `if (money >= price) { …купили; money = money - price; } else { …не хватило; }` + строка **после** оператора: «Вы вышли из магазина, у вас осталось N рублей» (выполняется в любом случае).
9. Ветвление как алгоритм + **две заглушки** `[здесь должна быть картинка: блок-схема неполного/полного ветвления]` — картинки не сделаны.
10. **Полезные советы**: (1) `==` vs `=` — «компиляторы C++ не считают это ошибкой, но код срабатывает не так»; пример с кошельком, где `if (money = 0)` выводит «У вас ещё остались деньги» при нуле; (2) отступы — что подчиняется условию, а что «выведется в любом случае»; упоминание будущих вложенных if «как матрёшка».

Чего в конспекте **нет**: `else if`/каскадов, вложенных if, логических операторов (&&, ||), работы с float, **ни одного образца вывода программы** (только код), картинок-блок-схем (заглушки).

## 2. Связи конспекта с «хорошими» заданиями

Нашлось пять типов связей. Хорошие задания — не «задачи по теме», а **вторая половина единой конструкции**: почти каждый элемент конспекта имеет парный элемент в заданиях.

### 2.1. Прямые цитаты и мостики-числа

| Конспект | Хорошее задание | Связь |
| --- | --- | --- |
| `if (number > 50) { cout << number; }` — первый пример синтаксиса | З. 1 (с преподавателем): код с `NUM > 50` → «Вы ввели число больше 50», запуски 67/32/**50** | ученик собственными руками переписывает и запускает *тот самый* первый пример из теории; прогон с 50 превращает подпись «> (больше)» из таблицы в наблюдаемый факт строгости |
| `P == 42` — пример сравнения на равенство | З. 10 (с преподавателем): `NUM == 42` → «Вы ввели 42»/«Вы ввели не 42» | то же число 42; проверка равенства из таблицы → первый else-пример |
| `A == 7`, `P == 42` (равенство) | З. 2: `PIN == 7766` «Добро пожаловать!» | сюжетная материализация `==` |
| Совет 1: `=` вместо `==`, пример с кошельком | З. 3: «замените `==` на `=`, введите правильный и неправильный пин-код, сравните» | совет *прочитан* в теории → *прожит* в практике; самая сильная пара «теория-профилактика → практика-вакцинация» |
| Совет 2: «этот текст выведется в любом случае» (код до/после if/else) | З. 13: «К оплате N рублей» в **обоих** образцах вывода | идея «общий код после веток» тренируется без слов — через считывание пары скриншотов |

### 2.2. Структурный параллелизм (композиция набора = композиция теории)

Конспект делится ровно в точке «ОБРАБОТКА ЛОЖНОГО УСЛОВИЯ»:

- **до неё** — неполный `if` → «Часть 1» заданий (з. 1–9: только одиночные if, с явным «программа ничего не отвечает» в ложной ветке);
- **после неё** — `else` → «Часть 2» (з. 10–16: везде if/else).

Заглушки картинок в конспекте называют это своими именами: «блок-схема с **неполным**… и **полным** условным оператором». Структура набора заданий — это структура конспекта, развёрнутая во времени урока. Именно этого требовал вердикт «плохого» файла (п. 1: «непонятно, как разбить теорию на два блока»): у хорошего набора точка разреза взята из конспекта.

### 2.3. Словарные мостики (самая незаметная и самая тонкая связь)

Русские имена операторов из таблицы конспекта дословно вшиты в формулировки заданий:

| Формулировка задания | Имя из таблицы конспекта | Оператор |
| --- | --- | --- |
| з. 4: «введёт число **не меньше** 100» | «>= (не меньше)» | `>=` |
| з. 6: «число 20 **или меньше**» | «<= (не больше)» — близкий парафраз | `<=` |
| з. 8: «скорость **больше** 60» | «> (больше)» | `>` |
| з. 5: «число **меньше** 12» | «< (меньше)» | `<` |

Ученик переводит формулировку в код *по таблице из конспекта*. Это работает только потому, что автор заданий сознательно пишет условия языком той таблицы. (Отдельно: полный пример конспекта использует `money >= price` — и первое денежное задание 4 требует ровно `>=`.)

### 2.4. Сюжетное наследование

Сквозной сюжет конспекта — **деньги и покупки** (йогурты в мотивации, покупка йогурта в else-примере, кошелёк в совете про `=`). Задания продолжают его: з. 4 — шоколадка за 100 ₽ (упрощённый до одиночного if вариант else-примера конспекта), з. 13 — скидка от 25 000 ₽ с вычислением суммы в ветке — прямой наследник паттерна `money = money - price;` внутри ветки («действием может быть любая команда», включая вычисление — тезис конспекта, находящий применение). Остальные сюжеты заданий (заряд, скорость, шаги) расширяют мир, не противореча денежному ядру.

### 2.5. Дозирование инструментов: задания используют ровно преподанное

- Все условия всех 16 заданий — **одно простое сравнение**: ровно объём таблицы конспекта. Ни одного &&/вложенности (их в конспекте нет).
- Единственный «экзотический» инструмент — `%` в финальном з. 16 — **мелькнул в конспекте** (`N%7 != K+3` в примерах выражений-условий) и подстрахован подсказкой «вспомните про оператор %». Т.е. даже кульминация не выходит за пределы показанного.
- З. 9 («понадобится два условных оператора») решается двумя независимыми if — конструкция части 1, не требует else до его введения.

### 2.6. Задания компенсируют слабости конспекта

| Дефицит конспекта | Компенсация в заданиях |
| --- | --- |
| Ни одного образца вывода программы (только код) | терминальные скриншоты почти в каждом задании |
| Не проговорено явно «если условие ложно и else нет — не происходит ничего» | з. 6 и 8: «программа ничего не должна отвечать» — явная формулировка |
| Заглушки вместо блок-схем | пары скриншотов (истина/ложь) частично играют роль наглядности |
| Совет про `==`/`=` — только текст | з. 3 делает его экспериментом |

## 3. Связи конспекта с «плохими» заданиями

Проверка каждого из 20 плохих заданий на «покрытость» конспектом:

| Покрыто конспектом | № заданий | Комментарий |
| --- | --- | --- |
| ✅ Да (if/else + одно сравнение) | 1, 2, 5, 6 | но сюжетно и словарно с конспектом не связаны: «дана переменная N» — ни денег, ни формулировок из таблицы |
| ⚠️ Формально да (один `%` в примере) | 11 | как и з. 16 хороших, опирается на мелькнувший `%` — но без подсказки и без сюжета |
| ❌ Каскад if/else if (не преподан) | 3, 4, 7 | сезоны, 12 месяцев, больше/меньше/равно |
| ❌ Паттерн «счётчик в ветке» (не показан) | 8, 9, 10 | формально «любые команды», но паттерна в конспекте нет |
| ❌ Вложенность / составные условия (нет в конспекте; «матрёшка» упомянута как будущее) | 12, 13, 14, 19 | |
| ❌ Разбор числа на цифры, float-математика, внепрограммная математика | 15, 16, 17, 18, 20 | счастливый билет, площади, палиндром, дискриминант, поцифровый пароль |

Итог: **строго покрыты конспектом 4–5 заданий из 20 (~25 %)**; у «хороших» — 16 из 16 (100 %). При этом даже покрытые плохие задания не используют ни сюжетов, ни словаря конспекта — они связаны с ним только темой. Плохой набор написан «про условный оператор вообще», хороший — «про этот конкретный конспект».

Показательная деталь: и плохое з. 11, и хорошее з. 16 опираются на одно и то же самое слабое место конспекта (единственное упоминание `%`), но хорошее ставит его в конец, оборачивает сюжетом и подсказкой, а плохое — в середину списка без страховки.

## 4. Выводы: критерии связности «конспект ↔ задания»

Дополнение к task-design-criteria.md — новый класс критериев **С (связность)**:

- **С1. Покрытие 100 %**: каждое задание решается только инструментами, *явно показанными* в конспекте (не «упомянутыми вскользь»). Инструмент, мелькнувший один раз, можно использовать только с подсказкой-напоминанием и лучше в конце.
- **С2. Первое задание практики = первый пример теории.** Переписывание кода, который ученик уже видел в конспекте, с экспериментальными запусками (включая граничное значение из условия примера).
- **С3. Структура набора повторяет структуру конспекта**: точки разреза теории на блоки = точки разреза практики на части. Если конспект не режется — это дефект конспекта.
- **С4. Словарная согласованность**: формулировки заданий используют русские имена операторов/конструкций из конспекта («не меньше» → `>=`); задания тренируют перевод «формулировка → оператор» по таблице теории.
- **С5. Сюжетная преемственность**: хотя бы одно-два задания продолжают сквозной сюжет конспекта (деньги/покупки), упрощая или развивая его пример.
- **С6. «Советы» конспекта конвертируются в задания-эксперименты** (типичная ошибка → задание-поломка).
- **С7. Задания закрывают дыры конспекта** (образцы вывода, явное поведение пустой ветки), а не дублируют его сильные места.
- **С8. Анти-критерий**: задание, требующее конструкции, о которой конспект лишь предупреждает «будет позже» («матрёшка»), — автоматический брак для этого урока.

## 5. Замечания о самом конспекте

1. **Незавершён**: две заглушки вместо блок-схем — тот же дефицит наглядности, который вердикт ставил в вину плохим заданиям (п. 7). Системная задача: иллюстрации к истинной/ложной ветке.
2. **Нет ни одного образца вывода программы** — весь «вывод» существует только в коде (`cout << …`). Ребёнку, читающему конспект без компьютера, не видно, как выглядит результат. Хорошие задания это компенсируют, но и в конспекте образцы бы не помешали (стиль тёмных терминальных блоков уже есть в заданиях).
3. **C++-специфика в ключевом месте**: совет 1 честно говорит «компиляторы C++ не считают `if (money = 0)` ошибкой». При переносе на Idyllium совет меняет смысл: там присваивание в условии — **ошибка компиляции** (см. language-analysis.md), и урок превращается из «бойся тихой ошибки» в «прочитай сообщение компилятора». Задание-поломка (з. 3) при этом становится даже полезнее.
4. Мелочь: «не больше»/«не меньше» как имена `<=`/`>=` — удачный словарный ход (см. С4), стоит сохранить при адаптации; в терминологии Idyllium-учебника тоже применим.
5. Порядок «сначала синтаксис с действиями-списком, потом что такое условие» — работает, потому что первый пример уже содержит осмысленное условие; менять не нужно.
