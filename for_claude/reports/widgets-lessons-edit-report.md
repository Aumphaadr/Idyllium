# Отчёт о редактуре 21 урока раздела «Виджеты»

Дата: 2026-07-24. Выполнена редактура всего раздела по карточкам ревью ([widgets-lessons-cards.md](widgets-lessons-cards.md)) и приоритетам ([widgets-lessons-review.md](widgets-lessons-review.md) §3). 6 параллельных редакторов; **каждый полный пример прогнан через `cli check`** (~120 прогонов + run для не-GUI программ image/fonts/audio); **все тексты ошибок в уроках — реально полученные**, ни одного выдуманного.

## Инфраструктура

1. 17 уроков мигрированы из слепка `packages/docs/lessons/widgets/` в `docs/manual-content/widgets/` (4 уже были там) — весь раздел теперь редактируется в одном месте; `LESSON_REPLACEMENTS` дополнен 17 записями.
2. Из `docs-build-site.ts` удалены теперь-мёртвые inline-правки: ветки `transformLesson` для label/slider/lineedit/frame и `transformLessonScript` для modal (их изменения вшиты в мигрированные файлы; идентичность проверена diff-ом до правок).
3. Сайт пересобран: 110 уроков, задвоений стилей нет, правки долетели до `docs/book/`.

## Валидация

Контрольный свип: **128 код-блоков** раздела — 90 полных программ компилируются, 21 намеренная ошибка падает с текстом, побайтово совпадающим с error-блоком урока, 17 фрагментов (проверялись редакторами в обёртках), **0 неожиданных провалов**. Каждый редактор дополнительно повторно извлекал блоки из финального HTML и сверял с компилятором.

## Для команды компиляции: удалённые формулировки Timer (вернуть, если API реализован)

Из timer.html удалены (дословно, для восстановления):
- `<li><code>running</code> — запущен ли таймер в данный момент (только для чтения)</li>`
- заголовок «Таймер имеет три метода для управления:»
- `<li><code>restart()</code> — останавливает и запускает заново (полезно при изменении интервала)</li>`

Если в вашей ветке `gui.Timer.running`/`restart()` добавлены — эти пункты стоит вернуть (и упростить паттерн перезапуска обратно). В моей ветке компилятор их не знает: `type 'gui.Timer' has no member 'running'` / `no method 'restart'`.

## Открытое

- Пример 4 в radiobutton теперь проверяет `is_selected` в обработчике — семантика надёжна при любом решении команды о том, приходит ли on_change при снятии выбора. Если команда зафиксировала семантику «только при выборе» — можно упростить, но текущий вид безопасен в обоих мирах.
- Runtime-тексты GUI-ошибок (например, value вне min/max в рантайме, если такая проверка появится) в headless CLI получить нельзя — при появлении Web IDE-раннера в тестовом контуре стоит сверить.
