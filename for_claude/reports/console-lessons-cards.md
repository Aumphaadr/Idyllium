## Уроки 1–8

### 1. setup — «Установка Idyllium» — скорее хороший
**Сильное:** Т3 — минимальный путь первым («устанавливать ничего не нужно», Web IDE), VS Code потом, в конце явная рекомендация для первых уроков. Т2/Т11 — коротко, конкретно. Т7 — финальный список «Что выбрать?».
**Слабое:** Т12 — ни одного скриншота (для урока-установки это главный инструмент); английские названия меню вслепую. Голос сползает на учителя («объяснять ученику, почему…»). «Файл расширения с расширением .vsix» — тавтология без пояснения термина.

### 2. hello — «Первая программа» — смешанный
**Сильное:** Т3 — лестница: write с `\n` → без переноса → `\n` в середине → числа. Т5/Т12 — 3 из 4 примеров с точными output-блоками. Т2 — правило кавычек («текст в кавычках, числа без»).
**Слабое:** Т10/АТ9 — «В отличие от print() в Python…» в первом же уроке кода. Структура программы (`use console;`, `main()`, скобки) не разобрана — главный пробел первого урока. У первого примера нет output-блока. Т9 — ни одной ошибки (напрашивалась забытая `;`).
**Особое:** юмор «Hello, my Lord» — безобидный. «Управляющая последовательность» — термин без определения.

### 3. variables — «Переменные и типы данных» — скорее хороший
**Сильное:** Т2 — метафора «ячейка в памяти» + три атрибута. Т7 — словарь пяти типов с примерами. Т12 — эталон «до/после»: «Кот сожрал5кг» → «Кот сожрал 5 кг». Т9 — две ловушки (типы, использование до объявления) с рамкой «Это не ограничение — это защита»; тонкость `float D = 5; // можно`.
**Слабое:** старт с определения без мотивации; первые примеры на буквах D, Q, N. Точных текстов ошибок нет (только `// нельзя — ошибка!`). Секции 3 и 5 ничего не выводят.
**Особое:** секция 4 — некомпилируемая программа «можно/нельзя» без показа реакции компилятора; юмор «64 алмаза», «ЪЕЪ или ЪУЪ?» — целевой.

### 4. constants — «Именованные константы» — скорее хороший
**Сильное:** Т1 — лучшая мотивация восьмёрки: «Переменная получила своё название не случайно» + 7 дней недели + «Синтаксически всё правильно, но неделя испорчена». Т9 — единственный в восьмёрке с точными текстами: `main.idyl:2: error: constant 'answer' must have an initializer`, `main.idyl:3: error: cannot assign to constant 'answer'`. Т3 — const → вычисляемая → уровня файла. Финальный критерий выбора const — практичный.
**Слабое:** Т4/АТ5 — секция «Константы для всей программы» использует `void function show_limit()` — синтаксис урока №24; весь урок пишет `writeln` (вводится в №7). Пример ошибок на абстрактном answer. Нет сводки «переменная vs константа».
**Особое:** CAPS_WITH_UNDERSCORE честно назван соглашением, не правилом.

### 5. input — «Ввод данных» — хороший
**Сильное:** Т1 — модель «ввод→преобразование→вывод», метафора «счёт в банке, в который никто не кладёт деньги». Т5/Т8 — периметр треугольника; медосмотр («Рома здоров. Свободен. Следующий!») — три типа ввода в одном сюжете. Т12 — эталон раздела: user_input подсвечен во всех прогонах. Т7 — списки функций ввода и дефолтов всех типов.
**Слабое:** Т9/Т12 — сбойный ввод не показан (ни текста ошибки, ни поведения). Голос: «ученик по-прежнему обязан чётко понимать…». Формула «не допускает неинициализированных переменных» рядом с примером именно такой переменной.
**Особое:** дефолты дополняют variables задним числом — связку стоило проговорить.

### 6. arithmetics — «Арифметика» — смешанный
**Сильное:** Т2 — правило: «если в результате теоретически может получиться дробное — результат float», разбор `10 / 2.5 = 4` («выводится как 4, хранится как 4.0»). Т10 — div/mod поданы в логике языка. Т3 — лестница `+ - *` → `/` → смешанные типы → div → mod.
**Слабое:** Т5/Т12 — div и mod немые (результаты в комментариях), output-блоков нет; секция 1 показывает вывод программы, которая ничего не печатает («Если бы мы захотели вывести…»). Битый пример: рабочий код + `int D = A / B; // ОШИБКА` в одном листинге с выводом `3.7` — по правилам урока это не скомпилируется. АТ8 — тотально A, B, C, A1–A4, R1–R4; мостик от периметра из input не использован. Т1 — мотивации нет. АТ7 — нет таблицы «операция → пример → тип результата».
**Особое:** `mod(x, 2) == 0` упоминает `==` до if/bool (без кода, терпимо).

### 7. colors — «Улучшенный вывод текста» — скорее хороший
**Сильное:** Т1/Т3 — writeln как «обёртка над write» с параллельным эквивалентом. Т12 — лучшая наглядность батча: крашеные span-выводы, липкость цвета обеими ветками, сброс `\e[0m` отдельно. Т9-стиль — «что подумал бы компилятор» про кавычки без `\`; «не превращайте программу в новогоднюю гирлянду».
**Слабое:** АТ7 — коды цветов не сведены в таблицу (а transforms строит на них трюк `A + 30`). Голос: «Вы пишете программу для начинающих — не нужно объяснять…» — фраза автора. Т9 — нет точного текста ошибки у экранирования. Т11 — перегружен (writeln, экранирование, `\t`, цвета, липкость, clear, этика).
**Особое:** НЕУДАЧНАЯ ШУТКА: `writeln("нар"); console.clear(); writeln("котики");` + «отсекли лишнее и оставили котиков» — собирается «наркотики»; заменить. Два `<!-- Section 3 -->` подряд; секции clear() и «не злоупотребляйте» дописаны после `<!-- Lesson navigation -->`.

### 8. transforms — «Преобразования данных» — скорее хороший
**Сильное:** Т1 — образцовая затравка («Idyllium не разрешает… Но что, если нужно?»). Т8/Т11 — «Практическое применение»: меню цвета, `A + 30`, `"\e[" + S + "m"` — мостик input+arithmetics+colors с корректным прогоном. Т7 — «Итог: три функции». Т12 — «Числовая сумма: 50 / Строковая сумма: 2030». Т2 — «функция — механизм, который превращает одни данные в другие» (корректный анонс темы functions).
**Слабое:** Т5 — ядро без прогонов (секции 2, 4, 5, 7 ничего не выводят); строки «НЕЛЬЗЯ» вшиты в листинги без error-блоков. Т9 — «завершится с ошибкой» — какой, когда, как выглядит — не показано. Конкатенация `+` объяснена мимоходом до уроков о строках. «to_int() и to_float() завершится» — рассогласование числа.
**Особое:** в финале нет сброса `\e[0m` — мелкое противоречие совету из colors.

## Уроки 9–16

### 9. math-basics — «Базовые математические функции» — смешанный
**Сильное:** Т5/Т12 — почти все примеры полные, выводы точные (3.68/3.67/3.68). Т3 — от `abs` к `clamp`; необязательный аргумент отдельно. Т9 частично — предупреждение про sqrt(<0); clamp с громкостью 115→100. Т10 — чисто.
**Слабое:** АТ1/Т1 — старт с «Подключение библиотеки math», мотивации нет; каталог 6 функций (АТ10-налёт). АТ8 — сюжет только у clamp. АТ7 — нет таблицы «функция — что делает — пример». Т9 — текста ошибки sqrt(-1) нет.
**Особое:** «не работает с комплексными числами на этом уровне» — корректный анонс. Порядок clamp(min, val, max) необычен, но согласован внутри курса. Формат float плавает между уроками (13 vs 16 знаков).

### 10. if — «Условный оператор и тип bool» — хороший (эталон раздела)
**Сильное:** Т1 эталонно — йогурт продолжает пройденный get_int, программа ломается вопросом «а что, если денег не хватит?». Т3 — минимальный if → несколько if подряд → полная форма. Т12 эталонно — обе ветки (хватило/не хватило) с подсветкой ввода; для трёх if — два прогона (42 и 0). Т6 — русские схемы. Т2/Т7 — простые определения + список 6 операторов. Т9 — `=` vs `==` по-Idyllium: «всегда ошибка компиляции. Так детская опечатка не превратится в серьёзный баг». Явное «программа ничего не выведет, потому что условие ложно».
**Слабое:** битый пример `if (money = 100) { // ОШИБКА! … }` — `}` проглочена комментарием; точного текста ошибки нет. Секция 8 — программа на A, B, C, D без приглашений и output-блока. Немая смена `>` на `>=` между секциями 3 и 5 (случай «денег ровно столько» молча меняет ветку).
**Особое:** «ЪУЪ!» — мемно, зайдёт; урок готовит bool к №13 — связка правильная.

### 11. increment — «Инкремент и декремент» — смешанный
**Сильное:** честность — тема переформулирована как «саморедактирование переменной», «Idyllium намеренно отказывается» от `++`; метафора «справа — источник, слева — получатель». Т1 — опирается на присваивание и math из №9. Т8 — score, скидка 50%, счётчик попыток.
**Слабое:** АТ9/Т10 — код `N++; M--;` с C++/Java/JavaScript и рассуждением про `++i` vs `i++`. Битый `int N = 10; … N /= 4;` — противоречит правилу «/ всегда float». Секция про `+=`/`-=` пришита ПОСЛЕ `<!-- Lesson navigation -->` и риторически конфликтует с предыдущей («пишите честно» → «вот сахар»). Т5/Т12 — секции 1–4 фрагменты без main(); полная программа без output. «Декремент: уменьшение на 10» ломает определение «на единицу». АТ7 — нет таблицы коротких форм.
**Особое:** `+=` дальше в loops/array не используется — сахар повисает.

### 12. random — «Случайные числа» — смешанный
**Сильное:** Т12 эталонно у сидов — три прогона с set_seed(0) дают одинаковые тройки, смена сида — новые. Т2 — «выглядят случайными, но полностью определяются сидом». Т4 — про массивы корректный анонс. Крючок RANDAR из Minecraft — удачное попадание.
**Слабое:** АТ1/Т1 — старт с «Подключение библиотеки» (кубик/лотерея не использованы). АТ9/Т10 — «Как и в Python или JavaScript…»; секция про криптографию — взрослое с пометкой «не для вас» (АТ4-налёт). АТ5 — `char some = random.choose_from(S);` — char вводится в №16. Т5 — фрагменты без main(); floor без `use math`. АТ7 — нет таблицы функций.
**Особое:** пропущена точка; float 16 знаков против 13 в math-basics; «от min до max включительно» для float — неточно.

### 13. bool — «Логические операции» — скорее плохой
**Сильное:** концепт-мостик «все операции — преобразования» (арифметика→числа, сравнения→bool, логика ест bool). Т7 — таблица истинности xor. Т9 — «числа, строки и массивы не превращаются в bool автоматически». Аналогия not() с унарным минусом.
**Слабое:** Т5/Т12 провал — НИ ОДНОЙ полной программы и НИ ОДНОГО output-блока; ученик не видит, что печатает `writeln(true and false)`. АТ8 — всё на A, B, C, D (а просилось «есть билет and есть паспорт»). АТ9/Т10 — целый code-блок Python с приоритетами чужого языка. Самопротиворечие: «Idyllium не заставляет запоминать таблицы приоритетов» — секцией выше сам вводит приоритет and → xor → or.
**Особое:** «Либо одно, либо другое. Но не всё сразу» — удачная формула xor.

### 14. loops — «Циклы» — скорее хороший
**Сильное:** Т5/Т12 — while/for/break/continue полные с точным выводом. Т6 — русские имена частей for («стартовое действие», «условие продолжения», «ежеитерационное действие»). Т3 — каждый цикл своей секцией; do-while честно мотивирован. Т10 — чисто.
**Слабое:** Т1 — мотивация («10 „Привет!" руками») стоит ЧЕТВЁРТОЙ секцией, после всех циклов — порядок перевёрнут. Т2 — «итерация» с первой строки без определения. ### 15. array — «Массивы» — скорее хороший
**Сильное:** Т1 — мотивация из боли: семь переменных a..g, «никто не будет писать 100 переменных»; в секции 7 боль закрыта циклом — кольцевая композиция. Т2 — эхо пройденного: «массив — набор ячеек» ↔ «переменная — ячейка»; «разница в масштабе». Т3/Т7 — разбор объявления по кусочкам; «Итог» — опорный конспект всех операций. **Слабое:** фактическая ошибка: `console.writeln(P[2]); // вывод второй ячейки` — противоречит соседней секции о нумерации. Битая скобка-в-комментарии `if (P > 50) { // ОШИБКА: …}`. Т5/Т12 — один output-блок на урок; в «Итоге» `random.create_float` без `use random`. АТ8 — P, K, B; сюжет только `["Кирка", "Топор", "Удочка"]`. «Как во всех современных языках» — мягкое Т10.

### 16. char — «Тип char как элемент строки» — скорее хороший
**Сильное:** Т1/Т2 — аналогия «int ↔ array» = «char ↔ string» — лучшая межурочная связка восьмёрки. Т12 — посимвольные «Пингвин»/«Журавль», длины, три ступени конкатенации. **Особое:** кириллица посимвольно — корректно молчит про кодировки (тема №23).

### 21. time — «Библиотека time» — смешанный
**Сильное:** Т2-находка — свойства без скобок: «мы читаем состояние метки, а не приказываем ей». Секция зон концептуально сильна: «in_timezone() не двигает время», `utc.unix == ekaterinburg.unix` → true — доказано выводом. Факты точны (week_day, from_unix(946684800), Екатеринбург +05:00).
**Слабое:** Т1 — старт с time.sleep без «зачем». Т5/Т12 — sleep без видимого вывода (нет writeln до/после). Внутреннее опережение — секция зон использует from_unix/.unix/«UNIX-время» до секций, где они вводятся. Плотность взрослого (UTC, эпоха, IANA) без опорной таблицы свойств (АТ7); Т9 — нет (ошибка неверной зоны напрашивалась).
**Особое:** метка 1769734536 = 2026-01-30, а «now» = 2025-11-29; секунды совпадают (…55:36) — примеры «одного момента» разъехались на 2 месяца — след редактирования.

### 22. types — «Библиотека types» — скорее плохой (как урок; как техтекст — сильный)
**Сильное:** техническая безупречность — всё перепроверено: 40000→-25536, 3000000000→-1294967296, битовые шаблоны, from_bin/from_hex, IEEE-разбор -12.5, сдвиг float32 4.5 → 3.009265538105056e-36. Т7 — две таблицы диапазонов; цветовая разметка бит. «Один шаблон — разные числа» проведено последовательно. Юмор: «Получилось безумие — значит, именно это безумие теперь и лежит в переменной».
**Слабое:** Т10/АТ9 в мотивации — «реальные языки — C++, Java, Rust — не всегда щадят новичков», «идентично тому, что происходит в C++». Т11/АТ10 — 18 КБ, 13 секций — материал 2–3 уроков; самопризнание «не для повседневного использования». Т5/Т12 — ключевой пример (переполнение uint8) ничего не печатает. АТ2 — «экспонента», «мантисса», «модульная арифметика», «IEEE 754» подряд. `console.set_precision(25)` нигде в курсе не введён (проверено grep).
**Особое:** секции «Битовые сдвиги» и «А дробные?» стоят ПОСЛЕ «Итога» и `<!-- Lesson navigation -->`, размечены `<section>`; тип строкой в from_bin("…", "uint8").

### 23. encoding — «Библиотека encoding» — хороший
**Сильное:** Т2/Т7 — «чтобы буквы разных языков не спорили за номера» + таблица «'Я': точка 1071 / win-1251 [223] / koi8-r [241] / utf-8 [208, 175]» — ядро урока таблицей и повторено в итоге. Т9 — лучший в восьмёрке: три точных текста (`character 'Ю' is not valid ASCII at position 0`, `invalid UTF-8 at byte 0 (0xD0): incomplete sequence`, `unknown encoding 'cp866'`) + объяснение кракозябр. Т5/Т8 — полные программы; шифр Цезаря «Hello World → Khoor Zruog» (верен) целиком на пройденном (mod, индексация, `+=`). Байты проверены («Привет» win-1251 — точен).
**Слабое:** Т1 частично — концептуальная мотивация без связки; главный потребитель (файлы) через два урока — не проанонсирован. Магические 65–90/97–122 без мини-таблички ASCII. Порядок кодировок в списке ≠ порядку list_encodings.
**Особое:** разметка ошибок `.error-message` vs `idyl-error-block` в functions — разнобой компонентов.

### 24. functions — «Создание собственных функций» — скорее хороший
**Сильное:** Т1 образцово — «мы уже многократно использовали функции» (math.round, sqrt, to_string, .contains) → «функция превращает входные данные в выходные». Т6 — русские заполнители (`имя_функции`, `входные_данные`). Т3 — минимальная int-функция → массив-аргумент → void → именованные → дефолты → main-как-функция. Т9 — точный текст `parameter 'name' without default value cannot follow a parameter with default value`. Область видимости по-детски точно; демистификация main.
**Слабое:** Т11 на пределе — 13.5 КБ, 11 секций (именованные + дефолты + main тянут на второй урок). Т8 — транслит `modul_chisla`, `chislo`. «Web IDE пока вычисляет возвращённое значение и не показывает его» — фраза-загадка. Пустые тела `{}` в примере ошибки; лишняя пустая строка в output draw_line.
**Особое:** вычисления верны (720, 24024); возврат к `i = i + 1` после `+=` в encoding.

## Уроки 25–32

### 25. libs — «Создание собственных библиотек» — скорее хороший
**Сильное:** Т1 — мотивация из роста программ + «весь гардероб в одной куче на полу». Т3 — сначала живой двухфайловый пример, потом синтаксис. Т2/Т7 — ✅/❌-список расположения файлов; сопоставление «системные vs собственные». Т10/Т11 — чисто, компактно.

### 26. files — «Работа с файлами» — скорее хороший (на границе с хорошим)
**Сильное:** Т1 — «До сих пор всё, что делала ваша программа, исчезало после её завершения». Т3 — запись→закрытие→полный пример; чтение→проблема `\n`→trim→has_next_line→полный пример. Т12 — содержимое файла отдельным стилизованным блоком `.file`; «котики» → «кот»/«ики» для read(3). Т8 — инвентарь «Кирка/Топор/Меч». «Считаются символы, а не байты» — точно после encoding.

### 27. directories — «Файлы и папки проекта» — хороший
**Сильное:** Т1+Т9 — старт от реальной ошибки ученика с точным текстом (`…directory does not exist`); метафора «носок в ящике после очень бодрой стирки». Т3 — create_directory → parents=true; remove → recursive=true. Рефрен безопасности: отказы объяснены заботой («защита от опечатки»), песочница `../`. Т12 — exists/is_directory/is_file с `true/true/false`.
**Слабое:** Т7/АТ7 — ~8 методов без таблицы (здесь нужнее всего). Т12 — list_directory и copy/rename без показанного результата. Т8 — «сейвы», но `write_line("Liam;12")` — необъяснённый формат с `;`. «readonly-свойство» — терминологический скачок; секция потоков — хвост files, а не папок.

### 28. math-advanced — «Продвинутые инструменты math» — смешанный
**Сильное:** Т12 — output на каждую секцию; честный `cos(60°) = 0.5000000000000001` с «это нормально». Т7 — итог «Важно помнить» (радианы, погрешности, ошибки log/sqrt). Т11 — компактен. Финал «не для калькулятора, а для моделирования мира».
**Слабое:** Т1/АТ1 — мотивации нет («Библиотека math предоставляет две важнейшие константы»). АТ10-lite — справочник; арксинусы и логарифмы — старшая школа в детском курсе. Т8/АТ8 — единственный сюжет «дальность полёта снаряда» — милитаристичен (мяч/катапульта мягче). Т5 — фрагменты вперемешку с полными программами.
**Особое:** `float deg = 180;` — int-литерал во float рядом с педантичными `50.0` — на грани, требует оговорки. log(-5) без точного текста.

### 29. matrix — «Двумерные массивы» — смешанный (ближе к скорее плохой)
**Сильное:** Т2 — «двумерный массив — это таблица», разбор типа изнутри наружу. Т3 — объявление → доступ → вывод → применения. Т12 частично — вывод таблицы честен вплоть до хвостовых пробелов. Применения (шахматы, «Сапёр», пиксели) + призыв «попробуйте мини-„Морской бой“».
**Слабое:** БИТЫЙ ПРИМЕР — «Сумма: 1424» неверно (по матрице 1231): единственный проверяемый результат урока ошибочен — ребёнок решит, что ошибся сам. «Полный» пример содержит `[ /* ... */ ]` — не запускается. АТ8 — 24 случайных числа без смысла (просились оценки/поле боя). Т9 — ни слова о граблях (строка/столбец, границы); Т7 — нет опоры «объявить/прочитать/записать/обойти».
**Особое:** 3D-куб — приемлемая декорация (дальше по курсу не используется).

### 30. recursion — «Рекурсия» — скорее хороший
**Сильное:** Т2 — «бесконечная лестница без последней ступеньки», вызов «кладётся поверх и ждёт» (стек без слова «стек»), «Звучит немного как фокус, но внутри всё честно». Т3/Т5 — sum_to → factorial, полные программы с выводами; словесная раскрутка вызовов. Прагматика — «побеждает не самый хитрый код, а самый понятный». Анти-пример bad_sum + вопрос-проверка «после каждого вызова задача становится проще?».
**Слабое:** Т9 — не показан текст ошибки бесконечной рекурсии (ребёнок гарантированно её увидит). АТ8 — только n/sum/factorial (матрёшки напрашивались). Т1 — «есть особый приём», потребности нет; «зачем, если есть цикл» — лишь в середине. Т7 — чек-листа нет.
**Особое:** «остановить программу глазами ещё до запуска» — спорная стилистика; висячий `\n` в output-блоках.

### 31. errors — «Типичные ошибки» — скорее хороший (жанр-каталог работает)
**Жанр:** формула «минимальное репро → дословный текст → одна строка совета» выдержана в ~20 записях — Т9, развёрнутый в урок; каталог играет роль Т7-опоры раздела. Т1/Т8 неприменимы, «нерабочие» примеры — норма жанра. Советы конкретны (div(a,b), .is_int(), arr.length > 0, list_encodings()).
**Сильное:** покрытие точно по пройденному (Т4 идеален). Секция «Как читать сообщения» (файл:строка/тип/описание) + «начинайте с первой ошибки».
**Слабое:** заголовок «Ошибки компиляции: строки» содержит пример про массив; строковых compile-ошибок нет; в комментариях скачок Section 7 → 9 — секция 8 потеряна. Warning показан, но не объяснён (а «типов ровно два»); единственное сообщение без номера строки. «Как читать» стоит В КОНЦЕ. Собственные `.error-message` вместо штатного idyl-error-block.
**Особое:** полный список дословных текстов сохранён в отчёте агентов; ⚠ `cannot assign 'float' to 'int'` — устаревшая формулировка на фоне парной полной; конфликт file-ошибки с directories.html; имя функции `double` в репро — рискованный идентификатор.

### 32. try-catch — «Обработка ошибок» — хороший (лучший в четвёрке)
**Сильное:** Т1 — дословная сшивка с errors + демонстрация остановки программы + потребность («заранее понимаем, что может пойти не так, и умеем предложить запасной путь»). Т3 — catch {} → catch (error) → запасное значение → finally → границы; правило «хотя бы один блок» после всех форм. Т12 — divide(3) и divide(0) в одном выводе показывают обе ветки; safe_int — три исхода. Т9/этика — «нельзя оборачивать половину программы в один огромный try», «try не прячет проблемы»; «Что try поймать не может» закрывает ложные ожидания. Т2 — «try так и переводится: „попробовать“»; «имя error не является особым словом».
**Слабое:** Т8 — сюжета нет (divisor, safe_int; «котики» как нечисло — единственная живая деталь). Т7 — нет финальной схемы трёх форм. Как финал раздела не даёт итога всей «Консоли».
**Особое:** ЕДИНСТВЕННЫЙ урок с заданиями («Попробуйте сами», 3 шт.) — легализовать формат или убрать. Номера строк в ошибках выверены. «Результат: 4» для `12 / divisor` — правило печати float нигде не проговорено.
