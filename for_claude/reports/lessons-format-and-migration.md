# Формат хранения уроков и безопасность миграции в manual-content

Дата: 2026-07-24. Написано по итогам миграции раздела «Консоль» (уже выполнена) и в качестве подготовки к «Виджетам».

## 1. Три слоя хранения

| Слой | Путь | Формат | Роль |
| --- | --- | --- | --- |
| Исторический слепок | `packages/docs/lessons/{cli,widgets,oop,examples}/NNN_slug.html` | **полные HTML-страницы**: `<head>` со стилями, `<body><main class="docs-main">`, hero-блок, навигация, инлайн-`<script>` демо | источник для уроков, ещё не переехавших в manual-content; НЕ редактировать |
| Ручной контент | `docs/manual-content/{console,widgets,oop,canvas,json,sqlite}/slug.html` | **чистые фрагменты**: последовательность `<div class="docs-section">`, при необходимости `<style>`/`<script data-lesson-script type="text/plain">` в теле | единственное место правок; после сегодняшней миграции здесь ВСЕ 32 урока консоли |
| Собранный сайт | `docs/book/content/<section>/<slug>.html` + `docs/book/lessons.json` | фрагменты после `lessonFragment()` | генерат; правки затираются `npm run docs:site` |

Маршрутизация в `tools/docs-build-site.ts`: `LESSON_REPLACEMENTS` (sourceFile → manual-файл; сейчас 27 console + 2 oop + setup), `MANUAL_LESSONS` (новые уроки с позицией `afterLessonId`), `LESSON_EXTRAS` (патчи-дописки; **пуст** после интеграции), `transformLesson`/`transformLessonScript` (точечные inline-правки в самом скрипте — см. §3).

## 2. Словарь разметки урока

- `<div class="docs-section">` + `<h2>` — секция (единственный контейнер; `<section>` не использовать).
- `<idyl-code-block><script type="text/plain">…код…</script></idyl-code-block>` — код Idyllium. Экранирование HTML-сущностей внутри: `&lt; &gt; &amp;`.
- `<idyl-output-block>…</idyl-output-block>` — вывод программы; пользовательский ввод внутри — `<span class="user_input">42</span>`; цветной вывод — span'ы с классами цветов.
- `<idyl-error-block>main.idyl:5:13: error: …</idyl-error-block>` — диагностика (легаси-вариант `.error-message` из старых уроков вычищен в консоли).
- `<table><thead>…<tbody>…` — опорные таблицы.
- GUI-демо (только widgets): `<div class="gui-demo-container">` → `<div class="gui-demo-window">` → `demo-content` с абсолютным позиционированием элементов-макетов; интерактивные `input/select` с классами `idyl-spinbox`, `idyl-combobox`, `idyl-frame` и т.п.; подпись `<div class="coord-note">`. Стили макетов — `docs/assets/gui.css` (копируется из `packages/docs/lessons/widgets/gui.css`) + локальные `<style data-lesson-style>`. Демо — **рукотворные макеты**, не рендер кода: соответствие коду держится только дисциплиной (главный источник рассинхронов).
- `<script data-lesson-script type="text/plain">…` — JS интерактивных демо; исполняется оболочкой учебника, текст экранирован (`<\/script>`).

## 3. Что делает сборка с фрагментом (`lessonFragment`)

1. `extractStyles` — вынимает ВСЕ `<style>` и переизлучает их шапкой фрагмента как `<style data-lesson-style>`; ⚠️ до 2026-07-24 тело от них не чистилось → при пересборке уже-собранного фрагмента стили задваивались (проявилось на console errors/files/types). **Исправлено**: тело теперь очищается, сборка идемпотентна.
2. `extractInlineScripts` — вынимает `<script>` БЕЗ `src=` и БЕЗ `type="text/plain"` → `transformLessonScript` (полная замена JS только для `widgets/015_modal.html`) → `escapeScriptText` (экранирует `</script>`) → добавляет хвостом как `data-lesson-script type="text/plain"`. Уже-обработанные скрипты (text/plain) повторно НЕ трогаются — идемпотентно.
3. `extractMain` — берёт `<main class="docs-main">` либо `<body>`, либо всё (для фрагментов — no-op).
4. `removeElementByClass` — удаляет `docs-hero` и `docs-lesson-nav` (комментарии-маркеры `<!-- Hero -->`/`<!-- Lesson navigation -->` остаются — их чистим руками при редактуре).
5. `transformLesson` — **inline-правки в коде скрипта** для 4 виджет-уроков: `002_label` (строковые цвета → colors.*, тексты), `005_slider` (диапазон 0–300/шаг 50), `006_lineedit` (font_size 20), `009_frame` (высота демо). Применяются к исходнику из `packages/docs` до записи.
6. Пришивается `extra` (`LESSON_EXTRAS` — сейчас пуст) и скрипты.

## 4. Насколько безопасна миграция «собранный → manual-content»

Проверено на консоли (32 урока) и по коду сборки:

| Аспект | Вердикт |
| --- | --- |
| Текст, код-блоки, output/error-блоки, таблицы | ✅ передаются байт-в-байт (diff после пересборки — только ведущие пробелы/финальный перевод строки) |
| Стили `<style data-lesson-style>` | ✅ безопасно ПОСЛЕ сегодняшнего фикса идемпотентности; до него — задвоение на каждом цикле |
| JS-демо `data-lesson-script` | ✅ идемпотентно: text/plain пропускается извлекателем и остаётся на месте; повторного экранирования нет. Нюанс: скрипт останется там, где был в момент копирования (хвост файла) |
| Патчи `LESSON_EXTRAS` | ✅ уже интегрированы и словарь пуст; при миграции новых разделов проверять, что ключ удалён, иначе дописка задвоится |
| Inline-правки `transformLesson` | ⚠️ собранные файлы их уже содержат; после миграции 4 виджет-уроков ветки в `transformLesson` станут мёртвым кодом (их `replace` не найдёт старых строк — поведенчески no-op), но их надо удалить для гигиены |
| `transformLessonScript` (modal) | ⚠️ то же самое: замена уже в собранном файле; ветку удалить при миграции modal |
| Манифест (названия, подзаголовки, порядок) | ✅ не зависит от replacement'ов (берётся из старого lessons.json + MANUAL_LESSONS) |
| Артефакты (`<!-- Hero -->`, `<!-- Section N -->`, `<section>`-вёрстка дописок) | ⚠️ переезжают как есть — чистить при редактуре (в консоли вычищено) |

**Итог: миграция безопасна.** Рецепт для «Виджетов» (когда дойдём до правок): скопировать 17 собранных уроков в `docs/manual-content/widgets/`, добавить 17 записей в `LESSON_REPLACEMENTS`, удалить 4+1 веток transform-хаков, пересобрать, сверить diff (ожидается только whitespace). 4 manual-урока (colors, fonts, image, audio) уже на месте.

## 5. Отличия виджет-уроков от консольных (важно для будущей редактуры)

1. **«Озвучка» — это демо, а не output-блоки**: у GUI-программ консольного вывода почти нет; роль Т12 играют HTML-макеты. Их соответствие коду ничем не проверяется — сверка «координаты/тексты в коде ↔ в демо» только ручная.
2. **Проверять примеры можно только `cli check`** (компилируемость): `run` GUI-программ в headless CLI не отрисует окно. Реальные тексты GUI-ошибок рантайма достижимы через Web IDE-раннер (использовалось при редактуре errors в консоли).
3. Демо-стили глобальные (`assets/gui.css`) + локальные; при правках демо смотреть оба.
4. У четырёх manual-уроков раздела формат уже чистый — на них можно равняться.
