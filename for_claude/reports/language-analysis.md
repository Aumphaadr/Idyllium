# Idyllium: подробный анализ синтаксиса и семантики ядра языка

Дата анализа: 2026-07-24. Версия языка: **IdylliumNext 1.1.3**.

Источники: `docs/ai/idyllium-ai-reference.md` (нормативный справочник), `docs/reference/api.json` (языковая секция + сигнатуры из standard library registry), `docs/language-contract.md`, уроки `docs/book/content/**` (110 уроков), `docs/architecture.md`, `docs/canvas-draft.md`, `docs/colors.md`.

---

## 1. Что такое Idyllium

Idyllium — **учебный язык программирования для детей и подростков**. Синтаксис C-подобный (фигурные скобки, `;`, статическая типизация), но язык сознательно отбрасывает «исторические сюрпризы» C-семейства в пользу предсказуемости:

- `23 / 10` — это `2.3`, как в школьной арифметике, а не `2`;
- текст — это текст, а не байты; кириллица в строках работает посимвольно;
- почти все неявные преобразования запрещены (`label.text = 42;` — ошибка);
- операторов `++` и `--` **не существует**;
- ошибки времени выполнения обязаны быть читаемыми, копируемыми и переживать машинный перевод.

Реализация (IdylliumNext) разделена на слои: `src/core` (лексер, парсер, AST, семантика, кодогенерация в JavaScript, реестр stdlib), `src/runtime` (исполнение сгенерированного JS в браузере/Node/VS Code WebView), `src/language` (редакторские сервисы). **Standard library registry — единый источник истины**: из одного декларативного описания получаются семантические проверки, автодополнение, hover, привязки рантайма и `docs/reference/api.json`.

Целевые площадки: Web IDE (GitHub Pages, `docs/index.html`), VS Code-расширение (VSIX), CLI.

## 2. Структура программы

Порядок в `.idyl`-файле: (1) директивы `use`, (2) глобальные переменные/константы, функции, классы, (3) `main()`.

```idyllium
use console;

main() {
    console.writeln("Hello, World!");
}
```

### 2.1. Точка входа `main`

- Педагогическая короткая форма `main() { ... }` трактуется как void-функция (без слова `function`).
- После изучения функций допустима полная форма с любым типом возврата: `int function main() { return 0; }`. Возвращаемое значение сейчас игнорируется Web IDE/GUI preview.
- `main` не принимает параметров; в программе ровно один `main`.

### 2.2. Модули

- `use console;` подключает стандартную библиотеку; каждая библиотека — отдельной директивой. Неподключённый модуль недоступен: `error: 'math' is not imported (use 'use math;')`.
- Пользовательский модуль — обычный файл проекта: `helper.idyl` → `use helper;`. Его верхнеуровневые переменные, константы, функции и классы доступны как `helper.name`, классы — `helper.ClassName` (`geometry.Point p;`).
- Модуль может содержать верхнеуровневое состояние и `void function ...`-коллбэки (важно для Canvas-проектов).
- Циклические импорты запрещены: `a.idyl:1: error: circular import detected: 'b'`.
- Конвенции учебника: один класс — один файл; имя файла = имя класса в нижнем регистре; `main.idyl` — короткий.

## 3. Лексика

- Комментарии: `// строчный`, `/* блочный */`. В JSON-файлах комментарии запрещены (это про данные, но учебник подчёркивает).
- Инструкции заканчиваются `;`. Отступ — 4 пробела (конвенция примеров).
- **Идентификаторы могут использовать кириллицу** (зафиксировано в language-contract; в уроке функций есть примеры с кириллическими именами).
- Строковые литералы — двойные кавычки, `char` — одинарные.
- Escape-последовательности: `\n`, `\t`, `\r`, `\e` (ESC), `\0`, `\\`, `\"`, `\'`. **Неизвестный escape — ошибка компиляции.**
- Литералы `true`, `false`, `null`.
- `UPPER_CASE` для констант — конвенция, а не правило парсера.

### Ключевые слова (по api.json)

| Группа | Слова |
| --- | --- |
| Структура и функции | `use`, `main`, `function`, `return`, `void` |
| Типы и значения | `int`, `float`, `string`, `char`, `bool`, `array`, `dyn_array`, `const`, `true`, `false`, `null` |
| Условия и циклы | `if`, `else`, `while`, `do`, `for`, `break`, `continue`, `and`, `xor`, `or`, `not` |
| Ошибки | `try`, `catch`, `finally` |
| Классы | `class`, `constructor`, `extends`, `parent`, `this`, `public`, `private`, `static` |

## 4. Система типов

### 4.1. Примитивы

`int`, `float`, `string`, `char`, `bool`, `void` (только как тип возврата; `error: cannot declare variable of type 'void'`).

### 4.2. Строгость

- `int` → `float` неявно разрешено (int пригоден там, где ждут числовой float).
- `float` → `int` — **ошибка компиляции** (`error: cannot assign 'float' value to 'int' variable`); нужен `to_int()` (усечение к нулю).
- Числа ↔ строки не преобразуются неявно ни в одну сторону.
- Явные глобальные преобразования: `to_int(x)`, `to_float(x)`, `to_string(x)` (принимают строку/число; `to_string` — любое значение).
- Проверки перед разбором строки: `text.is_int()`, `text.is_float()`.

### 4.2а. Значения по умолчанию (только в учебнике!)

Неинициализированная переменная получает дефолт: `int`→`0`, `float`→`0.0`, `bool`→`false`, `char`→`'\0'`, `string`→`""`; «мусорных» значений нет. Массив без инициализатора заполнен дефолтами (`array<int, 50> B;` — 50 нулей). Это правило описано только в уроках — в ai-reference/api.json его нет (см. inconsistencies.md, B13).

### 4.3. `null`

`null` — литерал языка, но **не** универсальное значение. Присваивать/сравнивать с `null` могут только библиотечные контейнеры, у которых «отсутствие значения» предусмотрено API: сейчас это `json.Value` и `sqlite.Value`. Примитивы, массивы, пользовательские классы, `json.Object`, `json.Array` — не nullable (`string name = null;` — ошибка компиляции).

### 4.4. Семантика значений vs ссылок

- **Массивы — значения.** Присваивание, аргумент, возврат из функции — независимая копия; вложенные массивы копируются рекурсивно. `==`/`!=` массивов — структурное сравнение.
- **Объекты классов (и библиотечные объекты) — ссылки.** `Counter second = first; second.increment();` меняет и `first` (api.json, раздел classes). Объекты в ячейках массива сохраняют идентичность при копировании массива.
- Пограничный случай из уроков ООП: `dyn_array<Dog>.add(tmp)` ведёт себя как добавление значения — одну временную переменную можно перезаполнить и добавить дважды, получив два разных объекта. Общая модель памяти в учебнике явно не сформулирована (см. inconsistencies.md).

## 5. Переменные и константы

```idyllium
int age = 12;
age = 13;
age += 1;   // также -=, *=, /=
```

`const` перед типом, для локальных и верхнеуровневых объявлений:

- инициализатор обязателен (`error: constant 'answer' must have an initializer`);
- присваивание (в т.ч. составное) запрещено (`error: cannot assign to constant 'answer'`);
- верхнеуровневая константа из `config.idyl` доступна как `config.NAME`;
- для массивов/объектов `const` защищает **привязку**, а не граф объекта: `items[0] = v` и мутирующие методы законны, `items = other` — нет;
- `const` не является модификатором поля класса или параметра.

## 6. Операторы

### 6.1. Арифметика

`+ - * /`. **`/` всегда возвращает float** — центральное решение языка. Целочисленное деление и остаток — глобальные функции `div(a, b)` и `mod(a, b)` (оператора `%` нет).

### 6.2. Сравнения

`== != < <= > >=`. Порядковые сравнения (`< <= > >=`) — только для чисел: `error: comparison '>' requires numeric operands`. Равенство `==`/`!=` работает и для строк (`answer == ""`), массивов (структурно), цветов (по каналам). Сравнивать массив с числом нельзя (`error: cannot compare 'array<int, 3>' with 'int'`). Присваивание внутри условия (`if (money = 100)`) — всегда ошибка компиляции. Унарный минус существует (`int y = -x;`).

### 6.3. Логика — словами

`and`, `or`, `xor`, `not` (символьных `&& || ^ !` нет). Правила:

- все операнды строго `bool`, truthy/falsy нет;
- приоритет (убывание): `not` → сравнения → `and` → `xor` → `or`;
- `and`/`or` — короткое замыкание; `xor` вычисляет оба операнда слева направо ровно один раз, истинен при ровно одном истинном;
- `not` — оператор с высшим приоритетом, но во всей документации записывается в форме вызова `not(is_ready)`; урок консоли даже утверждает «отрицание — только функция» (см. inconsistencies.md, B12). Для генерации кода безопасна форма со скобками.

### 6.4. Составные присваивания

`+= -= *= /=`. `++`/`--` отсутствуют принципиально (даже урок «Инкремент и декремент» переписывается под `+= 1`).

## 7. Управление потоком

### 7.1. Условия

`if / else if / else`. Условие — строго `bool`:

```text
error: if condition must be 'bool', got 'int'
```

Скобки `{}` можно опустить для ровно одной инструкции; **отступы грамматику не меняют**. `else` прилипает к ближайшему незавершённому `if`; если `if` уже «закрыт» другой инструкцией, компилятор сообщает, что `else` не имеет пары, и советует `{ ... }`.

### 7.2. Циклы

```idyllium
while (i < 5) { ... }
do { ... } while (x < 10);
for (int i = 0; i < 10; i += 1) { ... }
```

Условия всех циклов — строго `bool`. `break`/`continue` валидны только внутри цикла (`error: 'break' is only valid inside a loop`).

## 8. Массивы

### 8.1. Два вида

```idyllium
array<int, 3> numbers = [10, 20, 30];   // фиксированный: размер — часть типа
dyn_array<string> names;                 // динамический
```

- Индексация с нуля; выход за границы — читаемая ошибка рантайма: `runtime error: array index 5 out of bounds (size 3, valid indices 0-2)`.
- Литерал инициализации обязан совпадать по длине с фиксированным типом: `error: array initializer has 3 elements, but 'array<int, 5>' requires 5`.
- Двумерные массивы: `array<array<int, 6>, 4>`.

### 8.2. Свойство и методы

`values.length` — read-only свойство (не метод!).

Общие методы: `contains(v)`, `find(v)`, `count(v)`, `reverse()`, `sort()`.
Только `dyn_array`: `add(v)`, `remove_at(i)`, `resize(n)`, `insert(i, v)`, `join(other)`, `clear()`, `pop()`. Вызов на фиксированном — `error: method 'add' is only available on 'dyn_array'`.

### 8.3. Агрегаты — глобальные функции

`max(arr)`, `min(arr)`, `sum(arr)` (int-результат для int-массивов, float для float), `avg(arr)` (всегда float). Пустой или нечисловой массив — ошибка рантайма. Это глобальные функции, «не методы массива». ⚠️ В `api.json.globals` их нет — см. inconsistencies.md.

### 8.4. Преобразования

`array<T,N>` ↔ `dyn_array<T>` взаимно копируются, когда совместимы типы элементов; направление определяет целевой тип. `dyn_array → array<T,N>` — проверка длины в рантайме (никакого неявного обрезания/дополнения); несовпадение двух фиксированных размеров — ошибка компиляции.

### 8.5. Печать

Строка-элемент массива печатается в кавычках с экранированными управляющими символами: `["Кирка\n", "Топор\n", "Меч"]` — сознательно, чтобы ученики видели скрытые `\n`.

## 9. Строки и символы

- `text.length` — свойство.
- Методы: `contains`, `find`, `count`, `is_int`, `is_float`, `to_upper`, `to_lower`, `substring(start, length)`, `replace(old, new)`, `split(sep)`, `trim`.
- Индексация возвращает `char`: `char first = word[0];`. Выход за границы — `runtime error: string index 10 out of bounds (length 3, valid indices 0-2)`.
- **Строки иммутабельны**: `word[0] = 'm'` — ошибка компиляции («string characters are read-only»); создавайте новую строку (`word = word.replace(...)`).
- Конкатенация `+`: `string + string` и `string + char`; строка + число — ошибка, нужен `to_string()`.
- `substring(start, count)` — второй аргумент — **количество** символов (не конечный индекс); при нехватке возвращает до конца. `replace` заменяет все вхождения, регистрозависим. `split(sep)` → `dyn_array<string>`. Строки Unicode-осмысленны: операции считают символы, не байты.

## 10. Функции

```idyllium
int function sum(int a, int b) { return a + b; }
void function say_hello(string name) { ... }   // bare return; допустим
```

- Тип возврата → `function` → имя → типизированные параметры. Не-void функция обязана вернуть значение (`error: function with return type 'int' must return a value`; `error: void function cannot return a value`).
- Число аргументов проверяется: `error: 'add' expects 2 arguments, got 3`.
- Рекурсия разрешена.

### 10.1. Аргументы по умолчанию

- Необязательные параметры — строго после обязательных.
- Дефолтное выражение может ссылаться на более ранний параметр: `int function add_twice(int first, int second = first)`.
- Работают у функций, методов и конструкторов.

### 10.2. Именованные аргументы

`sub(right=50, left=30)`. Правила: позиционные — до именованных; позиционный после именованного запрещён; дубли и неизвестные имена запрещены. Работают у пользовательских функций, методов, конструкторов и невариадических библиотечных вызовов; **не** работают у вариадических (`console.write(...)`).

### 10.3. Функции как значения (коллбэки)

Callback-свойствам GUI/Canvas/audio присваивают либо имя функции, либо **инлайн-функцию**:

```idyllium
button.on_click = void function() { console.writeln("clicked"); };
```

Сигнатуры проверяются: `error: callback property 'on_click' expects function(): void or function(gui.Button): void, got function(gui.Label): void`. Многие коллбэки принимают отправителя (`sender`) опционально — допустимы обе формы. Общего типа «функция» для переменных нет: функции первого класса ограничены callback-свойствами.

## 11. Классы и ООП

### 11.1. Объявление

```idyllium
class Hero {
    string name;
    int hp;
    Health health = Health(100);      // инициализаторы полей разрешены

    constructor Hero(string ex_name, int ex_hp = 100) {
        this.name = ex_name;
        this.hp = ex_hp;
    }

    void function hit(int damage) { this.hp -= damage; }
    int function get_hp() { return this.hp; }
}
```

- Конструктор: слово `constructor` + имя класса. Один конструктор (перегрузка нигде не упоминается). Дефолтные и именованные аргументы работают.
- **`this.` обязателен** для полей и экземплярных методов внутри класса; голое имя поля трактуется как локальное/глобальное имя (и обычно даёт `'hp' was not declared in this scope`).
- Деструкторов нет (`error: destructors are not supported yet`). Освобождение ресурсов — явные `close()`/`stop()`, на GC не полагаться.
- Несколько полей одной строкой допустимы: `int r, g, b;`.

### 11.2. Создание объектов — без `new`

```idyllium
Hero hero("Mira", 100);        // педагогическая форма-объявление
Hero raven = Hero("Raven", 600);   // конструктор-выражение
heroes.add(Hero("Kaspar", 500));
return Hero("Aranthir", 1000);
bool strong = Hero("Ornella", 750).get_hp() > 700;  // временный объект
```

Вызов имени класса — выражение, создающее независимый объект; допустим везде, где ожидается выражение этого класса (включая инициализаторы полей). Класс из модуля: `geometry.Point(10, 20)`. Класс без конструктора вызывается только без аргументов. `new` не существует (`new Hero()` — в списке запрещённого).

### 11.3. Доступ

Секции в стиле C++: `public:` / `private:` (с двоеточием, действуют до следующего модификатора/конца класса). По умолчанию — фактически public. `protected` нет. Нарушение: `error: member 'BankAccount.balance' is private and can only be used inside class 'BankAccount'` (в уроках также встречается краткая форма `error: 'balance' is private in this context`).

### 11.4. Статические методы

`static void function meow() { ... }` — вызов только через класс (`Cat.meow()`). Ошибки: `error: instance method 'Cat.meow' must be called on an object`, `error: static method 'MathUtils.square' must be called on class 'MathUtils'`, `error: 'this' cannot be used in static method`, `error: static method 'square' cannot be called on object`. Статических полей в документации нет — только методы.

### 11.5. Наследование и полиморфизм

```idyllium
class Dog extends Animal {
    constructor Dog(string ex_name) {
        parent(ex_name);          // вызов конструктора родителя, первым
    }
    void function speak() { ... } // переопределение — просто та же сигнатура
}
```

- Одиночное наследование `extends`; `parent(...)` вызывает конструктор родителя (учебник требует «первым в теле конструктора»).
- Никаких `virtual`/`override` — диспетчеризация всегда динамическая: «Idyllium смотрит не только на тип переменной, но и на настоящий объект внутри неё».
- Подстановка подтипа работает в переменных, параметрах и библиотечных API (`gui.Window.add_child(gui.Widget)`, `gui.Canvas.draw(drawable.Drawable)`).

### 11.6. Композиция

Поля-объекты других классов + цепочки доступа `rect.color.r`; инициализатор поля конструктором-выражением даёт каждому экземпляру собственный вложенный объект.

## 12. Обработка ошибок: `try/catch/finally`

Statement-level, скобки обязательны. Формы: `try/catch`, `try/finally`, `try/catch/finally`. Голый `try` недопустим.

```idyllium
try {
    float answer = 10 / 0;
} catch (error) {
    console.writeln(error.message);     // причина
    console.writeln(error.file);        // файл (relative)
    console.writeln(error.line);        // строка
    console.writeln(error.to_string()); // "main.idyl:7: runtime error: division by zero"
} finally {
    console.writeln("Attempt finished");
}
```

- `catch` без переменной допустим. Переменная `catch (error)` — read-only, существует только внутри блока, её тип в исходнике не пишется.
- Ловятся **только штатные runtime errors Idyllium**. Не ловятся: ошибки компиляции, внутренние JS-сбои (дефекты реализации), остановка из IDE (проходит сквозь catch; `finally` при остановке выполняется на уровне JS, но дальнейшие Idyllium-вызовы не гарантированы).
- `try` лексичен: блок вокруг `win.show()` не поймает ошибку будущего GUI/Canvas-события — нужен локальный `try` внутри коллбэка.
- **`throw` нет**, типизированных/множественных `catch` нет.
- Идиома освобождения ресурсов: `try { ... } finally { input.close(); }`.
- Идиома «безопасного преобразования» из учебника:

```idyllium
int function safe_int(string text, int fallback = 0) {
    try { return to_int(text); } catch { return fallback; }
}
```

## 13. Формат диагностик

`файл:строка[:колонка]: error|warning|runtime error: текст` (стиль GCC). Примеры из документации:

```text
main.idyl:5: runtime error: array index 5 out of bounds (size 3, valid indices 0-2)
main.idyl:7: runtime error: cannot convert input to 'int' (expected integer, got "abc")
main.idyl:10: error: cannot assign 'string' value to 'int' variable
cli/023_libs.html:4:1: error: module 'draw' was not found
```

Тексты ошибок — англоязычные, «читаемые, копируемые, понятные после машинного перевода». Уроки дополнительно содержат шуточные русскоязычные warning-и (педагогический приём, не язык).

## 14. Чего в языке сознательно НЕТ

| Отсутствует | Вместо этого |
| --- | --- |
| `++` / `--` | `+= 1`, `-= 1` |
| `&& \|\| ^ !` | `and or xor not` |
| `%` | `mod(a, b)` |
| truthy/falsy | явные сравнения (`name != ""`) |
| `new` | вызов класса-выражения `Hero(...)` |
| указатели, деструкторы | ссылочные объекты + явный `close()` |
| словари/map | `json.Object` (строковые ключи) как практическая замена |
| lambda со стрелкой | `void function() { ... }` инлайн |
| исключения/`throw` | `try/catch` только для runtime errors стандартных операций |
| generics для пользовательских классов | есть только встроенные `array<T,N>`/`dyn_array<T>` |
| интерфейсы, namespaces, перегрузка операторов, async/await | — |
| неявная строковая конверсия чисел | `to_string()` |
| присваивание в `word[i]` | новая строка целиком |

`BACKLOG.md` и `spec/some_*` — дискуссионные материалы, **не** фичи языка.

## 15. Наблюдения о дизайне (моя оценка)

1. **Последовательность философии.** Все «острые углы» C-семейства либо убраны (`++`, truthy, неявные конверсии), либо заменены именованными конструкциями (`div/mod`, `and/or`). Язык оптимизирован под чтение ребёнком и под однозначность сообщений об ошибках.
2. **Гибрид семантик значений/ссылок** (массивы — значения, объекты — ссылки) прагматичен и совпадает с интуицией «коробка с числами» vs «живой объект», но это самое тонкое место модели; учебник его почти не проговаривает (единственное явное место — api.json).
3. **Строгие контейнеры без обобщений у пользователя**: generics существуют только у встроенных массивов. Для целевой аудитории достаточно; словари заменяются `json.Object`.
4. **Функции — не полноценные значения**: они присваиваются только callback-свойствам. Нет типа функции в системе типов исходника, что резко упрощает преподавание.
5. **Ошибки как часть учебной программы**: у каждого раздела учебника есть урок «Типичные ошибки», а референс требует генерировать и корректный, и намеренно ошибочный код с ожидаемым текстом ошибки. Это редкая и сильная педагогическая черта.
6. **Реестр stdlib как единый источник истины** — правильное архитектурное решение: api.json, подсказки и семантика гарантированно синхронны; расхождения возможны только между ручными документами (и они есть — см. inconsistencies.md).
