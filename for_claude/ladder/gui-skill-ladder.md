# Лестница знаний: раздел «Виджеты» (24 урока)

Порядок и содержание — по фактическому состоянию учебника на 2026-08-03 (`docs/manual-content/widgets/`, порядок — `docs/tasks/lessons.json`, секция `widgets`). Правила чтения статусов — те же, что в [README.md](README.md): «Введено» — можно требовать свободно; «Мелькнуло» — только с подсказкой-напоминанием, называющей инструмент; «Ещё НЕ знает» — жёсткий запрет (в карточках — самые соблазнительные ловушки; полный запрет — всё ниже по лестнице).

## GUI-специфика (дополнение к правилам README)

1. **Весь раздел «Консоль» (№1–33) — фоновый багаж.** Переменные, типы, `if`, циклы, функции, `random`, строки и их методы, массивы обоих видов, `math`, `time`, файлы — всё в статусе «Введено» с первого GUI-урока. Урок №1 прямо говорит: «всё, что вы выучили в консоли, работает здесь точно так же — меняется только сцена».
2. **Исключение из багажа — функция-значение.** Сквозной запрет консольного раздела на «колбэки-значения» снимается ровно в GUI-№2: безымянная функция `void function() { ... }` как значение свойства — **новая идея урока про кнопки**, а не багаж. Параметризованная форма (`void function(gui.Button sender)`) — отдельная новая идея №21 (мелькает раньше в №18 у `on_finished`). Именованная функция как обработчик (`btn.on_click = surprise;`) мелькает один раз в №12 — свободно требовать нельзя нигде.
3. **Проверка — кликом.** Кнопка-пустышка неотличима от живой до первого нажатия; молчаливые поломки — фирменный жанр раздела (каталог №24 насчитывает их три: забытый `add_child`, перекрытие, забытый `start()` — плюс «спрятал и забыл показать» из №17 и «мерил от окна» из №15). Следствия для заданий: (а) поведение расписывать «по кликам» — что и после какого нажатия должно произойти; (б) приёмка — только живым кликом преподавателя; (в) «нарисовал вид, не оживил» — главный обход раздела, вскрывается кликом за секунду.
4. **Верификация генератора:** `node cli.js check` компилирует GUI-программы полноценно; headless `run` окно не рендерит (выходит мгновенно). Все образцы прогонять через `check`; описания поведения — по семантике уроков.
5. **Минимальная обвязка** тем раздела: окно (`gui.Window` + `show()`) и сам изучаемый виджет. С №3 в обвязку де-факто входит `gui.Label`-табло — без него эффекты событий ненаблюдаемы. Консольный ввод (`get_*`) в GUI-программах не используется — его роль занимают виджеты ввода.
6. **Градиент заданий:** атомарные (тема + обвязка) → полукомплексные (+ ровно один инструмент: либо консольный, либо ранее введённый виджет) → комплексные (2–3 инструмента, «настоящие приложения») → звёздочки (комбинацию нужно угадать). Первое задание «у доски» — строго атомарное.
7. **Анти-обход:** данные — из `random`/динамики/ввода виджетами; для функций-обработчиков действует приём «спецификация вызовов» («клик по A даёт X, клик по B даёт Y, и так далее»); большие повторы — через массивы виджетов (№20+).

## Ход конём раздела (легитимные забеги)

- **`gui.Label` в №2** — урок кнопок активно использует Label (текст + координаты) в двух из трёх главных примеров: это рабочая обвязка наблюдаемости, разрешена в заданиях №2 в объёме `text`/`x`/`y`/`width`. Полные права — с №3.
- **`colors.RED/GREEN/BLUE` в №3–4** — урок Label сам ограничивает: «пока нам хватит трёх самых простых», полная палитра «через два урока». В заданиях №3–4 допустимы только эти три константы и только для `text_color`.

### 1. window — «Первое графическое приложение»

**Введено:** `use gui;`; `gui.Window`: свойства `width`/`height` (int, пиксели), `title` (string), `theme` (string: `"default"`, `"idyllium"`, `"dracula"`, `"breeze"`, `"oxygen"`; незнакомое имя — молча default); методы `show()`, `close()` (закрыто последнее окно → программа завершается), `add_child(виджет)`; `gui.Button` как «мебель»: `text`, `x`, `y`, `width`, `height`; координаты от **левого верхнего** угла, по умолчанию `(0, 0)`; правило «личное указание сильнее темы».
**Мелькнуло:** кнопка «пока ничего не делает» — события анонсированы (прав не даёт).
**Умеет:** создать/настроить/показать окно; расставить кнопки по координатам; сменить тему.
**Ещё НЕ знает:** событий (`on_click` — №2! кнопки только украшение); `gui.Label` (№3); цветов (№5) и шрифтов (№6). Наблюдаемость заданий — чисто визуальная: что и где стоит.
**Поломки урока:** забытый `use gui;` (`'gui' is not imported (use 'use gui;')` + эхо); молчаливая — забытый `add_child` («компилируется, окно есть, кнопки нет»).
**Словарь:** графический интерфейс (GUI), окно, виджет, пиксель, координаты, тема.

### 2. button — «Кнопки и события»

**Введено:** событие `on_click`: `btn.on_click = void function() { ... };` — **безымянная функция-значение** (снятие консольного запрета — новая идея урока!); обработчик вызывает не программист, а нажатие; обработчики читают и меняют любые виджеты и переменные, объявленные **выше** (замыкание на переменные `main` — состояние живёт между кликами); `win.close()` из обработчика — кнопка «Выход»; правило порядка объявления.
**Мелькнуло (ход конём):** `gui.Label` — в объёме `text`/`x`/`y`/`width` разрешён как табло (см. преамбулу).
**Умеет:** оживлять кнопки; вести счётчики между кликами; закрывать программу кнопкой.
**Ещё НЕ знает:** `font_size`, цветов, `visible`/`enabled` (№17!), `sender` (№21!), Timer (№22). Выразительные средства — текст, геометрия, `win.theme`.
**Поломки урока:** виджет объявлен после обработчика (`'label' was not declared in this scope` + эхо); кнопка-призрак (без `add_child`).
**Словарь:** событие, обработчик, нажатие (клик), безымянная функция.
**Заметка:** здесь рождается главная мысль раздела — «программа живёт и ждёт»; проговаривать вопрос «кто вызывает эту функцию?».

### 3. label — «Виджет Label»

**Введено:** `gui.Label` полноправно: `text` (string! числа — через `to_string`), `x`/`y`, `font_size` (int, пиксели; «влияет на отображение, не на координаты»), `text_color` (тип `colors.Color`); динамическая смена `text` из обработчиков; **перекрытие**: виджеты не двигаются сами, при пересечении координат накладываются; **z-порядок = порядок `add_child`** (первый — снизу, последний — сверху).
**Мелькнуло:** `colors.RED/GREEN/BLUE` (только эти три! полная палитра — №5); `colors.RGB()`/`colors.HEX()` названы без примеров.
**Умеет:** подписывать интерфейс; выводить числа через `to_string`; управлять наложением через порядок добавления.
**Ещё НЕ знает:** `background_color`/`border_color` (№5), `font` (№6), `width`/`height` у Label систематически не введены (width мелькнёт в №6).
**Поломки урока:** `label.text = random.create_int(1, 6);` → `cannot assign 'int' value to 'string' variable`; визуальная поломка перекрытия (без сообщения).
**Словарь:** надпись (лейбл), размер шрифта, перекрытие, порядок добавления.

### 4. progressbar — «Виджет ProgressBar»

**Введено:** `gui.ProgressBar`: `value` (int; «пока не трогали настройки — это проценты»), `min` (по умолчанию 0), `max` (по умолчанию 100); значение живёт между ними; подпись на полоске всегда в процентах (при min=0, max=200, value=150 → «75%»), отдельный лейбл не нужен; **универсальность `x`/`y`/`width`/`height`** — «эти свойства есть у каждого виджета» (правило сформулировано именно здесь).
**Мелькнуло:** «выпадающий список» назван как будущий виджет (без имени класса).
**Умеет:** показывать шкалы (здоровье, загрузка); менять `value` из обработчиков; перенастраивать шкалу через min/max.
**Ещё НЕ знает:** цветов полоски (`foreground_color` — №5!); событий у ProgressBar нет вовсе (и не появится).
**Поломки урока:** `pb.value = 0.5;` → `cannot assign 'float' value to 'int' variable` («половина полоски — это 50 из 100»).
**Словарь:** прогрессбар, шкала, уровень заполнения, проценты.

### 5. colors — «Цвета виджетов»

**Введено:** библиотека `colors`, тип `colors.Color`; создание: `colors.RGB(r, g, b)` (0–255), `colors.HEX("#2291bc")`, `colors.HSL(h, s, l)`; **16 констант** (`BLACK/WHITE/RED/GREEN/BLUE/YELLOW/CYAN/MAGENTA` + тёмные `GRAY/LIGHT_GRAY/DARK_RED/DARK_GREEN/DARK_BLUE/OLIVE/TEAL/PURPLE`) и `TRANSPARENT`; свойства виджетов `text_color`/`background_color`/`border_color` («у каждого цвета своё имя» — потому нет общего `color`); у ProgressBar особая тройка: `text_color` (проценты), `background_color` (пустая часть), `foreground_color` (заполненная); **наследование от окна**: `win.text_color` наследуют виджеты без собственного цвета, личная настройка важнее родительской.
**Мелькнуло:** «RGB, HEX и другие способы» — намёк на прочие функции.
**Умеет:** красить текст/фон/границы; собирать цвет тремя способами; вести стиль через окно-родителя.
**Ещё НЕ знает:** шрифтов (№6); `style`-строк (№11 — здесь только прямые свойства!).
**Поломки урока:** `label.text_color = "#FF0000";` → `cannot assign 'string' value to 'colors.Color' variable` (лечение — `colors.HEX(...)`).
**Словарь:** цвет, RGB/HEX/HSL, константа цвета, прозрачность, наследование цвета.

### 6. fonts — «Шрифты в GUI»

**Введено:** библиотека `fonts`, класс `fonts.Font`: единственный метод `load_from_file(путь)` (форматы ttf/otf/woff/woff2 определяются по содержимому, не по расширению); read-only свойства `src`, `format`, `is_loaded`; свойство виджета `font` (принимает объект `fonts.Font`); **наследование шрифта и `font_size` от окна** (`win.font`, `win.font_size`) — как у `text_color`; `font` отвечает за рисунок букв, `font_size` остаётся свойством виджета; отсутствующие глифы рисуются запасным системным шрифтом.
**Мелькнуло:** `label.width`; Google Fonts как источник (организационное).
**Умеет:** подключать свой шрифт из файла; вести типографику через окно; проверять `is_loaded`.
**Ещё НЕ знает:** IdySS `font-weight`/`font-style` (№11).
**Поломки урока:** файла нет → `runtime error: Font.load_from_file() cannot load '...': file does not exist`; мягкая — шрифт без кириллицы (запасные глифы, без сообщения).
**Словарь:** шрифт, файл шрифта, формат, загрузка, наследование, запасной шрифт.
**Заметка:** файлы-ресурсы кладутся в проект (как позже картинки и звуки) — первая встреча с ассетами.

### 7. spinbox — «Виджеты SpinBox и FloatSpinBox»

**Введено:** `gui.SpinBox` — поле для **целых** со стрелками ▲/▼ («котика не введёшь»); `gui.FloatSpinBox` — то же для дробных; свойства `value`/`min`/`max`/`step` (типы int у первого, float у второго); **дефолты заявлены явно: value=0, min=0, max=100, step=1** (обновление 1.2.8); **границы сторожат все способы ввода**: стрелки/колесо не докрутят за край, набранное с клавиатуры **зажимается в диапазон при подтверждении** (потеря фокуса или Enter; 999 при max=100 → 100), пустое поле откатывается к последнему значению; событие **`on_change`** (первое событие изменения в разделе!) — срабатывает при стрелках, клавиатуре и прямом вводе.
**Мелькнуло:** намёк на «рискованное текстовое поле» (LineEdit — №9, имя не названо).
**Умеет:** принимать числа безопасно; связывать `on_change` с табло; настраивать диапазон и шаг под задачу; выбирать int/float-вариант по смыслу.
**Ещё НЕ знает:** `gui.Slider` (№8), LineEdit (№9). Программное `value` вне диапазона урок №7 не обсуждает (это тема №8 у Slider) — в заданиях зажимание проверяем только «ручным» вводом с клавиатуры/стрелками.
**Поломки урока:** `spin.value = 0.5;` → `cannot assign 'float' value to 'int' variable` («половины игрока не бывает»).
**Словарь:** SpinBox, стрелки, диапазон, шаг, событие изменения.

### 8. slider — «Виджет Slider»

**Введено:** `gui.Slider` — ползунок; `value`/`min`/`max`/`step` (все int; **дефолты min=0, max=100** — заявлены явно); `step` даёт дискретный набор значений (0,50,100…); `on_change` при каждом движении; выбор инструмента: Slider — быстрый и грубый (громкость), SpinBox — точный (количество); **важное правило: «компилятор проверяет типы, а не диапазоны»** — `slider.value = 500` при `max = 300` проходит молча, диапазон — забота программиста; **поведение вне диапазона документировано (1.2.8)**: в свойстве честно лежит записанное число, ручка на экране прижимается к ближайшему краю, при первом движении пользователем `value` возвращается в диапазон; это сознательно НЕ ошибка — порядок настройки свободный (`value = 150`, потом `max = 300` — обычное дело).
**Мелькнуло:** «размер массива» как пример точной величины.
**Умеет:** грубые регуляторы; live-связку ползунок→табло; сознательно выбирать Slider/SpinBox.
**Ещё НЕ знает:** LineEdit (№9); вертикальной ориентации и FloatSlider (не существует в уроке); у Slider нет надписи-процентов — табло только через Label.
**Поломки урока:** `slider.value = "50";` → `cannot assign 'string' value to 'int' variable`; НЕ-поломка `value = 500` — теперь с документированным поведением (ручка у края, самовосстановление при движении) — годится для заданий-экспериментов с предсказанием.
**Словарь:** ползунок, ручка, диапазон по умолчанию, шаг, грубая настройка.

### 9. lineedit — «Виджет LineEdit»

**Введено:** `gui.LineEdit` — однострочный свободный ввод: `text` (string — «всегда строка, даже если внутри цифры»!), `placeholder`, `font_size`, `echo_mode` (`"normal"`/`"password"`/`"no_echo"`); событие `on_change` при каждом изменении; `gui.TextEdit` — многострочный брат (то же минус `echo_mode`; Enter даёт `\n` внутри `text`).
**Мелькнуло:** `text_color`/`background_color`/`border_color` у полей названы в шпаргалке без примеров.
**Умеет:** принимать текст; счётчик символов через `.length`; поле пароля; читать многострочный текст.
**Ещё НЕ знает:** валидации is_int здесь не тема (но она — багаж консоли №21 и легальна в заданиях!). Связка «LineEdit.text → to_int с проверкой» — золотое комплексное задание.
**Поломки урока:** `input.text = 42;` → `cannot assign 'int' value to 'string' variable`.
**Словарь:** текстовое поле, плейсхолдер, режим отображения, свободный ввод.
**Заметка:** здесь GUI получает полноценный ввод — «крепости» консольного курса переезжают в окна.

### 10. image — «Картинки в GUI»

**Введено:** библиотека `image` (`use image;`): `image.Static` — ресурс: `load_from_file`, преобразования `scale(x, y)` (отрицательное — отражение; ноль запрещён), `rotate` (кратно 90!), `tint(цвет)`, `with_opacity(0.0–1.0)`, `desaturate([amount])`, `crop(x, y, w, h)`, `export_to_file(путь)` — **каждое создаёт новый объект, исходник неизменен**; read-only: `is_loaded`, `src`, `width`, `height`, `format`, `has_alpha`; `gui.ImageBox` — место показа: `x`/`y`/`width`/`height`, `resize_mode` (`"fit"`/`"fill"`/`"stretch"`/`"original"`), `set_image(ресурс)`; один ресурс — много мест показа; `image.Animation` для GIF/APNG: `frame_count`, `get_frame(i)`, `frame_duration`, `has_uniform_frame_duration`, `get_frame_duration(i)`; ImageBox принимает анимацию тем же `set_image`.
**Мелькнуло:** регистрозависимость имён файлов.
**Умеет:** показывать и преобразовывать картинки; различать ресурс и виджет; крутить GIF.
**Ещё НЕ знает:** стилей (№11).
**Поломки урока:** файла нет → `runtime error: Static.load_from_file() cannot load 'cat.png': file does not exist`; `scale(0,0)` → `factors cannot be zero`; `rotate(45)` → `angle must be divisible by 90` (обе — runtime: «до запуска Idyllium не знает, какое число в скобках»).
**Словарь:** ресурс, кадр, формат, альфа-канал, режим вписывания, преобразование-копия.

### 11. styles — «Стили IdySS»

**Введено:** IdySS (Idyllium Style Sheets) — свойство `style` (string) у **каждого** виджета: пары «свойство: значение» через `;`; модель «наклейки» — style всегда побеждает одноимённое прямое свойство; снять — `style = "";`; наклейка не наследуется потомками; `+=` дописывает, позднее побеждает раннее; **словарь из 13 свойств**: `color`, `background-color`, `background` (градиенты!), `border-color`, `border-width` (0–20), `border-style` (solid/dashed/dotted/none), `border-radius` (0–100), `font-size` (6–96), `font-weight`, `font-style`, `text-align`, `opacity` (0.0–1.0), `padding` (0–40); `px` опционален (`12px` ≡ `12`), регистр не важен; цвета: имена строчными через дефис (`dark-blue`, `light-gray`, `transparent`), `#HEX`, `rgb()/rgba()` (4-й канал — прозрачность); градиенты `linear-gradient` (направление `to right`/`45deg`, 2–8 цветов, позиции в %) и `radial-gradient`; **сплошной цвет в `background` не пишут** — для него `background-color`; **три наклейки (обновление урока)**: `style` — всегда, **`style_hover`** — пока курсор наведён, **`style_active`** — пока виджет зажат; наклейки-настроения дописываются ПОВЕРХ обычной на время состояния и снимаются сами; секрет мастерства: hover — светлее, active — темнее; **IdySS молчит об ошибках** — опечатка внутри кавычек просто не применяется (граница строгости — по кавычкам: `style = 42` ловит компилятор Idyllium).
**Мелькнуло:** CSS как взрослый родственник (культурный контекст).
**Умеет:** стилизовать строкой; собирать градиенты; оживлять кнопки настроениями hover/active; диагностировать молчаливые опечатки глазами.
**Ещё НЕ знает:** `href` и библиотеки `url` (№12).
**Поломки урока:** молчаливые (`border-tadius`, `ellow`) — «опечатки в стилях ищут глазами»; `style = 42;` → `compile error: cannot assign 'int' value to 'string' variable` (проверено 1.2.8).
**Словарь:** стиль, наклейка, приоритет, градиент, молчаливая ошибка.
**Заметка:** идеальная тема для заданий-«найди опечатку глазами» — тренировка внимательности без компилятора-няньки.

### 12. links — «Гиперссылки»

**Введено:** свойство `href` у `gui.Label` (надпись становится ссылкой: подчёркивание, курсор-рука, открытие по клику); `style_hover` здесь только ИСПОЛЬЗУЕТСЯ (введён в №11 вместе со `style_active`); библиотека `url` (`use url;`): `url.open(адрес)` (только http/https — безопасность!), разбор адреса `scheme`/`host`/`path`/`query`/`port` (стандартные 443/80), `query_value(адрес, имя)`, `is_valid(строка)`, `encode`/`decode` (процентное кодирование, UTF-8 — привет консольному уроку кодировок).
**Мелькнуло:** **именованная функция как обработчик** (`void function surprise() {...}` + `btn.on_click = surprise;`) — единственное появление в разделе; `win.theme = "idyllium"` в примере.
**Умеет:** делать ссылки; открывать адреса кнопкой; разбирать и собирать URL.
**Ещё НЕ знает:** CheckBox (№13). Этика урока: «честно пишите, куда ведёт кнопка» — задания не должны учить обману.
**Поломки урока:** `url.open("file:///...")` → `runtime error: url.open() supports only http and https addresses, got 'file'`.
**Словарь:** ссылка, href, адрес (URL), протокол/сайт/путь/запрос, процентное кодирование, hover.

### 13. checkbox — «Виджет CheckBox»

**Введено:** `gui.CheckBox` — флажок: `text`, `is_checked` (bool), `x`/`y`/`width`/`height`; событие `on_change` при каждом переключении; **флажки независимы** («хоть все сразу»); bool-свойство прямо в `if (cb.is_checked)`.
**Мелькнуло:** `RadioButton` анонсирован (прав не даёт).
**Умеет:** настройки-переключатели; читать состояние по кнопке; реагировать на переключение.
**Ещё НЕ знает:** RadioButton (№14), групп.
**Поломки урока:** `cb.is_checked = "да";` → `cannot assign 'string' value to 'bool' variable`.
**Словарь:** флажок, галочка, состояние, независимые опции.

### 14. radiobutton — «Виджет RadioButton»

**Введено:** `gui.RadioButton`: `text`, `is_selected` (bool; предвыбор при старте), `group` (string; без него все кнопки контейнера — одна группа; свои имена — независимые группы), `x`/`y`/`width`/`height`; `on_change`; **ловушка двойного срабатывания**: при переходе выбора событие приходит от ДВУХ кнопок (включившейся и выключившейся) — внутри обработчика первым делом проверять `is_selected`; выбор применимости: RadioButton — ровно один из 2–5 взаимоисключающих, CheckBox — независимые.
**Мелькнуло:** слово «контейнер» (Frame — №15).
**Умеет:** группы переключателей; мгновенную реакцию с проверкой `is_selected`; выбирать виджет под задачу.
**Ещё НЕ знает:** Frame (№15).
**Поломки урока:** `rb.is_selected = "да";` → `cannot assign 'string' value to 'bool' variable`; поведенческая ловушка двойного `on_change` (без сообщения).
**Словарь:** радио-кнопка, группа, взаимоисключающий выбор, двойное срабатывание.

### 15. frame — «Виджет Frame»

**Введено:** `gui.Frame` — контейнер: `x`/`y` (относительно родителя!), `width`/`height`, `title`, `background_color`/`border_color`/`border_width`, метод `add_child(виджет)`; **координаты потомка — от угла рамки, не окна** (реальная позиция = сумма); вложенность рамок (иерархия); учёт габаритов (рамка должна помещаться в окно).
**Мелькнуло:** —
**Умеет:** группировать виджеты панелями; считать относительные координаты; вкладывать контейнеры.
**Ещё НЕ знает:** ComboBox (№16), `visible` (№17).
**Поломки урока:** молчаливая «мерил от окна» — «компилятор не помощник: виджет просто не там»; диагностика: «виджет уехал → проверь, от чьего угла отсчитывал».
**Словарь:** контейнер, родитель, потомок, относительные координаты, вложенность.

### 16. combobox — «Виджет ComboBox»

**Введено:** `gui.ComboBox` — выпадающий список: методы `add_item(текст)` (в конец; можно в рантайме!), `clear_items()`; свойства `selected_index` (int, с нуля, чтение И запись — единственный способ программного выбора), `selected_text` (string, **только чтение** — берётся из пункта сам); `on_change` при выборе пользователем (программная предустановка индекса событие НЕ вызывает); `x`/`y`/`width`.
**Мелькнуло:** —
**Умеет:** списки выбора; читать выбор текстом и номером; наполнять список из обработчиков.
**Ещё НЕ знает:** `visible` (№17), TabWidget (№19).
**Поломки урока:** `combo.selected_text = "Красный";` → `compile error: property 'selected_text' is read-only`.
**Словарь:** выпадающий список, пункт, индекс выбора, read-only.

### 17. visibility — «Видимость виджетов»

**Введено:** универсальное свойство **`visible`** (bool) у каждого виджета: `false` — «невидим, но жив» (в памяти, со всеми свойствами), **обработчики невидимого молчат** (нажать невидимую кнопку нельзя); менять можно в рантайме; **каскад контейнера**: скрытие Frame прячет всех потомков (не удаляя), показ возвращает как было; чтение в условии — toggle-паттерн `if (frame.visible)`; приём «виджет меняет сам себя в своём обработчике» — легализован явно; **`enabled`** (bool, добавлено в 1.2.9) — второй переключатель: `false` — виджет НА МЕСТЕ, но выключен (приглушённо-серый в гамме текущей темы, не реагирует на мышь/клавиатуру, события не срабатывают); каскад контейнера как у visible; паттерн «условие → доступность»: `start.enabled = agree.is_checked;` (без if!); пара для запоминания: «visible прячет то, чего сейчас не существует для пользователя; enabled выключает то, что существует, но недоступно».
**Мелькнуло:** `gui.ProgressBar` и `font_size` в примерах (оба уже пройдены ✓); CheckBox в примере enabled (пройден в №13 ✓).
**Умеет:** прятать/показывать элементы и целые панели; выключать и включать кнопки по условию; строить переключатели; экраны «меню → игра» на видимости; формы «кнопка спит, пока не выполнено условие».
**Ещё НЕ знает:** audio (№18).
**Поломки урока:** молчаливые близнецы «спрятал — и забыл показать» и «выключил — и забыл включить» (компилятор не ловит ни ту, ни другую); диагностика пропавшего виджета — искать правки его `visible`/`enabled` и те же свойства его контейнера.
**Словарь:** видимость, доступность, скрытый виджет, выключенный виджет, каскадное скрытие, переключение (toggle).

### 18. audio — «Работа со звуками»

**Введено:** модуль `audio`: `audio.Sound` (короткие эффекты — клики, выстрелы; наложение копий) и `audio.Music` (длинные треки); общие: `load_from_file`, `play()`/`pause()`/`resume()`/`stop()`, `volume` (float 0.0–1.0!), read-only `src`/`duration`/`is_playing`; только у Music: `loop` (bool), `position` (сек, чтение и запись — перемотка!), событие `on_finished` (не срабатывает при `loop = true`!); **две формы обработчика**: `void function()` и `void function(audio.Music current)` — первое появление параметризованного обработчика (полная теория — №21).
**Мелькнуло:** параметр обработчика (`current.src`) — до урока sender; `pause/resume/stop` у Sound — только в таблице.
**Умеет:** озвучивать кнопки; строить плеер (старт/пауза/продолжить/стоп); зацикливать фон; перематывать.
**Ещё НЕ знает:** TabWidget (№19), `sender` как систему (№21 — параметр `on_finished` здесь давать только с напоминанием!).
**Поломки урока:** `click.volume = 4;` → `runtime error: Sound.volume must be between 0 and 1, got 4` (явный разбор compile vs runtime).
**Словарь:** звук, музыка, громкость, зацикливание, позиция, событие окончания.
**Заметка:** ассеты кладутся в проект как шрифты/картинки; выбор класса — вопрос «это щелчок или фоновая музыка?».

### 19. tabwidget — «Вкладки»

**Введено:** `gui.TabWidget`: метод `add_tab(заголовок, виджет)` (обычно с Frame-страницей; порядок вызовов = номера вкладок с 0), `clear_tabs()` (только все разом — «убирать по одной Idyllium не умеет»); свойства `selected_index` (чтение/запись — программное переключение), `selected_title` (read-only), `tab_count` (read-only), `x`/`y`/`width`/`height`; `on_change` при переключении; **закон**: «что отдано во вкладку, то в окно не добавляют» — `win.add_child` только для самого TabWidget; координаты содержимого — от угла страницы вкладки; пустое состояние честно: `tab_count = 0`, `selected_title = ""`.
**Мелькнуло:** `is_visible` в шпаргалке урока (расхождение с `visible` из №17 — см. сигналы); `LineEdit.height`.
**Умеет:** многостраничные настройки; программно открывать вкладку; реагировать на переключение.
**Ещё НЕ знает:** массивов виджетов (№20).
**Поломки урока:** обе молчаливые — содержимое добавлено и во вкладку, и в окно (рамка дублируется поверх); забытый `win.add_child(tabs)` («та же ловушка, что с кнопкой в первом уроке»).
**Словарь:** вкладка, страница, заголовок вкладки, полоска заголовков.

### 20. arrays — «Массивы виджетов»

**Введено:** применение консольных массивов к виджетам: `array<gui.Label, 7>` (все элементы готовы сразу после объявления), `dyn_array<gui.LineEdit>` + `add()`/`remove_at()`/`length`; **опорный паттерн: создать массив → настроить каждый в цикле → `add_child` в том же цикле**; создание виджетов в рантайме (внутри обработчика: локальный виджет + `add()` + `win.add_child()` — легализовано примером); позиционирование новорождённых по `length`; **разграничение**: `visible = false` прячет с экрана (но остаётся в массиве и в подсчётах), `remove_at()` убирает из списка (но виджет остаётся на экране, координаты не перекладываются!) — «два разных действия, ни одно не заменяет другое», работают в паре.
**Мелькнуло:** `gui.Slider` с min/max/value ✓ (№8 пройден), `placeholder` ✓ (№9) — фактически всё уже легально.
**Умеет:** массовое создание однотипных виджетов; динамические списки полей; аккуратное удаление (спрятать + убрать из массива).
**Ещё НЕ знает:** `sender` (№21!) — общий обработчик на массив пока не различает, кто нажат: «кнопка N» реализуема только отдельными обработчиками.
**Поломки урока:** `btns.add(extra)` у статического массива → `compile error: method 'add' is only available on 'dyn_array'`; две полу-поломки без сообщений (убрал только из массива / только спрятал).
**Словарь:** массив виджетов, опорный паттерн, создание в рантайме, спрятать vs убрать.
**Заметка:** тема снимает ограничение «чудовищно долго»: 10 кнопок руками — боль, циклом — строчки; идеальный рычаг анти-обхода.

### 21. sender — «Отправители»

**Введено:** параметр обработчика `sender`: `btns[i].on_click = void function(gui.Button sender) { ... };` — ссылка на виджет, вызвавший событие (чтение И запись его свойств); тип параметра обязан совпадать с типом виджета; callback-свойство принимает `function(): void` ЛИБО `function(тип): void`; таблица сигнатур: Button/`on_click`, LineEdit/SpinBox/Slider/CheckBox/ComboBox — `on_change`; главный сценарий — **один обработчик на массив виджетов**, различающий нажатого.
**Мелькнуло:** `visible = false` ✓, вложенные циклы ✓ — багаж.
**Умеет:** общий обработчик для семейства виджетов; «кто меня вызвал»; экономить код на массивах.
**Ещё НЕ знает:** Timer (№22), Modal (№23).
**Поломки урока:** `gui.Label sender` у кнопки → `compile error: callback property 'on_click' expects function(): void or function(gui.Button): void, got function(gui.Label): void`.
**Словарь:** отправитель (sender), параметр обработчика, сигнатура.
**Заметка:** тема-развязка для №20 — теперь массив кнопок + один обработчик = клавиатура/поле игры; богатейшая зона комплексных заданий.

### 22. timer — «Объект Timer»

**Введено:** `gui.Timer` — НЕ виджет: без `add_child`, живёт независимо от окон; `interval` (int, миллисекунды; менять можно на ходу), событие `on_tick` (`void function()` или `void function(gui.Timer sender)` — таймер может остановить сам себя `sender.stop()`); методы `start()` (продолжить с места), `stop()` (пауза с сохранением накопленного), `restart()` (честный новый отсчёт — нужен после смены interval); read-only `running`; паттерн однократной задержки: в `on_tick` вызвать `stop()`.
**Мелькнуло:** `+=`, `random`, `font_size` — багаж ✓.
**Умеет:** секундомеры и отсчёты; периодическое обновление (случайные числа раз в секунду); отложенные действия; пауза/продолжить.
**Ещё НЕ знает:** Modal (№23).
**Поломки урока:** «молчаливый таймер» — забытый `start()` (компилятор молчит, тиков нет — первым делом проверять `start()`); `interval = "1000"` → `cannot assign 'string' value to 'int' variable`.
**Словарь:** таймер, интервал, тик, пауза/перезапуск, объект-невиджет.
**Заметка:** внимание — шпаргалка урока противоречит его же секции 4 (см. сигналы); в заданиях опираться на полный набор: `start/stop/restart/running` (реализованы, проверено ранее). Тема оживляет всё: анимация беглянки, автосекундомер, игры на время.

### 23. modal — «Модальные окна»

**Введено:** `gui.Modal` — НЕ виджет (без `add_child`; создаётся динамически, обычно внутри обработчика; после закрытия уничтожается; каждый показ — новое окно); один тип — три режима показа: `show_alert()` (сообщение + одна кнопка), `show_confirm()` (две кнопки), `show_input()` (поле ввода); свойства `title`, `message`, `confirm_text` (по умолчанию «OK»), `cancel_text` (confirm/input); события `on_confirm`/`on_cancel` с сигнатурой `void function(gui.Modal modal)` (имя параметра свободное); `get_input_value()` → string (внутри `on_confirm`; при отмене текст не приходит).
**Мелькнуло:** вложенность обработчиков (on_confirm внутри on_click) — не комментируется.
**Умеет:** уведомления; подтверждения опасных действий; запрос текста диалогом.
**Ещё НЕ знает:** конец новизны — дальше каталог ошибок.
**Поломки урока:** `win.add_child(m)` → `compile error: 'add_child' argument 1 expects gui widget, got 'gui.Modal'` («после семнадцати уроков рука сама тянется»).
**Словарь:** модальное окно, диалог, режим показа, подтверждение/отмена.
**Заметка:** золотая связка с уборщиком-паттерном консоли: подтверждение перед необратимым действием («Удалить всё?») — теперь диалогом.

### 24. errors — «Типичные ошибки»

**Введено:** систематизация; нового API нет. Формализовано: **z-порядок** (порядок `add_child`: первый — снизу); формат сообщений (compile — `файл:строка:колонка:`, runtime — `файл:строка:`; «GUI-ошибки выглядят как консольные»); правило «чинить с первой»; каталог 11 категорий: 3 **молчаливые** (забыл `add_child`; перекрытие; забыл `start()`), 6 compile (тип sender; int в text; необъявленный виджет; `add_child` для Modal; несуществующее свойство — `type 'gui.Button' has no property 'placeholder'`; read-only — `property 'selected_text' is read-only`), 1 runtime (границы массива виджетов).
**Мелькнуло:** `gui.TextEdit` (как обладатель placeholder), `frame.add_child`.
**Умеет:** классифицировать GUI-ошибку по сообщению; диагностировать молчаливые по чек-листу («не отображается → add_child?», «не тикает → start()?», «пропал → visible?»).
**Ещё НЕ знает:** конец раздела; анонс ООП («каждый виджет — это объект; в следующем разделе создадите собственные»).
**Словарь:** молчаливая ошибка, эхо-сообщение, тип `<error>`, порядок отрисовки, read-only.
**Заметка:** аналог консольного №32 — справочный; отдельный задачник не обязателен, материал уходит в поломки остальных тем.

**Все четыре закрыты обновлением 1.2.8 (проверено 2026-08-03):**

1. ~~**`is_visible` vs `visible`**~~ — ЗАКРЫТО: шпаргалка tabwidget теперь учит `visible`.
2. ~~**Противоречие внутри урока №22 (timer)**~~ — ЗАКРЫТО: шпаргалка перечисляет «два свойства, событие и три метода» (вкл. `restart()` и `running`) и верно объясняет разницу пауза/перезапуск.
3. ~~**Тихая зона Slider (№8)**~~ — ЗАКРЫТО: урок описывает поведение `value` вне диапазона (число хранится честно, ручка прижата к краю, при движении пользователя возвращается в диапазон; сознательно не ошибка).
4. ~~**SpinBox (№7)**~~ — ЗАКРЫТО: дефолты `value=0, min=0, max=100, step=1` заявлены явно; зажимание ручного ввода описано в тексте (999 при max=100 → 100; пустое поле откатывается).

Остались открытыми (не GUI, из консольных книг): хвост `ENOTEMPTY` у `file.remove()` на непустой папке; задвоенное имя функции в сообщении песочницы; runtime-ошибка кривого инициализатора матрицы с упоминанием `dyn_array`.
