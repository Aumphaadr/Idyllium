# Плацдарм для генерации заданий: правила игры

Здесь лежит формализованная «лестница знаний» раздела «Консоль» детского учебника Idyllium — фундамент для будущей генерации заданий. Составлено 2026-07-25 по фактическому содержимому уроков (`docs/manual-content/console/`, порядок — `docs/book/lessons.json`) с учётом критериев из отчётов команды документации (`from_docs_team/for_claude/reports/`: task-design-criteria.md — К/А/Ц/Н, conspect-tasks-alignment.md — С1–С8).

## Главное правило (закон зависимости)

**Задание по теме N может мимоходом требовать всё, что введено в уроках 1..N, и не может требовать ничего из уроков N+1..32.**

Пример-эталон от владельца проекта: «Преобразования данных» (№7) стоит раньше «Случайных чисел» (№11) — значит, в заданиях по random допустимо мимоходом преобразовывать данные, но в заданиях по transforms НЕЛЬЗЯ просить генерировать случайные числа: можно просить ученика придумать число из головы, нельзя — использовать `random`.

Это соответствует критериям С1 (задание решается только явно преподанным), К10 (ровно одна новая идея), А3 (скачок за программу — брак) и С8 (конструкция, о которой урок лишь сказал «будет позже», — автоматический брак).

## Доктрина «хода конём» (2026-07-24, от владельца проекта)

Закон зависимости — правило по умолчанию, но у него есть легитимное исключение: **сознательный забег вперёд**. В образовании такие забеги иногда жизненно необходимы; главное — не плодить их без необходимости. Признанные «ходы конём»:

1. **Базовая арифметика (`+`, `-`, `*`) — школьный фоновый багаж.** Ребёнок умеет складывать и умножать со школы, поэтому эти операторы доступны заданиям начиная с урока «Переменные» (№3) — раньше урока «Арифметика» (№5). Понятие типов при этом объясняется на пальцах: «сложить 5 и „банан“ — бессмыслица». Урок «Арифметика» из-за этого НЕ пустой: его настоящее содержание — правила ТИПОВ результата, а не «что такое сложение» (см. карточку №5).
2. **«Птичье» понимание функций — задолго до урока о функциях.** Уже с `console.write()` (№2) и особенно с `math.abs()` (№8) ученик практически владеет паттерном «вызови функцию → аргументы в скобках → результат можно присвоить». Этого птичьего уровня достаточно для всех заданий младших уроков; полное раскрытие устройства функций — только в №25.

Что из этого следует для генератора: `int c = a + b;` в задании по переменным — норма, а не нарушение; «вызовите math.round» в задании №8 не требует понимания сигнатур. Но саморедактирование `x = x + 1` — отдельная НОВАЯ идея урока «Инкремент» (№10), школьным багажом она не является.

**Критерий качества урока** (проверять при проектировании наборов заданий): если инструментарий урока позволяет придумать всего 2–3 принципиально новых задания — урок проведён плохо. Либо у урока мало собственного содержания, либо лестница неверно оценила его права.

## Три статуса инструмента

Лестница различает три статуса, и они дают разные права при генерации:

1. **Введено** — концепту УЧИЛИ: объяснение + примеры. Можно требовать в заданиях свободно (начиная с этого урока и далее).
2. **Мелькнуло** — инструмент показан один раз без полноценного объяснения (или только анонсирован). По С1: использовать в заданиях можно **только с подсказкой-напоминанием, называющей инструмент**, и лучше ближе к концу набора. Анонсы («о массивах позже») прав не дают вовсе.
3. **Ещё НЕ знает** — всё, что ниже по лестнице. Жёсткий запрет. В карточке каждого урока перечислены самые *соблазнительные* запреты — то, что генератору захочется вставить по привычке (полный запретный список — это просто все уроки ниже).

## Сквозные запреты для ВСЕГО раздела «Консоль»

Эти вещи не появляются ни в одном уроке раздела — задания раздела не могут требовать их вообще:

- Классы, объекты, `this`, конструкторы (раздел ООП).
- GUI-виджеты, Canvas, drawable, таймеры (разделы «Виджеты» и «Canvas»).
- Библиотеки `json`, `sqlite`, `gui`, `drawable`, `colors`, `fonts`, `image`, `audio`.
- Модульные константы (`config.NAME`) — урок констант учит только локальным и файловым.
- Вложенные функции, замыкания, колбэки-значения (`<тип> function(...)` как выражение).

## Правила формы задания (сжатая шпаргалка из критериев)

- Сюжет из мира ребёнка, пороги из реальности, программа-персонаж, результат самоценен (К1–К4).
- Образцы ввода/вывода обязательны, на каждую ветку; «ничего не выводит» проговаривается явно (К5, К6).
- Тестовые прогоны — часть условия; на этапах с преподавателем — плюс граничное значение (К8).
- Ровно одна новая идея; ≤ 15 строк кода; без copy-paste-веток (К10, К12, А2).
- Первое задание блока — переписать готовый код из теории и провести эксперимент (С2, Н3); есть задание-«поломка» (Н4); кульминация в конце (Ц4).
- Формулировки — словами из «Словаря» урока (С4): например, если урок называет `>=` «не меньше», условие задания пишется «не меньше».
