# Задачник: Обработка ошибок

Урок №33 раздела «Консоль» — последний. Составлен 2026-08-03 по [лестнице навыков](../ladder/console-skill-ladder.md), [критериям заданий](../reports/task-design-criteria.md) и [методичке Real-IT](../reports/real-it-methodology-extract.md). Все решения и образцы прогнаны через компилятор; задания с вводом дают точный образец «ввод → вывод».

**Для преподавателя.**
- *Доступно:* всё из уроков 1–32; из новой темы — `try { } catch { }`, форма с подробностями `catch (error)` (имя произвольно, живёт в блоке; свойства `.message` / `.file` / `.line`, метод `.to_string()`), `finally` (выполняется в любом случае), три формы (`try+catch`, `try+finally`, `try+catch+finally`), паттерн «запасное значение» (fallback), и границы возможностей: **try не ловит** ошибки компиляции и остановку программы.
- *Дисциплина урока:* `try` не прячет проблемы, а описывает разумный план на **ожидаемую** неудачу; опасный участок — как можно меньше, никаких «обернём полпрограммы».
- *Градиент:* **блок 1 — атомарные**, **блок 2 — реванши** (+ старые враги), **блок 3 — комплексные**, **блок 4 — звёздочки**. Карта — в заметке.
- *Словарь:* перехват, обработка ошибок, запасное значение, гарантированное завершение.

Тридцать уроков подряд мы **коллекционировали** ошибки выполнения: делили на ноль, читали пропавшие файлы, скармливали «котиков» в `to_int` — и каждый раз программа падала, а мы лишь читали сообщения. Сегодня — день расплаты: все старые враги будут пойманы. Это финал раздела, и он собирает всю коллекцию. **Важно:** границы `try` (что он ловит, а что нет) ученик нащупывает сам.

# Блок 1. Поймать и продолжить

## Практика с преподавателем

### Задание 1. Спасённое деление

Наберите:

```idyllium
use console;

main() {
    try {
        int divisor = 0;
        console.writeln(100 / divisor);
    } catch {
        console.writeln("На ноль делить нельзя");
    }
    console.writeln("Программа продолжает работу");
}
```

```
На ноль делить нельзя
Программа продолжает работу
```

Впервые за весь раздел деление на ноль **не остановило** программу: `try` попробовал, `catch` подхватил, жизнь продолжилась. Слово `try` так и переводится — «попробовать»; `catch` — «поймать».

### Задание 2. Досье на ошибку

Если для любых ошибок один ответ — хватает короткого `catch { }`. А если нужны подробности, дайте пойманной ошибке имя. Наберите:

```idyllium
use console;
use math;

main() {
    try {
        console.writeln(math.sqrt(-4));
    } catch (error) {
        console.writeln("Причина: ", error.message);
        console.writeln("Строка: ", error.line);
        console.writeln("Целиком: ", error.to_string());
    }
}
```

```
Причина: math.sqrt() expects a non-negative number, got -4
Строка: 5
Целиком: m.idyl:5: runtime error: math.sqrt() expects a non-negative number, got -4
```

`.message` — короткая причина, `.line` и `.file` — адрес, `.to_string()` — всё разом. Те самые сообщения, которые вы тридцать уроков читали с экрана, теперь лежат в переменной — делайте с ними что хотите.

## Самостоятельная практика

### Задание 3. Имя на выбор

`error` — не волшебное слово. Поймайте выход за границы массива (`a[100]` у массива из трёх ячеек) в переменную со своим именем — `catch (oops)` — и выведите `oops.message`. Убедитесь заодно, что снаружи блока `catch` переменная `oops` не существует (попробуйте — и прочитайте отказ).

```
Ой: array index 100 out of bounds (size 3, valid indices 0-2)
```

### Задание 4. Что try поймать не может

Эксперимент на границы возможностей. Оберните в `try` **ошибку компиляции**:

```idyllium
    try {
        int x = "текст";
    } catch {
        console.writeln("Поймал?");
    }
```

Запустите. «Поймал?» не напечатается — программа вообще не запустилась! `try` ловит только ошибки **выполнения**: то, что сломано на уровне типов и синтаксиса, компилятор останавливает до старта, и никакой `catch` тут не поможет. Ошибку компиляции чинят, а не ловят.

### Задание 5. Коллекционер

Проверьте хватку `catch` на трёх старых знакомых: `to_int("котики")`, `math.log(-5)` и `pop()` у пустого массива. Три маленьких `try`-блока подряд, в каждом `catch (e)` печатает `e.message`. Программа должна дойти до конца, объявив: «Пойманы все трое!»

```
'to_int' cannot convert 'котики' to int
math.log() expects a positive number, got -5
cannot pop from empty array
Пойманы все трое!
```

# Блок 2. Реванши

Старые враги — новое оружие. Каждое задание здесь вы уже решали в прошлых темах другими средствами.

### Задание 6. Вежливое число *(враг из темы ввода)*

Программа спрашивает число (строкой) и печатает его квадрат — а на «котиков» не падает, но вежливо отшучивается. В теме методов строк вы решали это через `is_int` — теперь оберните `to_int` в `try` и сравните: где проверка **до** прыжка, а где — страховка **во время**.

```
Введите число: котики
«котики» — не число, но я не в обиде.
```

### Задание 7. Сокровище 3.0 *(враг из темы файлов)*

Третья встреча с `treasure.txt`! В файлах он ронял программу, в папках его отводил `exists`, теперь — `try`: попытайтесь открыть и прочитать, а в `catch` — спокойное «сокровища нет». Какой из двух способов защиты вам милее — проверка или страховка?

```
Сокровища нет — но программа жива и в этот раз!
```

### Задание 8. Стражник индекса *(враг из темы массивов)*

Массив из пяти сокровищ, программа спрашивает номер ячейки и показывает содержимое. Ввод «100» больше не катастрофа: ловите выход за границы и отвечайте по-человечески — да ещё и подскажите допустимый диапазон (он, кстати, написан прямо в `error.message` — можно вывести её!).

```
Какую ячейку открыть: 100
Такой ячейки нет: array index 100 out of bounds (size 5, valid indices 0-4)
```

### Задание 9. safe_int *(универсальный солдат)*

Соберите функцию-страховку из урока — и она останется с вами навсегда:

```idyllium
int function safe_int(string text, int fallback = 0) {
    try {
        return to_int(text);
    } catch {
        return fallback;
    }
}
```

Проверьте три вызова: `safe_int("42")`, `safe_int("котики")`, `safe_int("не число", fallback=10)`. Паттерн называется «запасное значение»: не получилось — берём заранее выбранный запас. Но помните мудрость урока: запас должен иметь **смысл**, иначе `try` не страхует, а прячет.

```
42
0
10
```

# Блок 3. Собираем устойчивые программы

## Практика с преподавателем

### Задание 10. Пицца и finally

Блок `finally` выполняется **в любом случае** — и после успеха, и после пойманной беды. Наберите:

```idyllium
use console;

void function divide(int divisor) {
    try {
        console.writeln("Результат: ", 12 / divisor);
    } catch {
        console.writeln("Деление не удалось");
    } finally {
        console.writeln("Попытка завершена");
    }
}

main() {
    divide(3);
    divide(0);
}
```

```
Результат: 4
Попытка завершена
Деление не удалось
Попытка завершена
```

Пришли трое — пицца поделена, не пришёл никто — деление сорвалось, но «Попытка завершена» прозвучало **оба раза**. `finally` — место для того, что обязано случиться при любом исходе: закрыть файл, погасить свет, отчитаться.

## Самостоятельная практика

### Задание 11. Бронированный калькулятор

Программа спрашивает два числа (строками!) и делит первое на второе. Опасностей две: ввод может не быть числом, делитель может оказаться нулём — но у вас один `try` на весь опасный участок и `catch (e)` с настоящей причиной из `e.message`. И `finally`: «Калькулятор готов к следующему расчёту» — при любом исходе. Испытайте все три сценария: удача, «котики», ноль.

```
Делимое: 100
Делитель: 0
Не вышло: division by zero
Калькулятор готов к следующему расчёту
```

### Задание 12. Неубиваемый опросник

Финальная версия крепости: программа спрашивает возраст **до победного** — цикл `while` крутится, пока `try` не преуспеет, а каждый провал вежливо просит попробовать ещё. Ни «абв», ни «эх» не роняют и не пропускаются — пройдёт только честное число.

```
Ваш возраст: абв
Это не число, попробуйте ещё раз.
Ваш возраст: эх
Это не число, попробуйте ещё раз.
Ваш возраст: 25
Принято: 25
```

### Задание 13. Сейф с двумя замками

В файле `code.txt` должно лежать число-код. Программа читает файл и превращает содержимое в число — а сломаться может **на любом из двух этажей**: файла нет или внутри не число. Один `try` на оба этажа, `catch (e)` объясняет, что именно случилось (`e.message` различит!). Проверьте три сценария: файла нет; в файле «абракадабра»; в файле честное `1234`.

```
Код принят: 1234
```

```
Сейф не открылся: file.open() cannot open 'code.txt' for reading: file does not exist
```

### Задание 14. Чёрный ящик

Как самолёт: любая авария — в бортовой самописец. Постройте программу, где опасная операция (например, чтение дурного индекса) завёрнута в `try`, а `catch` **записывает** `error.to_string()` в файл `crash_log.txt` — и программа летит дальше. Загляните потом в лог: там лежит полное досье сбоя. Так работают настоящие системы: пользователь видит вежливое сообщение, а инженеры — подробный лог.

```
Сбой записан в чёрный ящик.
Полёт продолжается.
```

Файл `crash_log.txt`:

```
Авария: main.idyl:6: runtime error: array index 100 out of bounds (size 3, valid indices 0-2)
```

# Блок 4. Со звёздочкой

### Задание 15 ⭐. Сапёр ошибок

Викторина на эрудицию всей серии. Вот четыре мины: `100 / 0`, `math.sqrt(-4)`, `to_int("ъеъ")`, `pop()` пустого массива. **Сначала** — по памяти запишите на бумажке, что скажет каждая (вы встречали их все!). Потом сапёрская проверка: обезвредьте каждую своим `try`, печатая `e.message`, и сверьте с предсказаниями. Сколько из четырёх угадали дословно?

### Задание 16 ⭐. Три дороги защиты

Философская звёздочка. Решите одну задачу — «спросить у пользователя число» — **тремя** способами: проверкой `is_int` до преобразования (путь темы строк), функцией `safe_int` с запасным значением (з.9) и опросником до победного (з.12). Все три программы работают — а ведут себя по-разному: одна отказывает, вторая подставляет запас, третья настаивает. Напишите по строчке-выводу: когда какой путь честнее? (Настоящие программисты спорят об этом до сих пор — теперь можете и вы.)

### Задание 17 ⭐. Выпускной

Последнее задание раздела — соберите программу-визитку из всего, что умеете, с бронёй из сегодняшнего урока. Минимум: приветствие по имени; неубиваемый ввод числа; что-нибудь случайное; результат — в файл; и ни одной возможности уронить программу вводом. Состав и сюжет — ваши: это ваш выпускной проект консольного раздела. Оглянитесь: тридцать уроков назад вы печатали «Привет, мир» — теперь вы пишете программы, которые не падают.

### Минутка из внешнего мира. Цена необработанной ошибки

*Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.*

- 4 июня 1996 года ракета Ариан-5 взорвалась на 37-й секунде полёта. Причина — необработанная ошибка: число не поместилось в 16-битную ячейку (то самое переполнение из урока types!), сработала ошибка выполнения, а плана на неё не было. Цена — около полумиллиарда долларов. С тех пор «обработай или обоснуй, почему нет» — железное правило космического кода.
- Ваш «чёрный ящик» — не игрушка: у больших программ есть системы сбора сбоев, и когда приложение спрашивает «Отправить отчёт об ошибке?» — это тот самый `catch`, пишущий лог, только на миллионы пользователей.
- И мудрость напоследок: лучшие программисты не те, у кого не бывает ошибок, а те, кто ждёт их в правильных местах. `try` — это не признание слабости кода, а знак, что автор подумал о будущем.
