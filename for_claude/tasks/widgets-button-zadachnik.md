# Задачник: Кнопки и события

Урок №2 раздела «Виджеты» (второй курс). Составлен 2026-08-03 по [критериям заданий](../reports/task-design-criteria.md) и [методичке Real-IT](../reports/real-it-methodology-extract.md). Все программы прогнаны через компилятор (`check`); поведение при кликах описано по семантике урока и **проверяется живым кликом в Web IDE** — это и есть режим проверки всей темы.

**Для преподавателя.**
- *Доступно:* **весь консольный курс** (переменные, `if`, циклы, функции, `random`, строки, массивы — всё работает и здесь, «меняется только сцена») плюс урок «Первое графическое приложение»: `gui.Window` (`width/height/title/theme`, `add_child`, `show`, `close`), `gui.Button` (`text/x/y/width/height`), координаты от левого верхнего угла; из новой темы — событие **`on_click`**: `btn.on_click = void function() { ... };` — безымянная функция-обработчик, которую вызывает не программист, а **нажатие**; обработчики могут менять любые виджеты, объявленные **до** них; `win.close()` из обработчика — кнопка «Выход».
- *Мелькнуло:* `gui.Label` (текст и координаты — ровно в том объёме, что в уроке; его собственный урок — следующий).
- *Нельзя (рано):* цветов виджетов (№5!), шрифтов (№6), SpinBox/Slider/LineEdit и остального зоопарка, таймеров (№22), стилей. Палитра выразительных средств этой темы — **текст, координаты, размеры и тема окна**; этого хватает с избытком.
- *Проверка — кликом.* Особенность GUI: кнопка-пустышка **выглядит** в точности как живая — разница обнаруживается только нажатием. Поэтому у каждого задания поведение расписано «по кликам», и принимать работу нужно, кликая самому: обход «нарисовал вид, не оживил» вскрывается за секунду.
- *Градиент:* **блок 1 — атомарные + поломки**, **блок 2 — полукомплексные** (+ один консольный инструмент), **блок 3 — комплексные приложения**, **блок 4 — звёздочки**. Карта — в заметке.
- *Словарь:* событие, обработчик, нажатие (клик), безымянная функция.

Тридцать три урока наши программы жили как театральная пьеса: выполнились сверху вниз — и поклонились. Сегодня всё меняется: программа-GUI **живёт и ждёт**. Она ничего не делает сама — она реагирует. Кто дирижирует программой? Впервые — не код, а **пользователь**. Это самый крупный сдвиг в вашей программистской картине мира со времён циклов; кнопка — лишь повод о нём поговорить.

# Блок 1. Оживление кнопки

## Практика с преподавателем

### Задание 1. Большое и прекрасное ничего

Двухшаговая история. **Шаг 1** — соберите кнопку из прошлого урока:

```idyllium
use gui;

main() {
    gui.Window win;
    win.width = 300;
    win.height = 200;
    win.title = "Кнопка-пустышка";

    gui.Button btn;
    btn.text = "Нажми меня";
    btn.x = 50;
    btn.y = 50;

    win.add_child(btn);
    win.show();
}
```

Запустите и понажимайте. Происходит большое и прекрасное **ничего**: мы не сказали программе, что должно случиться. **Шаг 2** — скажите. Перед `win.add_child(btn);` вставьте:

```idyllium
    btn.on_click = void function() {
        btn.text = "Кнопка нажата!";
    };
```

Запустите и нажмите. Ожила! Разбор: свойству `on_click` присваивается **функция без имени** — и вызываете её не вы. Её вызывает **само нажатие**, каждый раз. Вы написали не команду, а **план на будущее**: «когда нажмут — сделай вот это». С этой строчки ваши программы начинают жить в ожидании событий.

### Задание 2. Битва за лейбл

Обработчик умеет менять не только свою кнопку — **любой** виджет, объявленный выше. Наберите:

```idyllium
use gui;

main() {
    gui.Window win;
    win.width = 400;
    win.height = 200;
    win.title = "Битва за лейбл";

    gui.Label label;
    label.x = 150;
    label.y = 30;
    label.text = "???";

    gui.Button leftBtn;
    leftBtn.text = "Мой лейбл!";
    leftBtn.x = 30;
    leftBtn.y = 100;
    leftBtn.width = 120;
    leftBtn.on_click = void function() {
        label.text = "Мой лейбл!";
    };

    gui.Button rightBtn;
    rightBtn.text = "Нет, мой!";
    rightBtn.x = 250;
    rightBtn.y = 100;
    rightBtn.width = 120;
    rightBtn.on_click = void function() {
        label.text = "Нет, мой лейбл!";
    };

    win.add_child(label);
    win.add_child(leftBtn);
    win.add_child(rightBtn);
    win.show();
}
```

Пощёлкайте обеими кнопками: два обработчика воюют за один лейбл. Заметьте порядок: `label` объявлен **до** обработчиков — иначе им не к кому обращаться.

## Самостоятельная практика

### Задание 3. Кнопка-попугай

Кнопка с надписью «Скажи ку». По клику меняет **свою же** надпись на «Ку!». Второй клик… а что случится при втором клике? Предскажите, потом проверьте.

### Задание 4. Кнопка «Выход»

Окно с прощальной надписью (лейбл) и кнопкой «Выход»: клик — `win.close()`, и программа завершается (закрыто последнее окно — жить больше негде). Заметьте: закрывается **окно**, а кнопка — лишь повод.

### Задание 5. Обработчик-сирота

Поломка. Напишите программу, где кнопка в обработчике меняет текст лейбла, — но объявите `gui.Label label;` **ниже** обработчика. Запустите и прочитайте отказ: в момент, когда компилятор читает обработчик, никакого `label` ещё не существует (знакомая история из мира переменных — «not declared in this scope», только теперь между виджетами). Лекарство: виджеты — до обработчиков, которые к ним обращаются.

### Задание 6. Кнопка-призрак

Ещё поломка, самая коварная в GUI: всё скомпилировалось, окно открылось… а кнопки **нет**. Устройте её нарочно: создайте кнопку с обработчиком, но «забудьте» `win.add_child(btn);`. Запустите. Программа не жалуется — просто кнопка не существует для окна. Запомните симптом: «компилируется, но не появляется» — первым делом ищите пропавший `add_child`.

# Блок 2. Плюс один консольный инструмент

Всё, что вы выучили за 33 урока консоли, работает внутри обработчиков. Подключаем по одному.

### Задание 7. Кликер *(+ переменная-счётчик)*

Фундамент величайшего жанра мобильных игр. Окно с лейблом «0» и кнопкой «Клик!»: каждое нажатие увеличивает счётчик (`int count` объявлен в `main` до обработчика!) и пишет его на лейбл (`to_string` в помощь). Проверка простая: десять кликов — на лейбле «10».

### Задание 8. Дверь с секретом *(+ условие)*

Кнопка-дверь с надписью «Тук-тук». Первый и второй клики ничего видимого не делают (но счётчик-то растёт!), а на **третий** дверь сдаётся: надпись меняется на «Ну входите уже». Условие `if` внутри обработчика решает, настал ли момент.

### Задание 9. Гадалка *(+ случайность)*

Магический шар: лейбл «Задай вопрос и нажми» и кнопка «Узнать судьбу». Каждый клик — случайный ответ из трёх: «Да!», «Нет.», «Спроси позже...» (`random.create_int` и три `if`). Проверка кликом: жмите, пока не выпадут все три судьбы.

### Задание 10. Выключатель света *(+ тема окна)*

Тумблер дня и ночи: кнопка «Ночь» переключает `win.theme` на `"dracula"` и меняет свою надпись на «День»; следующий клик возвращает `"default"` и надпись «Ночь». Внутри — `if` по текущей теме (её можно прочитать и сравнить как обычную строку!). Одна кнопка, два состояния, весь интерфейс перекрашивается на глазах.

# Блок 3. Настоящие приложения

Каждое задание здесь — маленькое законченное приложение. `main` строит сцену, обработчики играют спектакль.

### Задание 11. Регулятор громкости

Лейбл «50» и две кнопки: «−» и «+». Минус убавляет на 10, плюс прибавляет — общая переменная `volume` живёт между двумя обработчиками, лейбл всегда показывает актуальное. Пощёлкайте вниз до отрицательной «громкости»… непорядок? Кто помнит `math.clamp` из консольного курса — примените; остальным простим до времён SpinBox.

### Задание 12. Панель лифта

Табло-лейбл «Этаж: 1» и три кнопки «3», «2», «1» столбиком (как в настоящем лифте — тройка сверху!). Клик по кнопке — табло пишет «Едем на N». Три кнопки, три обработчика, одно табло — разделение труда как в «Битве за лейбл», только мирное.

### Задание 13. Викторина одним вопросом

Вопрос на лейбле («Сколько бит в байте?»), три кнопки-ответа: «6», «8», «10» — и лейбл-вердикт под ними. Верный ответ пишет «Верно!», неверные — «Мимо!». Эмбрион всех тестов и викторин мира: интерфейс — три кнопки, логика — какой обработчик что говорит.

### Задание 14. НЕ НАЖИМАЙ МЕНЯ

Окно с единственной кнопкой «НЕ НАЖИМАЙ МЕНЯ». Но кто удержится? Счётчик нажатий и лестница реакций: после первого — «Я же просил...», после второго — «Ну хватит!», после третьего — «Последнее предупреждение», а на четвёртом кнопка **закрывает программу**. Характер у приложения! Проверка — четыре клика до финала.

# Блок 4. Со звёздочкой

### Задание 15 ⭐. Золотая лихорадка

Полноценный кликер: лейбл «Очки: 0», кнопка «Копать золото» (+1 за клик) и кнопка «Заново» (обнуляет). Две кнопки делят одну переменную-счёт — и вот у вас игра, в которую залипали миллионы. Хотите глубины — пусть каждый десятый клик даёт +5 («золотая жила», `mod` в помощь).

### Задание 16 ⭐. Поймай меня, если сможешь

Кнопка-беглянка «Поймай меня!»: каждый клик — она **прыгает в случайное место окна** (обработчик меняет её собственные `x` и `y` на случайные в пределах окна). Игра на ловкость из шести строк логики. Тонкий вопрос на подумать: в каких пределах выбирать случайные координаты, чтобы кнопка не выпрыгивала за край?

### Задание 17 ⭐. Сапёрская рулетка

Три кнопки-двери, за одной — мина (номер загадан через `random` при старте, игрок его не знает). Безопасная дверь докладывает «Дверь N безопасна!», мина — молча **закрывает окно**. Сыграйте с соседом по очереди: чья рука дрогнет? Заодно осознайте: `random` сработал один раз при старте, а обработчики помнят его вердикт всю жизнь программы.

### Задание 18 ⭐. Пульт от чего угодно

Творческий финал. Соберите пульт из трёх-четырёх кнопок и табло-лейбла — а чем он управляет, решаете вы: телевизор (каналы), кофеварка (напитки), космический корабль (системы), питомец (покормить/погладить/выгнать с клавиатуры). Требования: у каждой кнопки — своё осмысленное действие, у приложения — характер, а хотя бы один обработчик должен использовать `if` или счётчик. Покажите пульт классу — пусть кликают.

### Минутка из внешнего мира. Мир, который ждёт

*Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.*

- Сдвиг, который вы сегодня пережили, называется **событийным программированием** — и на нём стоит почти всё, чем вы пользуетесь. Телефон не «выполняется сверху вниз» — он ждёт тапа. Мессенджер ждёт сообщения. Игра ждёт нажатия. Внутри каждого — тысячи таких же `on_click`, написанных «на будущее».
- Весь интернет держится на той же идее: у каждой кнопки каждого сайта есть обработчик (в JavaScript он зовётся почти по-нашему — `onclick`). Нажимая «Оплатить» в магазине, вы запускаете чей-то безымянный `void function()`.
- А философский итог такой: раньше ваш код был письмом — написал и отправил. Теперь он собеседник — молчит, пока с ним не заговорят. Хорошие интерфейсы отличает именно это: они терпеливо ждут и понятно отвечают.
