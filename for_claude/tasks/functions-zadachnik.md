# Задачник: Создание собственных функций

Урок №25 раздела «Консоль». Составлен 2026-08-03 по [лестнице навыков](../ladder/console-skill-ladder.md), [критериям заданий](../reports/task-design-criteria.md) и [методичке Real-IT](../reports/real-it-methodology-extract.md). Все решения и образцы прогнаны через компилятор; задания с вводом дают точный образец «ввод → вывод», со случайностью — помечены «например».

**Для преподавателя.**
- *Доступно:* всё из уроков 1–24; из новой темы — объявление `тип function имя(параметры) { … return …; }`, вызов, параметры любых типов (включая массивы), локальность параметров, `void`-функции (без `return`, вызов как команда), именованные аргументы (`area(height=3, width=5)`; сначала позиционные, потом именованные, без повторов), значения по умолчанию (обязательные параметры — раньше дефолтных), `main` как полноправная функция (`int function main() { return 0; }` — код завершения) и `system.exit(n)`.
- *Нельзя (рано):* **рекурсии** (№31 — функция не должна вызывать саму себя; если ученик случайно напишет — Idyllium остановит с читаемой ошибкой, но нарочно туда не ходим), собственных библиотек (№26 — всё в одном файле).
- *Словарь:* функция, параметр, аргумент, возвращаемое значение, void, значение по умолчанию, именованный аргумент.

**Главная угроза темы — обход.** Даже сильные ученики решают «функциональные» задачи одним `main()`: видимый результат тот же, а инструмент не тронут. Поэтому книга построена на **строительных лесах**: сначала функция дана готовой — и писать можно только `main`; потом дан готовый `main` с вызовами — и писать можно только тело функции. Обойти невозможно по построению. Свобода выдаётся постепенно: сперва с расписанными ролями («функция делает X, main делает Y»), и лишь в конце — «результат такой-то, структура ваша». Тема большая — это нормально растянуть на **два урока**: части I–II на первый, часть III и звёздочки на второй.

Определение держим одно на всю тему: **функция — это механизм для превращения одних данных в другие**. Вход → превращение → выход.

### Задание 1. Четыре раза одно и то же

Задача: вывести сумму цифр четырёх чисел. Мы умеем — циклом с `div` и `mod`. Наберите **целиком, ничего не сокращая**:

```idyllium
use console;

main() {
    int a = 352;
    int sa = 0;
    while (a > 0) {
        sa += mod(a, 10);
        a = div(a, 10);
    }
    console.writeln("Сумма цифр 352: ", sa);

    int b = 47;
    int sb = 0;
    while (b > 0) {
        sb += mod(b, 10);
        b = div(b, 10);
    }
    console.writeln("Сумма цифр 47: ", sb);

    int c = 1000;
    int sc = 0;
    while (c > 0) {
        sc += mod(c, 10);
        c = div(c, 10);
    }
    console.writeln("Сумма цифр 1000: ", sc);

    int d = 999;
    int sd = 0;
    while (d > 0) {
        sd += mod(d, 10);
        d = div(d, 10);
    }
    console.writeln("Сумма цифр 999: ", sd);
}
```

```
Сумма цифр 352: 10
Сумма цифр 47: 11
Сумма цифр 1000: 1
Сумма цифр 999: 27
```

Работает. Но признайтесь: **один** такой цикл выглядел нормально, а **четыре одинаковых** — уже тоска: четыре копии, четыре пары имён, четыре шанса опечататься. А если чисел будет двадцать?

### Задание 2. Тот же результат — без копий

Теперь волшебство. Опишем вычисление **один раз** — как собственную функцию — и просто позовём её четырежды:

```idyllium
use console;

int function digit_sum(int number) {
    int res = 0;
    while (number > 0) {
        res += mod(number, 10);
        number = div(number, 10);
    }
    return res;
}

main() {
    console.writeln("Сумма цифр 352: ", digit_sum(352));
    console.writeln("Сумма цифр 47: ", digit_sum(47));
    console.writeln("Сумма цифр 1000: ", digit_sum(1000));
    console.writeln("Сумма цифр 999: ", digit_sum(999));
}
```

Вывод — **в точности тот же**. А теперь пересчитайте строки обеих программ (правила отступов одинаковые — сравнение честное): версия с функцией почти вдвое короче, и каждое новое число теперь стоит **одну строку вызова**, а не семь строк цикла. Двадцатое число? Ещё одна строка, а не ещё семь.

Разберём анатомию: `int function digit_sum(int number)` — тип результата, слово `function`, имя и параметр; в теле — знакомый цикл; `return res;` — «вот мой ответ». А в `main` остались только вызовы: `digit_sum(352)` — функция приняла 352, превратила в 10 и вернула. **Функция — механизм для превращения одних данных в другие**: вход → превращение → выход. Параметр `number` живёт только внутри функции — в `main` его нет.

### Задание 20. Линия по заказу

```idyllium
use console;

void function draw_line(int L) {

    for (int i = 0; i < L; i += 1) {
```

```idyllium
    console.writeln(rectangle_area(5, 3));
    console.writeln(rectangle_area(height=3, width=5));
}
```


Во втором вызове аргументы идут в **обратном** порядке — но имена не дают их перепутать. Правила: сначала позиционные, потом именованные; после первого именованного возврата к позиционным нет; один параметр дважды не передаётся.

### Минутка из внешнего мира. Функции — везде, main — почти везде

*Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.*

- В **Python** функцию объявляют словом `def`, а тип не пишут вовсе: `def digit_sum(number):`. В **JavaScript** — словом `function` (знакомо!) или стрелочкой `=>`. В **C++** — почти как у нас, только без слова `function`: `int digit_sum(int number)`.
- Точка входа `main` — тоже мировая традиция: C++, Java, C#, Go начинают программу именно с неё, и возвращает она тот же код завершения, что вы видели в задании 33. А вот Python живёт без обязательного `main` — код выполняется просто сверху вниз, как наши самые первые программы.
- Именованные аргументы и умолчания — фирменная гордость Python (`greet(name="Мира")`); в C++ есть только умолчания, а JavaScript не умеет ни того, ни другого — там выкручиваются, передавая объект.

Так что выученное сегодня — не местный диалект, а общий язык ремесла: `def`, `function` или стрелка — механизм превращения данных везде один.
