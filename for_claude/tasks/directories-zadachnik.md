- *Нельзя (рано):* `try/catch` (№33) — вся защита строится **проверками `exists` до действия**, и это осознанная дисциплина урока.
- *Градиент:* **блок 1 — атомарные** (создание, проверки, список), **блок 2 — полукомплексные** (+ один инструмент), **блок 3 — комплексные** (сейвы, бэкапы, уборка), **блок 4 — звёздочки**. Карта — в заметке.
- *Словарь:* папка, файловая система, проверка существования, копирование, переименование, удаление, именованный аргумент.

Красная нить темы — **перезапускаемость**: программа, падающая при втором запуске, — недоделанная программа. Урок даёт и грабли (create на занятом месте), и лекарство (`exists`-страж). А заодно закрывается старый долг: помните «Пропавшее сокровище», где чтение несуществующего файла роняло программу? Пришло время реванша. **Важно:** падения второго запуска и прочие сюрпризы ученик открывает сам.

# Блок 1. Папки и проверки

## Практика с преподавателем

### Задание 1. Дом для файла

История с модификацией — как когда-то с делением на ноль. **Шаг 1:** попробуйте записать сейв прямо в несуществующую папку:

```idyllium
use file;

main() {
    file.ostream fout = file.open("saves/player.txt", "write");
}
```

Запустите и прочитайте отказ: файл-то создаётся сам, а вот папка — нет. **Шаг 2:** почините — перед открытием постройте дом:

```idyllium
use file;

main() {
    file.create_directory("saves");
    file.ostream fout = file.open("saves/player.txt", "write");
    fout.write_line("Liam;12");
    fout.close();
}
```

Программа отработала молча — а в дереве проекта выросла папка `saves` с сейвом внутри. Загляните!

### Задание 2. Второй запуск

А теперь — сюрприз. Запустите программу из шага 2 **ещё раз**, ничего не меняя. Упала?! Прочитайте, на что жалуется `create_directory`: то, что уже существует, она создавать отказывается. Лекарство — страж `exists`:

```idyllium
    if (not(file.exists("saves"))) {
        file.create_directory("saves");
    }
```

Вставьте страж и запустите трижды подряд — тишина и порядок. Запомните слово: программа стала **перезапускаемой**. Это главный урок сегодняшней темы: хорошая программа не боится второго запуска.

## Самостоятельная практика

### Задание 3. Детектор

Программа-детектор докладывает о пути `saves` всё: существует ли (`exists`), папка ли это (`is_directory`), файл ли (`is_file`) — и то же самое о `saves/player.txt`. Сверьте ответы с деревом проекта. Зачем три проверки вместо одной? Файл нельзя открыть как папку — а папку как файл.

```
saves: существует true, папка true, файл false
saves/player.txt: существует true, папка false, файл true
```

### Задание 4. Глубокое гнездо

Постройте одной командой трёхэтажную структуру `game/world/villages` — обычный `create_directory` тут откажется (родителей-то нет!), а с именованным аргументом `parents=true` построит всю лестницу разом. Проверьте детектором или глазами. Потом снесите всё одной командой `remove` — какой аргумент придётся дописать?

### Задание 5. Опись имущества

Выведите содержимое папки `saves` через `list_directory` — сначала целиком (одним `writeln`), потом убедитесь: список приходит **отсортированным**, чтобы на любом компьютере порядок был одинаковым.

```
["player.txt", "world.txt"]
```

# Блок 3. Сейвы, бэкапы, уборка

## Практика с преподавателем

### Задание 10. Копия и новое имя

Наберите:

```idyllium
use console;
use file;

main() {
    file.copy("saves/player.txt", "saves/player_backup.txt");
    file.rename("saves/player_backup.txt", "saves/liam_backup.txt");
    console.writeln(file.list_directory("saves"));
}
```

```
["liam_backup.txt", "player.txt", "world.txt"]
```

`copy` — копия, `rename` — новое имя (или переезд: пункт назначения может быть и в другой папке!). А теперь запустите второй раз — и снова знакомое падение: `copy` отказывается перетирать занятое место. Это не вредность, а защита от опечатки: молча уничтожать файлы язык не согласен. Как сделать программу перезапускаемой — вы уже знаете.

## Самостоятельная практика

### Задание 11. Бэкапер

Программа делает резервную копию `saves/player.txt` в папку `backup`. Полный ритуал перезапускаемости: если папки `backup` нет — создать; если старый бэкап уже лежит — сначала удалить его; потом копировать. Запустите трижды — ни единого падения.

```
Бэкап готов: ["player.txt"]
```

### Задание 12. Всё по полкам

В корне проекта завалялся файл (создайте `song.txt` программой). Наведите порядок: подготовьте папку `music` (страж!) и **перенесите** файл туда через `rename`. Докажите переезд: в корне файла больше нет (`exists` → false), в `music` — есть.

```
В корне song.txt: false
В music: ["song.txt"]
```

### Задание 13. Уборщик с совестью

Программа-уборщик разбирается с папкой `trash`: если её нет — радуется чистоте; если есть — **спрашивает подтверждение** и только после «да» сносит её со всем содержимым (`recursive=true`). Удаление — единственное необратимое действие в программировании: подтверждение — не формальность, а хорошие манеры.

```
Удалить папку trash со всем содержимым? (да/нет) да
Вычищено.
```

```
Мусора нет — чисто!
```

### Задание 14. Сейв-слоты

Как в настоящих играх: программа спрашивает номер слота (1–3) и что сохранить — и пишет в `saves/slotN.txt` (имя файла соберите склейкой с `to_string`). Папку, конечно, охраняет страж. В конце — список всех занятых слотов. Сохранитесь в пару разных слотов и в один и тот же дважды.

```
В какой слот сохранить (1-3): 2
Что сохраняем: Лиам, 5 уровень, лес
Сохранено в saves/slot2.txt
Слоты: ["player.txt", "slot2.txt"]
```

### Задание 16 ⭐. Побег из песочницы

Эксперимент-провокация. Попробуйте создать папку **за пределами** проекта: `file.create_directory("../escape")`. Запустите и прочитайте отказ. Idyllium держит все файловые операции в песочнице проекта — сколько `../` ни пиши, наружу не выберешься. Подумайте, от чего защищает это правило (подсказка: вспомните уборщика с `recursive=true` — и представьте его на свободе).

### Задание 17 ⭐. Отчёт о проекте

Программа-ревизор изучает корень проекта (`list_directory(".")` — точка означает «текущая папка»): перебирает содержимое и считает отдельно файлы и папки (`is_file`/`is_directory` по каждому имени). Итог — два числа. Проверьте на своём проекте и убедитесь глазами.

```
В проекте: файлов 3, папок 4
```

### Задание 18 ⭐. Генеральная уборка с отчётом

Соедините всё: программа создаёт папку `old_stuff`, кладёт в неё три файла-заглушки (циклом!), показывает опись, потом сносит папку рекурсивно — и в финале доказывает чистоту через `exists`. Каждый шаг — с сообщением в консоль: получится маленький спектакль о полном жизненном цикле папки — родилась, наполнилась, исчезла.

```
Создана old_stuff, внутри: ["a1.txt", "a2.txt", "a3.txt"]
Сносим...
old_stuff существует: false
```

### Минутка из внешнего мира. Всё это дерево

*Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.*

- Вся память компьютера устроена как одно гигантское дерево папок — ваш проект лишь веточка на нём. «Рабочий стол», «Загрузки», даже Корзина — обычные папки, и системные программы ходят по ним теми же `create`/`copy`/`remove`, что вы освоили сегодня.
- Песочница из задания 16 — не учебное упрощение, а взрослая практика безопасности: точно так же браузер не даёт сайту лазить по вашему диску, а мобильные приложения заперты каждое в своей папочке. Программе доверяют ровно столько файловой системы, сколько ей нужно.
- А привычка к перезапускаемости имеет солидное взрослое имя — **идемпотентность**: сколько раз ни запусти, результат один. Слово пригодится лет через пять на собеседовании — а привычка нужна уже сегодня.

**Карта градиента** (для подбора под силу группы):
- *атомарные* — з.1–5 (дом для файла с модификацией, сюрприз второго запуска и страж, детектор, гнездо, опись);
