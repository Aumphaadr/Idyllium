# Задачник: Создание собственных библиотек

Урок №26 раздела «Консоль». Составлен 2026-08-03 по [лестнице навыков](../ladder/console-skill-ladder.md), [критериям заданий](../reports/task-design-criteria.md) и [методичке Real-IT](../reports/real-it-methodology-extract.md). Все решения и образцы прогнаны через компилятор — многофайловыми проектами; задания с вводом дают точный образец «ввод → вывод», со случайностью — помечены «например».

**Для преподавателя.**
- *Доступно:* всё из уроков 1–25, включая собственные функции; из новой темы — проект из нескольких файлов в одной папке, `use имя_файла;` (**без** `.idyl`), вызов `библиотека.функция()`, «у библиотеки нет своего запуска — работает `main()` главного файла». Внутри библиотеки функции зовут друг друга по простому имени, без приставки; библиотека может подключать свои `use` (например, `random`).
- *Нельзя (рано):* файлов данных (`file.open` — №27), экспортируемых констант библиотек (уроком не показано), рекурсии (№31).
- *Честная рамка темы:* это, по сути, **третий урок практики функций** — вынос в отдельный файл здесь гарнир против скуки, а не главное блюдо. Поэтому правило повторов такое: в практике с преподавателем можно переносить **знакомые** функции (суть задания — сам переезд), а вот в самостоятельной практике все функции **новые**, которых в прошлой книге не было.
- *Градиент:* **блок 1 — механика переезда** (атомарные + поломки), **блоки 2–4 — три библиотеки с новыми функциями** (строки → числа → геймдев, от ролей к свободе), **блок 5 — звёздочки**. Карта — в заметке.
- *Словарь:* библиотека, модуль, главный файл, подключение.

Когда функций становится много, держать всё в одном файле — как хранить гардероб кучей на полу. Сегодня появляются полки: свои библиотеки. А чтобы третий урок функций не был скучным, строить будем три **настоящих** библиотеки — таких, которые не стыдно перетащить в следующий проект.

# Блок 1. Механика переезда

## Практика с преподавателем

### Задание 1. Первый проект из двух файлов

Впервые создаём **два** файла в одной папке. Файл `draw.idyl` — библиотека:

```idyllium
// draw.idyl — наша собственная библиотека
use console;

void function line(int L) {
    string res = "";
    for (int i = 0; i < L; i += 1) {
        res = res + '-';
    }
    console.writeln(res);
}
```

Файл `main.idyl` — главный, его и запускаем:

```idyllium
use console;
use draw;

main() {
    console.writeln("Строим забор:");
    draw.line(10);
    draw.line(4);
}
```

```
Строим забор:
----------
----
```

Разбор: `use draw;` — подключение **без** расширения; вызов — `библиотека.функция()`, точь-в-точь как `math.sqrt()` или `time.sleep()`. Ваша библиотека и системная подключаются одинаково — с сегодняшнего дня вы с создателями Idyllium в одном цехе.

## Самостоятельная практика

### Задание 2. Переезд ветерана

Возьмите свою `digit_sum` из прошлого урока (сумма цифр числа) и переселите её в библиотеку `mathtools.idyl`. В `main.idyl` подключите библиотеку и посчитайте сумму цифр введённого числа — вызовом `mathtools.digit_sum(...)`. Функция старая — переезд новый: убедитесь, что после переселения всё работает как раньше.

```
Число: 2026
Сумма цифр: 10
```

### Задание 3. Библиотека-призрак

Поломка. Напишите в главном файле `use ghost;`, не создавая никакого `ghost.idyl`, и запустите. Прочитайте отказ — компилятор честно сообщает о пропаже. А теперь опечатайтесь иначе: подключите настоящую `draw`, но вызовите из неё несуществующую `draw.circle(5)`. Два разных отказа — научитесь различать «нет библиотеки» и «нет такой функции в библиотеке».

### Задание 4. Грабли с расширением

Поломка, на которую наступает каждый первый. Напишите `use draw.idyl;` — с расширением — и запустите. Компилятор споткнётся о точку и выдаст целый ворох ошибок (вспомните правило из первой программы: читаем **первую**, остальные — эхо). Лекарство: в `use` расширение не пишется никогда.

### Задание 5. Заяц в библиотеке

Эксперимент. Допишите в конец `draw.idyl` собственный `main()`, который печатает «Я — тайный main библиотеки!». Запустите главный файл. Напечаталось ли? А теперь запустите сам `draw.idyl`. Что изменилось?

Вывод: выполняется `main()` только того файла, **который запустили**, — «библиотека» и «главный файл» это роли в конкретном запуске, а не звания навечно. Но чтобы не путать ни себя, ни товарищей: в библиотеках `main()` не пишем. Удалите зайца.

# Блок 2. Библиотека `strings.idyl`

Строим первую настоящую полку — инструменты для строк, которых в языке нет. Все функции новые; собираем их в один файл `strings.idyl` — к концу блока в нём будет три инструмента.

## Практика с преподавателем

### Задание 6. Повторитель — теперь навсегда

Помните звёздочку из темы циклов — «строковый повторитель», питоновское умножение строки? Тогда это был трюк на один раз. Сделаем его инструментом навсегда — первой функцией в `strings.idyl`:

```idyllium
// strings.idyl
string function repeat(string s, int n) {
    string res = "";
    for (int i = 0; i < n; i += 1) {
        res = res + s;
    }
    return res;
}
```

Из `main.idyl` проверьте: `strings.repeat("ку", 3)` и эхо для своего слова.

```
кукуку
```

## Самостоятельная практика

### Задание 7. Перевёртыш на полку

**Функция** `reverse(s)` в `strings.idyl` возвращает строку задом наперёд (накопитель с приставлением спереди — приём знакомый, а вот функцией он ещё не был). **`main`** спрашивает слово и показывает отражение.

```
Слово: кот
Отражение: ток
```

### Задание 8. Цензор

Самое интересное: **функция** `censor(text, secret)` заменяет в тексте запретное слово звёздочками **той же длины**. Внутри неё пусть трудится соседка по файлу — `repeat("*", secret.length)` (внутри библиотеки функции зовут друг друга по простому имени, без приставки!). Плюс `replace` из методов строк. **`main`** — короткая демонстрация на строке-литерале.

```
Пароль от сейфа — ******, никому!
```

### Задание 9. Секретный чат

Сборка на всей библиотеке: программа спрашивает сообщение и слово под запретом — и выпускает в эфир цензурированную версию. Весь труд делает `strings.censor`; `main` лишь спрашивает и печатает. Проверьте на длинном и коротком запретном слове — звёздочек всегда ровно по длине!

```
Сообщение: Встречаемся у старого дуба в полночь
Слово под запретом: дуба
В эфир: Встречаемся у старого **** в полночь
```

# Блок 3. Библиотека `numbers.idyl`

Вторая полка — фокусы с числами, построенные на превращениях «число ↔ строка».

## Самостоятельная практика

### Задание 10. Числовой клей

**Функция** `glue(a, b)` в `numbers.idyl` склеивает два числа в одно: `glue(12, 34)` → `1234`. Под капотом — превращение аргументов в строки, склейка и превращение обратно в число (`to_string` → `+` → `to_int`). **`main`** доказывает, что результат — настоящее число: прибавляет к нему единицу.

```
Склейка 12 и 34: 1234
Сумма склейки и 1: 1235
```

### Задание 11. Код сейфа

Шпионы собирают код сейфа из двух половинок: программа спрашивает день рождения и месяц и печатает `numbers.glue(день, месяц)` — а потом код «наоборот» (`glue(месяц, день)`). Убедитесь: от перемены мест склеиваемых меняется всё.

```
День рождения: 7
Месяц: 12
Код сейфа: 712
А наоборот: 127
```

### Задание 12. Перевёртыш числа

**Функция** `flip(n)` переворачивает число: `flip(123)` → `321`. Стройте через строку: `to_string`, разворот накопителем, `to_int`. А теперь вопрос-сюрприз: переверните `250`. Получилось… `52`?! Разберитесь, куда исчез ноль, — и сформулируйте, чем число отличается от строки с цифрами.

```
Перевёртыш 123: 321
Перевёртыш 250: 52
```

# Блок 4. Библиотека `game.idyl`

Главная стройка урока — библиотека для будущих игр. Ей можно (и нужно!) подключить `use random;` прямо внутри: библиотеки имеют право на собственные `use`.

## Практика с преподавателем

### Задание 13. Полоска здоровья

Каждая игра рисует полоску HP. Сделаем её функцией — первой в `game.idyl`:

```idyllium
// game.idyl
use random;

string function hp_bar(int hp, int max_hp) {
    int filled = div(hp * 10, max_hp);
    string bar = "[";
    for (int i = 0; i < 10; i += 1) {
        if (i < filled) {
            bar = bar + "#";
        } else {
            bar = bar + "-";
        }
    }
    return bar + "] " + to_string(hp) + "/" + to_string(max_hp);
}
```

Из `main.idyl` проверьте на 40/100, 100/100 и 7/20 — полоска обязана масштабироваться под любой максимум (в этом вся хитрость `div(hp * 10, max_hp)`).

```
Здоровье: [####------] 40/100
Здоровье: [##########] 100/100
Здоровье: [###-------] 7/20
```

## Самостоятельная практика

### Задание 14. Генератор лута

**Функция** `loot()` возвращает случайную добычу: внутри — два массива (`["Ржавый", "Стальной", "Огненный", "Легендарный"]` и `["меч", "щит", "лук", "шлем"]`), из каждого берётся случайный элемент, и они склеиваются через пробел. **`main`** выбивает три предмета подряд. Шестнадцать комбинаций из восьми слов — вот она, магия генераторов.

```
Выпал лут: Легендарный щит
Выпал лут: Ржавый лук
Выпал лут: Огненный меч
```

(Добыча случайная — у вас своя.)

### Задание 15. Монетка и крит

Две быстрые функции в ту же библиотеку: `coin()` возвращает строку «орёл» или «решка», а `crit(chance)` — `bool`: случился ли критический удар при шансе `chance` процентов (случайное 1–100 сравнить с шансом). **`main`** подбрасывает монетку и проверяет крит с шансом 30 и 90 — запустите несколько раз и убедитесь, что 90 срабатывает заметно чаще.

```
Монетка: орёл
Крит при шансе 30%: false
Крит при шансе 90%: true
```

### Задание 16. Приключение

Финал: разыграйте сценку **только на вызовах** `game.idyl`. Например: выпрыгивает гоблин; показать полоску здоровья; гоблин бьёт — здоровье падает, полоска обновляется; ваш ответ — крит или обычный удар (ветка через `crit`); с гоблина выпадает лут. Сюжет — ваш, требование одно: `main` должен читаться как сценарий из вызовов библиотеки, без «ручной» рисовки полосок.

```
Из кустов выпрыгивает гоблин!
Ваше здоровье: [##########] 100/100
Гоблин ударил! [######----] 65/100
Вы ответили обычным ударом — гоблин убежал.
С гоблина выпало: Стальной меч
```

(Крит и лут случайные — каждое приключение своё.)

# Блок 5. Со звёздочкой

Настоящая командная работа, как у взрослых. Один из вас пишет **только библиотеку**, второй — **только `main.idyl`** с тремя вопросами и подсчётом очков, не заглядывая в чужой файл. Потом сложите файлы в одну папку и запустите. Заработало с первого раза — поздравляем, вы освоили главный секрет командной разработки: договорённость о функциях важнее подглядывания в код.

### Задание 18 ⭐. Библиотека мечты

Придумайте и постройте собственную библиотеку из трёх функций, которых **вам** не хватало в Idyllium. Библиотека завелась в чужом проекте без единой правки? Так и живут настоящие библиотеки: написал однажды — пользуешься везде.

### Минутка из внешнего мира. Полки размером с планету

*Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.*

- То, что вы сегодня делали, — главный механизм всей индустрии. У Python есть склад библиотек PyPI, у JavaScript — npm: **миллионы** готовых полок, написанных такими же программистами. Нужна работа с датами, картами, нейросетями? Не пишешь сам — подключаешь.
- А теперь легенда. В 2016 году программист удалил из npm свою крошечную библиотеку **left-pad** — 11 строк кода, добивающих строку пробелами слева (по духу — сестра вашего `repeat`!). Оказалось, от этих 11 строк зависели тысячи проектов, включая гигантские, — и на несколько часов у половины интернета сломалась сборка. Мораль запомнили все: библиотеки — это сила, но и ответственность.
- Ваш `use strings;` и промышленный `import numpy` — одна и та же идея: стоять на плечах написанного раньше. Разница только в размере плеч.
