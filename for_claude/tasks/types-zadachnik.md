# Задачник: Библиотека types

Урок №22 раздела «Консоль». Составлен 2026-08-03 по [лестнице навыков](../ladder/console-skill-ladder.md), [критериям заданий](../reports/task-design-criteria.md) и [методичке Real-IT](../reports/real-it-methodology-extract.md). Все решения и образцы прогнаны через компилятор; задания с вводом дают точный образец «ввод → вывод», со случайностью и текущим временем — помечены «например».

**Для преподавателя.**
- *Доступно:* всё из уроков 1–21 — переменные, ввод, арифметика (`div`/`mod`), `writeln`/цвета, преобразования, `math.*`, `if`/`bool`, инкремент, `random`, логика, циклы, `time` (в т.ч. `.unix`), `const`, массивы с методами и агрегатами, методы строк (`count`, `substring`…); из новой темы — `use types;`: машинные целые `types.int8/16/32/64` и `types.uint8/16/32/64`, **молчаливое переполнение-оборачивание**, константы границ `types.INT8_MIN`… `types.UINT64_MAX`, методы `.to_bin()` и `.to_hex()`, обратные `types.from_bin(s, "тип")` и `types.from_hex(s, "тип")`, дробные `float32`/`float64`, `console.set_precision(n)` (0–25).
- *Нельзя (рано):* сдвигов и битовых масок (`shift_left`, `bit_and`… — №23!), `encoding` (№24), функций (№25).
- *Градиент сложности.* **Минимальная обвязка** — переменная types-типа и вывод: переполнение, `to_bin` и `to_hex` наблюдаемы без циклов и ввода. Строение: **блок 1 — атомарные**, **блок 2 — полукомплексные** (+ один инструмент, помечен), **блок 3 — комплексные**, **блок 4 — звёздочки**. Карта градиента — в заметке.
- *Словарь:* бит, переполнение, знаковый/беззнаковый, двоичная запись, шестнадцатеричная запись, мантисса.

Тема — «заглянуть под капот»: обычный `int` заботливо прячет биты, а `types` честно показывает, как числа живут в ячейках фиксированного размера. Урок не про игры, а про **понимание** — но истории тут самые игровые: обнуляющиеся счётчики, шаблоны-перевёртыши и цвета из веба. Аналогов в старых задачниках нет — всё с нуля. **Важно:** сюрпризы (оборот, «печать врёт») ученик открывает сам.

# Блок 1. Ячейки честного размера

Только тема и вывод: машинные типы и их характер.

## Практика с преподавателем

### Задание 1. Одометр

`types.uint8` — ячейка на 8 бит: от 0 до 255 и ни шагом больше. А что после 255? Наберите:

```idyllium
use console;
use types;

main() {
    types.uint8 N = 254;
    console.writeln(N);
    N = N + 1;
    console.writeln(N);
    N = N + 1;
    console.writeln(N);
}
```

```
254
255
0
```

После 255 счёт начался заново — как одометр старой машины после 999999. Это **переполнение**: все восемь бит заняты, расти некуда, и число молча оборачивается в начало. Заметьте: никакой ошибки — такова цена игры на машинном уровне.

### Задание 2. Паспорта типов

Границы каждого типа встроены константами — заучивать гигантские числа не нужно. Наберите:

```idyllium
use console;
use types;

main() {
    console.writeln("int8: от ", types.INT8_MIN, " до ", types.INT8_MAX);
    console.writeln("uint8: до ", types.UINT8_MAX);
    console.writeln("int32: до ", types.INT32_MAX);
    console.writeln("uint64: до ", types.UINT64_MAX);
}
```

```
int8: от -128 до 127
uint8: до 255
int32: до 2147483647
uint64: до 18446744073709551615
```

Буква `u` — unsigned, «беззнаковый»: минуса нет, зато плюсового запаса вдвое больше.

### Задание 3. Два портрета числа

Любое types-число умеет показать себя в двоичном и шестнадцатеричном виде. Наберите:

```idyllium
use console;
use types;

main() {
    types.uint8 A = 75;
    console.writeln("Биты: ", A.to_bin());
    console.writeln("Hex: ", A.to_hex());
    types.uint8 B = 255;
    console.writeln("А у 255: ", B.to_bin(), " и ", B.to_hex());
}
```

```
Биты: 01001011
Hex: 4B
А у 255: 11111111 и FF
```

Восемь бит — восемь лампочек: у 255 горят все, и в hex это знаменитое `FF` (два символа — ровно один байт).

# Блок 3. Собираем задачи покрупнее

## Практика с преподавателем

### Задание 14. Цвет для сайта

Жемчужина урока — из реальной жизни. Цвета в вебе записывают как `#FF8800`: три байта — красный, зелёный, синий, каждый в hex. Соберём такой код сами. Наберите:

```idyllium
use console;
use types;

main() {
    console.write("Красный (0-255): ");
    types.uint8 r = console.get_int();
    console.write("Зелёный (0-255): ");
    types.uint8 g = console.get_int();
    console.write("Синий (0-255): ");
    types.uint8 b = console.get_int();
    console.writeln("Код цвета: #", r.to_hex() + g.to_hex() + b.to_hex());
}
```

```
Красный (0-255): 255
Зелёный (0-255): 136
Синий (0-255): 0
Код цвета: #FF8800
```

Введённый вами код можно проверить в любом графическом редакторе — это настоящий, всамделишный формат. Теперь вы знаете, что `#FF0000` — это «красного на все 255, остального по нулям».

# Блок 4. Со звёздочкой

### Задание 19 ⭐. Печать врёт, сравнение — нет

Знаменитая ловушка, о которую бьются программисты всех языков. Посчитайте в обычном `float` сумму `0.1 + 0.2`, напечатайте её (увидите «0.3»!) — а потом сравните с `0.3` через `if (a == 0.3)`. Программа скажет… запустите и убедитесь сами.

Почему так — вы уже видели в задании 18: печать округляет, а сравнение смотрит на все знаки. Теперь **вылечите** программу: дробные сравнивают не на равенство, а на близость — придумайте проверку через `math.abs` и маленький порог вроде `0.0001`.

```
Печать: 0.3
НЕ равно 0.3!
После лечения: практически равно — так и сравнивают дробные!
```

### Задание 21 ⭐. Проблема-2038

В миллионах старых систем время хранится как число секунд с 1970 года — в **32-битной знаковой** ячейке. Однажды она переполнится, и часы этих систем сойдут с ума. Когда? Посчитайте: возьмите текущее время `time.now().unix`, вычтите из `types.INT32_MAX` — и переведите оставшиеся секунды в годы и дни (в году примерно 31 536 000 секунд; `div` и `mod` в помощь). Это не выдумка — инженеры всего мира прямо сейчас чинят эту проблему.

```
До переполнения 32-битного времени осталось 361786177 секунд
Это примерно 11 лет и 172 дня
```

(Число зависит от дня запуска — у вас будет своё. С каждым днём — всё меньше!)

### Минутка из внешнего мира. Когда байт ломал мир

*Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.*

Переполнения — не учебная страшилка, а причина реальных легенд:
- В оригинальном **Pac-Man** счётчик уровней жил в одном байте: на уровне 256 автомат рисовал на пол-экрана кашу из символов — игроки зовут это «kill screen». Вы смоделировали ровно его в задании 17.
- В 2014 году клип **Gangnam Style** набрал больше 2 147 483 647 просмотров — и сломал счётчик YouTube: тот хранился в `int32`. Инженеры спешно перевели его на `int64` — теперь запас до 9 квинтиллионов.
- А самая знаменитая легенда — «ядерный Ганди»: будто бы в старой Civilization миролюбие Ганди (1) случайно уменьшили на 2, байт обернулся до 255 — и главный пацифист истории начал ядерную войну. Разработчики потом признались, что это миф… но миф настолько красивый, что в новых частях игры Ганди-ядерщика оставили нарочно, как памятник переполнению.

Мораль инженера: выбирая размер ячейки, думай не о том, что в ней лежит сегодня, а о том, что в неё попытаются положить завтра.

**Карта градиента** (для подбора под силу группы):
- *атомарные* — з.1–8 (машинный тип + вывод; сюрпризы оборота: 4, 5; двойственность шаблона: 6, 7);
- *полукомплексные* — з.9 (+цикл), 10 (+ввод), 11 (+условие), 12 (+random), 13 (+методы строк);
- *комплексные* — з.14–18 (hex-цвета, mod-предсказатель, kill screen, точность float);

Красная нить — **у каждой ячейки есть край, и за краем — оборот**: молчаливый, честный, предсказуемый (з.16 доказывает: это просто `mod`). Тема нарочно «инженерная», без прикладной пользы здесь и сейчас, — но именно из неё вырастает интуиция, которая потом отличает программиста, понимающего машину, от заклинателя, повторяющего ритуалы. Идущий следом урок битовых операций обопрётся на `to_bin` из этого — навык читать «лампочки» стоит закрепить.
