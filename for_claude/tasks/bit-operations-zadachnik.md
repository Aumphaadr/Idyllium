# Задачник: Битовые операции

Урок №23 раздела «Консоль». Составлен 2026-08-03 по [лестнице навыков](../ladder/console-skill-ladder.md), [критериям заданий](../reports/task-design-criteria.md) и [методичке Real-IT](../reports/real-it-methodology-extract.md). Все решения и образцы прогнаны через компилятор; задания с вводом дают точный образец «ввод → вывод», со случайностью — помечены «например».

**Для преподавателя.**
- *Доступно:* всё из уроков 1–22, включая библиотеку `types` (`to_bin`/`from_bin`, `to_hex`, машинные типы); из новой темы — сдвиги `shift_left(n)` / `shift_right(n)` (крайние биты теряются, на освободившиеся места приходят нули; отрицательный аргумент — обратное направление; работают и на `float32`/`float64` — двигают биты без оглядки на смысл) и маски: `bit_and(mask)` (вырезать), `bit_or(mask)` (зажечь), `bit_xor(mask)` (переключить; двойное применение возвращает исходное), `bit_not()` (перевернуть всё). Маска — строго того же типа, что и значение. Все методы **возвращают** результат — сохраняйте его присваиванием.
- *Нельзя (рано):* `encoding` и кодов символов (№24 — XOR-шифруем только числа, не текст!), функций (№25).
- *Градиент сложности.* **Минимальная обвязка** — types-значение и вывод (`to_bin` из прошлого урока — глаза этой темы: без него результаты операций нечитаемы). Строение: **блок 1 — атомарные**, **блок 2 — полукомплексные** (+ один инструмент), **блок 3 — комплексные**, **блок 4 — звёздочки**. Карта — в заметке.
- *Словарь:* сдвиг, маска, битовое И/ИЛИ/исключающее ИЛИ, инверсия, флажок.

В прошлой теме мы **подглядывали** за битами — теперь начинаем **командовать**. И тема на редкость рукодельная: почти каждое задание — маленькая настоящая вещь: шифровальная машинка, байт-хранилище настроек, упаковщик данных, бегущий огонёк. **Важно:** открытия (сдвиг умножает! порядок ключей не важен!) ученик делает сам — не проговаривайте их заранее.

# Блок 1. Команды над битами

Только тема и вывод: двигаем и комбинируем биты, читаем результат через `to_bin`.

## Практика с преподавателем

### Задание 1. Сдвиг вправо и влево

Наберите:

```idyllium
use console;
use types;

main() {
    types.uint8 v = types.from_bin("00101011", "uint8");
    console.writeln("Было:   ", v.to_bin());
    console.writeln("Вправо: ", v.shift_right(3).to_bin());
    console.writeln("Влево:  ", v.shift_left(1).to_bin());
}
```

```
Было:   00101011
Вправо: 00000101
Влево:  01010110
```

При сдвиге вправо крайние правые биты **выпадают и теряются**, а слева приходят нули; влево — всё зеркально. Никто не предупреждает о потере — биты падают за край молча.

### Задание 2. Вырезать маской

`bit_and` сравнивает значение с **маской** и оставляет единицы только там, где они есть в обоих. Классика — вырезать кусок ячейки:

```idyllium
use console;
use types;

main() {
    types.uint8 value = types.from_bin("10110110", "uint8");
    types.uint8 mask = types.from_bin("00001111", "uint8");
    console.writeln(value.bit_and(mask).to_bin());
}
```

```
00000110
```

Маска `00001111` — как трафарет: старшая половина исчезла, младшая уцелела. И запомните: маска обязана быть **того же типа**, что и значение.

## Самостоятельная практика

### Задание 3. Зажечь флаг

Значение `00100100`, и нужно принудительно зажечь старший бит, не тронув остальные. Примените маску `10000000` через `bit_or` и выведите результат. `bit_or` оставляет единицу там, где она есть **хотя бы в одном** из чисел, — идеальная «зажигалка».

```
10100100
```

### Задание 4. Полный переворот

Возьмите `types.uint8` со значением 43, выведите его биты, затем `bit_not()` — и биты, и **число** результата. А теперь сложите исходное с перевёрнутым (`43 + …`). Какое число получилось и почему именно оно? (Подсказка спрятана в паспорте типа `uint8`.)

```
00101011
11010100 = 212
43 + 212 = 255
```

### Задание 5. Сдвиг за горизонт

Эксперимент-предсказание. Что останется от байта `00101011`, если сдвинуть его влево на **12** позиций — больше, чем в нём вообще битов? **Сначала предскажите**, потом проверьте. Все старые биты уехали за край, а из-за края приезжают только нули.

```
00000000
```

### Задание 6. Сдвиг задом наперёд

Ещё эксперимент. Сравните `v.shift_left(-3)` и `v.shift_right(3)` на одном значении. Совпало? Отрицательный аргумент просто разворачивает направление — знак командует «куда», а число — «на сколько».

### Задание 7. Туда и обратно

Волшебное свойство `bit_xor`: повторное применение той же маски возвращает всё как было. Наберите:

```idyllium
use console;
use types;

main() {
    types.uint8 secret = 65;
    types.uint8 key = types.from_bin("10110100", "uint8");
    types.uint8 encrypted = secret.bit_xor(key);
    types.uint8 decrypted = encrypted.bit_xor(key);
    console.writeln("Зашифровано: ", encrypted);
    console.writeln("Расшифровано: ", decrypted);
}
```

```
Зашифровано: 245
Расшифровано: 65
```

65 превратилось в неузнаваемое 245 — а второй поворот того же ключа честно вернул исходное. Запомните этот фокус: через пару заданий соберём на нём настоящую шифровальную машинку.

# Блок 2. Плюс один инструмент

### Задание 8. Как умножают процессоры *(+ арифметика)*

Возьмите число 5 и выведите рядом: `5 * 2` и `5.shift_left(1)`; затем `5 * 4` и `5.shift_left(2)`. Что вы обнаружили? Сдвиг влево на одну позицию — это умножение на 2, на две — на 4… Процессоры обожают этот трюк: двигать биты им куда быстрее, чем честно умножать.

```
Умножение: 10 и 20
Сдвигами:  10 и 20
```

А работает ли фокус в обратную сторону — сдвиг вправо как деление? Проверьте на чётном и на нечётном числе.

### Задание 9. Шифровальная машинка *(+ ввод)*

Соберите настоящий шифратор. Ключ вшит в программу константой (`const int KEY = 180;` — свой придумайте сами). Программа спрашивает секретное число (0–255) и выдаёт шифровку через `bit_xor`.

```
Секретное число (0-255): 65
Шифровка: 245
```

### Задание 10. Дешифратор *(+ ввод)*

Вторая половина машинки: программа спрашивает перехваченную шифровку и тем же ключом возвращает исходное число. Проверьте пару на себе: зашифруйте число первой программой, расшифруйте второй. А теперь — обменяйтесь шифровками с соседом (договоритесь об общем ключе!): его программа должна расшифровать вашу шифровку.

```
Перехваченная шифровка: 245
Исходное число: 65
```

### Задание 11. Негатив *(+ случайность)*

Сгенерируйте случайный байт и выведите его биты, а рядом — биты его «негатива» (`bit_not`). Убедитесь глазами: каждая лампочка перещёлкнулась.

```
Байт:    01111110
Негатив: 10000001
```

(Число случайное — у вас своё.)

### Задание 12. Чётность по последнему биту *(+ условие)*

У чётных чисел последний бит — всегда 0, у нечётных — 1. Программа спрашивает число и определяет чётность **без** `mod`: вырезает последний бит маской `00000001` через `bit_and` и смотрит, ноль там или единица. Проверьте на паре чисел и сравните с привычным `mod(n, 2)` — две дороги к одному ответу.

```
Число: 37
Нечётное (последний бит 1)
```

# Блок 3. Собираем настоящие вещи

## Практика с преподавателем

### Задание 13. Два числа в одном байте

Жемчужина у доски. В доме 16 этажей (0–15), на каждом до 16 квартир (0–15). Оба числа помещаются в 4 бита — значит, **пара упакуется в один байт**: этаж в старшую половину, квартира в младшую. Наберите:

```idyllium
use console;
use types;

main() {
    console.write("Этаж (0-15): ");
    types.uint8 floor = console.get_int();
    console.write("Квартира на этаже (0-15): ");
    types.uint8 flat = console.get_int();

    types.uint8 packed = floor.shift_left(4).bit_or(flat);
    console.writeln("Упаковано в байт: ", packed, " = ", packed.to_bin());

    types.uint8 mask = types.from_bin("00001111", "uint8");
    console.writeln("Распаковка: этаж ", packed.shift_right(4), ", квартира ", packed.bit_and(mask));
}
```

```
Этаж (0-15): 7
Квартира на этаже (0-15): 12
Упаковано в байт: 124 = 01111100
Распаковка: этаж 7, квартира 12
```

Разберите цепочку: `shift_left(4)` отвёз этаж в старшую половину, `bit_or` подселил квартиру в младшую, а распаковка — те же инструменты задом наперёд. Так пакуют данные по-настоящему: экономия памяти — половина инженерного ремесла.

## Самостоятельная практика

### Задание 14. Бегущий огонёк

Соберите гирлянду: байт — это восемь лампочек, и горит одна, крайняя правая (`types.uint8 light = 1;`). В цикле: показать биты, подождать `time.sleep(0.3)`, сдвинуть огонёк влево на одну позицию. Восемь шагов — огонёк пробегает всю гирлянду… а на девятом? Покажите и его.

```
00000001
00000010
00000100
...
10000000
Гирлянда погасла: 00000000
```

Огонёк убежал за край — вы вживую увидели потерю бита из задания 5.

### Задание 15. Настройки в одном байте

В сохранении игры все переключатели живут в одном байте: бит 0 — звук, бит 1 — музыка, бит 2 — вибрация (заведите маски-константы `00000001`, `00000010`, `00000100`). Разыграйте сценку: игрок включил звук и музыку (`bit_or`), потом передумал насчёт музыки (`bit_xor` — переключатель!), а в конце программа проверяет через `bit_and` и `if`, включён ли звук. После каждого действия показывайте байт.

```
Включили звук и музыку: 00000011
Переключили музыку: 00000001
Звук сейчас включён
```

Восемь ответов «да/нет» в одной ячейке — именно так игры и хранят свои галочки.

### Задание 16. Машинка с полной проверкой

Объедините шифратор и дешифратор в одну программу: спросить число **и ключ** (оба 0–255), показать шифровку, тут же расшифровать её и сравнить с исходным через `if` — совпало ли? Программа-самопроверка: если когда-нибудь «не совпало», значит, где-то опечатка.

```
Число: 100
Ключ: 200
Шифровка: 172
Проверка: расшифровалось обратно в 100 — машинка исправна!
```

# Блок 4. Со звёздочкой

### Задание 17 ⭐. Двойной замок

Шпион шифрует число **двумя ключами по очереди**: сначала XOR с первым, потом с вторым. Вопрос на догадку: в каком порядке крутить ключи при расшифровке — обязательно в обратном? Постройте опыт: расшифруйте двойную шифровку сначала ключами в обратном порядке, потом в том же самом — и сделайте вывод, которому позавидует иной взрослый программист.

```
Двойная шифровка: 184
Ключи наоборот: 65
Ключи в том же порядке: 65
```

### Задание 18 ⭐. Тайное тождество

Исследование. Возьмите любой байт и примените к нему `bit_xor` с маской из **всех единиц** (`11111111`). Выведите результат рядом с `bit_not()` того же числа. Что вы обнаружили? Сформулируйте открытие одной фразой — вы только что доказали, что одна из четырёх операций выражается через другую.

```
11010100
11010100
```

### Задание 19 ⭐. Химера

Сдвиг работает и на дробных типах — но у `float32` биты не равноправны: там знак, порядок и мантисса (вспомните прошлый урок). Сдвиньте `types.float32` со значением `4.5` влево на 3 и выведите биты до, биты после и само получившееся «число». Осмысленного умножения не выйдет — выйдет химера. Объясните по строению `float32`, **что именно** сломалось: чей бит уехал на чужое место?

```
01000000100100000000000000000000
00000100100000000000000000000000
3.009265538105056e-36
```

### Минутка из внешнего мира. Биты в дикой природе

*Это не задание — делать ничего не нужно. Просто любопытное из большого мира, читается за минуту.*

- Трюк «сдвиг вместо умножения» из задания 8 — не игрушка: в старых играх программисты писали `x << 3` вместо `x * 8`, выжимая скорость из слабых процессоров. Современные компиляторы делают эту замену сами — но читать чужой код с `<<` вы теперь сможете.
- Команда `chmod 755`, которой на серверах выдают права на файлы, — это те же битовые флажки: три бита «читать-писать-запускать» на владельца, группу и остальных. Админы всего мира щёлкают битами каждый день, как вы в задании 15.
- А XOR-шифр из вашей машинки — младший брат «одноразового блокнота»: если ключ случаен, длинен как сообщение и использован лишь однажды, такой шифр **математически невзламываем**. Это не преувеличение, а доказанная теорема — и на ней держалась связь разведок весь XX век.

Биты — не музейный экспонат из прошлого урока: ими прямо сейчас щёлкает весь мир.
